# 140 干员动作审计：出手对时、攻速、跑动步频、星熊格挡、塞雷娅 S3（2026-10-24）

用户原话（协调人转）：「星熊现在的格挡动作是不是在跑动的时候会有点奇怪，然后塞雷娅三技能丢盾牌显得很奇怪，看看能不能调整。同时看看目前所有干员的攻击帧和跑动帧和实际攻击触发等等是不是能好好对上，速度是否正常，进行审计。」

分支 `claude/anim-audit`（基于 main 550798898）。改动全部只动画面：五名有改动的干员（水月 / 星熊 / 塞雷娅 / 浊心斯卡蒂 / 乌尔比安）同 seed 240 秒 TRACE 都与 main 逐行相同。

## 1. 方法

- **对时探针** `tools/probes/anim_sync_probe.py` + `game/tests/anim_sync_probe.gd`：每名干员单独开一局（`--balance --bot=expert`，seed 1，60 秒），按 1/60 秒逐帧记录以下事件：
  - 起手（`attack_t` 跳升）；
  - 出手（`fire_t` 到点）那一帧的画面帧条和帧号；
  - 伤害结算（`dmg_out` 按来源的增量）；
  - 新弹体；
  - 跑步相位推进；
  - 收势让位；
  - 技能序列在移动中播放非跑动段的帧数。

  汇总成全员一张表，标出偏差超过 1 帧的项。只读，不改模拟。
- **实机录像** `tools/probes/anim_move_capture.py` + `game/tests/anim_move_capture.gd`：放技能或普攻时，队长按「走 45 帧、停 30 帧」来回移动，逐帧截图，合成 1/3 速 gif。
- **攻速推算**：读探针记录的普攻间隔 `cd`，结合帧条的 `attack_timing`，算出 1.5 / 2 / 3 倍攻速时动作窗口 `dur` 和间隔的关系。
- 表格与录像在主仓库 `build/anim_audit_1024/`（不进 git）：
  - 改前表 `table_before.md`、改后表 `table.md`；
  - 新旧 gif 各三组；
  - 对照图 `cmp_*.png`。

## 3. 已修（纯画面）

### 3.1 出手帧播完再让位（`character.gd act_anim_yield / _sq_atk_yield`）

- **改前**：`elapsed >= attack_fire_at` 且在移动、没有 `move_*` 跑动版时，当帧就让给跑步。
- **改后**：加一个条件，只有画面帧号已越过出手帧（`_act_frame(elapsed) > _act_frame(attack_fire_at)`）才让位。也就是先完整显示出手那一帧，然后才切跑步，收势照旧不拖。技能序列里的普攻变体（`_sq_atk_yield`）同样改。
- **结果**：改后表里所有技能的出手帧偏差都是 0，不再出现 `other{run}`。
- **悬浮干员**：新加 `sprites.hover_attack = true`（目前只有浊心斯卡蒂）。跑步是悬浮飘行、腿不交替的干员，移动中出手动作照常播完，不让给跑步条。

### 3.2 星熊 S1 格挡 + 跑动

- **原因**：S1 序列是 `s1 → s1_guard（单帧定格，3 秒窗口）→ s1_counter`，没有 `run` 段。窗口里一移动，画面就停在单帧举盾姿势平移，看起来是原地滑行。
- **修法**：用 `tools/op_1x/native_extra.py` 从原作 Spine 出一条新帧条 `op_hoshiguma_s1_guard_move@1x.png`，8 帧，与跑步条同节奏。
  - 上半身取原生 `Skill t=0` 的举盾姿势，腿用 run_trial 的跑步步态（`move_attack` 模式，与移动攻击同一管线）；
  - 序列加 `"run": "s1_guard_move"`；
  - 序列跑动段现在和普通跑步共用 `run_ph` 相位，步频随移速变化。原来只有名为 `run` 的帧条才这样，现在 `character.gd _sq_frame` 和 follow 的推进条件已放宽。
- **结果**：改后探针里星熊 `s1_guard` 不再出现在「移动中滑行」名单。对照见 `cmp_hoshiguma_s1.png`、`hoshiguma_0_old/new.gif`。

### 3.3 塞雷娅 S3「钙质化」放盾

- **原作**（PRTS Spine，`build/prts_ref/saria`）：
  - `Skill_Begin` 把盾平放到身后地上、武器放到身前地上；
  - `Skill_Loop` 不改这两个槽，运行时它们留在地上；
  - `Skill_End` 第 4 帧把盾拿回手里。
- **改前**：1 倍帧条起手第 2 帧盾就凭空消失，循环和收势都没有地上的盾，这就是「丢盾牌很奇怪」。另外，循环段没有 `run` 段，10 秒里一移动就整段原地滑行。
- **修法**：`native_extra.py` 按原生动画重出三条帧条（帧数 / 逐帧时长 / 出手帧不变，出手时刻不变）：
  - 起手 `op_saria_skill`：放盾全过程；
  - 循环 `op_saria_skill_s3_loop`：叠上地上的盾和武器；
  - 收势 `op_saria_skill_s3_end`：前 3 帧盾和武器还在地上，第 4 帧拿回手里。

  另新加跑动段 `op_saria_skill_s3_run`（原生 Loop 的空手上半身 + 跑步腿）。序列加了 `"run"`，移动时播空手跑，停下回到脚边有盾的循环。
- **用户 10-24 定：技能期间全程空手打**（见 §7.2）。循环段 / 收势段不再画地上的盾，起手放盾那一下正好被钙质化晶柱特效盖住，没有「停下出现、起步消失」的问题。

## 4. 已查、不改（只出结论）

- **短施法动作没有跑动版**：星熊 S1 起手 / 收势约 0.5 秒、逻各斯 S1 起手 0.67 秒，移动中放会短暂平移。要彻底解决，得给每个技能动作做 `move_*` 帧条。建议等用户觉得明显时再按人补，管线同 §3.2。
- **德克萨斯**（texas-block 在改）：移动中技能出手画面是跑步（12/12）。她的技能起手走 SegTexas 冲刺段，不经过 `act_anim_yield`，交给 texas-block 一并看。
- **乌尔比安**（ulp-charge-fx 在做 S3）：技能出手时画面是 `tether_native`，原生动作链接管，对时由原生链负责，没看到偏差。
- **拉普兰德**（lappland-lord 在改）、**维什戴尔**（wisadel-s2-run 在改）：本轮数据都正常，普攻出手 0 偏差、跑步不滑；她们分支合入后建议重跑探针。
- **推进之王**：技能出手时画面是「待机」，这是原设计（技能取消号令，复用原生持锤 Idle），不是问题。

## 7. 用户 10-24 追加决定与实现

用户原话：「塞雷娅技能期间能不能改成跑动拳击？用 spine 编辑器。星熊需要格挡吗，这游戏格挡感觉没有什么用啊」→「格挡我觉得可以修改为她可以站在原地不跑动，吸引一部分怪物的仇恨，然后发动防御反击」→「星熊 S1 按站定嘲讽 + 防御反击做（队长时不定身），塞雷娅技能期间空手拳击也一起做。」

### 7.1 星熊 S1「战意」：站定嘲讽 + 防御反击（玩法改动）

- 新积木 `verb.taunt_guard`（只能放技能 do，docs/61 已登记）：
  - **队员时**：出手时记下站定点，技能期间钉在那里不跟队长（`data_operator.follow_target` → `taunt_anchor`）；
  - **队长时**：照常移动（移动时播 §3.2 的举盾跑动条）；
  - **嘲讽**：每帧把半径 `s1_taunt_r`（200 × 攻击范围倍率）内的近战杂兵改追她，用的是召唤物诱饵同一套 `e.aggro`。Boss 和宝箱不受影响；
  - **结束反击**：执行 `on_end`，「举盾反击」以自身为中心，半径 120、击退 360，倍率 = `s1_mult` 2.0 + `s1_per` 0.1 × 期间拉到的不同敌人数。不设上限，嘲讽半径和 3 秒窗口就是软限制；
  - 画面：脚下金色虚环标出嘲讽范围，出手时飘「战意」，结束时飘「反击 ×N」。
- 原「格挡下一击」（`verb.negate_next`）积木保留可用，星熊 S1 不再用它。天赋「战术装甲」的概率格挡没动。
- 文案：「{$s1_window} 秒内举盾坚守原地，吸引半径 {$s1_taunt_r} 内近战敌人的仇恨（作为队长时可照常移动）；结束时向周围反手重斩（半径 {$s1_r}，×{$s1_mult}，每吸引一名敌人再 +{$s1_per}）并击退」。
- 回归 `hoshiguma_taunt`（`game/tests/hoshiguma_taunt_test.gd`，12 项）：
  - 队员站定，队长跑开 40 帧，偏移 < 2 px；
  - 4 只杂兵都被拉到、往她身上靠；
  - Boss 不吃嘲讽；
  - 结束打出举盾反击；
  - 原积木倍率不被改写。
- 这项改了玩法，星熊的同 seed 结果与 main 不同，属预期。数值是首版，按 docs/111 的口径等下一轮批跑再调。

### 7.2 塞雷娅 S3：技能期间空手拳击（纯画面）

- **出拳动作**：在原生 `Skill_Loop` t=0 的空手站姿上逐帧转左臂（面朝右时在前的那只）、胸和后臂，得到 8 帧出拳。左臂 IK 混合为 0，走 FK。关键帧表 `PUNCH` 在 `tools/op_1x/native_extra.py`，第 4 帧出拳打满，出手帧与普攻条相同。
- **跑动版**：`run_trial.js` 的 move_attack 模式新支持 `poses`（`posedFrame(i, k, raw)` 只返回骨架），出拳上半身直接接跑步腿，与移动攻击同一管线。spine 编辑器读的是同一套骨架数据，以后要逐帧微调手臂，可以在编辑器里打开同一份姿势继续改。
- **新帧条**：`op_saria_skill_s3_attack`、`op_saria_move_skill_s3_attack`。json 里时序抄普攻的 `attack_timing`，序列加 `"attack": "skill_s3_attack"`。
- **代码**：`character._move_swap` 允许技能循环里的普攻变体（`sq_atk`）在移动中换跑动版；`_sq_atk_yield` 在变体有跑动版时不让位。
- **结果**：录像（`build/anim_move/v2/saria_2.gif`，技能期间照常普攻、走停来回）里循环段的出拳 205 帧，其中移动中 112 帧换成跑动拳击；不出拳时站着播循环、移动播空手跑。
- **定稿：冲拳**（用户依次反馈「看不太出来双手，能不能手往前伸」→「拳头好像太大了」→「都不要放大」→「第一帧双手举过头有点奇怪」→「拳击就改成冲拳」）：前手（左臂）直线打出，后手收到腰侧，胸口前倾 14°；打出的几帧把前臂画在白毛领上层，1 倍下能看出拳头。不拉长不放大，蓄力只收到腰前。中途试过双拳前推、手臂 ×1.3 / 拳头 ×1.4 和 ×1.1，都被否了。实机里技能晶柱特效较密，站在队长身前的博士也会挡一部分。
