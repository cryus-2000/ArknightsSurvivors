# 229 特效美术统一规范（11-02 初稿）

**适用范围：** 所有新做或重做的战斗特效，包括 pixelfx、Codex 帧条、pixgen 大贴图 + 代码驱动、GDScript 程序绘制四条路线。目标是四条路线最后收敛成一套观感。

**不在范围内：**
- 人物本体精灵（干员和怪物都不管）。
- 终结技主视觉：冲击帧和终结技专属大贴图另按 docs/198 / 216 执行，本规范只约束终结技里顺带用到的通用小件。

本规范**不改游戏代码**。§9 的五份分工开工时才按条款改。

来源：
- docs/228（pixelfx 评估与试点，斯卡蒂 / 星熊 / 能天使）
- balance `render/optical_col_*`、`render/optical_fx_cap`
- docs/50、206、226（帧时）
- docs/87 §4.3（设定色与 PRTS 一致）
- 用户口径：10-30 否掉规整放射 / 同心圈；10-31 冲击帧只给终结技；11-02 包体办法「可以没问题」

## 0 硬数字速查

| 项 | 规定 |
|---|---|
| 密度 | 1x 美术像素 = **2 世界像素**（Game.PX），@2x 帧条是 1 贴图像素 = 1 世界像素，和 64 画布 @2x 干员同密度。游戏里按半径适配时，每个 1x 像素允许占 **1.6–2.2** 世界像素；**超过 2.2 一律违规**（斯卡蒂旧刀光 6.2、星熊旧力之锯 3.4、斯卡蒂旧潮环 3.2 都是反例） |
| 色板 | 每位干员 **7 阶**（暗 → 设定色 → 白），见 `tools/pixelfx_fx/house.js` 的 `OP`（设定色按 PRTS；低三阶 = 设定色 × 明度 35 / 60 / 80%、饱和度不降，发光特效不往深海黑靠，11-02）。敌方危险色 **#ff2667**（optical_col_danger h .95 s .85 v 1），Boss **#ff6726**，海嗣发光 **#4dc9ff**，敌弹 **#33ceff**，我方灯火 **#ff9640**，掉落 **#fff1bf** |
| 帧率 | 普攻命中 / 枪口 **24**；技能、敌方 **20**；人物姿势仍按原帧条（8–12）；拖尾、颗粒由程序逐帧画，不进帧条 |
| 时长 | 主体：普攻命中 **≤ 0.2 s**（≤ 5 帧 @24），枪口焰 ≤ 0.15 s；技能 **0.3–0.6 s**（≤ 12 帧 @20）；敌方落点爆 ≤ 0.4 s。**余韵另给**：普攻 +0.15 s、技能 +0.6 s、敌方 +0.4 s，alpha ≤ 0.4（§2.5）；**敌方预警时长 = 判定前摇，严格一致**；终结技另论 |
| 亮暗 | 第 1 帧核心爆亮、白色只在核心，之后冷却；近白像素占全帧 **≤ 12%**，验收硬卡（§2.4） |
| 形状 | 不规整：外缘按噪声起伏，重复元素间距随机（±30% 以上）；**禁止**等距放射、等距同心圈、同一子图等距排列 |
| 发光 | **光晕单独成 `<名>_glow` 条、游戏里加色叠画**（§2.7，k 缺省 0.5）；通道亮度上限 **1.4**（render/optical_fx_cap，tint 不超过 1.3 留余量） |
| 体量 | 刀光弧 = 伤害半径 × **0.85**；直线斩 = 全长 × 1.0；地面圈 = 半径 × 1.0；命中特效 ≤ 敌人半径 × 1.5 |
| 色数 | color 层与 glow 层各 **32 色**调色板 PNG（实测比 64 色小 5–10%，肉眼无差；大块半透明的可试 24 色，过 vreview 才用） |
| 单条上限（调色板 PNG，本体 + glow 合计） | 普攻 **≤ 4 KB**；技能 **≤ 24 KB**；敌方 **≤ 14 KB**；单张显存 ≤ 2 MB |
| 每人上限 | 普攻 ≤ 8 KB；技能合计 ≤ 65 KB |
| 总增量 | 20 人 + 敌方合计 **≤ 1.7 MB**（PNG，11-02 用户定光晕 + 余韵后从 1.2 放宽；用音频腾出的 1.39 MiB 补），导出后约 1.4 MB（Godot 导出约为调色板 PNG 的 0.83 倍，实测见 §2.9） |
| 冲击帧 | 整屏白 + 黑剪影**只给终结技**，技能 / 普攻 / 敌方都不准用 |

## 2 条款

### 2.1 像素密度
- 帧条按游戏里的最终尺寸画，**不靠运行时放大**：
  - 1x 帧条（`名.png`）在游戏里按 2 世界像素 / 像素画；
  - @2x 帧条（`名@2x.png`）按 1 世界像素 / 像素画。
- 按伤害半径适配的特效（blade 的 fit / k、ob_fx 的 fit），算出来的每 1x 像素世界像素必须在 **1.6–2.2**。超出就重画一档尺寸，**不许改 max_scale 硬放**。
- 同一特效需要两档以上尺寸（如普通 / 强化半径差 1.5 倍以上），出两张帧条。

### 2.2 色板
- **深海环境梯度：** `#06142a #0b2d55 #134f86 #1f7fb5 #3fb4d8 #8fe3ef #d9fbff #ffffff`。只给烟、碎石、焦痕这类非发光部分用，不用纯黑。**发光特效（刀光、法术、能量、命中）最暗一阶不往 `#06142a` 靠**，用干员色阶低阶，淡出靠 alpha（11-02 改，docs/238：原写法让发光特效描了一圈深蓝黑）。
- **干员色阶：** 7 阶，暗 → 设定色 → 白，初值由各干员 JSON 的 `col` 生成，写在 house.js `OP`。
  - 设定色以 PRTS 立绘为准（docs/87 §4.3），接手会话核对后改 `OP`，并在提交说明里写出处。
  - 水月 JSON 没有顶层 col，要先补。
  - 星熊试点的力之锯用了红色色阶，而她 JSON 的 col 是金色 #f2bf4c。A 组要按 PRTS 核实她技能特效的颜色，再定是保留还是改。
- **功能色**（取自 balance，改要动 balance，不要在特效里另写）：
  - 危险 #ff2667（h .95）
  - 敌潮 #ff2626（horde h 1.0，危险色随潮汐向它插值）
  - Boss #ff6726
  - 海嗣发光 #4dc9ff，精英 #a6e4ff
  - 敌弹 #33ceff
  - 灯火 #ff9640
  - 掉落 #fff1bf
  - 环境 #566b6b
- **我方与敌方分色：** 色相 **0.92–0.98、饱和度 > 0.6 的品红红**留给敌方危险色，我方特效不准大面积使用。
  - 能天使 / 维什戴尔 / 斯卡蒂（浊心）的红偏这一区（浊心 h ≈ 0.97 正落在里面），它们的特效靠白热芯 + 偏暖高光（往 h 0.0–0.03 拉）来区分。
  - 浊心斯卡蒂的设定红与危险色冲突。**用户 11-02 定：保留设定红，靠明暗区分**——她的色阶偏暗偏深（低明度血红 + 近黑暗部 + 白色高光，中段最亮的红 v ≈ 0.6，不出现亮洋红中间阶），与敌方高明度高饱和的危险色 #ff2667 拉开；敌方危险色不改，敌方预警另靠固定轮廓区分。色阶见 house.js `OP.skalter`（Art.OP_RAMP 同步）。

### 2.3 帧率
- 普攻命中、枪口：24 fps；技能：20 fps；敌方：20 fps；终结技里的通用小件：20 fps。
- 人物姿势帧条不在本规范范围，按原帧条。
- 拖尾、跟随目标的颗粒、余波环由程序逐帧画（world.tb_*、fx_grains），不进帧条。

### 2.4 亮暗节奏
- **爆亮：** 第 1 帧（最多 2 帧）核心最亮；**白色只在核心**，不铺成整块白（11-02 改：原写「最亮两阶 ≥ 40%」被做成白椭圆 / 白弯月，docs/238）。
- **近白 ≤ 12%**（整条帧条的非空像素里）是验收硬卡，超了返工。口径（11-03 统一）：近白 = RGB 最小通道 > 0.85 且饱和度 < 0.2（亮黄 / 亮金不算白）。豁免：单帧 ≤ 32×32（@2x）的小火花 / 星点；设定色本身近白的干员（拉普兰德、幽灵鲨）按「核心以外用色阶第 4 阶以下」验。最终以统一录像的 vreview 整屏探针为准。
- **冷却：** 之后往暗降阶，外缘先暗、芯最后暗（house.js `heat(t, cool)`，cool 缺省 0.35 s）。
- **收尾：** 末段用溶解、碎裂或散成颗粒，**不用棋盘格抖动淡出**（试点里能天使、斯卡蒂旧帧条的末帧都是棋盘格）。半透明一律用真半透明，pixelfx 里用 `p.blend` / `p.disc`，Codex 交付时用 alpha 通道。
- **帧条最后一帧必须为空。**

### 2.5 时长档
| 档 | 时长 | 帧数上限 |
|---|---|---|
| 普攻命中 | ≤ 0.2 s | 5 帧 @24 |
| 普攻枪口焰 | ≤ 0.15 s | 4 帧 @24–30 |
| 普攻弹道 | 循环 ≤ 4 帧 | — |
| 技能 | 0.3–0.6 s | 12 帧 @20 |
| 敌方预警 | **等于判定前摇**，由程序画，不用帧条 | — |
| 敌方出手 / 落点爆 | ≤ 0.4 s | 8 帧 @20 |
| 终结技 | 另论 | — |

**余韵（用户 11-02 定，docs/238）：** 上表是「主体」上限。主体之后可以另加余韵——火星带重力落地、烟团散开、焦痕 / 水渍慢慢淡掉，这是 pixelfx 手感的一大半：
- 普攻余韵 ≤ 0.15 s（用户 11-02 定，普攻量大、要限频），技能余韵 ≤ 0.6 s，敌方落点余韵 ≤ 0.4 s（且不得盖住预警）。
- 余韵段 alpha ≤ 0.4、像素稀疏（不铺满），帧率可降到 15（house.js `FPS.tail`、`DUR.basicTail / skillTail`、`TAIL_ALPHA`）。
- 普攻余韵仍走三档限频；满屏时第三档只留主体、砍掉余韵。帧时统一在全部美术合完后测（§9 第 5 条）。
- 帧数上限相应放宽：普攻 ≤ 5 + 3 帧，技能 ≤ 12 + 9 帧。

### 2.6 形状语言
- **一个焦点：** 每个特效只有一个焦点（刀头、落点、命中点），其余是它的余波。
- **外缘不规整：** 用噪声起伏（pixelfx `noise()`），不用周期正弦。斯卡蒂试点第一版用正弦被预审抓出「等距切片」，这是前车之鉴。
- **重复元素：** 水柱、锯齿、火星这类元素，间距和大小随机，变化幅度 ≥ ±30%。
- **禁止**（用户 10-30 已否）：
  - 等距放射线
  - 两道以上等距同心圈
  - 同一子图等距并排（斯卡蒂浪墙 fx_skadi_wave 现在就是这样）
- **地面圈：** 画在透视椭圆上（sy 0.55，同游戏地面圈），远半圈在人物身后、近半圈在前。

### 2.7 发光
- **分层（用户 11-02 定，docs/238）：** pixelfx 的柔和感全在 light 加色层。导出时 light 层单独存成 `<名>_glow` 帧条（黑底、32 色调色板），游戏里在加色层 fx_add 按本体同一变换叠画（`vfx.px_glow`，积木 / 普通帧条 / 连携帧条三处入口都接了），**不再烤进颜色后量化**（那样会被量化吃掉，原作半透明像素 65–91%、我们烤进去后普攻只剩 5–23%）。
- `<名>_glow` 和本体一样登记在 art.gd 本组块（帧数 / fps 同本体），`tools/pixelfx_export.py` 会打印两行。
- 光晕强度 opts.light 缺省 0.5（house.js `GLOW.k`，导出脚本自动加），半径约核心的 2–3 倍（`GLOW.ring`）。color 层本身保持硬色阶、不做柔光。
- **游戏里：** 大光由 optical 层负责，按 render/optical_* 走。
  - 通道上限 render/optical_fx_cap = **1.4**（FD.col_cap），帧条 tint ≤ 1.3。
  - 局部光预算 optical_local_light 1.6，不要用多叠几层来绕开。
- 近白像素占比 ≤ 12%（vreview 探针口径），超了就发白。

### 2.8 体量
- 刀光弧：落在伤害半径的 **0.85**（用户 11-02 看斯卡蒂对照后定）。
- 直线斩：长度 = 判定全长，宽度 ≤ 判定宽。
- 地面圈：外沿 = 判定半径。
- 命中：≤ 敌人半径 × 1.5。
- 敌方落点：= 判定半径，不许更大，否则玩家会误判躲避范围。

### 2.9 体积与性能
- **导出流程：** 用 `tools/pixelfx_export.py`（或照它的做法）：以原点为中心对称裁边、去掉末尾空帧、32 色调色板 PNG。**不许存回 RGBA**。试点原先存 RGBA，10 张帧条 154 KB；改存调色板后 55 KB。
- **导出体积实测：** 导入后的 .ctex 是调色板 PNG 的 **0.78–0.89 倍**（试点合计 54.7 KB → 45.7 KB），网页导出再经 export_web 的 WebP 无损最高档。所以按 PNG 体积记账即可。
- **单条上限：** 见 §0。超了按这个顺序处理：先裁帧数 → 再降到 24 色 → 再降 fps → 最后缩画布。
- **运行开销：**
  - 每个实例每帧一次贴图绘制，和现在的帧条一样。
  - 新特效不许新增每帧的 GDScript 逐像素运算。pixelfx 的 draw() 不移植成 GDScript（docs/228 §4，B 路线不可行）。
- **同屏和限频：**
  - 普攻命中沿用现有三档火花的同屏上限和限频口径（vfx.gd `_tier_fx`），新帧条只替换画面，不加实例。
  - 技能特效同一干员同屏 ≤ 6 个。
  - 敌方落点特效同屏 ≤ 12 个（后期按 docs/226 分层）。

### 2.11 变体与实时火星（用户 11-02「加上」）
- **变体：** 每条 pixelfx 帧条导出 **3 个种子变体**（普攻 2 个）：`<名>`、`<名>_v1`、`<名>_v2`，各带 `_glow`，全部登记在本组块。targets 里写 `"variants": N`（缺省 3）、`"seed"`（首个种子，缺省 1；写在 opts 里的 seed 也认）。
- **播放：** 游戏在开播时（`vfx.fx_sprite`、积木 `ob_fx.fx_spawn`、连携 `ult.strip` 三个入口）对名字含 `_px_` 的帧条自动：随机挑一个变体、随机沿自身朝向轴镜像、转 ±0.1 弧度（`vfx.px_vary`）。**地面类（fx_sprite ground、积木 layer floor、连携 layer back）和全部敌方 fx_e_px_* 只挑变体、不镜像不转角**（透视与判定椭圆要对齐，E 组 11-03）。只用视觉随机数 vrng，判定不动，同 seed TRACE 不变。各组不用改代码。
- **实时火星：** targets 里写 `"spark": [颗数, 色阶下标 0–6, 速度]`，导出时写进 `<名>` 登记的第 3 项（`"fx_x_px_hit": [5, 24.0, [6, 5, 180.0]]`）。开播那一刻用现有火星（`vfx.sparks`）喷一把，颜色取本人色阶（`Art.op_ramp`；敌方 fx_e_px_* 取危险色阶），方向 = 特效朝向（有朝向时），同屏上限、低画质减半照旧（docs/226）。建议：命中 4–8 颗、爆点 8–14 颗，速度 120–220；普攻 ≤ 4 颗。
- **预算：** 变体计入 1.7 MB 总预算和每人上限；超了先减变体数（技能 3 → 2），再按 §2.9 顺序裁。
- **覆盖表：** docs/237 增加「变体数」「火星」两列，按人验收时一起看。

### 2.10 冲击帧
整屏白 + 黑剪影是用户定的**终结技专属**做法（10-31），技能、普攻、敌方一律不用。技能可以用局部 1 帧爆亮代替。

## 3 普攻档（用户 11-02 追加）

pixelfx 可以给普攻写专属特效，不必用库里的模板，但必须按普攻预算：

| 项 | 规定 |
|---|---|

## 6 普攻火花按规范改良（不换 pixelfx，只借手法）

现有三档火花在 vfx.gd:373 `_tier_fx`，GPU 迸溅在 optical_particles，CPU 颗粒在 fx_grains。要点：
1. **偏心十字闪：** 顺着打击方向的那一臂最长（≈ 2 倍），反向最短，替代对称星。
2. **首帧爆亮、0.05 s 后降一阶：** 现在光团是线性淡出，改成 1 帧白 → 色阶冷却。
3. **火星：** 长度随速度拉伸，两色（头白尾色阶第 3 阶），寿命随机 ±40%，抛射角集中在打击方向 ±0.9 rad，不要 360° 均匀。
4. **颜色：** 用干员色阶第 4–6 阶，不用通用白黄。
5. **数量和寿命不加：** 只改形状和颜色，保持现有帧时（docs/50 §26.3 颗粒层 0.1–0.3 ms）。

## 8 加进 vreview 检查单的自动项

建议加进 `vreview_lists.json` 的 ult_fx / skill_fx：
1. **放大检查（离线，不用模型）：** 对帧条和 JSON 的 fit / 半径算每 1x 像素的世界像素，> 2.2 报高。脚本可以放进 `tools/pixelfx_export.py --check`，或做成快检项。
2. **棋盘格淡出：** 帧内 2×2 交替透明的像素块占非空像素 > 15% 报中。
3. **近白占比：** > 12% 报中（现有探针）。
4. **末帧非空：** 帧条最后一帧非空像素 > 0 报中。
5. **等距重复：** 沿弧 / 线做自相关，周期峰值 > 0.8 报高（对应「拼接感」）。模型现在常把同一刀光换角度复用也报成拼接，这一项用离线算法代替模型判断。
6. **敌我同色：** 我方帧条里色相 0.92–0.98、饱和度 > 0.6 的像素占比 > 20% 报中（敌方危险色保留区）。
7. **单条体积：** 超过 §0 的档位上限报中。
