# 68 · 潮汐合约：危机合约式自选难度（设计 + 概念，2026-10-12）

> 用户 10-12：「难度可以改成自选条目」「奖励暂时只给荣誉」。
> 制作人方向：标准 / Ⅳ / Ⅷ 留作「推荐合约」（= 今天的修正表原样，现有校准继续有效）；新增「自定义合约」；只有推荐合约按 50–70 校准，自定义是玩家自选的挑战；每条的风险分来自云端单条实测，不靠猜；不能有「白给分」的条目。
> 本轮**只做设计与概念图，不改玩法代码**。概念图：`python tools/concept_contracts.py` → 主仓库 `build/contracts/`（见 §4.7）。
> 相关：难度目标 docs/38 §8.12（每档参考机器人 50–70，含超时）、停刷 §8.14、难度页 T5s docs/67 §12 / docs/37 §8、动效 docs/62。

## 0. 一页结论

- **16 条合约，5 组**（敌群 4 / 精英与 Boss 3 / 灯火与资源 3 / 环境与控制 3 / 时间 3），37 个档。14 条只用现有 dmod 键，2 条（领袖、限时）要新旋钮。
- **推荐合约 = 条目之和，逐键相等**：`tools/concept_contracts.py` 把条目表合成修正表，与 `balance.json difficulty/hard | extreme`（经 `dmod_for_level` 拼底）逐键核对，Ⅳ = 8 条、Ⅷ = 9 条，**全部一致**。代价是两个「窄档」（利齿 +20 / +25%、残烛灯油 −30 / −40%）和 Ⅷ 不含 Ⅳ 的「寒潮」（今天的表就是这样），见 §1.3。
- **风险刻度要改口径（需要拍板）**：「0 / 4 / 8」「每档至少 1 分」「分数按实测」三条不能同时成立——Ⅳ 拆出来就有 8 条。建议细刻度：**Ⅷ 锚定 20、Ⅳ 实测落在 8–12**（初始猜测 Ⅳ 10 / Ⅷ 20），预设名仍叫 Ⅳ / Ⅷ。§1.5。
- **校准不用改代码就能开跑**：现有 `--bal=difficulty/standard/<键>=<值>` 能拼出 14 条的任意组合。推荐「随机组合 + 逻辑回归」而不是逐条 A/B，同样精度省约 5 倍局数；全套约 6 050 局 ≈ 200 核时（4 个 16 核云端例行任务约 3–4 小时）。§2。
- **荣誉**：每名主控「通关过的最高潮位」徽记（选人 + 图鉴 + 档案），结算显示本局合约与潮位、干员最佳 / 全干员最佳；存档只存「通关过的条目组合」，潮位随校准重算。不解锁任何东西。§3。
- **自定义解锁门槛**：制作人提的「通关 Ⅳ」可行；我更推荐「**通关标准即解锁**」——只给荣誉，没有可钻的空子，还能给卡在标准与 Ⅳ 之间的一般玩家一条台阶（普通机器人 标准 7% → Ⅳ 3%，高手 70% → 46%）。§3.6，待用户定。
- **工时**：P1（推荐合约改条目 + 自定义条目板 + 结算 + 干员纪录 + 徽记）约 42 小时；P2 校准约 10 小时人工 + 云端；P3 每周合约约 10 小时。§5。

## 1. 条目表

### 1.1 规则

- **一条合约 = 一个主题，1–3 档**，档内累计（Ⅱ 档包含 Ⅰ 档的意思，风险写累计值）。同一条只能选一个档。
- **每个 dmod 主键只属于一条合约**，所以合成没有冲突：选中的档把自己的键直接写进修正表。唯一例外是灯标刷新间隔 `beacon_every`：几条合约各带一个乘数（`beacon_x`），相乘后写入。
- **补偿跟着条目走**：今天 Ⅳ / Ⅷ 表里的放宽项（`hunt_dur`、`hunt_ring_hp`、`beacon_every` < 1、`boss_fight_enemy_hp`）不单独成条，挂在引起它的那条合约上（围猎补偿挂「厚壳」，灯标补偿挂「残烛」「永痕」）。这样推荐合约 = 条目之和仍逐键成立，自选时补偿也跟着来；条目板和修正列表里用绿色「补偿」行写明，不藏。
- **风险分**：每档一个整数，档间严格递增；分数由 §2 的实测换算，下表是初始猜测（按「Ⅳ = 10、Ⅷ = 20」凑的）。
- **互斥**：只在两条合约管的是同一件事、叠起来明显不可加时设（§1.2 末）。
- **预设专用窄档**：为了让 Ⅷ 能精确拆出来而存在的档（和相邻档只差一点点）。条目板上用虚线框画，手动升降档时跳过；只在「载入 Ⅷ」时出现，分数与下一档相同，不给白分。P2 整形时删掉（§2.6）。

**拆不干净的地方（不影响 P1，P2 整形时处理）**
1. **Ⅷ 不含寒潮**：今天 Ⅳ 有控制收紧（ctrl_start 300、frost_max 2），Ⅷ 没有（走全局 400 / 3）。所以推荐合约不是嵌套的。§8.12 的 HM6 实测控制旋钮对熟练几乎零效果（65% → 65%，p 1.00），把寒潮 Ⅰ 加进 Ⅷ 预计不改 Ⅷ 胜率，但要 112 局确认。建议 P2 加进去（玩家直觉是 Ⅷ ⊇ Ⅳ），见开放问题 3。
2. **两个窄档**：利齿 Ⅰ / Ⅱ（+20% / +25%）、残烛 Ⅰ / Ⅱ（灯油 −30% / −40%）。P2 若测不出差，Ⅳ 直接改用 Ⅷ 的那一档（Ⅳ 略难一点点）并跑 Ⅳ 确认轮，窄档删除。
3. **补偿挂靠是设计选择**：围猎补偿只按敌人生命走（Ⅳ 1.2 × 0.85、Ⅷ 1.7 × 0.7，正好是「圈上海嗣生命约等于标准档」的意图）；灯标补偿拆成残烛 ×0.8、永痕 ×0.75。单选残烛时灯标变多可能让它净变易——这正是 §1.6 要测的。

### 1.5 风险刻度：为什么建议不用「0 / 4 / 8」

- 约束冲突：Ⅳ 有 8 个不同主题的旋钮、Ⅷ 有 9 个；如果每条至少 1 分、档间严格递增，Ⅳ ≥ 8、Ⅷ ≥ 9，凑不出 4 / 8。要保 4 / 8 只能把 Ⅳ 的旋钮捆成 4 张复合合约（例如「海嗣强化 = 生命 + 伤害 + 大群」「Boss 强化 = 生命 + 预警」「昏灯 = 灯火 + 灯油 + 源石锭」「寒潮」），自选粒度会粗到失去意义。
- **建议：细刻度，Ⅷ 定义为 20**（与原作 0–18 级、危机合约十几到三十几的手感一致），Ⅳ 的值交给实测（旧数据推算约 8.5：高手 标准 70% / Ⅳ 46% / Ⅷ 18%，按 logit 等比）。推荐合约的名字照旧叫「波涛迭起·Ⅳ / ·Ⅷ」，卡片角上另写「潮位 10 / 20」。
- 精度代价：细刻度下 1 分 ≈ 高手胜率 2.5–3 个点，逐条 A/B 测不准（112 局标准误约 ±1.6 分），所以 §2 改用随机组合 + 回归。
- 如果用户坚持 4 / 8：按上面的复合合约做 8–10 条，每条 1–2 档，§2 的方法不变，只是单位换成「Ⅷ = 8」。

### 1.6 「白给分」风险清单（P2 必须先测这些）

| 条目 / 档 | 为什么可能白给 | 依据 | 测出白给时怎么办 |
|---|---|---|---|
| 大潮 Ⅱ（+60%） | 大群是主要经验来源，人多经验多 | close7：Ⅷ 1.6 → 1.2 反而变难（39% → 21%，经验 −24%） | 加 `horde_xp` 让大群总经验不涨，Ⅷ 跑确认轮 |
| 残烛（任一档） | 带的灯标补偿 ×0.8 可能超过灯火惩罚 | §8.12：灯标 +20 灯火、圈内安全 | 把补偿从残烛挪到永痕，或补偿减半 |
| 拮据 Ⅰ（−10%） | 源石锭少 10% 几乎买不到少一件 | 机器人商店行为简单 | 并档（Ⅳ 改 −25%） |
| 狂澜 Ⅰ、寒潮 Ⅰ / Ⅱ | 机器人反应型旋钮测不出，人却感觉得到 | §8.12 HM4–HM6 熟练全部 p 1.00 | 不给 0 分：取高手 / 普通两种机器人里较大的那个；仍 < 0.5 分则只留在推荐合约里，不上条目板 |
| 精英频率（未收录） | 精英多 = 经验 ×10、宝箱、灯油 65% | close6b：精英频率、杂兵数量会让机器人更强 | 已改用「领袖」（只加精英属性，不加数量） |

规则：**测出 ≤ 0 的档不能上条目板**；测出 0–0.5 分的档要么加强、要么并入相邻档；推荐合约里的这类档可以留（推荐合约整体是校准过的），但条目板上不单独卖分。

## 2. 校准方案（P2；不用改代码就能开始）

### 2.1 尺子

- **机器人**：高手（expert）。理由：它在标准 / Ⅳ / Ⅷ 的胜率约 70 / 46 / 18–25%，整段都不贴天花板也不贴地板；熟练在标准档约 85–90%，单条效果会被天花板压扁。熟练只用来复核推荐合约（它是 Ⅳ / Ⅷ 的参考机器人）。
- **单位**：u = (logit p高手(标准) − logit p高手(Ⅷ)) ÷ 20。旧数据 u ≈ 0.12 logit/分；同一提交、同一批里重测，不跨轮相减（§8.12 口径）。
- **一档的分** = 该档的 logit 效果 β ÷ u，四舍五入；档间至少差 1，不够就按 §1.6 处理。

### 2.2 为什么不逐条 A/B

37 个档逐条各跑 112 局配对 = 4 144 局，单条标准误约 0.19 logit ≈ ±1.6 分，还只测了「加在标准上」这一个点。随机组合设计（每局随机抽一张合约，所有条目同时变化）用逻辑回归一次估出全部 37 个 β：3 600 局时每个 β 标准误约 0.08 logit ≈ ±0.7 分，而且样本本来就落在玩家真实会选的叠加区间里，能顺带估交互。

| S0′ 参考 | Ⅳ / Ⅷ 原样（熟练是这两档的参考机器人，确认 50–70 没被别的提交挪动） | 熟练 | 2 × 224 = 448 |
| S1 随机组合 | 每局一张随机合约：每条以 0.4 概率入选、入选后档位均匀抽，丢掉互斥与初始猜测风险 > 30 的；7 主控 × 512 seed；合约由 seed 决定、可复现 | 高手 | 3 584 |
| S2 复核 | §1.6 的可疑档 + 回归里不确定（分数在 x.5 ± 0.3）的档，加在 Ⅳ 上同 seed 配对（共用一份 Ⅳ 基线） | 高手 | 约 8 × 112 = 896 |
| S3 整形确认 | 窄档并档、寒潮进 Ⅷ、可能的 `horde_xp` 之后，Ⅳ / Ⅷ 新旧同 seed 配对 | 熟练 | 2 × 2 × 112 = 448 |

合计约 **6 050 局**。按批跑中位 2 核分钟一局（docs/44：墙钟中位 119 秒）≈ **200 核时**；按用户已给的授权（大批量测试可直接建一次性云端例行任务）建 4 个（每个 16 核）并行，约 **3–4 小时**出全部数据。新旋钮两条（领袖、限时）要等 P1 代码合入后补跑 S1 的一个子批（约 900 局）。

### 2.4 怎么跑（现在就能跑）

14 条只用现有键，`--bal` 已支持多次覆盖难度表（`Bal._load` 逐个应用，`dmod_for_tier` 认 `difficulty/standard/*`）。例如「厚壳 Ⅱ + 潮不止息 + 永痕 Ⅰ」：

```
python3 tools/balance_run.py --game game --jobs "$GODOT_MAX_PROCS" --preset starts --bots expert --seeds 1 --seed0 101 \
  --out build/cloud/ct-s1-0101 --tag ct-s1-0101 \
  --extra="--maxt=1000 --tier=0 --bal=difficulty/standard/enemy_hp=1.45 --bal=difficulty/standard/hunt_ring_hp=0.78 \
  --bal=difficulty/standard/hunt_dur=0.78 --bal=difficulty/standard/boss_fight_enemy_hp=1 --bal=difficulty/standard/final_stop_mobs=0 \
  --bal=difficulty/standard/mire_permanent=1 --bal=difficulty/standard/beacon_every=0.75"
```

S1 需要一个小脚本 `tools/contract_calib.py`（P2 写）：`gen` 按 seed 生成合约与对应 `--extra`，`fit` 读 BALANCE 行做带主控固定效应的逻辑回归，输出每档 β、标准误、换算分、与初始猜测的差、推荐合约的预测和与实测比较。P1 合入后改用 `--contract=shell:2,endless:1`（P1 加的调试参数，等价于上面那串 `--bal`）。

### 2.5 复核「推荐合约 = 条目之和」

- 用 S1 的回归预测 Ⅳ、Ⅷ 的 logit 差，与 S0 实测比：差距 ≤ 0.3 logit（约 3 分）视为可加；超过就在回归里加交互项（先查 潮不止息 × 大潮 Ⅱ、永痕 × 孤灯、负伤 × 利齿），仍不行就整体缩放分数。
- 推荐合约显示的潮位 = 条目分之和（不另造一个数）；Ⅷ 不一定正好 20，以条目和为准，偏差写进本文。
- 推荐合约本身的胜率目标不变（§8.12：熟练 50–70，含超时），S3 确认。

### 2.6 定分与整形规则

1. 每档分 = round(β / u)，至少 1；同条目档间至少 +1。
2. β ≤ 0 的档不上条目板（§1.6 处理后重测）。
3. 推荐合约里测不出差的窄档并掉，Ⅳ 跑确认轮。
4. 分数表带版本号（`risk_table`），存档里的纪录按条目重算（§3.4），改分不会让玩家「掉纪录」以外的东西出问题。

## 3. 荣誉（不解锁任何东西）

### 3.1 什么算「通关」

- 打死最终 Boss 进入胜利结算（`victory_flow.record_win`），**四个结局都算**（平凡即是喜乐 / 静谧时代 / 息潮的代价 / 如星空般深蓝）。
- 不算：死亡、中途退出、限时条目超时（判负）、Boss 演练（`g.trial.active`）、练习（`Cfg.practice_active`）、图鉴演示、任何带 `--` 启动参数的测试局（与 `Cfg.save()` 同一判定）。
- 倍速（1.5× / 2×）照算。对内包「全部解锁」时纪录照常写（纪录是真打出来的）。
- 自定义合约通关**不解锁推荐档**：`diff_unlocked` 仍只由推荐合约推进（标准 → Ⅳ → Ⅷ），推荐路线保持是引导路线。

### 3.2 记什么

- **每名主控**（开局干员 `g.ch.id`）通关过的合约条目组合，只留「帕累托前沿」：被另一组合逐条不高于的组合删掉。任何档间递增的分数表下，最高潮位一定在前沿上——所以以后重新校准分数，最佳纪录照样算得对。每人上限 16 组，超出时按当前分数表留最高的 16 组。
- 每组带：条目 `{id: 档}`、结局 id、用时、日期、版本、当时的潮位（只作历史显示）。
- 派生量（不存）：干员最佳潮位、全干员最佳、通关过合约的干员数。

### 3.3 结算面板（`contracts_settlement.png`）

- 统计四行里「难度」换成「合约：波涛迭起·Ⅷ / 自定义 · 10 条」；右上一块潮位徽记（大）+「斯卡蒂 18 → 19」。
- 合约片两行：每条一片（局内 A 风格 `UI.chip`，左色条 = 组色），写「厚壳 Ⅱ +3」。
- 纪录三行：干员最佳（新纪录挂金色「新纪录」片，沿用解锁难度那片的颜色）、全干员最佳（带干员名）、通关过合约的干员 N / 14。
- 按钮：同合约再来 R（原「再次探索」）、修改合约 C（回到条目板，带上本局合约）、回到标题 T。
- 失败 / 超时：合约片与潮位照常列，纪录行换成「本局未通关 · 不计入纪录」。Boss 演练与练习不显示合约区。
- 动效沿用 docs/62 §3.21「战绩逐行盖章」：潮位徽记最后一个盖下，新纪录时徽记数字从旧值滚到新值。

### 3.4 选人与图鉴徽记（`contracts_badges.png`）

- **潮位徽记**：像素六边盾 + 像素字数字，冷色（不用警示黄，选人 B+ 和图鉴 C4' 里都一样）。分段按推荐合约之和，校准后自动移动：未通关「-」暗灰空盾；通关标准（0）钢蓝边；1 到 Ⅳ−1 藏青底青边；≥ Ⅳ 潮水底；≥ Ⅷ S4 反白；≥ Ⅷ + 10 反白 + 潮线 + 泡沫光。
- 选人：名册卡右下角；顶栏「难度 波涛迭起」小标换成「合约 潮位 N」；左侧档案名下一行「合约纪录 最佳潮位 18 · 10 条 · 结局三 · 10-12」。
- 图鉴：名册卡右下角同一枚徽记；干员档案名字区下一行「合约纪录」，点开列出最佳那一局的条目、结局、日期。
- 图鉴首页 / 设置不加全局排行榜（只有本地纪录）；「全干员最佳」只在结算和图鉴档案页角落显示。

### 3.5 存档（`settings.cfg` 新段 `[contracts]`）

| 键 | 类型 | 说明 |
|---|---|---|
| `contract_ver` | int | 1 |
| `risk_table` | String | 生成纪录时的分数表版本，例如 `"68-guess"`、P2 后 `"68-c1"` |
| `mode` | String | `"preset"` / `"custom"`（上次选的是推荐还是自定义）；推荐档下标仍存在 `progress/difficulty` |
| `custom` | Dictionary | 条目板上次的选择 `{"shell": 2, ...}` |
| `clears` | Dictionary | `{op_id: [{"tags": {...}, "ending": "deep", "t": 702, "date": "2026-10-12", "ver": "2.0.x", "risk": 19}, ...]}`（前沿，≤ 16 组） |
| `legacy_tier` | int | 迁移来的「旧存档已通关的推荐档」，−1 = 无（见下） |

**迁移**（`contract_ver` 不存在时，一次性）：
- `custom` = 上次选的推荐档对应的条目（第一次打开条目板看到的就是熟悉的那一档）；`mode = "preset"`。
- **对内包 / 调试版**：有 `user://runs/runs.jsonl` 时回填——`meta.result == "win"` 的行按 `meta.start_op` + `meta.diff`（0 / 4 / 8 → 标准 / Ⅳ / Ⅷ 的条目）写进 `clears`。对外包不记对局（docs/43），没有这个文件。
- **对外包**：没法知道是哪名干员通关的，只按 `diff_unlocked` 写 `legacy_tier`（1 = 通关过标准，2 = 通关过 Ⅳ；通关 Ⅷ 不改 `diff_unlocked`，所以认不出来）；图鉴档案页角落显示「旧存档：已通关 Ⅳ（干员未记录）」，各干员徽记从下一局起记。
- 「全部解锁」只在内存放开条目板门槛，`clears` 不受影响；测试局不写存档（同现行）。
- 对局记录 `runs.jsonl` 的 meta 加 `tags`、`risk`、`risk_table`；BALANCE 行加同样三项，供 P2 脚本直接读。

### 3.6 解锁门槛（待用户定）

- 制作人方案：通关 Ⅳ 后开自定义（= 与 Ⅷ 同时解锁，`diff_unlocked ≥ 2`，不需要新存档字段）。
- **我的推荐：通关标准即开**（`diff_unlocked ≥ 1`）。只给荣誉，没有可以刷的东西；对卡在标准与 Ⅳ 之间的一般玩家，「标准 + 两三条」是一条台阶（普通机器人 标准 7% / Ⅳ 3%，高手 70% / 46% 之间缺一档）；推荐路线照旧引导。代价是新玩家第一次通关后多一个界面要理解——第一次打开条目板时载入 Ⅳ 的条目并在说明条写一句「这就是波涛迭起·Ⅳ，加减条目自定义」。
- 未解锁时条目板页签可以点开看（同现行「未解锁档也能翻过去看效果」），出发换成灰边「通关波涛迭起后解锁」。

## 6. 开放问题（给用户）

1. **风险刻度**：同意改用细刻度（Ⅷ = 20、Ⅳ 按实测约 8–12），还是坚持 0 / 4 / 8（要把条目捆成复合合约，自选会变粗）？
2. **自定义解锁**：通关标准即开（推荐），还是按制作人原案通关 Ⅳ 才开？
