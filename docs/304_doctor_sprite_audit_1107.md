# 304 博士帧条核查与补画派单（2026-11-07）

> 起因：用户在选人界面看到博士是很粗的大像素（比其他干员糙得多），问「帧率条是不是还是旧版本」。结论：**是，而且没有更新的版本可接**——博士只有 1 倍（64 画布）的美术，@2x 文件是它的逐像素 2× 放大。本文写现状、证据、补画方案，并带一份可直接交 Codex 的派单（§5）。本次不改游戏素材和代码。

## 1. 现状（main，`game/art/operators/doctor/`）

| 动作 | @1x | @2x | 帧数 | @2x 与 @1x 的关系 |
|---|---|---|---|---|
| idle | 256×64 | 512×128 | 4 | **逐像素 2× 最近邻放大（0 个像素不同）** |
| run | 512×64 | 1024×128 | 8 | 同上 |
| hurt | 128×64 | 256×128 | 2 | 同上 |
| death | 256×64 | 512×128 | 4 | 同上 |

- `game/data/characters/doctor.json`：`size 64`、`foot [32,60]`，没有 attack / skill / entry（博士不攻击、不受击伤）。
- 有效像素：身体高约 40 个 1 倍像素、宽约 19 个，21 色以内。其他干员（拉普兰德、斯卡蒂等）是 @2x **原生**画的，身体约 64 个 @2x 逻辑像素高、色数 ≤24 但有脸、发丝、衣褶细节。界面（选人 / 图鉴 / 招募）用 @2x 精细版，所以博士在这些界面里每个「大像素」是 2×2 屏幕像素 × 界面放大倍数，看上去最糙。
- 对照图：[docs/img/doctor_vs_ops_1107.png](img/doctor_vs_ops_1107.png)（同倍率最近邻放大：博士、拉普兰德、斯卡蒂 idle f0）。

## 2. 历史：为什么是这样

1. 09-25～10-13：博士旧版 48 画布（96 @2x 两帧待机等），`art/archive/incoming_1028/doctor_2x_handoff.md`（96×96 @2x，原生，但只有 2 帧待机）。
2. 10-18：用户批准「先放进游戏」的 128 画布**原生 @2x 跑步**（Codex `pixel_revision_07`，合入 `87d5cf61e`，1024×128、8 帧、10 fps）。当时 handoff 已写明待返修：头部起伏 0.7px、前倾 26°、新旧待机比例 / 朝向不一致、描边不统一。
3. 10-23/24：Codex 按「同队风格」重做一套 **1 倍 64 画布**（idle / run / hurt / death，`codex/art a732d70f`，`35c57ee62` 接入），@2x 只是该 1 倍的放大副本，**覆盖了** 10-18 的原生 128 跑步。
4. 10-28 资产整理（docs/189）只搬了目录，没改内容。

所以「旧版本」准确说是：10-24 的 1 倍统一版就是现行版，它的分辨率口径比 10-20 后的干员标准（docs/87 §10-20 更新、docs/104）低一级。仓库、`codex/doctor-runtime`、`codex/doctor-style-integration`、Codex 工作树 `event-cg-1029`、`art/archive`、`art/itch` / `art/promo*` 等分支里都没有更高分辨率的**新**博士（只有上面第 1、2 条的旧原生件，风格与现行不一致，不建议回接：接回会让跑步和待机比例、描边又对不上）。

## 3. 脚下的「重影」不是素材问题

选人界面立绘的脚部有一段淡出的重复像素：这是 `title_op_pick.gd::_op_char` 的**设计**——立绘底部 28% 逐行渐隐（让脚收进地面），全部干员都一样。博士 idle 帧里脚底（y=121 行）之下没有额外像素，四个动作的 `bbox` 底边都是 121，不是帧条里多了一段。博士腿是深色，渐隐段在浅色底板上显得更突出，才看着像「重影」。如果用户嫌明显，可以单独给暗色立绘减小渐隐比例（界面会话的小改动，非本任务）。

## 4. 补画方案

**目标**：博士与其他干员同一档——@2x 原生 128 画布，身体约 64 @2x 像素高，脚底锚 (64,120)，色数 ≤24，外描边 `#080E18` 1 新像素，动作之间不跳朝向。**不是**把 1 倍放大再描一遍。

- 谁画：Codex（docs/104 流程：先静态 f0，再按部件分层做动画，三层验收人眼先行）。博士没有 PRTS 立绘，造型以已批准的设计参考为准：`art/archive/incoming_1028/doctor_1x_1023/idle_candidate_v2.png` 与 `co_doctor_style_rework_1018/idle_design_reference_02.png`（深色兜帽遮面、长外套、青色袖带、橙色识别点、空手，面罩不加眼嘴）。
- 范围：idle 8 帧（现 4 帧；与其他干员一样呼吸 1–3px）、run 8 帧、hurt 2 帧、death 4～6 帧。不要 attack / skill / entry。
- 工作量：f0 静态一轮（含 1～2 轮修改）+ 三个动作各一轮；按此前博士 1 倍的节奏估约 2 个 Codex 会话日。代码侧只需核对 `doctor.json` 的逻辑锚（现 `foot [32,60]`，素材脚底 (64,120) 与之对应，不用改）和 `index.json`，由 Claude 收货时做，约半小时；收货后要重跑 `art_lint --ops doctor` 并去掉 10-18 的临时豁免。
- 替代方案（更省）：只重画 idle 和 run（常驻看到的两条），hurt / death 先沿用 1 倍放大——会留一小段粗糙在受击和倒地，博士按设计不攻击也不受击，所以这两条实际几乎看不到。**建议先走这个，一个会话日。**
- 不建议：对 1 倍放大件做平滑 / 抗锯齿 / AI 超分（画面口径是像素风，会糊且脱离 docs/87 的色数与二值透明规则）。

## 5. 派单（交 Codex，可直接复制）

> 【任务 · 博士 @2x 原生帧条重画】
> 背景：博士现行帧条是 1 倍 64 画布的 2× 放大，在选人 / 图鉴 / 招募界面显得比其他干员粗很多（对照 `docs/img/doctor_vs_ops_1107.png`）。请按 docs/87、docs/104、docs/108 做**原生 @2x** 版本，只交 @2x（1 倍由我们导出）。
> 造型：延续现行博士（深色兜帽遮面、长外套、青色袖带、橙色识别点、空手、朝右 3/4），设计参考见 `art/archive/incoming_1028/doctor_1x_1023/` 的 `idle_candidate_v2.png` 与同目录 `actions/`；面罩不加眼嘴；不要新增配件。
> 规格：单帧 128×128，脚底中点 (64,120)，身体高约 64 @2x 像素，透明二值，外描边 `#080E18` 1 新像素，色数 ≤24；与同队干员（拉普兰德 / 斯卡蒂 / 逻各斯）并排对照时头身比与笔触一致，不要再出现 1 倍放大的方块感。
> 交付（第一批，建议先交这两条）：`doctor_idle@2x.png`（1024×128，8 帧，4 fps 呼吸 1–3px，末帧可回 f0）、`doctor_run@2x.png`（1024×128，8 帧，10 fps，头部起伏 1–2.5px、前倾 ≤15°、脚不穿地）。第二批：`doctor_hurt@2x.png`（2 帧）、`doctor_death@2x.png`（4–6 帧，末帧躺平，最后一帧停住）。
> 流程：先交 idle f0 静态与「博士 / 拉普兰德 / 斯卡蒂」同倍率三列对照图，我们确认后再做动作；动画走分层合成，不要平图挪像素。每批附 manifest（帧数、fps、脚底、SHA-256）和 handoff md，放 `art/incoming/doctor_2x_1107/`，不要覆盖 `game/art/` 下任何文件。
> 验收：`python tools/art_lint.py --ops doctor` 过；实机看选人（`title_op_pick`）、图鉴、招募卡三处。
