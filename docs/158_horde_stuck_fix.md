# 158 「怪物身上冒着红光卡在原地」修复

> 2026-10-26，用户 iPhone 实机（itch 网页 03460dbc8）：「有些怪物身上冒着红光卡在原地没有动」。分支 `claude/red-stuck-fix`，基于 origin/main df7bbadc。

## 1. 原因

- **红光**：深溟引痕者生命低于一半后的狂暴色调（脉动橙红 + 脚下红光圈，`world._draw_enemy_full` 的 `rage_fx`）。其他怪卡住也不会变红，但它们站着不动，很快就被打死；引痕者血厚，被打到半血变红后仍站着，所以用户看到的是「红的卡住」。
- **卡住**：10-25 的大群「慢慢来」（docs/150）给每只大群怪加了分批出发的延迟，写在 `wake_t` 上。`wake_t` 是钵海收割者「苏醒」的计时，只在收割者的招式里倒计时（`enemy_ai._reap`）。其他怪身上的 `wake_t` 永远不会减少，而移动、额外招式都在 `wake_t > 0` 时停住，于是这只怪从此原地不动、也不出招。
  - 每只都有 0–0.4 秒随机抖动（`horde_jitter`），所以连第一批也会卡。
  - 合围大群「后几股原地等一下再出发」（`close_ring_delay`）同样写在 `wake_t` 上，同一个问题。
- 和手机、30 帧、低画质无关：无界面自动对局（高压档、高手）里探针也抓到了狂暴引痕者 `wake_t = 0.62` 卡在离队长 682 的地方。

## 2. 修法

- 出发延迟改用单独的 `depart_t`（`spawner._horde_loose` 和合围后几股），在敌人更新的决策段统一倒计时（`run/enemies.gd`，和 `wind` / `pose` 同处）。
- `depart_t > 0` 时：不移动、不出额外招式、领头怪不冲锋（与原意相同）；倒计时到 0 后照常追击。
- 收割者自己的苏醒计时 `wake_t` 不变。

## 3. 验证

- 录屏夹具 `game/tests/horde_depart_capture.tscn`：一圈 28 只大群（含 4 只半血狂暴的引痕者）按围猎型分批出发，40 秒。修前 28 只全部停在出生点；修后全部按批次出发、围到队长身边。左右对比 `build/horde_stuck_before_after.mp4`。
- 回归测试（`enemy_attack_variety_test`）：大群分批延迟写在 `depart_t`、不碰 `wake_t`；5 秒后每只都离开出生点（修前这条会失败）。
- `--only enemy_attack_variety / core / prot / enemy_identity / enemy_status`。
- 玩法改动（大群真的会围上来了），同 seed TRACE 预期变化；10-25 之后测的胜率（含大群的批跑）都带着这个 bug，大群比设计的弱，修复后难度会上升，建议协调人合入后补一轮常规档复测。

**原作**（水月与深蓝之树普通作战关卡，解包 `levels/obt/roguelike/ro3/level_ro3_n_*`，逐波数敌人；随机组按候选数平均；生命取图鉴 0 级，未含紧急作战加成）。按区对应本作阶段：

**判断**：
1. **按只数算，普通怪确实太多**：本作「高阶 + 精英」三段都只有 3–5%，原作是 10% → 20% → 43%，后段差了一个数量级。后段底海滑动者一种就占了七成。
2. **按生命算，前段已经偏重、后段偏轻**：高阶 + 精英占生命 39%（原作约 30%），中段 36%（原作约 46%），后段 31%（原作 75%）。前段压力主要来自少量高血量的引痕者，后段压力主要靠滑动者的数量。
3. 原作的曲线是「后期敌人数不涨、精英占比翻倍」；本作是「后期数量翻倍、组成几乎不变」。这和用户「后期普通怪太多」的观感一致，也是手机帧率压力的主要来源（后段每局 1093 只）。

**建议（未实施，等用户定）**：
- 中段把刷新池里约三成普通怪换成高阶，后段换一半：目标「高阶 + 精英」只数中段约 12–15%、后段约 25–30%（取原作的一半到七成，幸存者类要保留割草感）。
- 换的同时按「生命池不变」压总只数：后段每局刷出从约 1100 降到约 700–800，单只更强；同屏数下降，手机帧率受益（本次实测 10 只重型怪约 +2–4 ms 中位，而少 300 只普通怪省得更多，需实测）。
- 后段底海滑动者在池里的权重减半，空出的份额给收割者 / 奠基者 / 巢涌者（同种上限按比例放开）。
- 都是 `waves.json` 的阶段池和 `balance.json` 刷新率改动；改后按 docs/146 同口径复测三段压力与胜率（无认知高手 30–40%）。

## 7. 高阶单只开销（帧时，10-26 协调人要求分段）

- **网页 iPhone 仿真**（同种子 13、9:00–10:00、各两局轮换）：P50 58.1 / 52.1 对 49.6 / 45.6 毫秒（约 +12%）；同屏敌数 55–57 对 61–64。网页有同屏上限（自动档 65），旧版被上限挡住，新版只数少的好处吃不到，单只更贵就直接体现在帧时上。真机参考：main bb0a2f04e iPhone Chrome P50 35.2 / P95 50.2 毫秒（不含本改动）。
- **桌面分段**（`--prof`，同局新 / 旧配比轮换）：总帧时持平。新版只数约为旧版的一半（38 对 75），排序绘制与逻辑总量没涨；单只绘制约 55 µs，旧版约 39 µs（+40%）。
- **贵在哪**（逐只按种类与画法路径计时）：画法缓存外的原路径约 55–65 µs / 只，缓存内约 25 µs。高阶有六到七成时间走原路径，滑动者只有三成。原因依次是：受击形变（高阶血厚、一直挨打）、蓄力 / 出手帧、举肢准备态。逻辑（AI）单只开销和普通怪相当。
- **已降**：举肢准备态收进缓存（签名 [6] `_dc_prep`，`--dccheck` 14305 次 0 不一致），奠基者原路径占比 4.1 → 3.5 只 / 帧，收益小。
- **降不了（不改玩法 / 手感的前提下）**：受击形变和出招帧是打击反馈与预警，要进缓存得把形变量和帧号拆进签名，等于重写原路径，收益约每只 30 µs，暂不做。
- **可选（改低配玩法，等用户定）**：网页自动档同屏上限按「高阶算 1.5 只」计，帧时可回到旧版水平；代价是低配机后期高阶更少。
