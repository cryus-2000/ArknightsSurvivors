# 246 pixelfx「转平面」试验 · 斯卡蒂（11-05）

**结论摘要**
1. 用户 11-05：「我们能不能试试看做把 pixelfx 的二维平面给转移到我们这个平面上来，然后再结合我们的 notia 特效。我还是不死心。」本稿只做斯卡蒂（不是浊心斯卡蒂），挂开关 `fx/px_plane`（缺省 0 = 关），出三栏对比给用户用眼睛判断。
2. 开关三个值：`0` 当前游戏原样；`1` 转平面版；`2` 旧做法原样贴（对照用，重现之前「像贴纸」的问题）。终结技不动。
3. 只改画面：同种子 TRACE 开关逐行一致（§4）。
4. 图与录像在本机 `Claude outputs/px_plane_skadi_1105/`（三栏对比每招一张 + 2 倍局部、三档并排、8:00 起 20 秒开 / 关 mp4）。

## 1. 协调人诊断的三个丑因，各怎么解决

| 丑因 | 旧做法（`fx/px_plane = 2` 重现） | 转平面版（`fx/px_plane = 1`） |
|---|---|---|
| ① 视角错位：pixelfx 按横版侧视 / 正俯视画，圆是正圆、刀光平躺在画面上 | 整张帧条按出手方向旋转，正圆不压扁，盖在所有单位上面 | 每招拆两层：**贴地层**（接触阴影、湿痕、冲击环、积水）生成时已按 `combat.GROUND_Y`（0.72）压扁，画在地面层、被单位挡住；**立起层**（刀光幕、水柱、潮刃浪头）保持竖直，进 `world._sorted_fast` 按脚底 y 和敌人一起排序（排序项 kind 7），脚下有接触阴影 |
| ② 像素密度不统一 | 帧条按判定半径 ÷ 拟合半径小数缩放 + 任意角旋转，屏上混着 1.3 / 1.4 / 1.7 倍等几种像素 | 帧条用 pixelfx 按目标尺寸逐件生成（`tools/pxplane_bake.py`），1 帧条像素 = 1 美术像素，游戏里只按 `g.PX`（2）整数放大、不旋转，原点对齐 2 世界像素格；方向件（横扫、潮刃、浪墙）按 5 个平面角（−90 / −45 / 0 / 45 / 90°）预生成，另一半水平翻转 |
| ③ 不吃场景光 | 光晕烤进颜色（色 + 光层合成一张），整张一个亮度 | 帧条只用色层（不含光晕），当普通物体画在世界层，跟单位一样被环境暗色、光学层光照压暗 / 受光；白热像素出 **emit 点表**（每帧 ≤ 48 点）进光学发光层（同 `world._glow_pts` 的 `g.glow_next` 格式）；命中 / 爆点挂一盏 ≤ 0.15 秒的照地点光，走 `fx_recipe` 的灯光预算（`fx/recipe_dl` / `recipe_dl_sum`） |

质感：命中处少量大颗水滴（`fx_recipe` 颗粒池的 `ink` 材质：有重量、落地成水点、停 0.55 秒后熄灭；普攻 2–4 颗、S1 4–8、S2 7–13），颗粒和照地光只在转平面版出现。受击反应（本人色闪 + 重击局部停顿）沿用 `fx/recipe_hitreact`，旧做法对照（2）不加。

## 2. 每招拆法与三档

帧条源：`tools/pixelfx_fx/water/ak-skadi-pp.js`（pixelfx 效果文件，`part` 选件、`layer` 选层、`view: raw` 出旧做法版）。色：本人深海蓝 7 阶（pixelfx `house.js` `OP.skadi`）+ 最暗压底一阶；精二点缀海绿 `#5ff0cc`。不用危险红。大面积区域只画边 + 内侧淡渐变（α ≤ 0.16，抖动），不平涂。

| 招 | 立起层 | 贴地层 | E0 | E1 形状差 | E2 质变 |
|---|---|---|---|---|---|

## 3. 实现

- `game/scripts/render/fx_pxplane.gd`：事件 → 一次性件表（立起 / 贴地 / 旧做法），绘制、emit、方向挑选。只用 `g.vrng`（颗粒）。
- 接管借配方系统：`fx_recipe.gd` 的 `enabled()` 在 `fx/recipe` 或 `fx/px_plane` 任一开时为真；`recipe(id)` 对斯卡蒂只在 `fx/px_plane > 0` 时返回 `data/fx_pxplane/skadi.json`（颜色组给颗粒 / 光 / 受击反应），对其他干员只在 `fx/recipe > 0` 时返回，两个开关互不影响；`_ev` 把斯卡蒂的事件转给 `fx_pxplane`；`draw_floor / draw_over / draw_auras` 对斯卡蒂改走 `fx_pxplane`。
- 钩子：`ob_core.exec_shape` 圆形 / 锥形判定结算后一行 `_FXR.ev(o, "shape", {...})`（没被接管时第一行就返回）；`data_operator.draw_auras` 接管时不画斯卡蒂 S3 的常驻程序圈；`world._sorted_fast` / `_se_draw` 加排序项 kind 7。潮刃、浪墙直接读玩法状态 `o.hw.waves` 画。
- 帧条：`game/art/fx/pxp/pxp_*.png`（115 张，共约 0.7 MB）+ `game/data/pxp_skadi.json`（帧数 / fps / 尺寸 / 原点 / emit 点表）。重新生成：`python tools/pxplane_bake.py`（需要本机 pixelfx 库 `build/pixelfx`），之后 Godot `--import` 一次。
- 旋钮：`fx/px_plane`、`fx/px_plane_tier`（≥ 0 强制画面档，三档图用）、`fx/px_plane_emit`（emit 点亮度，缺省 0.8）。

## 4. 斩击的刀剑感（11-05 用户看中间稿：「斩击本身是不是没有那种刀剑感」）

第一版是腰高的一条等高竖直光带（「刀光幕」），读起来像一圈水幕。改成：
- **腰高的水平刀痕**：大剑横扫扫过的那一片，按 SY 压扁、抬到腰高，地上有投影阴影；**月牙形**——中段厚、两头收成针尖，最厚处偏刀头；
- **刃**：外缘 1 美术像素白刃线（刀尖走过的路），出手第一帧刀尖外 40% 一道径向刃光；内部顺弧的速度纹；内沿抖动变稀，不平涂；
- **快**：第 0 帧已扫出 55%、第 1 帧扫满（热白），之后从刀尾往前收，约 5 拍（0.33 秒）收完；
- **命中斩痕**：被砍中的至多 2–4 只身上一道斜的 1 美术像素白芯线（两侧浅蓝、两头收尖），3 拍收掉；精二交叉成 X；
- 精一：内圈晚一拍的第二刀（双刃，暗一阶）；精二：白刃线内侧一道海绿副刃 + 刃外浪沫点。

## 5. 帧率统一（协调人 11-05 补充：「我们的帧数和 pixelfx 的帧数是不是没对上」）

- 旧 pixelfx 帧条 fps 五花八门（4、10.67、12.8、13.33、13.71、19.2、24），60 Hz 下 12.8 fps = 每帧停 4.69 个游戏帧，显示成 4 / 5 帧交替，一卡一卡；游戏自己的爆发特效 16 fps，弹体位移又是 60 Hz 平滑，几套节奏混着。
- 转平面版统一一个动画时钟：帧条一律按 **15 fps** 烘焙（时长不对增删帧，不改 fps），选帧按全局节拍 `floor(g.t × 15)`，同屏所有件同一拍换帧，60 Hz 下每帧正好停 4 个游戏帧；潮刃 / 浪墙的画面位置也按同一节拍跳格、对齐美术像素格（浪的字典里记 `_pxq`，玩法不读）。颗粒和照地光照旧平滑，颗粒位置取整到像素格。
- 旋钮 `fx/px_plane_fps`（缺省 15）：设成别的值就退回「各件按该小数帧率播 + 平滑位移」；旧做法对照（2）按 `fx/px_plane_raw_fps`（缺省 12.8）播。
- 并排录像：`fps_before_after_atk.mp4`、`fps_before_after_s1.mp4`（左 12.8 fps + 平滑，右 15 fps 统一节拍；精二普攻 / S1，图鉴演示 30 帧原速，局部 2 倍）。

## 8. 看图判断（Claude）

- **解决了的**：③ 和 ② 并排，视角（压扁 + 腰高 + 阴影 + 和怪物按 y 互相遮挡）和像素格（全屏一种像素大小）的差别一眼可见；② 的正圆、旋转锯齿、混尺寸像素都没了。斩击改版后刀痕读得出是剑砍的。
- **还不够的**：
  - 「吃光」在暗场景里效果有限：色层被压暗后蓝色刀痕仍主要靠 emit 白刃撑亮度，和 ① 当前游戏比整体并不更有「光」的感觉；
  - S2 水柱偏细、偏暗，读成几道竖线而不是一大柱水；涌潮 / 回澜的贴地环内侧抖动渐变在 2 倍下看得出网点；
  - Noita 感只来自少量水滴和照地光，主形仍是干净的图形化月牙，离 Noita 的「物质感」还远。
- 结论倾向：「转平面 + 统一像素 + 统一帧率」解决的是旧做法的硬伤（像贴纸、像素乱、节奏卡），值得留作所有帧条特效的口径；但只靠它，pixelfx 风格本身未必比 docs/245 的原作改编配方更好看，交用户用眼睛定。
