# 218 源石锭藏品：商店按售价保底（11-01）

## 1. 问题与口径

有些藏品的效果是「立即获得源石锭」。在商店里买这类藏品可能亏：

- 藏品价格 = 档价（基础 10、稀有 14）× 第几位商人（1 / 1.5 / 2）× 本次已购件数涨价（每件余货 +20%，藏品再 +30%）× 商店倍率。
- 例：古旧钱币原给 10 锭，第三位商人那里买过几件后卖 18，花 18 只拿回 10。

用户 11-01 定的口径：

- 越买越赚可以。
- 只保证不会亏。

第一版（f2e55c7e9）走了另一条路：去掉希望系的源石锭、把 4 件下架、修循环。这版整体撤回，改成下面的保底规则。

## 2. 规则

旋钮 `shop/ingot_relic_floor`，缺省 1.2。设为 0 = 改前。

从商店买的藏品，如果效果里有「立即获得源石锭」（`on_gain ingots`），实际到手：

> max(原数额, ceil(实付价 × 1.2))

- 补给箱、事件、随机给藏品拿到的，照原数额。
- 招募时、击败 Boss 时给的源石锭（#10、#14、#184、#251 的触发）不算「立即获得」，不保底，也不改。
- 卡面：商店货架上的卡写实际能拿的数额，例如「源石锭 +22（按售价保底）」。成交涨价后，余下货品的卡面跟着改。只有保底数额高于原数额时才改写，否则照原文。
- 熔铸之后（最后一位商人离开），诡意行商的商店照样保底，到手的锭照常进熔铸池。

## 4. 实现

- `game/data/balance.json`：在 `shop` 段新增 `ingot_relic_floor: 1.2`。
- `game/scripts/run/shop.gd`：
  - `ingot_floor(id, paid)` 算保底数额。
  - `ingot_desc(it)` 改写货架卡面。`roll` 出货后、`buy` 成交涨价后各调用一次。
  - `buy` 买藏品前把保底数额交给 `rfx.ingot_floor`，`gain_relic` 之后清零。
- `game/scripts/relic_fx.gd`：
  - `on_gain ingots` 取 `max(数额, ingot_floor)`。
  - 新增 `instant_ingots(id)`，用来查立即得锭数额。
- 测试 `relic_impl_test`：
  - 实付 18 → 22。
  - 实付 10 → 12（浮点不多进一）。
  - 原数额更高时照原数额。
  - 不给锭的件没有保底。
  - 卡面文字；商店到手 22、补给箱照原数额 18。
