# 38 · Boss 重做方案（v3，2026-09-26，用户已确认 §7；代码结构商定中）

> **本版依据**
> - 用户要求：把所有新加的机制放在一起判断风险，给出最新一版方案。
> - 用户已确认：目标时长中期 25–40 秒、最终 60–90 秒；硬控只打编队，永远不打主控。
> - 材料：v2.1 全文；32 条逐条对过代码、两轮复核的风险（附录 A）；稳妥、体验、交付三份独立草案；一轮完整性审查（15 处漏洞本版已全部补上，见 §3.3）。
> - 结论先行：v2.1 的问题主要不是机制太多，而是：好几类机制在现有代码里立不住；几条安全规则能被绕过；Boss 战和全局日程（缩圈、事件箱）互相撞车。v3 的顺序是：先修地基（B0），再上不加血的框架（B1），然后逐只 Boss 纵切。每做完一只，先批跑，再给用户试玩，通过后才做下一只。

## v3 相比 v2.1 改了什么

1. **新增 B0：先修现存问题。** 这些问题现在就在影响玩家，和重做无关：骑士冲锋计时卡死；预警画出来的范围比实际判定小；Boss 招式仍会让主控僵直，僵直时按不出冲刺；Boss 一死，大群不带预警直接刷出；同一个 seed 在 10:05 前后结果不一致。
2. **不再把 Boss 血量全局 ×5。** 撤销 `boss_hp_time_div 600→150`。中期 Boss 曲线不动；最终 Boss 每只单独设血量系数，重做完一只才开一只。
3. **最短时长由「看得见的阶段」保证。** 靠阶段卡点和每幕最短时长（阶段护盾）。v2.1 的每秒软上限降级为隐形的「伤害预算」，默认关闭。删掉 ×2.0 增伤封顶和灰色伤害数字。
4. **慢的一端有兜底。** 拖太久 Boss 会「力竭」变脆，但不会狂暴。中期 Boss 拖过 120 秒会撤退。
5. **失败只加危险，不加血。** 每只 Boss 最多回涨一次血条，这一次就算一道卡点。
6. **「破韧」和「破绽」合并成一个状态「破绽」。** 韧性以伤害为主，控制只算加成。Boss 自己的跪地、脱手用独立字段，不会被韧性换算清掉。
7. **场地就是冻结的黑潮圈，不另画符文环。** 只对最终 Boss。中期 Boss 在场时，黑潮连「预告」一起暂停；Boss 登场前 45 秒内不开新一轮。这样 7:00 登场时圈一定是静止的。
8. **主控保护落到扣血的最后一步。** 单发 40% 上限在所有倍率之后截断；Boss 招式附带的侵蚀算进上限；任意 2 秒内 Boss 伤害合计 ≤50%；恢复满血保护；Boss 带来的持续伤害设总上限。
9. **环的规则理顺。** 缺口环归为「可走躲」，给出缺口宽度、扩散速度、错开角度的下限；所有连发（含多重凝视）间隔 ≥0.6 秒；接潮旋转线限速。
10. **会干扰编队的 Boss 从 5 只减到 3 只**（伊比利亚狙击、偏执泡影囚笼、骑士冻结），每只只用一种方式。删掉「挡枪」「拉走干员」「技力流失」。
11. **中期 Boss 两幕，最终 Boss 三幕。** 每只 Boss 有一个只属于它的招牌动作。
12. **Boss 冲锋改成真实位移**（只对重做完的 Boss）。新增圆形障碍表；地图上的石柱在 Boss 战里也登记为障碍，看得见的柱子都一样挡。
13. **全局日程和 Boss 战联动。** Boss 战不刷精英；大群顺延并给完整预警；横幅排队。**结局事件箱不因 Boss 顺延**，避免慢构筑错过结局。
14. **流明灯塔在最终 Boss 场地里的规则**写进 §1.7（待 Q3）。
15. **泪改成免伤的机制物件**，只响应主控。
16. **主控承伤预算**写进 §1.2，用来反推招式频率和单发伤害。
17. **评价只展示，奖励改成源石锭。** 终结一击是纯演出。
18. **实施按 Boss 纵切**；并行协作约束按实际代码重写（game.gd 约 9 处，不是 4 处）。
19. **新增** §3 风险评估、§4 删除与推迟清单、附录 A 风险表。

| 卡门 | 7:00 | 高手 42s | 4760 |
| 接潮双体 | 7:00 | 高手 34–49s | 合计约 5300–6100 |

| **伊莎玛拉**（最终） | 10:00 | 中位 25s，最短 4s | 18000 |
| 伊祖米克（最终） | 10:00 | 中位 41s（含无敌学习阶段） | 10400（35% 血量出场） |

报告里还有一条：高手维什戴尔打中期 Boss，平均 **11 秒**。

原因，按影响从大到小：
1. **血量涨得太慢。** Boss 血量 = 基础 × (1 + t/600)，10 分钟才翻一倍；同期普通怪涨到 5 倍，玩家输出涨得更快。
2. **没有任何「最短时长」保护。**
3. **增伤乘区能叠满。** 弱点、灯光、终局藏品可以一起乘。
4. **招式太少、太好读。**
5. **没有「Boss 战」的场面。**

### 0.2 和重做直接相关的代码现状

- **骑士冲锋是假的。** Boss 的冲锋、后跳，都是往击退速度 `e.kb` 里写一个值；重甲敌人还要 ×0.3。结果骑士预警线画 520，实际只冲约 100px；塑路者约 213px；卡门后跳约 288px。
- **冲锋计时 `dash_t` 永不递减（现存 bug）。** 骑士冲过一次之后：每次碰到主控都挂冰霜；二阶段「再冲锋」永远不触发；贴图一直停在冲锋帧。
- **画的和判的不一样（现存问题）。** 地面圆画成压扁的椭圆，判定却是正圆。以 r70 为例，下方比画面多判约 44px。
- **Boss 仍会让主控僵直（`pstun`）。** 写入点正好 3 处：冲击环（enemies.gd 约 335 行）、预警僵直（boss_ai.gd 约 313 行）、神经损伤溢出（combat.gd 约 71 行）。僵直期间按不出冲刺。
- **单发伤害的倍率在扣血前才全部乘完。** `enemy_hit` 先乘灯火 <30 的 ×1.15，`hurt()` 里再乘藏品承伤（骨血 ×1.8），最后才扣护甲。侵蚀按「伤害 × 侵蚀系数 × 2」另外进侵蚀池，之后逐帧直接扣血，不管无敌和冲刺。泡影凝视和爆裂、蔑死体、斥亡体的侵蚀系数都是 0.5，所以一发 40% 实际约等于 80%。
- **受击后无敌只有 0.45 秒。** 连发招式的间隔如果是 0.6 秒，每一发都能打中。
- **黑潮缩圈时间表。** 150 秒开始，每轮「预告 20 秒 → 收缩 25 秒 → 稳定 45 秒」。第 1 轮 170–195 秒收到 1300；第 2 轮 240 秒预告；第 3 轮 330 秒预告；**第 4 轮预告在 420 秒左右，正好和 7:00 Boss 登场撞在同一时刻**。缩圈计时靠逐帧累加，而 `update_zone` 又在刷 Boss 之前执行，谁先谁后取决于帧误差。
- **结局事件箱的时间窗。** 决意 1（240–300）和 3:30 Boss 重叠；骑士留守（440–470）、决意 2（445–480）和 7:00 Boss 重叠。事件箱每 20 秒最多刷一个，前一个没打开会挡住后一个。
- **流明灯塔跟着主控走。** S3 灯塔每帧跟到主控脚下，半径 220，持续 10 秒。灯塔里的主控完全不吃圈外掉血和掉灯（combat.gd 约 152 行），也不吃溟痕（enemies.gd 约 306 行），还会清空侵蚀和神经损伤。docs/26 写它「不动」，和代码不一致。
- **泪是 60 血的普通敌人**（enemies.json），编队和范围伤害能打碎它。站在泪上每秒受 6 点真伤。
- **装填被打断时写的是 `e.stun = 6.0`**（combat.gd 约 278 行），Boss AI 的「能不能出招」也看 `e.stun`。
- **Boss 战刷怪倍率写死在代码里（0.8）。** `balance.json` 里的 `spawn_boss_mult` 没有任何代码读取。
- **没有手动技能。** 13 名干员都没有手动技能，幽灵鲨 S2 已经改回自动（docs/23:61）。所以 v2.1 动作表里的「手动技能」一行不成立。
- **地图石柱是静态的。** 按地图哈希随机生成，只挡主控（而且要有 `prop_pillar` 贴图才生效），Boss、子弹、预警线都不和它碰撞。
- **攻速减益只罚水月。** `g.atk_slow` 全仓只有水月读取（间隔 ×1.5，约 −33%）。

## 1. 通用框架

### 1.0 名词（只解释这一次）

| 名词 | 意思 |
|---|---|
| 主控 | 玩家操控的开局干员，唯一会掉血的角色，攻击也从她身上打出 |
| 编队 | 跟随主控的其他干员，不会死，自动攻击、自动放技能 |
| 击杀用时 | 从 Boss 能受伤（名片结束）起，到它死亡为止的秒数 |
| 卡点 | 血条上的刻度，比如 50%、66%。一次伤害最多打到刻度为止，然后 Boss 无敌 0.8 秒，进入下一幕 |
| 幕 | 两个卡点之间的一段战斗，每幕有自己的招式和新元素 |
| 阶段护盾 | 某一幕打得比最短时长还快时，Boss 停在刻度上并发光，直到这一幕满时长为止 |
| 破绽 | Boss 倒地或硬直，受到的伤害 +40%。一个名字、一个数值、一套画面 |
| 韧性 | 血条下方的细黄条，打满就进入破绽 |
| 预警 / 锁定 | 招式生效前画在地上的范围。预警先跟着主控移动，「锁定」之后就不再移动 |
| 可走躲 / 必须冲刺 | 招式分两类：走路就能躲开的，和只能靠冲刺（冲刺时无敌）穿过的 |
| 部件 | 场上可以打掉的目标物，例如核心分形、茧壳、根须 |
| 机制物件 | 不能被伤害打掉、只响应主控动作的物件，例如伊莎玛拉的泪、伊祖米克的灯柱 |
| 力竭 | 战斗超过目标上限后，Boss 逐渐变脆 |
| 场地 | 最终 Boss 战时冻结的黑潮圈 |
| 招式令牌 | 同一时刻只允许一个需要玩家应对的大招。双体 Boss 也共用这一个名额 |
| 白名单 | `balance.json` 里的 `boss_v2` 列表。只有列在里面、已经重做完的 Boss，才用新的血量和新规则 |
| L 窗口 | leaderbal 工作树合入 main 之后，集中改 `character.gd` / `squad.gd` 的那一次提交 |

### 1.1 目标时长与验收口径

| 类型 | 目标中位 | 每名主控的 P10–P90 | 最短不低于 |
|---|---|---|---|
| 中期 Boss（3:30 / 7:00） | 25–40s | 15–60s | 12s |
| 最终 Boss（10:00） | 60–90s | 45–120s | 40s |

- 击杀用时从「可受伤」算起，名片和登场阴影不算。
- 伊祖米克 20 秒的学习期算在 60–90 秒以内，所以她的输出期只有 40–70 秒。
- 验收必须按主控分组看，不能只看总体中位数。

### 1.2 血量与主控承伤预算

**血量**
- **全局曲线不改**，`boss_hp_time_div` 保持 600。
- **中期 Boss 的曲线也不改**，快的一端交给 §1.3。只有某只 Boss 单独偏离目标时，才给它设 `hp_scale`。
- **最终 Boss**：在 `enemies.json` 里给每只加 `hp_scale`，进了白名单才生效。用下面的时长预算反推：
  - 目标时长 = 固定时段 + 有效血量 ÷（主控中位 DPS × 机制输出税）
  - 固定时段：卡点、重生、茧、变身、学习这些打不动的时间。除伊祖米克外，每只合计不超过 12 秒。
  - 有效血量：本体，加上唯一一次回涨，再加上独立形态（外壳、变身形态）。
  - 主控中位 DPS：用 `--balance --nodeath` 批跑实测「Boss 实际受到的 DPS」，取 13 名主控的中位数。不用高手终局 DPS。
  - 机制输出税：因为走位、跑去处理机制而损失的输出比例。
- 删掉 v2.1 的「13 万量级」。它和 ×5 曲线实际算出的 2.6–4.5 万自相矛盾。

**主控承伤预算（新增）**

最终 Boss 从中位 9–25 秒拉长到 60–90 秒，主控要多扛 3–7 倍的招式轮数。所以每只 Boss 的招式频率和单发伤害，要先过这张预算：

- **目标**：中位玩家在一场 Boss 战的目标时长内，受到的 Boss 来源伤害（招式、接触、Boss 子弹、Boss 溟痕、侵蚀），扣掉战斗中的回复后，**不超过最大生命的 60%**。
- **估算公式**：预期承伤 ≈ Σ（每种招式出现次数 × 单发伤害 × 假设命中率）− 战斗中回复。
  - 假设命中率：可走躲 30%，必须冲刺 40%，连发按每发 30%。
  - 战斗中回复：主控每秒 1 点，无人机每 6 秒 2%。
- **用法**：每只 Boss 纵切开工时，先在 §2 那只 Boss 的「承伤预算」一行填出招式表，再定数值。超出预算时，先降频率，再降单发。
- **核对**：批跑实测「Boss 战承伤 ÷ 最大生命」的中位数，超过 60% 就回调。

数值由 balance 会话落地，Boss 会话只加字段和默认值。

### 1.3 阶段卡点与每幕最短时长（保证最短时长的主力）

- **卡点位置**
  - 中期 Boss：50%，共两幕。
  - 最终 Boss：66%，另有第二道。骑士、泡影的第二道是「第一次归零后回涨」，取代 33% 卡点；伊莎玛拉是 33% 变身；伊祖米克是学习期结束后的 66% 和 33%。
  - B1 时还没重做的最终 Boss，先统一用 66% 和 33% 两道。
- **触发方式**：只在「伤害前高于刻度、伤害后不高于刻度」时触发，不按时间轮询血量。Boss 本身处于无敌时（学习期、假死）不触发。
- **过卡点时**：无敌 0.8 秒，不飘「无效」。同时取消这只 Boss 所有还没结算、瞄准主控的预警，之后 0.8 秒内不出新招。
- **卡点奖励**：最终 Boss 每过一道卡点，掉 1 个回复道具和 1 个灯油，让卡点也是一次喘息。
- **每幕最短时长**：中期每幕至少 6 秒；最终每幕至少 13 秒（伊祖米克有 20 秒固定学习期，每幕至少 10 秒）。从这一幕可受伤时算起。
  - 打得太快时，Boss 停在刻度上，升起**阶段护盾**：刻度发光，血条闪金。
  - 最后一幕的护盾，停在这一幕血池剩 3% 的位置。伊莎玛拉的最后一幕是变身形态那条细条；本体回到 2% 跪地是演出，不受护盾影响。
  - 护盾期间打出的伤害，对重做完的 Boss 照常积韧性。时间一到护盾碎掉，下一幕通常一开场就是破绽。这样强构筑溢出的伤害变成了下一幕的爽点，而不是白打。
- **按结构算的最短用时**（假设伤害无限大）：

| Boss | 算法 | 最短 |
|---|---|---|
| 中期（任一只） | 6 × 2 + 0.8 | 12.8s |
| 最后的骑士 | 13 × 3 + 0.8 + 重生 5 | 44.8s |
| 偏执泡影 | 13 × 3 + 0.8 + 茧 8 | 47.8s |
| 伊莎玛拉 | 13 × 3 + 0.8 + 变身 2 + 跪地 3 | 44.8s |
| 伊祖米克 | 学习 20 + 10 × 3 + 0.8 × 2 | 51.6s |

- 这套规则从 B1 起对全部 8 只 Boss 生效，不加血也能消灭「2 秒打死」。

### 1.4 伤害预算（原「软上限」，降级为保险丝）

- 每只 Boss 有一个隐形的令牌桶：每秒补充「有效血量 ÷（最短时长 × 0.8）」，最多存 4 秒的量。额度用完后，超出部分只算 35%。
- **默认关闭。** 只有批跑发现阶段护盾出现得太频繁（前 10% 以外的构筑也常见），才打开。
- 以下情况不计入预算：破绽期间、打部件时、接潮一方假死时。
- **玩家完全看不到。** 删掉灰色数字。
- 删掉 ×2.0 增伤乘区封顶。它和血量、卡点重复，还会把骑士骨血（藏品 225）变成陷阱藏品。建议 balance 会话把骨血的增伤和承伤都从 +80% 降到约 +50%。
- 文档不再承诺「软上限保证最短时长」，保底由 §1.3 负责。

### 1.5 破绽与韧性（待 Q1）

- **破绽**只有一种状态：受伤 +40%。
  - 普通破绽 3 秒：韧性打满、核心被打碎、根须被拆、冲锋之间的喘气。
  - 大破绽 5 秒，带跪地或长枪脱手的动作：装填被打断、冲锋撞墙、茧壳被打破。
  - 画面统一：身上裂纹光、血条变金、副标题倒计时。
  - 破绽期间伤害预算暂停。时长固定，不受控制时长类藏品和 `control_mult` 影响。
- **Boss 自己的硬直用独立字段 `e.break_t`。** 破绽、跪地、长枪脱手、装填被打断，一律写 `e.break_t`，不写 `e.stun`，也不经过下面的韧性钩子。Boss AI 判断「能不能出招」时同时看 `break_t`。现在「装填被打断写 `e.stun = 6.0`」的做法，在该 Boss 重做时改掉。
- **韧性以伤害为主**：每打掉 1% 最大生命积 1 点。第一次破绽要 25 点，之后每次 ×1.5。所以任何阵容一场都能破韧约 2 次。
- **控制只是加成**，由 `enemies.gd` 里一个中心钩子统一处理，**只对白名单 Boss 生效**：
  - 这类 Boss 身上出现的 `e.stun`，一定来自玩家一方（因为它自己的硬直写在 `break_t`）。钩子把每帧新增的眩晕时长换成韧性（1 秒约 5 点，同一来源有 0.5 秒冷却），然后把 `e.stun` 清零。
  - 这顺手修掉了现在「水月能把 Boss 锁死」的问题。
  - 各干员脚本里的 `not e.boss` 不用动。
  - L 窗口之后，只单独给推进之王、艾丽妮去掉这个判断，作为控制型干员的高光（每人一个提交）。
- **Boss 免疫击退**：在 `enemies.gd` 施加击退速度的那一行（约 128 行），对白名单 Boss 直接忽略 `e.kb`。Boss 自己的冲锋、后跳已经改用脚本位移 `e.move`（§1.14），不受影响。这样不用去改十几个写 `e.kb` 的文件（其中 8 个是干员脚本）。
- 泡影「被晕超过 0.3 秒就进二阶段」和悬浮 Boss 的「被控坠落」，在泡影进白名单的同一个提交里改掉：前者改为由卡点驱动，后者改为由破绽事件驱动。

### 1.6 慢的一端：力竭与撤退（待 Q2）

- **力竭**：战斗超过目标上限（中期 40 秒、最终 90 秒）后，副标题亮出「力竭」，Boss 换成喘息的着色。
  - 每 10 秒受伤 +15%，最多 +60%。
  - 招式间隔 +50%。
  - 韧性需求 −25%。
  - 只让 Boss 变弱，不让它狂暴。
- **中期 Boss 撤退**：在场超过 120 秒，进入 10 秒撤退演出，离场时掉一半奖励。下一只 Boss 的登场时间不受影响。
- **最终 Boss 登场时**，如果还有残留的中期 Boss，直接撤场并给全额奖励。
- 这些规则只让 Boss 变弱，不改时间表，也不改结局判定。

### 1.8 登场、演出与终结（全部不震屏）

- **出生点**：距主控 280–320，在屏幕可见范围内（水平 ±300、竖直 ±200），并且离场地边至少 180。
- **登场保护**：Boss 的接触伤害和出招一样，要登场 2 秒后才生效。
- **名片**
  - 每个存档第一次遇到这只 Boss 时，完整显示 1.8 秒，期间暂停游戏。可以按 Esc、确认键或点击跳过；名片期间不响应冲刺键。
  - 之后再遇到，只显示 0.6 秒的标题横幅，不暂停。
  - 存档要新增 `seen_bosses` 字段。
- **屏外箭头**：Boss 在屏幕外时，在屏幕边缘画箭头指向它，复用商人现有的边缘指示。
- **换幕**：本体闪白 → 一圈纯视觉的环（不造成伤害）→ 横幅显示阶段名 → 血条刻度点亮。换幕只用这一种信号。
- **受击**：闪白 1 帧，形变 5%。**不做**每次大伤害的 40ms 顿帧。
- **Boss 死亡**
  - 清掉它自己的预警、冲击环和子弹，主控获得 1.5 秒无敌。
  - 顿帧只在这一刻有一次，受设置里的顿帧开关控制。
- **最终 Boss 死亡**
  - 进入新状态 `S.FINISH`：暂停模拟，只播约 1 秒纯视觉演出（慢动作滤镜 + 4–6 个小爆点 + 奖励喷出），之后再判胜利。
  - 平衡批跑和无画面模式直接跳过这段。
- **终结一击**：输出最高的干员立绘切入，配她的 skill_3 语音。纯演出：不调用技能，不移动主控，演出期间主控无敌。骑士、伊莎玛拉改用专属台词。
- 本方案所有名字里的「震荡」「冲击」都只是地面上的扩散波，**不调用任何镜头震动**。

### 1.9 预警规范

- **画即判**
  - 所有地面形状统一走一个函数：`GROUND_Y = 0.72`，判定改为椭圆（纵向距离先除以 0.72 再比较），判定点统一用主控脚底。
  - 现有的圆形预警、寒冰领域、抛石、溟痕，以及场地边，都迁到这个函数。
  - 自动测试断言：每种预警在 8 个方向上，画面边缘外 4px 的点都不能被判定命中。
- **看得清**
  - 预警的外轮廓和终点标记，画到一个独立的覆盖层上：在所有角色之后绘制，不受环境色压暗，不会被怪海遮住。地面填充留在原来的层。
  - 亮度分级：会伤人的预警一律「白芯 + 深色描边」，Boss 主题色只用来填充；只减速的地形用低亮度纹理，不发光。
- **两类招式**
  - **可走躲**：锁定后留给玩家的时间 ≥（半宽或半径 + 12）÷ 105 + 0.1 秒。105 是主控移速被压到下限（70%）时的速度。举例：宽 26 的光束约 0.34 秒，r45 的落点约 0.64 秒，r70 约 0.88 秒。
  - **必须冲刺**：只用于「没有缺口、覆盖全场」的招式，目前只有伊祖米克的全场地波一种（还可以站进灯柱光圈躲）。用专属样式（白色双描边 + 冲刺图标）。全场所有来源合计，任意两次之间 ≥2.0 秒（冲刺冷却 1.2 秒 + 0.8 秒余量）；卡点后 1.2 秒内不出。
- **环的分类（修正 v3 草稿的内部矛盾）**
  - **缺口环 = 可走躲。** 要求：
    - 缺口在主控所在距离上的弧长 ≥80px（主控判定直径约 24，两侧各留 28）；
    - 扩散速度 ≤220px/s（现有冲击环是 320）；
    - 缺口位置在环出现前 ≥0.8 秒就画出；
    - 同一招的多圈：缺口朝同一方向时，相邻两圈间隔 ≥0.6 秒；缺口方向不同时，相邻两圈错开 ≤25°，间隔 ≥1.2 秒。
    - 冲刺穿过仍然有效，但只是备选，不计入冲刺调度。
  - **小冲击环**（跃击、震地的余波）：最远不超过预警圆，按落点圆算可走躲。
- **时序**
  - 预警总时长至少 0.6 秒。难度加成只压缩「追踪」那一段，不压缩锁定之后的时间。
  - 追踪落点：半径不超过 45，结算前至少 0.5 秒锁定。
  - **所有连发**（三连线、三连弹、多重凝视依次高亮）每发间隔至少 0.6 秒。间隔仍比受击无敌（0.45 秒）长，所以每发都可能打中，合计伤害另有上限（§1.11）。
- **旋转伤害线**（接潮第二幕）：属于可走躲。转速上限按「线端速度 ≤105px/s」算，线长 260 时 ≤20°/s，保证主控在任何位置都能走在线前面。不计入冲刺调度。
- **归属**：每条预警、冲击环、敌方子弹都带 `owner` 字段（是哪只 Boss 放的），方便过卡点和死亡时清理。
- **遮挡**：有障碍物时，直线预警画到障碍为止，并画一个「被挡住」的端盖；判定也按截断后的长度算。
- **机器人共用判定**：每种预警形状提供一个 `danger()` 函数，游戏判定和机器人走位共用它。

### 1.10 读图预算

- **招式令牌**：每场战斗一个，双体、部件、随从共用。同一时刻最多 1 个需要应对的大预警，另外最多 1 个目标物。
- Boss 大招蓄力期间，泪、囚笼、子嗣、根须的计时器全部暂停。
- **持续地形上限**：Boss 溟痕 ≤12 块、冰痕 ≤1 组、溟痕带 ≤3 条、冰墙 ≤4 道。
- **安全区优先**：安全区（灯柱光圈等）里不生成危险区，而且安全区画在危险区上面。
- **新元素数量**：中期每幕 1 个，最终每幕最多 2 个。
- **全屏边缘光同一时刻只显示一种**，优先级：圈外 > 低血 > 溟痕 > 昏暗。
- 机器人记录「同屏需要玩家应对的事情数」峰值。超过 2 的机制优先调；这是调参信号，不是硬门槛。

| 登场与死亡 | 接触伤害登场 2 秒后才生效；出生点远离主控；Boss 死后清理残留并给主控 1.5 秒无敌 | 冒烟测试 |

**实现口径（B0-4 已实现，以下三点待用户确认）**：代码在 `run/combat.gd` 的 `lose_hp` / `_boss_clamp` / `_guard`，旋钮都是 `boss/*`（`Bal.v`，默认值即现值），脚本测试 `tests/prot_test.tscn`。
- **2 秒合计的口径**：两种理解同时截，同一份伤害在每种口径里只算一次——①「Boss 扣血 + 追加的 Boss 侵蚀」（本表原文，窗口满时追加的侵蚀也作废）；②「实际扣血，含 Boss 侵蚀结算」。只要一种时删掉另一份记账即可。
- **满血保护的「受击前生命」**：生命 ≥90% 之后 `boss/fullhp_guard_combo`（2）秒内的 Boss 伤害算同一轮连击，都能触发；触发后兜底到这一轮结束，并把池里待流出的 Boss 侵蚀算进去（「生命 − 池里 Boss 侵蚀」≥10%，多出的 Boss 侵蚀清掉）。默认 40% / 50% 上限下，字面规则（只看这一发之前）永远不会触发，所以默认按连击算；设为 0 即字面规则。
- **额外旋钮 `boss/corrode_pool_cap`（0.40）**：池里的 Boss 侵蚀合计上限。Boss 在场时侵蚀流出被封顶，不封池子会越攒越多，Boss 一死集中流出。

### 1.12 针对编队的规范

- **只有 3 只 Boss 会干扰编队，每只只用一种方式**：伊比利亚狙击离场、偏执泡影囚笼、骑士寒冷冻结。
- **锁干员不画地面预警**：干员头顶出准星，加一个 1 秒的填充圈，然后生效。这一下对主控 0 伤害、不判命中。
- **选人规则**：选离 Boss 最近的一名编队干员，这样玩家可以用站位影响结果。以下情况排除：
  - 主控（每次重新检查，兼容 leaderbal 的换主控）；
  - 离场中的干员；
  - 4 秒内被控过的干员；
  - 正在放技能的干员。
  - 没有可选的人就跳过这一招，**绝不改成打主控**。
- **上限**：同一时刻最多 1 人被控；冻结或囚禁最长 2 秒，离场 4 秒；结束后 4 秒内不会再被同类控制。
- **实现（L 窗口，一次提交）**
  - `character.gd` 加一个通用的「被控」状态（剩余时间和类型）。`squad.update` 遇到被控干员，就跳过它的行动和技力充能：技能计时、技力、凯尔希的 Mon3tr 一起暂停，光环和被动照常生效。
  - 不改任何干员脚本，写进 docs/23 的契约。
  - L 窗口之前，这 3 只 Boss 的编队干扰先不上（骑士先只显示寒冷层数）。
- **救援**：主控靠近 0.6 秒，或冲刺穿过，都能立刻解救；被救出的干员获得 50% 技力。不救的话，到时间自动解除。
- **显示**
  - 编队卡灰化，显示图标和倒计时环。
  - 世界里被控的干员整体着色。
  - 寒冷 ≥6 层时，给干员一层淡蓝色作为预警。不画雪花格。

### 1.17 实现约定（写给实现会话；2026-09-26 与「架构」会话商定）

**结构**
- Boss 实例 = 敌人字典 `e` 上挂一个对象 `e.brain`（`scripts/bosses/<id>.gd`，继承 `scripts/bosses/boss_base.gd`，`extends RefCounted`，持有类型化 `g: Game`，照 docs/39 §2）。不用按 type 查表的无状态模块：Boss 状态多，无状态最后还得塞回字典。
- `brain` 持有 `e`、`e` 又持有 `brain`，是循环引用：Boss 死亡或移除时必须 `e.brain = null`。
- 「把 `new_enemy` 的键整体复制进旧字典」这类代码（如 `reveal_mimic`）会连带复制或覆盖 `brain`，写时留心。
- 不单独建 `boss_api.gd`：包装方法（`hurt_leader`、`warn`、`spawn_minion`、`fx`、`banner`）放在 `boss_base.gd`；各 Boss 脚本只调基类。
- `run/enemies.gd` 里调用 Boss AI 的那一行：`e.brain` 存在就调它，否则走旧 `boss_ai.gd`（新版开关关着的 Boss）。
- Boss 必须经 `spawner.spawn_enemy()` 生成（自动做 `check_enemy` 字段校验，docs/39 §7）；Boss 专属字段只加在 Boss 身上，所有敌人都读的字段加进 `new_enemy` 模板。
- 数值旋钮一律 `Bal.v("boss/...", 默认值)`。
- 随机数：抽招式、预警位置等玩法随机只用 `g.rng`；粒子、抖动等纯画面只用 `g.vrng`（05329b2 的教训）。
- 模块里的 game 常量写 `Game.X`（如 `Game.PX`、`Game.S.PLAY`）。被 `set/get` 按字符串访问的变量（`STAT_SYNC`）必须留在 `game.gd`。
- Boss 血条、韧性、阶段刻度属于界面：只读状态、只画自己，用 `ui.gd` 的控件和配色（docs/39 §3）；动 `screens/hud.gd` 前先和 UI 会话打招呼。

**扣血与卡点**
- **主控扣血统一入口** `combat.lose_hp(amount, src)`：原有 6 条路径（`combat.hurt()`、缩圈持续伤害、`enemies.gd` 的每秒 6 点、侵蚀结算、`enemies.gd` 另一处、`game.gd` 灯火熄灭掉血）全部改走它。单发上限、2 秒合计上限、满血保护、持续伤害上限都在这里判断，新增扣血来源自动受保护。
- 卡点与阶段护盾放 `combat.damage()`：所有对敌伤害（干员经 op_api、藏品、骑士、子弹）都走它。卡点用独立字段 `e.gate_i / e.gate_t`，不复用 `e.phase`、不写 `e.invuln`；`damage()` 里的无敌判断为「`e.invuln` 或 `gate_t > 0`」。钳制写在扣血那一行、所有倍率之后，真伤也走这里，所以「扣挠之手」的递归伤害也穿不过卡点。
- Boss 回血（`boss_ai.gd` 两处）和血量衰减（`enemies.gd` 一处）是直接改 `e.hp`：卡点只拦伤害、不管回血。
- Boss 自己的硬直写 `e.break_t`；出招判断同时看 `e.stun` 和 `e.break_t`。复活、进茧、变身、假死统一走从 `damage()` 归零分支抽出的 `boss_on_zero(e)` 钩子；`kill()` 只处理真正的死亡。
- 装填读条改名 `reload_ch`，被打断的逻辑只对带弹药的 Boss 生效。
- 在第一次运行 Boss AI 之前设置好「是不是最终 Boss」；`--bosstest` 对结局 Boss 也要设置。
- 编队找最近敌人时跳过无敌目标（卡点那 0.8 秒不算无敌）。
- 机制计数一律不用 `e.hits`，改用「攻击动作」：每名干员每 0.5 秒最多计 1 次；持续伤害、溅射、藏品、召唤物都不计。
- 音乐二段按幕切换；修掉伊祖米克一出场就切二段。

**验证与提交**
- 验证用 `python tools/check.py --jobs 4`（f0a2053 起统一这样跑；新工作树自动导入；失败时报告末尾列出失败项 / 原因 / 日志路径）；说明改动前后差别用 `--ab <提交>`（05329b2 之后随机序列换了一套，更早的报告不能当基准）。
- 提交只按自己的路径：`git commit -m … -- <路径>`；共享文件里混有别人未提交的改动时，只暂存自己的块。

### 2.1 塑路者（中期，3:30 为主）——越打越多

- **第一幕：分裂（100% → 50%）**
  - 震地：落点圆，r≤90，打中只减速，不僵直。
  - 冲撞：真实位移 360，冲撞期间碰到才伤人。
  - 新元素「分裂」：每掉 10% 最大生命，分出 1 只分形；最多 5 只，20 秒后自灭。
  - 护栏 R22：按掉血触发，不按被打次数，所以高频构筑不吃亏。
- **第二幕：核心（50% 卡点）**
  - 新元素「核心分形」：场上最老的那只分形发光，变成部件，编队会优先打它。场上分形不足 3 只时，Boss 先吐出 3 只。
  - 打碎核心：其余分形全部崩解，Boss 普通破绽 3 秒。
  - 12 秒内没打碎：剩下的分形冲回本体，每冲回一只，冲撞多 1 段（最多 3 连）。不回血，冲回途中也不伤人。6 秒后出现新核心。
  - 护栏 R21：失败只加危险，不加血。3 连冲撞受 2 秒合计上限约束。
- **破绽来源**：核心被打碎、韧性打满。
- **安全要点**：3:30 时玩家约 Lv.12、编队只有 2–3 人，所以这场只教一件事：打核心。
- **相比 v2.1**：删掉按被打次数分裂、溟痕路痕、塑路冲刺、合流回血、第三幕。路痕和「合流强化」留作 B7 的难度 ≥5 变体。
- **专项验收**：高频阵容（Logos + 流明）和大单发阵容（维什戴尔 + 乌尔比安）刷出的分形数，相差不超过 1.5 倍。

### 2.2 圣徒伊比利亚 / 圣徒卡门（中期）——老猎人的枪

两人是同一个人，**同一局里互斥**：中期 Boss 抽取时按人物而不是按条目排除。所以她们共用「装填打断」，不会在一局里重复出现。

**共用规则：装填**
- 弹药打空后读条：伊比利亚 4 秒，卡门 3 秒。副标题显示进度。
- 下面任意一条都能打断：
  - 读条期间累计受到 5% 最大生命的伤害；

**原则**：机制开发不等美术。缺图时用程序变形和换色顶替；到货后只改数据，不改代码。

### 6.1 接入底座（Claude 在 B1 做）

- 帧条后缀改成一个共用列表，加载和探测都遍历它，以后新增后缀只加一项。
- 帧数自动推算：帧数 = 帧条宽度 ÷ 本体单帧宽度（考虑 @2x）。去掉 `draw_enemy` 写死的 4 帧，以及死亡帧对 `V6_FRAMES` 手工登记的依赖。fps 用默认值，需要时在 `enemies.json` 里覆盖。
- 命名差异用 `art.gd` 的 ALIAS 表对应。
- `--bosstest` 和图鉴打印两份清单：「缺图、走了回退」和「有图但没接入 / 尺寸不整除」。图鉴里展示每只 Boss 的全部帧条，方便肉眼核对。
- 帧条只放在 `art/incoming` 根目录；否则要把 docs/22 的网页构建改成递归复制（现在只复制根目录的 png）。

### 7.1 为了「以后方便修改」的结构（已和「架构」会话商定，细则见 §1.17）

- **每只 Boss 一份数据** `data/bosses/<id>.json`：血量系数、幕与卡点、每幕最短时长、场地半径、招式表（预警形状 / 伤害 / 冷却 / 启用幕）、编队干扰开关与间隔、帧条名与缺图回退、「启用新版」开关。
- **全局旋钮**一律 `Bal.v("boss/<键>", 默认值)`：缺配置时用代码里的默认值，所以先不改 `balance.json`；要调时在 `balance.json` 加 `boss` 段即可（和平衡会话约好再加）。
- **代码**：`scripts/bosses/boss_base.gd` 放通用部分，并包好 `hurt_leader / warn / spawn_minion / fx / banner` 这些方法；每只 Boss 的脚本只调基类，不直接调 `g.combat`、`g.vfx`，以后主场景再改只动基类一处。
- **逐只切换**：「启用新版」开关关着的 Boss 仍走旧 `boss_ai.gd`。
