## 0. 结论

1. **Codex 列的三块 GDScript 绘制，整块拿掉的上限加起来只有约 3.5 ms**（手机网页仿真，同局轮换「画 / 整块不画」，8:00–9:20）：维什戴尔脚下层 + 上层 −1.5 ms、立起的 PixelFX −0.8 ms、全部敌人本体 −1.25 ms。docs/305 §9 的 6.98 / 4.63 / 5.5 ms 是带分块打点、CPU 满载时量的，打点把各段放大了数倍（同 docs/50 「探针放大约 2 倍」的经验）。**剩下的 20 多毫秒不在这几块里**，下一步要看引擎 / 浏览器那一侧（光学层、后期、整屏像素量）。
2. 做了 Codex 提的第一项：**敌人画法缓存收进受击形变（squash）和托起（air）**——桌面 night3 8:00–9:20 有约 26% 的敌人绘制只因这两种状态退出缓存。做完同局轮换两轮网页净差 −0.3 / +0.9 ms，**量不出收益**（与上面「全部敌人本体只值 1.25 ms」一致）。保留它是因为顺带修了缓存路径一处与原路径不一致（下 §2），且 TRACE / `--dccheck` 都干净。
3. 本机（RTX 4060 笔记本、Edge、iPhone 横屏 844×390 @3x 仿真、中画质）安静时 8:00–9:20 平均 **27–28 ms（约 36 帧）**；Codex 那几轮 48–63 ms 时机器 CPU 中位 55–100%。**桌面仿真已过 30 帧，手机真机慢在哪要真机数据**（GPU 填充率 / Safari），本机仿真量不出来。

## 2. 改动（c5b420443）

- `world._dc_ok`：squash > 0、air > 0 不再退出缓存（`OPT_DCSQ` 2^33 置位时照旧退出，只供 `--optab`）。
- `world._dc_emit`：逐帧补压扁缩放 `sq`（同原路径 `(1 + 0.3k, 1 − 0.25k)`；有压扁时走 `_espr`、不走图集快速路径，几何与原路径同一函数）；托起时画影子、`draw_off.y` 抬高（同原路径，`Pxp.air_look`）；发光点按 `sc × sq.x`。
- 修：缓存路径的配方受击色（`Fxr.react_col`）透明度没封顶 `hit_a + 0.1`，原路径有。原来闪白总伴随压扁、整只走原路径，所以没暴露；第一遍 `--dccheck` 抓到 292 处，全是这一项。
- 验：同 seed 13（240 秒，中画质，开窗口 `--fixed-fps 60`）新 / `--optold=8589934592` TRACE 逐行相同；`--dccheck` night3 8:00–9:20 抽查 18180 次、0 不一致。

## 4. 下一步建议

- GDScript 侧剩下能抠的都是 1 ms 级。要接近手机 30 帧，先拿真机数据（iPhone Safari / Toy）看是 CPU 还是 GPU 受限；GPU 受限就看光学层分辨率、后期、整屏半透明层数（维什戴尔红雾、灯火圈）。
- 同样的「整块拿掉」轮换可以继续量：光学层 / 后期 / 地面层 / HUD，找真正的大头。

## 6. 整层上限：CPU 还是 GPU（11-07 晚，协调人派）

同一手机场景（`--mobile --dpr 3`，即 2532×1170 级整屏像素，中画质，8:00–9:20，同局轮换）。等全机 CPU < 40% 且无其他 Godot 连续 2 分钟后才跑，但跑的过程中负载仍在波动，**三轮之间基准不同（52 / 97 / 130 ms），只看同一轮内的相对差**。

| 轮换 | 开 | 关 | 关掉省 |
|---|---|---|---|
| 整个世界绘制（临时开关，tmp/skipworld-1107 e7a1079e2，已删） | 51.7 | 21.3 | **−59%**；绘制调用 336 → 138 |
| 整个光学层（`--stackab` 32） | 129.9 | 116.9 | −10% |
| 开分辨率缩放（`--stackab` 128） | 129.9 | 125.5 | −3%（噪声内） |

**结论：CPU 受限，不是 GPU 填充 / 后期**。降渲染分辨率几乎不省，关光学层（含后期合成）只省一成；世界层的绘制提交（GDScript 画图 + 引擎处理画布命令）占六成。所以「手机中画质缺省开分辨率缩放 / 降后期档」**不推荐**，省不到东西还会糊。

### 6.2 方案（按 CPU 受限）

1. 维什戴尔、安洁莉娜贴地层改合批 / 减量：先量网页净差，大于 3 ms 才动。
2. 排序实体：敌人缓存已覆盖 75%（§1–2），剩下的是干员本体与额外身体，空间不大。
3. 不建议：手机缺省开分辨率缩放、降后期档（实测省不到，且高配看起来会变差，违背「掉帧才降」）。
