# 310 成长节点可视化普查（20 名干员，11-07）

来源：用户 11-07「检查一下所有干员的这种成长是不是都可视化的」（协调人转）。标准同能天使「对空优先」（docs/298）：**玩家选了以后，能不能在实机画面上 1 倍像素看出变化**。基于 integ `claude/integ-1105` a1f42c5da。本文只出清单与建议，不动代码。

## 0. 结论

- 普查 20 人 × 每人 2 普通 + 2 分支（节点 4 两选一）+ 4 路线（节点 5）+ 精一 / 精二，共约 160 项。
- 按每行主判定（160 行）：**明显 101、看不出 59**（偏小 29、混同 19、无画面 11；混同 = 画了，但和已有特效一模一样，选没选看不出）。另有 9 行整体明显、其中一部分偏小（多是精一普攻强化，如星熊反击架势、艾丽妮挑刺），§4.2 一并列出。
- **头号原因是系统性的，不是节点没写画面**：转平面渲染（`fx/px_plane` 1，docs/254）接管干员后，`o.fx()` / `o.sparks()` / `spawn_fx_sprite` 画的东西**全部不画**（`character.gd:653-658` 直接 return，仅 `KEEP_PFX` 白名单例外；另外非 keep 的 `ring` 本来就跳过，`character.gd:666`）。docs/202 写节点时给的提示环、火花、光点大多走 `o.fx`，所以代码里「有画面」、实机看不到。约 20 项属于这一类（§2）。
- 其余是：复用基础特效同一帧条（混同）、1 像素细线 / 3–5 像素小标记（偏小）、纯技力 / 回复 / 减速（无画面）。
- 修法全部可以只改画面、不改数值（§4）；只有 2 项建议改机制，单列 §5 先给方案。

## 1. 方法

1. 按 `game/data/characters/*.json` progression 导出全部节点（含 branch 两选项、routes 四路线、精一 / 精二含普攻强化），逐条在 `seg_<id>.gd`、`render/fx_pxplane*.gd`、`data_operator.gd`、`blocks/ob_*.gd` 里找触发时真正进屏幕的绘制（只算转平面下实际会画的路径）。
2. 判定：**明显**（新元素，1 倍一眼可辨）/ **偏小**（≤ 约 8 美术像素、1 像素线、< 0.15 秒或被基础攻击淹没）/ **混同**（同帧条同色同尺寸）/ **无画面**（只有数值、技力条、HUD 数字或飘字）。
3. 可疑项用图鉴演示（`tools/elite_demo_shots.py --nodes N --route`）选前 / 选后同帧对照抽查（§6）。
4. 全员共有、不逐条重复：`growth/visible_nodes` 1 让每个普通节点再 +6% 范围或 +0.2 发额外弹（docs/249 §3）——6% 范围单节点几乎看不出，靠 4 个节点累计；精英化有 `elite_show` 定格 + 横幅 + 脚下光池，精一 / 精二本身都看得出。精英化里的**天赋纯数值部分**（伤害 / 治疗 / 技力加成）统一视为无画面，但精英化整体已有新技能 + 演出，不列入待改。

## 2. 系统性原因：转平面下 `o.fx` 不画

`character.gd draw_pfx()`：`Fxr.owns(self)` 为真（20 人都在 `fx_pxplane.gd IDS`，`fx/px_plane` 1）且该干员不在 `Pxp.KEEP_PFX` 里 → 整个粒子层 return；`o.sparks`、`spawn_fx_sprite`、`slash_fx`、`ObHw` 绘制同样跳过（`op_api.gd:419-450`）。只有 `_FXR.ev(...)` 事件交给 `fx_pxplane*` 画、以及少数 cv 状态绘制（`*_gm_draw`、`sm_draw_over`、`mf_draw_guards`）进屏幕。
