# 155 溟痕「一下子一长串，然后就不动了」修复

> 2026-10-25，用户在玩：「溟痕有个问题，会一下子生成一长串，然后后面就不动了」。分支 `claude/mire-trail-fix`，基于 origin/main 1cf4e827。

## 1. 原因

不是跳帧或补帧：溟痕生成都按时间走，没有一帧补齐积压的循环。问题出在三条规则叠在一起：

1. **一长串**：深溟引痕者狂暴后每 0.7 秒就在脚下铺一片小溟痕。10-24「溟痕常驻」之后这些拖痕不再消失，追着队长跑几秒就连成一长串。
2. **后面不动**：
   - 所有溟痕共用一个 32 片的总上限，拖痕、喷吐者落点、飘航者神经弹、奠基者死亡留痕都算在里面；地图自然刷新也和这个总数比（上限 24）。拖痕把名额占满后，全图再也刷不出新溟痕，地上的溟痕就定格了。
   - 灯火在 30 以上时，队长身边 200 内的溟痕会收缩（docs/147）。新拖痕半径只有 8，低于「小于 10 就消失」的门槛，引痕者贴近队长后，新铺的拖痕当帧就被收掉，看起来也是「不再长」。
3. 录屏验证（`game/tests/mire_trail_capture.tscn`：4 只狂暴引痕者追着绕圈走的队长，灯火固定 50，60 秒）：修前前 10 秒铺出两长串，之后基本不再有新拖痕；修后全程都在铺，每只身后一段短尾巴，旧的慢慢淡出。

## 2. 修法

| 项 | 修前 | 修后 |
|---|---|---|
| 拖痕节奏 | 每 0.7 秒一片，站着不动也铺 | 每走 40 铺一片（`enemy/trail_spacing`），按距离均匀推进 |
| 拖痕长度 | 不限，常驻 | 每只引痕者最多留 8 片（`trail_max`），更旧的 1.5 秒淡出 |
| 怪物留下的溟痕 | 和其他溟痕共用 32 片总数 | 单独计数，上限 16（`mire_enemy_cap`），超出时最老的一片淡出 |
| 地图自然溟痕 | 和总数比 24 | 只和自然溟痕比 24；满了就淡出离队长最远、且超过 520 的一片（`mire_recycle_d`），再刷新的 |
| 灯火退散 | 新溟痕当帧就可能被收掉 | 出现后 3 秒内不收缩（`lamp/mire_ward_grace`）；新拖痕起始半径 8 → 12 |
| Boss 溟痕 | 总数 < 32 才留 | 总数 < 48 才留（不进怪物溟痕计数，仍按 6 秒到期） |

- 淡出中的溟痕不伤人、不长、不随灯火变化，透明度按剩余时间降到 0 后移除；不是瞬间消失。
- 常驻规则不变：没被挤掉的溟痕照旧常驻，只有引航灯标能净化。
- 数值都在 `balance.json`（`enemy` 段 5 个、`lamp` 段 1 个）。

## 3. 实现

- `run/combat.gd`：`add_enemy_mire()` 统一入口（打 `src` / `t0`，超量淡出最老的），`fade_mire()`。
- `enemies/enemy_ai.gd`：引痕者拖痕按距离铺、每只限量。
- `enemies/shot_pool.gd`、`run/combat.gd`（奠基者死亡留痕）：改走 `add_enemy_mire`。
- `run/spawner.gd`：自然溟痕只和自然的比上限，满了淡出最远的一片。
- `run/enemies.gd`：淡出倒计时；灯火退散加保护期。
- `world/map.gd`：淡出透明度。

## 4. 验证

- 修前 / 修后同场景左右对比：`build/mire_trail_before_after.mp4`（60 秒，7.5 帧 / 秒，手机可看）。
- 测试：`--only core / prot / boss_boundary / enemy_attack_variety / enemy_identity / public_gallery`。
- 玩法改动，同 seed TRACE 预期变化；没做云端胜率复测（拖痕只在引痕者半血后出现，影响面小），需要时再跑。
