# 凯尔希削弱方案：Mon3tr 有血条、会倒、治疗分配（2026-10-29；用户 10-29 定 5 项后已实现，见 §7）

起因：用户 10-29 要削凯尔希，并说「m3 的血条可以高一点，否则太容易死了」。协调人转的四点：Mon3tr 加血条且怪会打它；治疗在队长与 Mon3tr 间分配（谁低奶谁、队长危险时队长优先）；倒下后 15–20 秒复活，终结技熔毁用掉 Mon3tr 后同样走倒计时；先查怪会不会打召唤物，要不要主动吸仇恨。

## 1. 先查的结论

| 问题 | 现状（读代码） |
|---|---|
| 怪会打队友 / 召唤物吗 | **平时不会**。近战怪只朝队长走、只在 `enemies.gd` 接触判定里伤队长；敌弹、Boss 招式、区域都只认队长。例外两处：① 指挥模式「突击」中，队友被近战怪碰到掉血、血空倒地 25 秒（`squad.gd _tick_hp`，docs/114 §7–8，血量 = 队长上限 × 职业系数 × 5，缺省倒地率 ≈ 17%）；② 召唤物诱饵（`ob_summon.gd _sm_decoy`：`decoy_r` 内近战怪改追它、接触扣 `e.dmg × hurt_mult`、血空消失），只有测试干员 `sstest` 在用。 |
| Mon3tr 现在 | `invuln: true`，永久随行、不会受伤；走随行分支 `mf_step`，**不经过 `_sm_decoy` 的受击段**。 |
| 已有可复用的 | 召唤物自带 `hp / max_hp / flash` 与头顶血条（`ob_summon.gd` 约 534 行）；队友血条与倒地读秒（`hud_banners.gd _draw_op_hp`、`hud_squad.gd`）；`verb.heal` 已经「同时治骑士同伴」（`data_operator.gd _heal`，`when: hurt_any` 含骑士）——分配治疗是同一处。 |

结论：要让怪打它，**必须新写随行召唤物的受击**；仇恨不用新做，诱饵那套现成。

## 2. 方案

**受击（不吸仇恨，推荐）** 只有「碰到它的近战怪」才伤它：每只怪每 1 秒一次，`e.dmg × m3_hurt_mult`（0.4，同诱饵缺省）。不改怪的走向，队长受到的伤害不变。理由：吸仇恨等于给队长加减伤，和「削弱」方向相反；Mon3tr 站在队长与敌群之间（10-29 刚改的前跃落点），本来就是最先被碰到的。敌弹、Boss 招式、区域、侵蚀不打它（v1，同突击队友）。备选 B：圈内 40% 的怪改追它（同突击仇恨 `aggro_share`），Mon3tr 更像坦克，但队长更安全，削弱要加码。

**血量** 上限 = 队长当前生命上限 × `m3_hp_k`（3.0），随成长同比例涨。队长 120–150 时约 360–450。推算：怪接触伤害 5–22（`enemies.json`），× 0.4 = 2–9 / 次；轻接触（2–3 只）约 9 HP/s，撑 40 秒以上；重围（8 只同时贴着）约 29 HP/s，约 15 秒见底。所以「一局倒 1–3 次」落在重围段。非战斗（3 秒没被碰）约 20 秒回满（`m3_regen_secs`）。

**倒下 / 复活** 血空倒地 `m3_revive_secs`（18 秒，原作天赋「Mon3tr」再部署 25 秒）：躺在原地（没有倒下帧条，先用待机帧转 90° 的灰影，同无 death 条的队友），倒计时头顶读秒；到时在队长身边起身，回 50% 血、1 秒无敌。倒地期间不出手、不接响应动作（「护主」跃击跳过）。熔毁终结技冲出去自爆后：**同一倒计时**（docs/198 §4.4 原写 8 秒，改 18 秒，一局 3–4 次约 54–72 秒不在场）。S3「指令：熔毁」8 秒内 Mon3tr 无敌、不会倒（技能主体，倒了就没得放）。

**治疗分配** 每一拍治疗（`heal_cd` 3.5 秒一拍、战术协同 ×1.3）只给一个人：
1. 队长危险 → 队长：生命 < 45%，或最近 3 秒掉了 ≥ 20% 最大生命，或神经损伤 ≥ 60%。
2. 否则谁的生命百分比低奶谁；差距 < 5 个百分点留给队长（防来回切）。
3. Mon3tr 倒地 / 满血 → 队长。Mon3tr 拿到的拍数在任意 10 秒内不超过 40%（`m3_heal_share_max`，防把队长饿死）。
4. 给 Mon3tr 的量 = 同百分比 × Mon3tr 上限 × `m3_heal_k`（2.0）。单拍约 14 HP，对战斗中的失血杯水车薪——Mon3tr 靠血池和脱战回血，治疗主要的作用是**占掉拍数**。
5. S1「结构加固」（清神经损伤）永远给队长。**庇护**（治疗溢出触发的减伤，现 `guard_red` 0.1、5 秒）只在落到队长身上溢出时触发，不因 Mon3tr 的拍触发——这是削弱的主要来源（见 §3）。
6. 治疗拍的起手条件 `hurt_any` 加上「Mon3tr 没满血」。

**画面** Mon3tr 血条沿用队友血条样式（队长生命条下方一行，`hud_banners.gd`；受击白闪、倒地写「倒地」+ 读秒）；头顶短血条（已有 `s.hp` 那条）受伤后 3 秒显示。

## 3. 削弱幅度估计（推算，未实测，云端配对前不下结论）

现状基线（docs/111）：凯尔希单人开局标准档 **85%**（各开局最高；塞雷娅 83、斯卡蒂 77、维什戴尔 62）。docs/88（10-14，当时庇护 20%，现已改 `guard_red` 0.1）：凯尔希的减伤（庇护近乎常驻 + 结构加固）与治疗一样大。

| 来源 | 估计 |
|---|---|
| Mon3tr 不在场：倒 1–3 次 × 18 秒 + 终结技 3–4 次 × 18 秒 ≈ 72–126 秒 / 一局 15 分钟（8–14%） | 凯尔希队总输出约 −3～6%（Mon3tr 占比未量，需 `hit_sources` 拆分） |
| 治疗拍被分走 20–35%（战斗中）：治疗收入同比例降 | 队长净回复约 −0.15～0.25 %/s |
| 庇护：每拍刷新 5 秒、拍间隔 3.5 秒，近乎常驻；少 1/3 的拍就出现空档，在场率约 95% → 70–75% | 额外约 −2.5% 伤害减免（10% × 25%） |
| 合计 | 凯尔希续航约 −12～18%；开局胜率约 **85 → 74–78%**（±6 点），回到斯卡蒂 / 塞雷娅档，仍高于维什戴尔 |

吸仇恨方案 B 会把这个数字抬回去 3–5 点；若用户觉得不够狠，加码顺序：`m3_revive_secs` 18→22 → `m3_heal_share_max` 40→50% → `m3_hp_k` 3.0→2.5。

## 5. 验证

- 开关 0：同 seed TRACE 与 main 逐行相同（核对没带出别的改动）。
- 校准：用遥测里的 `m3.downs` 调 `m3_hp_k`，目标一局中位 2 次（0 次 ≤ 20% 的局、≥ 5 次 ≤ 10% 的局），Mon3tr 在场时间 ≥ 88%（含熔毁终结技的不在场）。
- 削弱：云端配对（凯尔希开局标准 48 局 + 固定队 md1 28 seed × 2 档），开 / 关各一组；目标开局 74–78%。改的是玩法，同 seed 本来就不会逐行相同，只看胜率与续航指标（承伤 / 治疗 / 庇护在场率）。

## 7. 用户定稿与实现（10-29，分支 `claude/m3-hp`）

用户对 §6 的回答：① 吸仇恨——**要**（用备选 B：Mon3tr 周围一定比例的怪改追它）；② 熔毁期间**不**无敌；③ 倒下爆炸——精二前不爆、精二后触发「不毁重构」小爆；④ 庇护**算** Mon3tr 身上的溢出治疗；⑤ 复活 18 秒（熔毁终结技后同样 18 秒）。

与方案的差异（都是定稿后的调整）：
- 仇恨：`m3_aggro_r` 150 内、`m3_aggro_share` **0.35** 的近战怪（非 Boss、非箱子）改追它；按怪 id 的黄金比哈希定（不取随机数、结果不变，`m3_hp.gd _contact`），初值，按一局倒 1–3 次的目标调。
- 受击：同方案（每只每秒一次 × 0.4）；倒地期间不被打、不拉仇恨、不接「护主」跃击。
- 庇护算 Mon3tr 的溢出后，「Mon3tr 比队长低 5 个百分点才分到」的迟滞留着就永远溢不出（单拍约 3% < 5%）：`m3_heal_gap` 改 **0**（Mon3tr 只要比队长低就能分到，占比上限 40% 兜底），Mon3tr 接近满血时的一拍溢出触发庇护；削弱因此比 §3 估计的少一块（庇护在场率不再掉那 5%），需云端配对看。
- 熔毁终结技（docs/198 §4.4）还没合进 main：留了接口 `M3.down(o, s, kd, secs, silent)`（silent = 自爆用掉它，不触发倒下小爆、不弹提示），接终结技时调它，秒数取 `m3_revive_secs`。
- 倒下小爆：`blocks.summons.mon3tr.on_down`（cond `elite >= 2`；半径 `rebuild_r`、× `rebuild_mult` 真实伤害、眩晕 `rebuild_stun`，来源记「Mon3tr · 熔毁」）。
- 遥测：BALANCE 行 `m3`（`downs` 倒地次数 / `down_secs` 不在场秒数 / `hurt` 受伤 / `regen` 回血 / `heal_to_m3` 与 `heal_ticks_m3`）；`--m3log` 打倒地 / 复活 / 治疗落点（找录像时刻）。
- 开关：`balance.json kaltsit/m3_hp`（0 = 回旧行为），旋钮 `kaltsit/m3_*` 同 base 键名，`--bal=` 覆盖。
- 画面：队长血条下一行「Mon3tr」（同队友行样式；倒地换灰色复活进度 + 「倒地 N」），头顶短血条（受击后 3 秒 / 低于 60%），倒地画待机帧转 90° 的灰影 + 读秒弧；`hud_allyhp.top_shift()` 把灯火行 / 状态胶囊一起下移。
- 文案：图鉴简介 / 治疗说明 / 精二说明同步（`kaltsit.json` 的 attack.desc、gallery.desc、精英二 desc）。
- 测试：`m3_hp_test`（check.py 项 `m3_hp` / `m3_hp_off`）。

## 10-31 修：两根血条 + 队友治疗看不出（用户截图反馈，分支 `claude/m3-bar-heal`）

- 两根血条：删掉 `m3_hp.draw_bar`（身上的细条），只留 HUD 头顶条（`hud_allyhp._draw_m3_overhead`）。程序体退路（`ob_summon.sm_draw` 通用召唤物细条）也排除 Mon3tr。其他召唤物只有通用细条一根，HUD 不画，没有叠条。
- 治疗目标（机制 bug）：原来只有凯尔希自己的治疗拍（`split: true`）会分给 Mon3tr；另一名医疗流明的治疗全部走 `heal_leader`，Mon3tr 从来拿不到，队长满血时流明干脆不出手。现在流明的回复拍（`seg_lumen._h3_mend`，含技能回复）走 `m3_hp.heal_pick_mate`，分配规则与凯尔希同一套：
  - 队长危险（生命 < `m3_danger_hp`、神经高、3 秒内掉血多）时一律给队长；
  - Mon3tr 百分比更低才给它；
  - 10 秒内给 Mon3tr 的拍数不超过 `m3_heal_share_max`（记在凯尔希身上，两名医疗共用）。
- 治疗量：本来给队长的量按队长上限折成比例，再 × Mon3tr 上限 × `m3_heal_k`（同凯尔希口径）。另外，队长满血但 Mon3tr 受伤时流明也会出手（这时也照常加灯火）。
- 画面（`m3_hp.heal_fx`，凯尔希 / 流明共用），治疗打到 Mon3tr 身上时：
  - 施术者手部到 Mon3tr 胸口的治疗光束，命中端一团闪光；
  - 脚下一道扩散环；
  - 身上冒 7 颗绿色治疗粒子；
  - 头顶飘绿色「+数字」，和队长被治疗时一样。
  - 流明的另加他的灯笼命中图。
- 数值影响（无头 600 秒 × 2 种子，水月队长 + 凯尔希 + 流明）：
  - 流明给 Mon3tr 34 / 48 拍，其中 28 / 41 拍发生在队长满血时（原来不出手）。
  - 从队长身上分走的只有 6 / 7 拍，合计约 22 / 33 点生命（约队长上限的 15–20%，摊在整局里）。
  - 凯尔希给 Mon3tr 的拍数不变（23 / 48）。
  - 结论：队长生存几乎不受影响，Mon3tr 在场时间变长。
