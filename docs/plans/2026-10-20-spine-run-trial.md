# Spine 部件跑步试做（2026-10-20，干员）

目标：看能不能用原生 Spine 骨骼和部件直接调出像素小人的跑步，代替逐帧手绘。只试做和出图，不接入游戏、不改 game/。

## 1. 结论

抬腿口径（10-20 用户按推进之王旧 run 条定）：摆动腿离地按相位给像素，后踢 13、回收 8、前摆 3、前伸 2（@2x）。除浊心斯卡蒂外，所有人都用这一口径（`run_trial.js` 的 `LIFT_PX`）。

总体看：步态、前倾和次级摆动可以全自动生成，适合批量出初稿。剩下的问题（遮挡、手挡脸、裙子）每人手调 2–4 帧就能解决。铃兰、塞雷娅受限于原作部件画法，要靠补部件。

图在 `build/spine_run_trial/<id>/`：`*_run.gif`（0.6 秒）、`*_run_slow.gif`（4 倍慢放）、`*_x8.png`（8 倍逐帧带网格）、`*_vs_old.png/.gif`（与现有 run 条对照，GIF 左旧右新）、`*_strip@2x.png`（1024×128 帧条）、`editor_pack/`（编辑台数据包）。旧条里 96 画布的（安洁莉娜、星熊、凯尔希、斯卡蒂、浊心斯卡蒂、德克萨斯）是旧尺度，对照时按原点 (48,92) 对齐，人物本来就小一圈。

## 2. 方法

脚本在 `tools/spine_run_trial/`（只读素材，输出到 build/）：

1. **读原生骨架**：`load.js` 读 PRTS 原生 skel / atlas（3.5 用转出的 JSON，3.8 直接读二进制），基础姿势取 Idle t=0。
2. **步态表**（`run_trial.js`，8 帧）：每条腿 8 个相位（触地、下压承重、经过、后蹬、离地后踢、屈膝回收、前摆、前伸），用脚踝相对髋的位置和脚掌转角表示，单位是本人腿长。两腿相差 4 帧。双节 IK 保持骨长，膝盖始终朝前；支撑相反复迭代，把鞋底网格的最低点贴到 Idle 地面。摆动相按 `LIFT_PX` 的像素高度贴目标。
3. **躯干**：髋部整体前倾，胸部再加一点前倾，头部回正一部分（保住脸的可读性）；身体在下压帧最低、腾空帧最高。
4. **手臂**：空手与同侧腿反向摆，肘角随摆幅变化。持武器的手有三种做法：`holdPose` 给上臂 / 前臂的绝对角（推进之王扛锤）；只做小幅摆动（多数人）；`relativeArms`，只在原姿势上小幅摆（武器或盾挂在髋上的，如塞雷娅、德克萨斯，避免手脱离武器）。武器绕握点转，握点不漂移。
5. **次级摆动**：头发、尾巴、衣摆、绳带按骨骼名正则匹配；链根向后拖，各节按链深度滞后摆动（跑步 2 倍频，飘行 1 倍频）。
6. **像素化**：每个附件单独渲染 4 倍图 → 按 alpha 加权做 4×4 BOX 平均 → 二值透明（阈值 96；整件低于阈值的细节保留最大覆盖的格子）→ 映射到 bz_18 部件包的原色调色板 → 按层序合成。缩放与 bz_18 静态包一致（`bz_scale × source_scale`），画布 128 @2x。纵向让鞋底贴原点：Idle 鞋底映射到 y=120（最后一行 119），和游戏原点、旧 run 条一致（bz_18 按整身包围盒放置，推进之王因此悬空约 4 像素，10-20 已修）。铃兰的法杖下端在部分帧会低于地面 1–4 像素，还没处理。
7. **编辑台数据包**：每次运行都会写 `build/spine_run_trial/<id>/editor_pack/`（`pack.json` + 八帧世界骨骼 + 层序 + 链 / 武器 / 中文标签 + 调色板，地面平移到 y=0）。编辑台用 `--source <editor_pack>` 打开，就以脚本姿势为底稿手调，再导出。推进之王另有 `--editor-ops`，把姿势换算成相对 Codex 旧 Run 骨骼的修正操作，供旧数据包使用。

每人一个配置 `cfg/<id>.json`：躯干、腿、手臂的骨骼名，持武器的手，武器骨骼，次级骨骼正则，以及参数（前倾、步幅、起伏、摆臂、肘角；飘行另有 floatBob / floatTrail / floatKick / floatKnee）。

## 3. 编辑台：3.8 支持与通用数据包（10-20）

- **按文件头选运行库**：`server.py` 读骨架版本，`.skel` 取 hash 之后的第二个字符串，`.json` 取 `skeleton.spine`。3.5 用 `spine-canvas-3.5.51.js`，3.8 用 `spine-canvas-3.8.js`；运行库目录默认是主工作区的 `build/prts_ref/_node`（`--runtime-dir` 可改），`--runtime` 仍可显式指定。其他版本直接报错。
- **8 人 3.8**：艾丽妮、逻各斯、流明、水月、归溟幽灵鲨、铃兰、乌尔比安、维什戴尔（文件头都是 3.8.99）。另外 10 人是 3.5.51。
- **前端**：3.8 走 `SkeletonBinary` 读 `/native.skel`。动画混合参数和世界顶点接口的差异封装在 `pose_core.js` 的 `applyAnimation` / `worldVertices`；支持 3.8 剪裁附件（按层序裁到 endSlot）。关节标签、默认关节、导出文件名由数据包提供。
- **通用数据包**：`--source` 指向含 `pack.json` 的目录就按通用包载入；原推进之王 Codex 包照旧可用，来源指纹不变，旧 draft 仍能套用。
- **导出**：除 256 场景外，多出 `strip@2x.png`（128 @2x、原点 (64,120) 的裁切，游戏口径）。
- **已验证**：浏览器里打开铃兰（3.8）和浊心斯卡蒂（3.5）的数据包并导出，与脚本出图逐帧只差采样边缘，每帧约 25–40 像素；12 人的数据包都能由 `load_project` 载入并选对运行库。测试：`test_core.cjs` 新增 3.5 / 3.8 动画与顶点兼容；`test_server.py` 新增文件头版本识别、运行库选择、3.8 通用包载入（含指纹随骨骼变化、帧数不符时拒绝）、128 @2x 帧条导出。
- **还没有**：「对全部帧应用」开关、按相位的曲线编辑、命令行导入；嘴部没有 bz_18 的 mouth_sampling 特殊处理。

## 4. 共同限制

网格变形（deform）停在 Idle t=0，衣摆、裙子只能跟着骨骼转，没有布料形变；手放到大头前面会挡住脸，要手调层序或握点；胸、胯的侧向转身（两条腿前后交叠时的透视）做不出来，只能靠层序；正面画法的鞋在侧向跑步里看起来像碎步。

## 5. 建议的批量流程

1. 每人写一份 `cfg/<id>.json`（约 15 分钟：从 `node load.js cfg/<id>.src.json` 的骨骼清单里挑名字）。
2. `node run_trial.js cfg/<id>.json` → `python sheet.py ...` 出初稿，看 x8 和对照 GIF，调参数，一般 2–3 轮。
3. 有问题的帧用编辑台打开 `editor_pack` 手调，导出 `strip@2x.png`。
4. 按 docs/104 §4 三层验收（人眼先行）→ 用户批准后再接入。

## 6. 需要 Codex 补的替换部件

只补部件，不画整帧（docs/104 §3）。每件按原作 PRTS 立绘配色、和现有部件同网格，作为同一槽位的替换附件。

**铃兰（必须）**：现在像碎步，原因有三：裙摆是从胸 / 腰垂下的整片网格，把大腿和膝盖全盖住；腿部只有小腿和鞋两段可见；鞋是正面画法，侧向跑时看不出脚尖方向。
1. **侧向鞋**：左右各一只，脚尖朝右，鞋底平。跑步时替换 `F_L_Foot` / `F_R_Foot` 槽。
2. **膝盖 + 大腿下段**：左右各一段，接在小腿上端，长度约原小腿的 0.6。抬腿帧（相位 4–7）露在裙摆下面。
3. **裙摆分片**：把 `F_Coat_c*` / `F_Coat_d*` 那片裙摆拆成前片和后片：前片跟前腿大腿，后片跟后腿大腿。各附一张「后飘」版本，下摆向后约 15°，跑步时替换。
4. 尾巴、耳朵、头发不用补，现有骨骼已经能摆。

**塞雷娅（建议）**：盾和长外套挡住腿，身体正面朝向。
1. 侧向鞋（同铃兰第 1 项）。
2. 外套下摆分前 / 后两片（同铃兰第 3 项的拆法），让后腿后踢时能露出来。
3. 盾的位置不动。

**星熊（可选）**：腿被大盾挡住，按造型可以接受；想更清楚的话补侧向鞋即可。

## 9. 斯卡蒂跳劈（10-20 用户要求，试做）

同一套脚本加了关键帧模式：`cfg.keys` 逐帧写髋位移 / 前倾、两脚（着地贴地或空中相对髋）、两臂绝对角、剑角；`front` 帧把剑改到持剑手之前绘制。配置 `cfg/skadi_leapslam.json`，画布 224（剑举过头，原点平移 48 保持 (64,120) 相对位置），8 帧逐帧时长 140/70/70/100/50/130/110/100 ms（共 0.77 秒）。

帧序：蓄力下蹲、剑拖后 → 起跳、剑上抡 → 上升 → 最高点、剑在脑后 → 下劈、剑转到身前 → 落地劈中、剑尖触地 → 停顿 → 收势回到拖剑跑姿。

10-20 修手位：持剑的右臂在原层序里位于头和帽子之下，大头小人的头紧挨肩膀，手一抬到胸口以上就被头挡住或盖住脸。所以第 3 帧把手放在髋后、剑竖在背后蓄力；第 4–6 帧手留在髋前，用 `top` 把右臂、剑、拳头移到最前绘制，靠剑身的大弧线表现下劈，手不再上抬。随后按用户意见把劈下段的手往前伸（第 5–7 帧手臂前下 35–50°），同时把这三帧的前倾降到 8–10°、头回正 60%，避免大头压到前伸的手上；落地弓步加宽。小人手臂短，再往前伸会盖住脸，力量感要靠刀光或冲击特效来补。

图在 `build/spine_run_trial/skadi/leapslam/`。没有刀光特效；落地帧剑尖会插进地面 1–2 像素；横向位移约 12 像素写在帧里，接入时如果要原地播放，需要扣掉。

## 10. 斯卡蒂全向回旋 / 反手斩（10-20 用户要求，试做）

- **全向回旋**（三技能「涌潮悲歌」的 attack_spin，`cfg/skadi_spin.json`）：蓄力 → 正面横扫 → 剑伸直出手 → 转背面（整帧镜像，剑在身后）→ 背面横扫 → 转回正面、剑在身后 → 正面收招 → 回到拖剑跑姿。转身靠 `flip` 整帧水平镜像，原点在画布中线，镜像后脚下位置不变。
- **反手斩**（天赋「深海掠食者」第 3 次横扫后的追加斩，`cfg/skadi_backslash.json`）：剑在身前低位 → 向上挑 → 剑竖起转到身后 → 向后上方斩出（出手）→ 剑落到身后低位 → 回到拖剑跑姿。
- 共同做法同跳劈：手保持在髋位，剑在身前的帧用 `top` 把右臂、剑、拳头置前绘制。两套都是 8 帧，逐帧时长写在配置的 `ms` 里。游戏现用的是 6 帧 12fps（回旋），反手斩目前复用 attack；接入时按游戏的帧数和出手帧重排。
- 限制：镜像帧在编辑台数据包里没有标记，进编辑台看到的是未镜像的姿势；回旋没有刀光，360° 的感觉主要靠镜像和剑位切换，建议配合现有 fx_slash_circle_deep。
