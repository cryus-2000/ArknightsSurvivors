## 2. 设计规则（三类成长共用）

### 2.1 三个可见维度与「视觉签名」

| 维度 | 玩家看到的变化 | 对应藏品方向 |
|---|---|---|
| 数量 | 多一发弹 / 多一道剑气 / 多一只召唤物 | §3 §4.2 §5.1 |
| 尺寸 | 判定圈、刀光、锤击、召唤物体型变大 | §4.1 §5.2 |
| 时长 | 召唤物 / 效果多撑一会儿 | §5.2 |

每件改造藏品**必须带一个画面上一眼认得出的签名**，没有签名就不改（继续当数字藏品）：额外弹有不同的弹体 / 角度、剑气是新的飞行体、范围是看得见的更大圈、召唤物是新的身影。

### 2.2 叠层递减（不设硬上限）

同一效果每多一层，边际收益 ×衰减，永远加得上，但越来越少：

- **数量类**（弹 / 剑气 / 召唤物）：第 i 层的「额外单位权重」`w_i = 0.7^(i−1)`，累计额外单位 `E = Σ w_i`（1，1.7，2.19，2.53，2.77，2.94 … 趋近 3.33，**渐近而不是封顶**）。`E` 的整数部分是确定的发数，**小数部分用累加器**（每次出手把 `E` 的小数加进该干员的计数器，满 1 多一发）——不用随机数，同 seed 逐字节可复现，也不会出现「一会儿 2 发一会儿 3 发」的抖动感以外的随机。
- **尺寸类**（范围 / 体型）：每层增量 ×0.8（+12%，+9.6%，+7.7%…，渐近 +60%）。画面上另有「缩放上限」（`FX_SCALE_MAX` 3.2 等）兜底，超过的部分只算判定、不再放大特效（与 §6 一致）。
- **获取侧软限制**：沿用爆率，不加持有上限。

### 2.3 总伤预算：单发递减、总伤适度上升

额外单位不是白送的双倍伤害。设每个额外单位对总伤的「效率」`ε`（基础档 0.15 / 稀有 0.20 / 核心 0.30），总伤 `T = 1 + Σ ε_i·w_i`，**每发伤害 = T ÷ (1 + E)**（在 0.4–0.65 之间）：

| 例：+1 发（稀有 ε 0.20） | 层 1 | 层 2 | 层 3 | 层 4 | 层 6 |
|---|---|---|---|---|---|
| 额外发数 E | 1.00 | 1.70 | 2.19 | 2.53 | 2.94 |
| 总伤 T | ×1.20 | ×1.34 | ×1.44 | ×1.51 | ×1.59 |
| 每发伤害 | 0.60 | 0.50 | 0.45 | 0.43 | 0.40 |

对不会因为「多一发」而变强的干员（单体治疗、纯技能输出等），**效果退化成 `T` 的直接增伤**（等价于原来的 +x%），保证改造后藏品对所有人的价值不低于旧版；画面签名只在读得到该属性的干员身上出现。这条规则使「改造 = 同样的数值预算 + 额外的画面」，不改变 E 流派整体强度（需跑 `--lanes E` 校验，§8）。

### 2.4 与「贯穿」「穿甲弹」的区别

| | 贯穿（卡）/ 穿甲弹（藏品） | 本稿的「+1 发」 |
|---|---|---|
| 解决什么 | **一条线上**多个目标（子弹穿过去） | **多条线**打不同目标（扇形散开 / 连发） |
| 单发伤害 | 不减（卡）/ 每穿一名 −15%（穿甲弹） | 额外发每发 0.4–0.65 |
| 总伤 | 敌人排成线时才高 | 目标分散时也高（反而对密集团更稳） |
| 同时持有 | 额外发**继承 `min(底穿, 1)`** 的穿透，不继承穿甲弹的「穿全部」（防止 发数 × 穿透 相乘爆炸）；穿甲弹本身对主弹照旧 | |

### 2.5 其它共同约束

- 玩法随机数只用 `g.rng` / `rng_op`（累加器法不用随机），同 seed 对旧局不变（`synergy` 同款开关思路：每类效果一个 `balance.json` 旋钮，缺省 1，置 0 退回旧数值藏品）。
- 干员积木数据驱动：新增属性 / 规则尽量走 `stat_defs.gd` + `relic_effects.json`，不在 `relic_fx.gd` 写死数值（docs/35 的约定）。
- 文案、关键词按 docs/76；原作专有名词需可查证（PRTS 优先），下文「关键词」列的新词是**通用词**（散射、连发、剑气、增幅），不冒充原作术语。

## 3. 远程：投射物 +1

### 3.1 哪些干员有投射物、「多一发」怎么读

| 干员 | 现有攻击 | +1 发的读法 | 现有基础 |
|---|---|---|---|
| 能天使 | `projectile`（连发，`op_shots`） | 直接 `op_shots +1`：多一发，各发独立索敌，不够目标时 ±spread 扇形 | **已有** |
| 逻各斯 | `bolt`（弹） | 多一道法术弹，优先打不同目标，目标不足时 ±8° 扇形 | 需接 `op_shots` |
| 流明 | `lantern`（光弹） | 多一颗光弹，同上 | 需接 |
| 铃兰 | `foxfire`（狐火） | 多一团狐火 | 需接 |
| 艾雅法拉 | `shell`（抛射） | 第二枚炮弹落在次优目标（×0.6 起），同「礼尚往来」做法 | 样板：`_h4_twin` |
| 维什戴尔 | `cannon`（炮击 + 余震） | 额外炮弹 = 次优目标，与分支节点「礼尚往来」同源；节点已开时第三发起才吃本藏品的递减曲线 | `_h4_twin` |

读法的共同规则：**目标 = 最近 n 个不同目标，不够用同目标 ±spread 错开**（照能天使 `_fire_round` 的口径，不另造索敌）；额外弹的弹体用与主弹同款但小一号（×0.8 体型）、略浅的颜色，一眼分得出「哪发是多出来的」。

## 4. 近战：范围扩大 + 普攻剑气

### 4.1 范围（尺寸）

近战干员的判定半径已经读 `op_range`，`slash_fx` 的半径也是同一个数（`ob_core.exec_shape`），所以 `cone / circle` 形状的**判定和刀光已经是同步放大的**。待核对（§8 第 1 步，纯画面清单）：

| 形状 | 干员 | 视觉是否随 `op_range` | 需要做的 |

### 4.2 普攻额外剑气

近战普攻每次出手额外射出一道**剑气**（飞行体，沿朝向直线飞，命中后消失，不被目标数限制但每命中一名 −10%，最低 50%——与「穿甲弹」同一口径但更温和）。拉普兰德 / 斯卡蒂已有自己的剑气，读法：**她们的剑气 +1 道（扇形 ±12°）而不是叠第二套**。

## 5. 召唤物：+1 / 体型 / 持续时间

### 5.1 召唤物 +1

规则：**每个召唤物种类的 `cap` +1（受 §2.2 递减的累计小数向下取整，小数用累加器 → 逐步兑现）**，新增的那只是**副体**：伤害 ×0.6、体型 ×0.85、同款贴图略浅，不继承精英化形态；到期规则同本体。这样「多一只」看得出，又不会比本体强。

| 干员 | 召唤物 | 现有 | +1 的读法 |

| 维什戴尔 | 魂灵之影（精二 2 个） | 0 / 2 | 第 3 个影子，开炮间隔按 `fire.gap × k` 顺延（`seg_wisadel._h4_souls_sync`）；精二以前无影子，不适用 |

## 6. 手机帧率预算与降级规则

基准：手机网页 ≥30 帧、入门本 60 帧（memory：低配帧率目标）；画质自动档（`Cfg.auto_level`）已有分级；爆炸 / 命中去重（0.2 秒 / 半径 24）已有。下面的数字是**起点，必须由 perf 会话用 `--fixed-fps` 轮换对照测一遍再定**，不当最终值。

| 规则 | 画质满档 | 自动降级档 1（手机默认起步） | 档 2（掉帧时） |
|---|---|---|---|
| 额外弹（散射 / 连发）的枪口焰 + 拖尾 | 全画 | 只画弹体 + 短拖尾 | 只画弹体（4 像素点），**命中特效按 0.2 秒 / 24 半径合并**（泛化维什戴尔那条） |
| 同屏额外弹体数上限 | 64 | 32 | 16；超出的**不生成实体**，伤害并入主弹（总伤不变）并在主弹上画一个小「+n」闪点 |
| 剑气同屏上限 | 24 | 12 | 6；超出的并入普攻伤害，剑气命中特效同样合并 |
| 召唤物副体 | 全动画 | 非本体副体用待机循环（不跑攻击动画帧条） | 副体静止站位 + 只在出手瞬间闪一下（伤害照算） |
| 体型放大 | 按比例 | 按比例（贴图缩放几乎免费） | 同 |
| 范围放大的特效 | 帧条按半径缩放 | 同 | 缩放封顶 `FX_SCALE_MAX`，超出只算判定 |

- 额外弹 / 剑气是**实体对象**（不是 fx），命中走正常网格查询；优化点只在「少生成」「少画」，不动判定。
- 伤害并入主弹的「小 +n」不是新 fx kind，复用 `spark`。
- 验收：iPhone 仿真下，E 流派三件满层 + 能天使 S3 倾泻（子弹最密）+ 怪群 12 只，帧时不低于改造前 +10%；超了就把对应档的上限再砍一半。
