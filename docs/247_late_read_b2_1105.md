**结论**
1. 三项都做了，各一个独立开关、缺省 0 = 关、只改画面：`render/light_share`（V4）、`render/ground_ring_edge`（V9）、`render/crowd_env_dim`（V10）。同 seed TRACE：全关 vs 全开 576 行逐行一致（到 9:35），全关 vs 各项单开 486 行逐行一致（到 8:05）。
2. V9 效果最明显：8:00 地面光环叠层占战场区 16.5% → 1.8%（只开 V9）/ 2.1%（全开），9:30（全开）2.3% → 0.9%；成片的紫色巢穴光盘没了，只剩呼吸的虚线边。
3. V10 按活敌数压暗地面 / 溟痕 / 环境颗粒：8:00 系数 0.87、9:30 0.85（暗 13–15%）；整帧平均亮度 0.170 → 0.163、0.147 → 0.144，画面不更亮；我方特效平均亮度不变（0.377 → 0.375），亮度占比 13.3% → 14.4%、14.1% → 14.3%。
4. V4 在这几帧里**几乎看不出差别**：8:00 我方照地候选只有 5 个（全都入选，剩下 7 盏照旧给敌弹），9:30 我方本来就占满 12 盏。瓶颈是「我方候选少」不是「排序」；已加「每一下命中挂一盏 0.12 秒照地光」补候选，但截图的非实时步长（约 0.066 局内秒 / 帧，光学层不是每步都跑）下命中光很少被拍到（入选的命中光 0–1 盏）。V4 的实际观感**未验证**，需要实时录像或实机看。
5. 未完成（云端额度用完，协调人 11-05 叫停）：20 秒开 / 关录像**未做**；三个额外 TRACE 用例（维什戴尔机器人局、凯尔希召唤局、遥乡 + 旗帜局）**未跑**；只开 V4 的 nofriend 分层**未拍**；快检在 V4 命中光改动之前的提交上通过（171 项 0 失败），**最终提交未重跑快检**。

## 1. V4 `render/light_share`：照地光按我方 / 敌方分账
- 总盏数仍是 `optical_dl_max`（12），着色器数组不变，GPU 开销不变。
- 候选加两位：阵营（我方 / 敌方：敌弹、带 `enemy` 标的帧条、`fx_boss*` / `fx_enemy*`）和伤害档（终结技 3 > 重击 2 > 普攻 1）。
  - 帧条：`vfx.fx_sprite` 生成时打 `lt`——终结技演出期间（`ult.playing()`）3；该干员在技能持续期间（`squad.update` 里 `skill_active()`）2；其余 1。只在开关开时写。
  - 刀光：二档以上记 2。
  - **命中光**：`vfx.hit_react` 里我方每一下非持续伤害命中都在命中点登记一盏 0.12 秒照地光（技能 / 暴击 / 弱点 / 三档命中记 2，其余 1，终结技期间 3；只留最近 24 盏；半径 `light_share_hit_r` 64 × 0.8 / 1 / 1.3）。第一版只挂在三档命中上，结果技能命中恒为 0 档、几乎不出光，已改。
- 选灯（`optical._share_pick`）：① 我方保底 `round(12 × light_share_ally)` = 6 盏；② 份额内先给外部来源（见 §5），再按「档 × 10 + 强度」取我方候选；③ 剩下的盏数在所有没入选的候选（我方 + 敌方）里照旧按强度取。我方候选不够 6 个时，空出的盏数自然给敌方。
- 队长周围局部光预算（`optical_local_light`）对份额内的灯最多压到 `light_share_floor` 0.7 倍（原来近战后期正好在这里被压暗）。
- 三档命中的 GPU 迸溅不再吃 `optical_local_bursts`（原来超 4 次压到 0.4 透明度）。
- `optical_glow_budget`（全屏发光预算）没动：它在着色器里按整屏发光度算，分不出我方 / 敌方，要分账得改成两张掩码，不在本批。

## 5. 和配方试点（`claude/fx-recipe-pilot`，docs/245）怎么接
那边在 `optical._dyn_lights` 里直接 `FxRecipe.lights_for(g, vr, nmax)` 先占至多 `fx/recipe_dl`（4）盏、不超过一半，和本分支的同一段会冲突（合并试验：`optical.gd` 两处冲突，一处是 preload 行）。合并时这样解：
```gdscript
const FxRecipe = preload("res://scripts/render/fx_recipe.gd")
const LateRead2 = preload("res://scripts/render/late_read2.gd")
...
		var share: bool = LateRead2.on("light_share")
		if share:
			# 配方灯走「我方份额内再分配」：份额内先给配方至多 fx/recipe_dl 盏，剩下的我方份额再按伤害档给其它候选
			share_source("recipe", func(v: Rect2, n: int) -> Array: return FxRecipe.lights_for(g, v, n * 2), int(Bal.v("fx/recipe_dl", 4.0)))
			cand = _share_pick(cand, nmax, vr)
		else:
			var mine: Array = FxRecipe.lights_for(g, vr, nmax)   # 原配方分支写法照旧
			var rest: int = nmax - mine.size()
			if cand.size() > rest:
				cand = _top_n(cand, rest)
			cand.append_array(mine)
```
- `lights_for` 里有 `mini(recipe_dl, nmax / 2)`，传 `n * 2` 让它按 n 给；返回的候选是 4 位格式，`_share_pick` 补成我方 / 普攻档，并计入 `dl_stat.ext`。
- 也可以在 `_ready` 里登记一次（`share_source` 是持久表），效果相同。
- 接口：`optical.share_source(名字, Callable(vr: Rect2, n: int) -> Array, quota)`；quota ≤ 0 或 Callable 失效即注销。份额内按登记顺序先给来源，再给档位排序。

## 7. 附带发现：云端截图的光学观感是关的
- 云端 xvfb 用 llvmpipe 软渲染，画质自动档落到「低」，`optical.wanted()` 为假：光学观感整层（灯火光池、辉光、发光预算、特效照地光）都不画。第一轮截图所有帧照地光 0 盏，才发现。
- 本次截图一律加 `--quality=high`。**docs/243 的诊断截图（同一套脚本，没带这个参数）很可能也是在光学关的情况下拍的**，§3.2 关于 `optical_glow_budget` / `optical_dl_max` 的结论是从代码读出来的，截图量测里没有这一层。建议协调人转告诊断会话复核。
- 另：平衡模式下光学层的 `_process` 不是每个模拟步都跑（15 秒局内约 29 次），寿命短于约 0.5 秒的照地光在截图里很难被拍到；V4 命中光（0.12 秒）在实时游戏里按 60 帧计约 7 帧可见。
