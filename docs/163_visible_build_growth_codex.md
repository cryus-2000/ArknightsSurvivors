## 3. 获取、等级与叠加

保持藏品持有件数不限，不修改爆率、商店价格、稀有度、升级卡和其他藏品。

现行 `relic_fx.gd` 的纯属性件最多 3 级，等级增量系数为 **1 / 0.7 / 0.5**；带触发效果的通常只有 1 级。七件中 #130 带命中回技力，当前为 1 级；其余六件为 3 级。首版保留这些等级上限，不能因为改成 rule 后默认退成 1 级。

- 新数量效果按每件自身等级累计：`E(L) = Σ 0.7^(i−1)`，1 / 2 / 3 级为 **1 / 1.7 / 2.19** 个额外单位。
- 新尺寸 / 时长效果按每件自身等级累计：`S(L) = Σ 0.8^(i−1)`，为 **1 / 1.8 / 2.44**。例如 #64 的新增范围为 **18% / 32.4% / 43.92%**。
- 数值预算和保留的旧增益仍用现行累计系数 `A(L) = 1 / 1.7 / 2.2`，不偷偷把旧第三级 0.5 改为 0.49。
- #58 与 #59 分别累计、相加；#63 与 #56 同理。可以同时存在散射与延迟补发，但额外发不会再次派生额外发。
- 数量的小数部分用整数定点累加器兑现，按「干员 + 藏品 + 合资格动作」记录；每次实际出手推进一次，暂停、渲染和索敌空转不推进。用 1 / 100 单位足以精确表示首版三档，不消耗随机数。
- 升级保留不足一个单位的余数；离队清理，新加入实例从零开始；切队长保留。读档按是否保存进行中的对局接入，不能只依赖显示帧重建。
- 卡面直接展示当前 / 下一级的实际增量；详细说明写「升级后增益递减」。不再给这些复合效果套通用的「本级 70%」一行，因为数量、尺寸与数值的曲线不同。

单件无限升级属于另一个产品取舍，本稿不把它混入可见成长。若以后要求开放，需要一并改抽取、升级、存储与展示，不能只改 `max_lv`。

## 4. 远程：增加发射，保留原有攻击

### 4.1 一次普攻的含义

在普攻动作的出手入口建立一次编号；原本的连射、多弹、精英化追加都属于这次动作的基准攻击。藏品每次动作结算一次，不能挂在每颗弹命中、每段余震或每个技能 tick 上。

能天使保留 `op_shots`、技能弹药消耗和基础连射。维什戴尔保留「礼尚往来」原发数 / 系数、余震、残影与魂灵同步。藏品额外弹不消耗技能弹药，不再次触发这些派生机制；原本的主攻击路径继续照旧。

### 4.2 伤害预算

用同一攻击在**去掉本次两件藏品增益**后的直接伤害定义基准，保留其它藏品、职业与干员成长。对该动作计算 #58 / #59 的增量预算 `B58 / B59`：等于在现行属性计算顺序中分别加入 `ε × A(L)` 时带来的直接伤害增量。不能在已经吃过这两件增益的伤害上再乘一次 ε。

每件藏品每颗额外弹分配 `B / E(L)`；长期平均产生 `E(L)` 颗，平均增加 `B`。整数兑现造成某次攻击多一颗、某次少一颗，这是确定性节奏。一级、原本单弹 100 且无其它增益时，#58 为「原弹 100 + 额外弹 25」，#59 为「原弹 100 + 补发 35」。原弹伤害不被分摊削弱。

对现有多发动作，B 按这次动作原有直接伤害总量计算，不拿单颗伤害冒充全动作预算；不把余震、追击、处决等派生收益计进 B。多目标和 AoE 的实际命中收益另测，不把预算称为最终 DPS。

未进入以上拆分的远程独立技能 / 持续伤害走等量属性增益；治疗和增益效果不因为藏品多弹被重复释放。实现需给每类伤害明确分类，防止重复加成与漏加成。

### 4.3 目标、穿透与触发

- 散射优先不同目标；自动攻击沿用已有射程、视线与优先级。目标不足时允许打同一目标，用小角度偏移区分，不强制丢弃这份预算。
- 手动攻击遵守玩家指向，不改成全方向索敌。无目标时沿玩家方向发射，不为了生成藏品弹而阻止原本允许的空放。
- 连发沿出手时锁定的方向，间隔用模拟时间 0.08 秒；不重新寻找另一侧目标。目标死亡可以自然落空，不追补伤害。拥有者离队 / 倒下 / 对局结束取消尚未发射的队列；切队长不取消。
- 额外远程弹第一版只命中一个目标；原有主弹的贯穿卡和穿甲弹保持原样。AoE 类型额外弹保留对应的落点伤害形状，预算只结算一次，不复制二次爆炸和追击链。
- 额外弹标记为藏品来源，禁用再次散射 / 连发、干员弹药消耗、命中叠层、技力回收和递归追击；普通击杀、掉落、归属与遥测仍正常。例外必须逐条登记，不用笼统复制全部 `on_hit`。

## 5. 近战：范围与剑气分开处理

#64 新增的是合资格近战的普攻范围，不连带扩大所有技能、治疗与光环。新增范围乘到普攻最终几何尺寸，旧 `op_range`、#81、#140 原规则保留；画面与判定读取同一最终几何量。身体和武器精灵不整体放大。

## 6. 召唤：先有可靠生命周期，再加数量

适用种类：海嗣、替身、魂灵之影、触手桩；Mon3tr 例外。不把瞬时触手命中、余震或普通追击冒充可复制的召唤实体。对应种类尚未解锁时，保留数值收益，不提前生成。

副体显示尺寸为本体的 85%，复用帧条与原有材质色；不改变身体碰撞、阻挡、吸引仇恨或移动规则。副体不复制技能、治疗、共鸣、减速光环、出生 / 死亡触发；只执行列入白名单的直接攻击。

#129 保留普通追击的原 +35% 增益；可复制召唤物把这份预算分到本体与副体。建议本体取 +15%，副体合计分配剩余 +20% 的原本同种召唤物输出预算。原稿「副体固定 60% 再加本体 15%」不再采用，因为本来只有一只时就远超原 +35%。若一个种类原有 N 只，剩余预算按 N 只的基准输出合计分配，不能每只本体各自再派生一组副体。

这只是同目标持续输出的预算，副体位置、覆盖、空转会改变实战结果。Mon3tr 保留原增伤并将身体显示尺寸 +15%；判定和攻击范围保持原样。#130 对常驻召唤物只增加体型，持续时间部分不生效，并在说明中写清，不擅自把无限时长兑换成更多攻击力。

小数数量的兑现周期按种类规定：限时实体按一次正常召唤事件兑现；常驻的魂灵之影按原有一轮攻击调度兑现临时副体，完成该轮攻击即回收。不得每帧增加 cap 或无限积累实体。#129 升级后现有实体不被结束；在下一次合资格事件应用新数量。#130 的尺寸立即更新，限时寿命按「新的总寿命 − 已存活时间」重算，不重置年龄，不延长技能本身。

`SM_TOTAL_CAP = 24` 目前是数据召唤模块的上限，手写魂灵 / 替身 / 触手桩不能假定已被统计。实施时给新副体明确统一统计与稳定准入顺序；所有设备使用同一规则。副体不得挤掉本体；预算耗尽时不生成本次副体、不补伤害，累加器照本次事件消费，不在腾出空间后集中补发。此时收益会降低，必须作为压力场景披露，不能声称总伤守恒。

## 7. 手机与确定性

所有画质共用实体数、目标、移动、碰撞、出手与生命周期。画质只裁剪拖尾长度、枪口火花、命中粒子、精细帧动画与光晕；额外弹保留简化弹体，副体保留轮廓。攻击动画若参与出手时钟，只省绘制，不能停逻辑动画。

不新增按实际 FPS 变动的玩法上限。各模块已有硬容量需要清点，新增副体和弹体的容量处理必须按模拟状态决定，并在各档一致。若性能仍不足，重新评估全平台一致的数量方案，不能暗中减少手机命中数。

性能验收分两层：同机 / 同浏览器 / 同版本的前后对照，报告中位帧时、P95 / P99、内存、最慢 5 秒；真机再确认 30 帧目标。仿真 P95 增幅 ≤10% 可作为首轮回归预算，但基线已经低于 30 帧时，满足相对预算不代表达标。

至少覆盖：常见一层、合法最高等级、多发能天使技能、维什戴尔炮击、近战剑气密集、召唤混编、实际后期怪群压力。原稿「12 只怪」只作隔离场景，不当后期验收。
