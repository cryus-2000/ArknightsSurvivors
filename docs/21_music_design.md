## 版本沿革

- **v1.0**：深海氛围电子，37 秒循环四层。体检（2026-09-26）：80–90% 能量在 120 Hz 以下，手机 / 笔记本外放响度掉 8–10 LU；
  三段同速同调听不出推进；分层几乎常开且不对小节；危险层的心跳和低血心跳音效打架。
- **v2.0**（同日）：用户在 A 深海氛围电子 / B 电子 + 管弦两个 demo 里选 B。三段升调、分层按「强度」驱动并落在小节线上
  （强度规则与标定见下文，v3 沿用）；Master 挂 HardLimiter；预定义 Voice 总线（网页版运行时建的总线接不上输出）。
- **v3**（同日）：用户提出两点——战斗曲参考 mudeth《Machine in the Walls》（《以撒的结合：Antibirth》陵墓层）的风格；
  肉鸽音乐要无限循环。demo C（`Claude outputs/bgm_demo_c_0926`）通过后落地：
  - 风格：只借参考曲可测的风格参数，**不借任何旋律 / riff / 和弦进行**：约 144 BPM、以强力和弦为主（很少强调三音）、
    响段是长音和弦墙（每 1.5–2.5 秒换一个）、鼓偏稀（2 / 4 拍军鼓）、低频与中低频厚重、响段 / 静段交替、声场宽。
    编制：降 D 调双轨失真吉他（硬左右）、贝斯、摇滚鼓（骑镲）、管风琴、合唱、羽管键琴、主奏吉他。
  - 无限循环：从「固定长度循环」改成「8 小节一句的乐句，句尾按局势挑下一句」，同一句不紧挨着重复，顺序永远不会固定重来；
    去掉换段扫频 / 落点冲击这类「预告」音效（新段句首自带的镲就是段落感）。
- **竖琴音准修正**（同日，用户确认）：`gen_music.pluck`（Karplus-Strong）的循环延迟只能取整数采样，实际音高 SR / (p − 0.5)
  比目标偏高，音越高越偏：标题最高的竖琴音（MIDI 97）偏 +125 音分，开场 / 胜利循环 +56、Boss 击破 +49、商店 +36。
  改成生成后按「实际 / 目标」音高比放慢读取，修后实测全部 0 音分。随机数消耗不变，按三轮重做了标题、开场、商店、胜利循环、
  Boss 击破五首，其余声部的随机细节不变（商店除外：它的旧文件是用后来改过的代码生成的，音符不变、随机细节变了）；
  Boss 登场、失败循环、win / lose 没有竖琴，没动。修前 / 修后对比在 `Claude outputs/harp_fix_0926`。

### 商人配乐替换（2026-10-27）

- 来源：用户指定的 `E:/download_chrome/m_sys_rglk1shop_intro.mp3` 与 `m_sys_rglk1shop_loop.mp3`。前奏解码为 972797 帧（22.058889 秒），循环段 3434813 帧（77.886916 秒），均为 44100 Hz 双声道。
- 按前奏 → 正文顺序解码拼接，降采样至 **32000 Hz、双声道**，再编码为 `game/audio/music/shop.ogg`（Vorbis quality 4）；不裁切、不拉伸、不额外淡化两段接点，保留原音量。降采样后 3198266 帧、99.945813 秒（帧取整差小于一个输出采样）。文件 1576615 → 1468956 字节（减少 6.83%）。
- Godot 的 `loop_offset` 设在前奏结束处；导入配置与 `sfx.gd` 同时设置，保证有导入缓存和直接读原文件时一致。进入商店从头播放，正文结束回到 22.058889 秒，离开商店沿用原有淡出和选曲，再次进入重新播放前奏。
- 音乐仍走 Music 总线，音量、静音和自动测试静音规则照旧。`gen_music.py shop` 是旧合成曲生成器，不要用于重建现用 `shop.ogg`。
- 复现转换：FFmpeg 分别解码两份 MP3 为 44100 Hz 双声道 float32 PCM，按上述顺序拼接，输出使用 `-ar 32000 -c:a libvorbis -q:a 4`；从原 MP3 重做，不对旧 OGG 二次转码。循环点是秒数，仍为 972797 / 44100，不应随输出采样率改成除以 32000。

#### 网页音频内存核查（2026-10-27，仅方案，未改播放引擎）

- 本地导出 `build/release/final_2f7c7d76f/web/index.js`：`_godot_audio_sample_register_stream` 固定 `numberOfChannels = 2`、`sampleRate = GodotAudio.ctx.sampleRate`。上游 `AudioDriverWeb::register_sample` 先按 `mix_rate * length` 生成样本。因此只降源文件采样率、码率或改源文件为单声道，不能按同样比例削减这条网页样本路径的 PCM 缓冲。
- 商人整曲单份缓冲估算：48 kHz 混音时 **36.60 MiB**；真正以 32 kHz 混音时 **24.40 MiB**。这是 `时长 × 混音采样率 × 2 × 4` 的理论值，不是浏览器总内存实测。
- 同一导出的 `Sample.getAudioBuffer()` 调用 `_duplicateAudioBuffer()`，播放节点另拿一份完整 AudioBuffer，复制过程中还有临时 Float32Array。48 kHz 下，缓存加一个播放副本约 **73.20 MiB**，不含临时解码数据、浏览器内部副本与引擎堆。
- 当前 `Sfx.sample_mem_mb()` 只遍历 `streams` 和 `seq`，漏掉 `groups`（标题、商人、整首最终 Boss 等）、语音缓存及其他独立播放器，也未计播放副本。旧性能记录中的音频数字不能视为全部音频占用；应先按实际注册缓冲及播放副本补齐统计。
- 优先方案：① 验证网页混音率降至 32 kHz（影响所有声音，必须读取实际 AudioContext.sampleRate，并检查 Safari / Chrome）；② 网页播放节点共享不修改的 AudioBuffer，避免每次整段复制（须检查播放、暂停、循环、重入及独立节点状态）；③ 曲目退出且所有使用者停播后释放样本缓存，回来时重新注册（可能产生解码卡顿，需预载）。这些改动尚未实施。
- 引擎有内部注销入口，当前上游 `_bind_methods()` 未将 `unregister_stream_as_sample` 公开给 GDScript；本机 Godot 4.7.2 无头探针也确认 `AudioServer.has_method(...) == false`。本地网页 JS 有清理入口，接入需处理引用和播放生命周期。仅把曲子拆成多段而不回收样本，全部播过之后仍会累计完整曲长的缓存。
- 降采样验证：FFmpeg 解码确认 32 kHz / 双声道、时长差小于一个输出采样、峰值约 -2.25 dBFS；Godot 直接读取新 OGG 并从末尾循环，回到 23.397 秒（循环点 22.059 秒之后），断言通过。按用户要求不跑快检；未做手机实机听感或内存实测。
- 流式 BGM 可避免完整 PCM 常驻，但本项目已记录无线程网页流式几乎无声（docs/50 §30.5），本次未重新启用。浏览器媒体元素流式播放属于另一条实现路线，还需处理首次手势、Music 音量、页面隐藏和前奏接循环。
- 依据：[Godot 网页音频驱动](https://github.com/godotengine/godot/blob/master/platform/web/audio_driver_web.cpp)、[网页音频 JS](https://github.com/godotengine/godot/blob/master/platform/web/js/libs/library_godot_audio.js)、[AudioServer 方法绑定](https://github.com/godotengine/godot/blob/master/servers/audio/audio_server.cpp)，并与上述本地导出代码交叉核对。上游链接为核查时的 master，后续引擎升级需重新确认。

  E B 主题（激战层主奏 + 下方三度和声）。每句都收在 A（属）上，任何一句后面都接得上任何一句。
- 层：base 平静（贝斯长音、管风琴柔和音栓、合唱「呜」、羽管键琴琶音、管风琴旋律）/ pulse 交战（双轨节奏吉他墙、

- 每个文件 = 0.1 秒静音预留 + 8 小节正文 + 1.6 秒余音（尾端淡出）。各层增益按「同名轨在五句里拼起来测」统一定，句与句之间音量一致。

## 强度（game.gd `_update_music`）

每帧打分（计时都按局内时间 `t`，暂停 / 选卡时不走，平衡批跑加速时也对）：

| 项 | 分 |
|---|---|
| 800 像素内的敌人数 ÷ 正常密度（55 + 0.25·t），超出 1 的部分 | × 1.0 |
| 场上有精英 | + 0.45 |
| 大群预警 / 到达后 15 秒 | + 1.0 |
| 安全区收缩中 | + 0.45 |
| 近 4 秒净掉血 > 12% 生命上限（当前生命低于 4 秒均值；治疗抵掉的不算） | + 0.5 |
| 威胁等级 ≥ 4 | + 0.15 |

档位：≥ 1.15 且**连续 1.5 秒** → 2 激战（过滤一闪而过的密度尖峰）；≥ 0.35 或开局 20 秒后 → 1 交战；否则 0 平静。
升档马上（sfx 落在下一个小节线），降档要这一档连续 12 秒不够格，之后每 8 秒降一档。
Boss 倒下后 12 秒压回平静层喘口气（除非局面够激战），同时清掉 Boss 前残留的大群计时。
单项里只有大群能独自拉满；精英（在场约一半时间）、缩圈、掉血都要和别的叠上才到激战。
危险层：生命 < 35%（回到 42% 以上才关）、熄灯、在安全区外。技能生效**不再**计入（几乎一直有技能在放）。
`--musiclog` 打印状态切换（`MUSIC`）与每 5 秒一行采样（`MUSICS`：敌人数、300 像素内、精英、大群、缩圈、净掉血、威胁、生命）。

### 标定记录（2026-09-26）

- 第一轮 6 局（高手 / 普通各 3）：800 像素内敌人数中位 30 秒 37、1 分 52、2 分 68、3 分 112、5 分 121、8 分 150；
  事件占比（开局 20 秒后）：精英在场 48–52%、大群 15 秒窗 26–30%、缩圈 20%、净掉血 4–5%。
- 第一版权重（正常密度 46 + 0.2·t、×1.2、门槛 1.0、保持 15 秒）：5 秒采样模拟激战 42%，但实机逐帧判定测出 55%（单局 42–69%）——
  逐帧会抓到采样漏掉的尖峰，再被保持时间拉长。于是加「连续 1.5 秒」、门槛 1.15、正常密度 55 + 0.25·t、保持 12 秒（模拟约 32%）。
- 第二版实机 5 局（`--musiclog` 按状态切换计时）：平静 6% / 交战 61% / 激战 32%（单局 28–41%），
  每局激战 5–10 次、每次中位约 21 秒——激战是一段段的高潮，不再常开。
- 注意：`--balance` 每帧跑 8 步模拟，配乐计时必须按局内时间走（`t` 的差），按帧 delta 走会让大群窗口虚长数倍。

## sfx.gd 约定（v3）

- 两种曲目：`MUSIC`（整首循环：标题 / 图鉴 / 出发前 / 开场 / 商人 / 结算循环）与 `SEQ`（乐句式：战斗三段 / Boss / 最终 Boss）。
- 乐句式曲目有两组播放器（每组 = 各层 + 危险层）轮流用：当前句唱到「下一次混音开播时正好到句长」那一帧，
  在另一组里开播下一句，从「那一刻 - 句长」秒开始（先走 0.1 秒预留，正文正好接在上一句末尾）；上一句的余音在原组里响完。
  位置按第一层的 `get_playback_position() + get_time_since_last_mix()`（音频时钟），再加 `get_time_to_next_mix()` 预测开播时刻；
  拿不到播放位置（刚开播、网页版采样播放）时退回墙钟。
- 挑下一句：`SEQ_NEXT` 衔接权重（自己不接自己）× `SEQ_BIAS[强度]`（平静多给 C、激战多给 B / D / E），上上句再 ×0.4 防止来回；
  专用随机数 `music_rng`，不碰对局随机流。平静时一段从 C 句进，其余从 A 句进。
- `play_music(name)` 每帧调用，同名无副作用。切换规则：
  - 战斗换段：当前句唱完、下一句的位置直接接新段的第一句（不另加提示音）。
  - Boss 登场：旧曲 1.5 速淡出，Boss 曲第一句落在 `boss_in` 第 0.75 秒的太鼓重击上。
  - Boss 倒下回战斗：先让 `boss_down` 响 1.2 秒，战斗曲再从第一句 2 秒淡入。
  - 局外曲目互切：1 秒交叉，接着上次的位置放（见「局外配乐」）。
  - 其余：新曲从头 1.25 秒淡入，旧曲 1.7 秒淡出。
- `set_battle(lv, danger)` / `set_final_phase(p2)`：同 v2，进层落在当前句的小节线上（提前 0.1 秒、0.1 秒淡入），危险层可按拍进，
  退层等小节线、2 秒淡出；新开播的一句直接带着当前各层音量。
- `play_overlay(name, gain_db, from)`：两个叠加播放器。Master 总线挂 HardLimiter（-0.5 dB）。

### 验证（2026-09-26）

无界面引擎录音（`AudioEffectRecord` 挂 Music 总线，140 秒走一遍平静 → 交战 → 激战 → 危险 → 换段 → Boss → 回战斗 → 最终 Boss → 二阶段）：
- 句序：battle1 C → A → B → D →（换段）battle3 A → E →（Boss）A → C → D →（回战斗）battle3 C → B →（最终）A → C → D，两组播放器正确轮换。
- 衔接：八个句界前后 0.4 秒内最低电平只比中位低 2–5 dB（没有断音）；相邻两句相对 16 分网格的偏差 1–9 毫秒（不到一个混音块）。
- 注意无界面的哑音频驱动混音速度会比实时慢 5–15%，按墙钟排程在这里会错拍，这正是位置一律按音频时钟算的原因。

### 混音优先级（`sfx.gd` 的 `play()`，78d55f1 / ece8332）

一次性音效共 32 个播放器；循环音（`loop_start / loop_pitch / loop_stop`）、语音、配乐各用独立播放器，不占这 32 个。
