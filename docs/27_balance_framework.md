# 27 · 数值平衡框架（P5）

> 2026-09-25 起。目标：在「类幸存者爽游」的前提下，让 8 名干员、各条藏品流派与任意编队组合都能玩、都能赢、但都得动脑。
> 本文是**架构与工作流**；具体数字都在数据文件里（§3），改数不改文档、改文档只改目标与结论。

---

## 1. 体验目标（先定感觉，再定数字）

| 阶段 | 时间 | 玩家应该感觉到 | 数值含义 |
|---|---|---|---|
| 探索 | 0:00–3:30 | 「我一个人也能站住，但队伍在哪？」 | 单人开局任何职业都能撑到第一个 Boss；输出刚好够清怪，不够清屏 |
| 成型 | 3:30–7:00 | 「引擎点着了」：第二、三名干员入队、精一、藏品开始联动 | 输出增速 > 敌人生命增速；大群从「躲」变成「收割」 |
| 掌控 | 7:00–10:00 | 清屏爽感 + 精英 / Boss 是考试 | 小怪一碰就死，但精英 / Boss / 大群里的进化体仍需走位与技能节奏 |
| 大考 | 10:00 | 最终 Boss | 成型的队伍 60–75% 能赢；乱选的队伍 30–40% |

**不能出现的**（框架 §34–36）：某一套编队 / 流派同时最快成型、最强清屏、最强打 Boss、最能生存；每局伤害构成都一样；某个干员选了就等于自杀。

### 1.1 硬指标（`--balance` 机器人，难度 0，≥ 5 seed）

| 指标 | 目标 | 说明 |
|---|---|---|
| 单人开局撑到 3:30 | 每名干员 ≥ 90% | 「任何职业都能开局」（docs/23 §10） |
| 三人编队胜率 | 预设编队 55–75%，任意两两组合 ≥ 35% | 太高 = 无聊，太低 = 挫败 |
| 干员伤害占比（三人队） | 每人 15–50% | 没人是挂件，没人一个人打完 |
| 8 名干员单人 10 分钟平均存活 | 最强 / 最弱 ≤ 1.35 | 全员可玩：差距靠技能表现力，不靠面板 |
| 等级里程碑 | 2:00 ≈ Lv7、5:00 ≈ Lv17、8:00 ≈ Lv26、10:00 ≈ Lv32 | docs/23 §8 |
| 第一次精一 / 精二 | ≈ 1:00–1:40 / 6:00–7:00 | 成型节奏 |
| 次要来源占比（无人机、藏品触发、援护） | 10–20% | 副系统是加分项不是主力 |

## 2. 分层模型：谁负责什么

```
玩家感受
 ├─ 敌人压力曲线    data/balance.json  enemy 段   （生命 / 攻击 / 刷怪率随时间；精英 / Boss 倍率）
 ├─ 成长节奏        data/balance.json  xp、levelup 段（经验曲线、卡池概率、招募时机）
 ├─ 干员基础数值    data/characters/<id>.json  base 段（攻击 / 间隔 / 射程 / 技能倍率）
 ├─ 干员档位        data/balance.json  operators 段 （±5% 的 add 修正，写入 op:<id> 作用域）
 ├─ 干员成长线      data/characters/<id>.json  progression（每节点 +15% / +20%，精一精二解锁）
 ├─ 博士 / 全队被动  doctor.gd PASSIVES（上限 4 种，各自叠层）
 ├─ 藏品            data/relics.json + relic_effects.json（流派 / 稀有度 / 权重）
 └─ 难度            data.gd DIFFICULTY（逐级叠加负面，不动基础曲线）
```

**原则**：每一层只调自己的旋钮。发现「维什戴尔太强」→ 先看 `characters/wisadel.json base`，不动 `balance.json enemy`；发现「所有人 7 分钟后都被大群淹」→ 动 `enemy` 曲线，不动任何干员。

## 3. 干员：基础数值 + 档位

### 3.1 基础数值（`base` 段）

每名干员脚本里用 `base("key", 默认值)` 读数，JSON 缺键就用代码默认值，所以 JSON 与代码永远同值起步。键名约定：

| 键 | 含义 |
|---|---|
| `atk` | 普攻基础伤害（凯尔希为 `m_atk` = Mon3tr） |
| `cd` | 普攻间隔（秒，被 `op_aspd` 除） |
| `range` / `reach` | 远程索敌距离 / 近战触及半径（被 `op_range` 乘） |
| `aoe` / `aura` / `block_r` | 范围类半径 |
| `s1_* s2_* s3_*` | 各技能倍率 / 数量 / 半径 |
| 其他 | 天赋系数（`quake`、`shade`、`hit_sp`…） |

### 3.2 档位（`balance.json operators`）

按原作口碑分档，但**全员可玩**是硬约束，所以档位只做 ±5% 的 `add` 修正（`op_atk` / `op_skill_power` 等）：

| 档 | 干员 | 修正 | 强在哪（不靠面板） |
|---|---|---|---|
| S+ | 维什戴尔 | 攻 +5%、技能强度 +5% | 三段爆炸 + 残影连锁：清群、打精英都行，是「爽」的代表 |
| S | 艾雅法拉、凯尔希 | +3% / +3% | 火山持续 AoE；真伤 + 治疗双修 |
| A+ | 塞雷娅、铃兰 | 技能强度 +2% | 生存 / 增幅型：让别人变强 |
| A | 水月、推进之王、斯卡蒂 | 0 | 基准 |

档位差异的真正来源是**技能表现力**（连锁、AoE、控制），不是数字。调档位系数只用于最后微调（±2% 一档）。

### 3.3 职业预算（设计时用来估算 base 的参考）

单体 DPS 基准（普攻，未计 1.25 灯火加成）≈ **25–35**：

| 职业角色 | 直接 DPS 预算 | 补偿 |
|---|---|---|
| 主输出（近卫 / 狙击 / 术师 / 特种） | 100% | — |
| 节奏（先锋） | 85% | 全队技力 |
| 保护（重装） | 70% | 阻挡 + 减伤 + 治疗 |
| 治疗（医疗） | 65%（Mon3tr） | 持续治疗 |
| 增幅（辅助） | 65% | 减速 + 易伤 + 全队攻击 |

技能预算：S1 ≈ 3–5 秒普攻伤害；S2 ≈ 8–12 秒；S3 ≈ 15–25 秒或 8–14 秒的形态变化。永久型技能（凯尔希 S2、铃兰 S2）按「一次性 +30% 效率」计。

## 4. 敌人压力曲线（`balance.json enemy`）

- 生命：`base × (1 + min(t, hp_knee)/hp_div + max(t − hp_knee, 0)/hp_late_div)` → 2:00 ×2、8:00 ×5、10:00 ×5.4
- 攻击：`base × (1 + min(t, dmg_knee)/dmg_div)` → 8:00 封顶 ×2.85
- 刷怪率：`spawn_base + t/spawn_div` 只/秒；Boss 在场 ×0.8，灯火 < 30 ×1.15
- 精英：生命 ×7、攻击 ×1.3、经验 ×10；Boss：`base × (1 + t/boss_hp_time_div)`
- 难度 1–10：逐级叠加（data.gd），不改曲线形状

**调曲线的判断标准**：所有编队在同一时间点集体死亡 → 曲线太陡；所有编队都在 10:00 前把最终 Boss 打到 0 → 曲线太平。只有一两个编队掉队 → 别动曲线，去看那两个编队。

## 5. 流派与编队

流派沿用 docs/08 的六条藏品流派（A 伞击 / B 触手 / C 控制 / D 收割 / E 低灯火 / S 援护）。编队制之后流派由**编队职业组合**决定主体，藏品做放大：

| 组合 | 期望玩法 | 应该赢在 | 应该输在 |
|---|---|---|---|
| 双输出 + 辅助 | 清屏 | 大群、中期 | 灯火低时的 Boss |
| 输出 + 医疗 + 重装 | 站桩 | Boss、生存 | 大群拖太久 |
| 先锋 + 任意 | 技能循环 | 技能型干员成型快 | 面板低 |
| 三近战 | 高风险高回报 | 击退 / 眩晕控场 | 远程精英 |
| 三远程 | 风筝 | 前期 | 被贴身 |

每种组合都应有 ≥ 35% 胜率、不同的伤害构成（§1.1）。

## 6. 工作流：怎么测、怎么改

### 6.1 机器人

`--balance` 的机器人（game.gd `_bot_pick`）像一个懂玩的玩家：优先干员深度 / 技能卡，Lv 8 前见招募必招，全队被动按权重选（`balance.json bot`），填充卡只在没得选时拿。`--botrandom` 退回纯随机（用来测「乱选」的下限）。

### 6.2 批跑

```bash
python tools/balance_run.py --preset solo --seeds 5        # 8 名干员单人开局
python tools/balance_run.py --preset squads --seeds 5      # 6 个预设编队
python tools/balance_run.py --preset pairs --seeds 2       # 28 个两人组合（粗筛）
python tools/balance_run.py --squad wisadel,suzuran,saria --seeds 5 --extra "--botrandom"
```

输出到 `build/balance/<tag>_<时间>.md`：胜率、存活、等级里程碑、终 Boss 剩余、精二占比、伤害来源、死因。一局 10 分钟模拟约需 2–4 分钟真实时间，8 并行。

### 6.3 改数流程

1. 跑基线（solo + squads，≥ 5 seed），记录到 §8。
2. 对照 §1.1 硬指标，找**最偏离**的一项。
3. 按 §2 找到该改的层，只改一层、一次改一个方向（±10–15%）。
4. 重跑受影响的矩阵；不受影响的编队应当基本不变（否则改错层了）。
5. 通过后把结论追加到 §8，提交时带上 `build/balance/*.md`。

### 6.4 护栏（改数前后都要看）

- `tests/test_core.gd` 全绿。
- 单人开局每名干员 3:30 存活率不掉。
- 任何一次改动不能让某个编队胜率变化超过 25 个百分点（否则是 bug，不是平衡）。
