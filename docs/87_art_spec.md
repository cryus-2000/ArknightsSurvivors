# 87 · 人物帧条统一规格（干员 / 博士 / 敌人，唯一权威版）

> 2026-10-13 起草。起因：用户 10-13「出现了这么多次返修的情况，是不是可以统一一下规则？这样可以减少返修的次数」。
> 以前的规格散在 docs/05、24、27、63、64、69、73、84、85、86 里，每张返修单只写当次问题，Codex 每次只看当次单子，同类问题反复出现（待机朝左、待机正面朝前、待机定格、跑步滑行 / 后仰、配色发白、skill 末帧 ≠ idle f0、脚底不齐）。
> **从现在起：人物帧条一律以本文为准**。旧文档里与本文冲突的条款作废（旧文档顶部已加指针）；本文没写到的细节（某个角色的造型、武器、出手帧）仍看该角色的工单。
> 机检：`python tools/art_lint.py`（§7）。**工具全绿（没有未豁免的 FAIL）才能交付**；WARN 要在 handoff 里逐条说明理由。

## 0. 适用范围

- 干员（`op_<id>_*`）、水月（`player_*`）、博士（`doctor_*`）：本文全部适用，art_lint 全部检查。
- 召唤物、人偶、道具帧条（Mon3tr、归溟幽灵鲨人偶、灯塔等）：§1 的透明 / 描边 / @2x / 命名适用；画布尺寸、锚点按各自工单。
- 敌人、Boss（`e_*`、`boss*`、`bosses/`）：§1 的朝右、二值透明、外描边、@2x 逐帧对应、命名与 manifest 适用；尺寸 / 帧数 / 动作按各自工单。art_lint 暂不查敌人。

## 1. 通用硬规格

| 项 | 要求 | 机检 |
|---|---|---|
| 单帧尺寸 | 48×48（1x）与 96×96（@2x），**以 96px 为主绘制**，48px 是备用版 | `size` FAIL |
| 帧条 | 横向一行等宽排列，RGBA PNG；宽 = 帧数 × 单帧宽 | `size` FAIL |
| 帧数 / fps | 见下表；与 `game/data/characters/<id>.json` 的 `sprites.<动作>.frames` 一致（manifest 与 json 不一致时 Claude 改 json，但交付前要在 handoff 里写明） | `size` FAIL |

| 脚底中心 x | 待机、跑步的脚底中心尽量在 24 ± 2；偏了要在 handoff 写明量得的 x（Claude 改 json `foot`） | `foot` WARN |
| 朝向 | **只画朝右**（朝左由程序镜像），所有动作同向，见 §2 | `facing` FAIL |

| 动作 | 帧数 | fps | 说明 |
|---|---|---|---|
| `_idle` | 4 | 4 | 呼吸循环，见 §3.1 |

## 2. 姿态与朝向（所有动作）

1. **一律朝右 3/4 侧身**：身体和脸转向右前方，前脚在右、武器在身前右侧，头发 / 披风 / 尾巴自然落在身后（左侧）。
2. **待机不得正面朝前**（脸、身体正对镜头、双脚并排对称）。选人 / 图鉴的大图就是 `_idle` f0 放大，正面待机在并排时最显眼（docs/86 艾雅法拉、铃兰）。
3. **待机不得朝左**（docs/84 乌尔比安；本次基线又查出推进之王，附录 B-1）。
4. 动作之间切换**不跳朝向**：idle → run → attack → skill → idle 全部朝右，skill 末帧回到 idle f0，attack 收势回到接近 idle 的姿势。
5. 参考（朝右 3/4 侧身待机的标准样子）：斯卡蒂 `op_skadi_idle@2x.png`、浊心斯卡蒂 `op_skalter_idle@2x.png`、流明 `op_lumen_idle@2x.png`（均在 `art/incoming/`）。`python tools/art_lint.py --ops <id>` 会生成 `build/art_lint/compare_<id>.png`：上排是本人 idle f0 / run f0 / attack 出手帧 / skill 末帧 + 三名参考的待机，下排是本人待机 4 帧与跑步 6 帧，青线 = 脚底 92 行。
6. 姿态细节照 `art/incoming/character_posture_constraints.md`：不伸脖子，前倾靠躯干整体倾斜。

## 3. 动作质量

### 3.1 待机（docs/73 的指标）

- 4 帧呼吸：f0 中位 → f1 下沉 1px → f2 最低 2px → f3 回升；**上半身（头、躯干、手里的武器）整体随呼吸上下 1–3px（@2x 2–6px）**，脚底不动。
- 二次运动：头发末梢、尾巴、衣摆、挂饰、武器尖端比身体晚一帧，幅度 1px（@2x 1–2px）。
- 静止部位（脸、衣纹、盾面）逐帧同一组像素，只随呼吸整体平移，**不要每帧重绘造成闪烁**。
- 机检 `idle`：相邻帧剪影变化（4 对循环平均）≥ 0.03、几乎相同（< 0.005）的相邻帧至多 1 对 → 否则 FAIL（定格）；身体起伏不在 1–3px → WARN。

### 3.2 跑步（docs/69 §C + docs/85 的指标）

- 6 帧循环：f0 前脚着地 → f1 下沉（−1px）→ f2 过渡（两腿交叉，+1px）→ f3 另一只脚着地 → f4 下沉 → f5 过渡。最低限度是「着地 / 下沉 / 过渡」三个姿势循环两遍，但三个姿势的腿必须明显不同；左右腿分得出（一侧稍暗一档）。
- **两腿交替、后脚蹬地脚跟抬起、前脚落地膝盖伸直**；两只鞋都要露出来（裙摆、盾、尾巴不能把腿全挡住）。
- **上半身随步伐上下 1–2px（@2x 2–4px）**，头发 / 衣摆 / 尾巴 / 武器尖端比身体晚一帧摆 1–2px。上半身钉死不动 = 滑行。
- **前倾为正且 ≤ 25°**（不能后仰；轻步角色 ≤ 10–15°，按角色单子）。
- 着地脚在着地 → 下沉 → 过渡三帧里往后移 2–4px（1x），不要六帧钉在同一个 x；脚底中心漂移 ±6px 以内；每帧离地 ≤ 3px，至少一帧贴 46 行。
- 静止部位不闪（同 §3.1）。
- 机检 `run`（口径同 `tools/run_cycle_review.py`，@2x 量、折成 1x 像素）：整体剪影变化 ≥ 0.035、腿部变化 ≥ 0.10、头部起伏 1.0–2.5px、上半身变化 ≥ 0.004、停顿帧（剪影实质变化 < 0.005 的相邻对）至多 1 对 → 否则 FAIL；前倾不在 0–25° → WARN，超出 5° 以上 → FAIL（前倾按头部 / 髋部重心量，武器会带偏，FAIL 时以目测为准）。
- **数字达标但看起来仍像滑行，以目测为准。**

### 3.3 攻击

- 出手帧（manifest `fire`）与前后帧剪影明显不同（异或 ≥ 0.10）；标志物每帧都在。
- 枪械出手帧枪口高度与瞄准帧差 ≤ 2px（1x），后坐靠枪和肩膀后缩表现（docs/64 §4-2）。
- 身体不横移出格子（位移由程序做）。
- 收势回到接近 idle f0 的姿势、朝向不变。

### 3.4 技能

- 蓄力 → 出手帧 → 保持 → 收回；**末帧 = idle f0 逐像素相同（1x 与 @2x）**。所以改 idle f0 时必须同步改 skill 末帧。
- 机检 `skill_end`：@2x 不同 → FAIL；只有 1x 备用版不同 → WARN。存量 12 人 + 博士（这条规则定之前交付的）只 WARN，重画 idle 或 skill 时必须对齐。

### 3.5 多条技能帧条 + 循环状态：json `sprites.skills`（10-16，首例铃兰）

一名干员三个技能各一套动作（docs/97 J 批附表：S1 发力条、S2 定格、S3 持续循环）时，帧条按动作各登记一个 `sprites` 槽（和 `skill` 一样写 `{tex, frames, fps, foot, fire}`），再用 `sprites.skills` 把技能序号接到槽上；非 `idle / run / attack / skill` 的槽要列进 `extra_sprites`（否则不加载）。没写 `skills` 的技能照旧走单条 `skill`（`skills[i].anim` 可换条），其他干员不用改。

```json
"sprites": {
  "skill":         {"tex": "op_suzuran_skill_s1", "frames": 3, "fps": 8, "foot": [32, 60], "fire": 1},
  "skill_s2_hold": {"tex": "op_suzuran_skill_s2_hold", "frames": 1, "fps": 4, "foot": [32, 60]},
  "skill_s3":      {"tex": "op_suzuran_skill_s3", "frames": 3, "fps": 8, "foot": [32, 60], "fire": 1},
  "skill_s3_loop": {"tex": "op_suzuran_skill_s3_loop", "frames": 2, "fps": 4, "foot": [32, 60]},
  "skills": {
    "s1": {"anim": "skill"},
    "s2": {"intro": "attack", "hold": "skill_s2_hold", "hold_ms": 250},
    "s3": {"start": {"anim": "skill_s3", "frames": [0, 1]}, "loop": "skill_s3_loop", "end": {"anim": "skill_s3", "frames": [0, 2]}}
  }
},
"extra_sprites": ["skill_s2_hold", "skill_s3", "skill_s3_loop"]
```

| 写法 | 播法 | 出手窗口（attack_t / fire_t，决定技能效果与 acting()） |
|---|---|---|
| `{"anim": 槽}` | 单条播一遍（同 `skills[i].anim`） | 时长 = 帧数 / fps，出手 = `fire` 帧中点（与原单条口径一致） |
| `{"intro": 槽, "hold": 槽, "hold_ms": N}` | intro 条第 0 帧按其 fps 播一帧 → hold 条定格 N 毫秒 → 待机 | 时长 = 1 / intro fps + N / 1000，**出手 = 定格开始** |
| `{"start": 段, "loop": 槽, "end": 段}` | start 播一遍 → 技能生效期间（`skill_active_left(i) > 0`）loop 按 fps 循环 → end 播一遍 → 待机；技能不计时（永久 / 次数型）就跳过 loop 直接收势；`end` 可省 | 时长 = start 段帧数 / fps，出手 = start 条 `fire` 帧中点；loop / end 纯画面 |

- 「段」= 槽名，或 `{"anim": 槽, "frames": [帧号…]}`（只播这条里的这几帧，顺序随写）。铃兰 S3 一条 3 帧（f0 起手 / f1 发力 / f2 收势）拆成起手 [0, 1] 与收势 [0, 2]。
- 出手帧语义不变：`fire` 到点调 `_release_skill()`，技能特效 / 积木在那一刻生效；hold / loop / end 期间不再有出手。循环期间起手的别的动作（普攻 / 另一技能）压过循环，播完接着循环；起手 / 收势途中被别的动作打断则序列作废回待机。
- **`attack` 槽（可选，10-16，首例水月 S2）**：`{"start": …, "loop": …, "end": …, "attack": 槽}`——技能持续期（loop 阶段）内的普攻画面改播这条「技能期间攻击变体」，播完回 loop。对齐口径：变体的 `fire` 帧中点对齐普攻条的出手时刻（普攻条带 `fps / fire` 就是 `(fire + 0.5) / fps`，字符串槽 / 没写的按 `attack_dur / 2`），所以变体 `fire` 之前的帧在出手时刻之前播、之后的帧在之后播，比普攻窗口长的部分照播完（下一次普攻起手则从头重新对齐）。**只换画面**：`attack_t / fire_t / 朝向` 等模拟量不动，同 seed TRACE 不变。没写 `attack` 槽的照旧用普通 `attack` 条压过循环；`start_attack` 显式指定了别的帧条（`anim` 参数）的普攻不换；hold 型序列没有这个槽。水月 S2 写 `"attack": "skill_s2_attack"`（8 帧 6fps fire 3，`player_skill_s2_attack@2x`）；维什戴尔 S3 装填巨炮期间的炮击直接写 `"attack": "skill_s3_loop"`，`sprites.skill_s3_loop` 补 `fire: 1`（manifest contract）——蹲射循环条自己从 f0 起对齐 f1 出膛播一遍再回循环，不再用站姿 `attack` 条压过蹲姿。校验：`attack` 须是帧条名（不能写 `frames` 段）、要有 `loop`、槽要在 `sprites` 且列进 `extra_sprites`；`art_lint` 把它当本人身体。
- 校验（`validate_operator`）：键只能 s1–s3；有 `hold` 必有 `intro`，`hold` 与 `start` 不能同写；引用的槽要在 `sprites` 且带 `tex`，非主动作要列进 `extra_sprites`；`frames` 要在该条帧数内。
- 机检：`art_lint.roster` 把 `skills` 引用的槽当本人身体（描边 / 色数 / 贴地同主动作）；循环帧属造型离地的按单条帧条豁免 `(op, "ground", 槽)` 登记（铃兰 `skill_s3_loop` 微浮 2px）。
- 同 seed：hold / loop / end 只改画面；出手窗口随起手段的帧数 / fps 变，改接线等于改出手时机，TRACE 对照要说明（铃兰接入记录见 docs/97）。

#### 统一技能姿态（docs/105，2026-10-17）

`sprites.skill_pose` 已删除，出现即校验失败。持续技能统一写进 `sprites.skills.sN`：

```json
"s3": {"start": "skill", "enter": "float_in", "loop": "float",
       "run": "float_move", "attack": "float_attack",
       "end": {"anim": "float_in", "reverse": true},
       "shadow": 0.7, "shadow_a": 0.55}
```

- `start` 仍独自决定出手窗口和出手帧。用户确认保留安洁莉娜原 `skill` 的 7 / 12 秒窗口、3.5 / 12 秒出手；不得直接换成 `float_in` 改变玩法时序。
- `enter` 为可选的施法后纯画面段：start 结束且技能仍生效时播放，再进 loop。其他动作可暂时遮住 enter，期间暂停 enter，播完继续；不延长 `attack_t`、不修改 `fire_t`。技能提前结束时转 end。省略或缺图则直接进 loop。
- `run` 为持续期移动条，缺省或缺图回 loop；按该条 fps 循环，跑停沿用 40 / 20 的速度滞回。`attack` 沿用上文出手对齐规则。三者只用于有 start / loop 的序列，不用于 hold。
- 段可写 `reverse: true`，倒放整条或指定的 frames 子段，不修改原帧表；loop / run 也按其帧表循环。
- `shadow` / `shadow_a` 分别为影子大小 / 不透明度系数（0–1，缺省各为 1），进入和退出以 0.25 秒缓动。带 enter 时施法阶段保持地面影子，enter / loop 期间缩淡，end / 序列作废后恢复。
- 所有引用槽（含 enter / run）都校验加载清单与子段边界；`art_lint` 统一识别为本人身体。未写技能契约的干员保持原单条逻辑。
- 单条 `anim` 不得混写 intro / hold / start / enter / loop / run / attack / end；start 型必须有 loop。持续循环或 enter 被另一技能序列遮住时保留阶段与进度，后者结束后恢复；原技能已结束则只播 end（没有 end 则跳过），不恢复技能效果或逻辑出手窗口。
- 回归：`angelina_skill_anim_test` 检查原施法窗口、enter 被普攻遮住后的续播、移动与攻击变体、倒放、影子、玩法 RNG 与非法契约；铃兰 / 水月回归继续保留。

## 4. 配色与明度

### 4.1 观感背景

游戏画面是观感预设 L4 / L5（`render/look`，`game/scripts/render/look.gd`）：角色受光封顶 ×1.12、亮度缺省 100%、暗部曲线、鲜艳度 +0.18；L5 另加白色不偏黄。主控不再被灯火截成纯白，但**身上没有暗部、全是中间调的配色**在 L4 下仍然发灰发白（德克萨斯、星熊，docs/64 §7.4 / §7.5）。所以配色的要求是「大块暗 + 少量亮」，不是凑平均明度。

### 4.2 通用范围（idle@2x 4 帧，去掉透明与全部 `#080E18`；Y = 0.2126R + 0.7152G + 0.0722B）

| 指标 | 通用范围 | 说明 |
|---|---|---|
| 近黑占比（Y < 40） | ≥ 10% | 已验收参照 17–44%；德克萨斯 / 星熊返修前 0–3% 是发白的主因 |
| 亮部占比（Y ≥ 160） | 8–35% | 脸、白衣、饰边、发光点；超过 35% 整个人发白 |
| HSL 明度均值 (max+min)/510 | 0.30–0.50 | 只作参考，不能单独当判据（docs/64 §7.5：Logos 0.477 但有 20% 近黑） |
| L4 受光变亮（40 ≤ Y < 160，乘 1.12 后 Y ≥ 160） | ≤ 12% | 主控站在灯下会被抬白的中间调 |

- 落在通用范围外，art_lint 报 `tone` WARN（不 FAIL）；交付时在 handoff 说明理由（例如原作就是白衣浅发：凯尔希、铃兰）。
- 角色单子可以覆盖范围，覆盖值写进 art_lint 的 `TONE_OVERRIDE`：德克萨斯 近黑 ≥ 35%、亮部 ≥ 8%、HSL 下限放到 0.20（docs/69 A）；星熊 近黑 ≥ 25%、亮部 18–30%、HSL 0.33–0.40（docs/69 B）。
- docs/63 §1 的「非描边平均明度 ≥ 0.41」**作废**，改用上表。
- 黑衣角色：大块近黑（Y < 40）做衣服 / 甲的背光面，靠白衬衫、饰边、武器、瞳色做亮点；别用整片中灰或蓝紫中间调铺底。
- 瞳色、发色在四组动作里一致，按用户批准的参考。

### 博士混合画布接入（2026-10-18）

博士 `sprites.<action>_foot` 可覆盖默认 `foot`（逻辑像素），用于新 128 画布跑步与旧 96 画布待机／倒下共存。跑步保持 10 fps，8 帧一循环 0.8 秒；不改变移动速度。检查工具使用相同锚点，并在比较不同画布的头部朝向前透明补宽，禁止缩放人物参与朝向比较。当前用户批准先接测试版的视觉遗留项、源文件校验值及临时豁免见 `art/incoming/doctor_run_handoff.md`。

## 2026-10-18 三人全动画与分段时序
维什戴尔、塞雷娅、铃兰试验分支支持 sprites.attack.attack_timing（duration、fire_time、active_ratio、windup_ratio）。详细运行规则、来源、测试与限制见 [三人全动画接入](plans/2026-10-18-three-attack-timing.md)。未配置的动作仍使用旧 fps/fire；不得仅改帧数推算事件秒数。

技能片段可声明 frame_durations 与 fire_time，单条、序列与图鉴读取同一秒数。透明加边画布允许 96 逻辑像素 / 192 @2x，但必须保留原像素密度、完整武器及锚点，不能据画布把人物放大。


### 原生部件烘焙动作接入（2026-10-20，推进之王 / 乌尔比安）

`data_operator.gd` 的 `NativeMotion` 是纯显示适配，顶层 `native_motion` 声明视觉攻击时长；未配置的干员保持旧路径。`sprites.<slot>.frame_durations / fire_time` 继续控制原有玩法窗口与事件，不能用新帧数扩大伤害间隔。显示收势可超过旧逻辑窗口，但新动作会重启显示，不能额外触发伤害。

推进之王 S1 / S3 开启使用正常持锤 Idle，独立 Command 已按用户要求取消；S2 跟随真实 `sg.leap_t`，帧 5 开始于实际落地，不再叠加旧程序整身旋转 / 抬高。乌尔比安身体跟随 `anchor.phase`；离手锚使用原生四刃组件和环心原点，锁链从当前帧 `hand` 连接点连向实际锚点；回旋为原生部件整身烘焙，不叠加第二套程序锚。

所有部件按原始遮挡层序合成；画布按整条共同裁窗选 128 或 256，绝不逐帧缩放。256 帧保持同一像素密度，槽内 `foot` 同步调整，因此角色不会按画布尺寸放大。输出为烘焙帧条，不能宣称已交付可编辑 Spine 网格工程。
