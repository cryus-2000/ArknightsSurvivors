# 114 指挥模式（第 1 步原型）

状态：原型（10-21），分支 `claude/command-mode`，未合 main。第 2 步目标优先、第 3 步接局外成长（docs/109）和正式按键，另做。

## 1. 用户已定

- 一个键循环切换，不用长按：**随行**（缺省，现状）→ **突击** → **归队** → 自动回随行。归队途中再按 = 突击。
- 归队要先集合（10-21 用户看录屏后定）：全员快速回到队长身边后站定约 0.4 秒（`command/gather`），像集合完毕，再回随行；不要冲回来就接着走。
- 突击：队友自己找怪打，不回队长身边；离队长最远约 1.5 屏（实现取 1.5 个半屏宽 = 960 世界像素，见 §3），超出就往回收。
- 医疗、辅助默认不突击：干员 json `command.roam: false`（安洁莉娜、凯尔希、流明、浊心斯卡蒂、铃兰已写），个别干员可改 json 破例。
- 屏幕外的队友在屏幕边缘画方向标记。
- 突击耐力（10-21 用户定，不做队友血条）：全队共用一条，显示在指挥键旁。突击时按时间消耗，满耐力约 15 秒（10-21 看视频后改 25 秒）；**耗尽自动归队**（走集合停顿那套）并进冷却，回到约 30% 才能再突击；不突击时慢慢回满，空到满约 30 秒（同比例改 50 秒；回得比扣得慢，防反复刷）。只按时间扣——「被怪碰到额外扣」用户否了（玩家控制不了 AI 队友）。耐力不足时按键不切，队长头顶飘「耐力不足」。
- 设计理由：玩家是博士，指挥是核心身份；操作必须极轻（注意力在走位上，网页和手机也要能用）。

## 2. 操作

| 输入 | 键位 | 说明 |
|---|---|---|
| 键盘 | **F** | Tab / C 已是属性面板，Q / E / J 技能，Space / Shift / K 冲刺，V 倍速；F 在局内空闲（只在商店里是刷新） |
| 手柄 | **LB**（LT 同） | 局内上下文原来没用左肩键；RB = 冲刺 |
| 触屏 | 「指挥」键 | 暂停键左侧同一行（桌面 `(vs.x-118, 186)`，手机 `y=160`）；离冲刺 / 技能 / 攻击键与编队区都远，不挡摇杆；可在「设置 → 触屏按键布局」里挪 / 缩放（键名 `cmd`） |

HUD：非触屏时编队区（源石锭框）上方右对齐一行「指挥 · 随行」+ 按键牌（手柄显示 LB），颜色随模式：随行青、突击金、归队绿。触屏时模式名写在「指挥」键圈里。屏外队友：屏幕边缘一个小头像（10-21 用户定）——用编队卡同一份待机帧条（`o.portrait()`，图鉴 / 选人也是这份），按第 0 帧最上面的不透明像素裁出约 26 美术像素见方的头部（`hud_banners._head_src`，每人扫一次缓存），画成 30 像素；外圈 = 职业色（`Character.CLASS_COL`，同图鉴 / 选人），外侧细线 = 当前模式色，箭头职业色指向队友；贴在避开顶栏 / 底部提示的框边上，压在 HUD 之上。缺贴图时退回职业首字。

## 3. 实现

- 状态：`squad.stance`（0 随行 / 1 突击 / 2 归队），`squad.cycle_stance()` / `set_stance()`；切换记进 `squad.stance_log`，`--trace` 时打印 `CMD t=… stance=…`（不进 TRACE 行）。
- 站位：`character.follow()` 里，突击时用 `roam_target()` 代替 `follow_target()`（编队位 / 近战前压）：以干员自己为中心 `command/search` 内最近的敌人（离队长 ≤ `command/leash`），站到它朝自己一侧 `cmd_reach()` 处；有滞回（目标死 / 出圈才换，近 50 以上才换更近的）；没怪回编队位；落点夹在 leash 圈里。`cmd_reach()`：近战取 `blocks.follow.gap`，普攻带 range 的远程取 range × `command/range_k`。
- 速度：随行原样（lerp，不限速，> 700 瞬移归位）；突击限速 队长移速 × `command/roam_speed`；归队 lerp 加快 + 限速 × `command/recall_speed`，全员离随行站位 < `command/recall_done` 或满 `command/recall_max` 秒后进入集合：全员原地站定 `command/gather` 秒（`squad.gather_t`），再自动回随行。突击 / 归队时瞬移阈值放宽到 leash × 1.6。
- 耐力：`squad.stamina`（0–1）/ `squad.exhausted`，`squad._tick_stamina()` 每帧：突击扣 dt / `stamina_secs`，到 0 → `exhausted` + `set_stance(归队)`；其余回 dt / `regen_secs`，回到 `min_start` 解除冷却。`cycle_stance()` 发起突击前查 `can_roam()`。HUD：桌面在「指挥 · 随行」下方一条 180×7 的条（10-21 由 120×4 加宽）（突击金、冷却灰、其余青，白刻度 = `min_start`）；触屏在指挥键外圈一道弧。
- 找怪只经 op_api `nearest_enemies`，不抽随机数。
- 开关：`data/balance.json` 的 `command.on`（缺省 1）；0 = 不画按钮 / 标签，按键无效（对照用 `--bal=command/on=0`）。
- 机器人：缺省随行（`command/bot_roam` = 0）；`--bal=command/bot_roam=1` 突击常开：开局突击，耐力耗尽归队后一回到 `min_start` 就再突击（首段 15 秒，之后约 4.5 秒突击 / 9 秒回复循环）。测试钩子 `--cmdat=秒,秒,…` 到点按一次指挥键（录片用）。

| 旋钮 command/… | 缺省 | 含义 |
|---|---|---|
| on | 1 | 总开关 |
| leash | 960 | 突击离队长最远（世界像素） |
| search | 520 | 找怪半径（以干员为中心） |
| roam_speed | 1.3 | 突击限速（× 队长移速 150） |
| recall_speed | 4.0 | 归队限速 |
| recall_done | 28 | 归队归位判定距离 |
| recall_max | 3.0 | 归队最长秒数 |
| gather | 0.4 | 归队到位后站定秒数 |
| stamina_secs | 25 | 突击耐力满 → 空秒数 |
| regen_secs | 50 | 不突击时空 → 满秒数 |
| min_start | 0.3 | 低于它不能发起突击（耗尽后的冷却线） |
| range_k | 0.6 | 远程站位 = 射程 × 它 |
| bot_roam | 0 | 机器人局突击常开（受耐力限制） |

## 4. 已知局限（原型）

- 一部分干员的普攻 / 技能以**队长**为中心或只打队长身边的怪（斯卡蒂大剑「在队长身边横扫」、浊心斯卡蒂声浪、推进之王「冲到队长身边的敌人面前」、塞雷娅阻挡圈等），突击后这部分输出不跟着走——第 2 步要逐个定「突击时以谁为中心」。
- 敌人只追队长，突击的队友不吸引仇恨；队长身边少了近战，承伤会变（见 §6 数据）。

## 5. 命名

10-21 用户定：随行 → **随行**、突击 → **突击**、归队 → **归队**（代码标识符仍是 GUARD / ROAM / RECALL、stance 0 / 1 / 2）。
按键 / 标签名用户未定，先保留「指挥」；候选：指挥、战术、号令。
（按 docs/76 §2：「部署、撤离」是原作词，但原作指放上 / 撤下场，不借用。）

## 7. 突击三件套原型：仇恨 / 职业走位 / 队友生命与倒地（10-22，分支 `claude/command-aggro`）

用户 10-22 提的新想法，做成原型看效果，**未定是否保留**。三项各有开关，和耐力合起来可以任意组合对照。

### 7.1 规则

- **仇恨**（`command/aggro`）：只在突击中生效。敌人 A 段决策时（`enemies.gd`），身边 `aggro_r`（240）内有突击队友，就找最近的那名；每只怪第一次进圈时用 `rng_enemy` 掷一次，小于 `aggro_share`（0.4）的改追这名队友，结果一直保留。随行 / 归队时不调用，也不抽随机数。Boss、宝箱不受影响；只改近战式移动方向，远程怪照旧对队长开火，各类冲刺 / 招式（`eai.pattern`）也照旧对准队长。
- **职业走位**（突击时的 `roam_target`，`character.cmd_role()`）：
  - 近战（近卫 / 先锋 / 特种）：选身边最近的怪，贴着怪群靠自己这一侧打，不往里钻（同首版）。
  - 远程（狙击 / 术师）：站在离目标「射程 × 0.6」的圆上，每帧往前挪 `kite_step`（0.5 弧度）绕圈；被贴近就后退。编队位单双号决定顺时针 / 逆时针。
  - 重装：取队长身边最近 6 只怪的中心，站到「队长 → 怪群」连线上离队长一半处（40–160），把怪挡在外面。
  - 医疗 / 辅助照旧不突击（json `command.roam: false`）。
- **队友生命**（`command/hp`）：生命上限 = 队长当前生命上限 × 职业系数 × `hp_mul`（10-22 调成 5，§8.4）（重装 1.2、近卫 0.9、先锋 0.8、特种 0.75、辅助 / 医疗 0.65、术师 / 狙击 0.5；balance `command/hp_k_<职业>` 或干员 json `command.hp_k` 可改）。只在突击中受伤：被近战怪碰到扣「怪的接触伤害 × `op_dmg_k`」，每人每 `op_inv`（0.5）秒最多一次；敌方子弹不打队友（原型）。不突击时回血，空到满 `hp_regen_secs`（30）秒。头顶小血条只在突击中、受伤后 3 秒、倒地时显示。
- **倒地**：血空倒地 `revive_secs`（25）秒。倒地期间不出手、不充技力、不吸引仇恨、不受伤，原地躺着。到时原地复活；归队时随队闪回队长身边、继续复活计时（10-22 改，§8.2；原为集合完毕时在队长身边立即复活）。复活回到 `revive_hp`（50%）生命，并有 `revive_inv`（1）秒无敌。画面：有 death 条的 15 人播一遍停在末帧（略压暗）；没有的画躺倒的灰色剪影（待机帧转 90°）。10-22 用户定倒地统一用 death 条（claude/retreat-to-downed 在补），已去掉原先的共用退场闪光。头顶灰条 = 复活倒计时。
- **耐力**（`command/stamina`）：同 §1；关掉后可以一直突击，耐力条不显示。

### 7.2 三种组合怎么理解

| 组合 | 开关 | 玩起来 |
|---|---|---|
| 耐力限时 | stamina 1 · hp 0 | 首版：突击有时长上限，队友不会倒，风险只在队长身边空了 |
| 血条风险 | stamina 0 · hp 1 | 不限时，风险换成队友会倒地 25 秒；玩家要看血条主动归队 |
| 两者都有（缺省） | stamina 1 · hp 1 | 时长和血量双重限制，最保守 |
| 都关 | stamina 0 · hp 0 | 突击无代价，只当对照 |

仇恨在四种组合里都开（缺省 1），对照时可用 `--bal=command/aggro=0` 单独关。

### 7.3 统计

BALANCE 行新增 `cmd`（切过模式的局才写，没用指挥模式的局 BALANCE 与 main 逐字相同）：`roam`（突击累计秒数）、`downs`（倒地次数）、`aggro`（被引走的怪数）、`switch`（切换次数）。`--trace` 时倒地打印 `CMD t=… down <干员>`。

### 7.4 机器人小样（4 组合，仇恨都开）

`balance_run.py --preset squads --seeds 3`（normal 机器人、标准档、6 编队 × 3 seed = 每组 18 局），突击组都加 `--bal=command/bot_roam=1`（能突击就突击），再按组合关 `command/stamina` / `command/hp`。基于 main 3985dd87。输出 / 秒 = 全队总输出 ÷ 存活秒；承伤 / 分 = 队长受到的伤害；括号是相对随行。

| 组合 | 局数 | 胜 | 存活秒 | 输出/秒 | 承伤/分 | 突击秒 | 倒地/局 | 引走怪/局 |
|---|---|---|---|---|---|---|---|---|
| 随行（不突击） | 18 | 6/18 | 531 | 862 | 167.6 | 0 | 0.0 | 0 |
| 耐力开 · 血条开（缺省） | 18 | 5/18 | 574 | 905 (+5%) | 200.9 (+20%) | 205 | 5.4 | 302 |
| 耐力关 · 血条开 | 18 | 1/18 | 422 | 510 (-41%) | 144.9 (-14%) | 423 | 7.1 | 211 |
| 耐力开 · 血条关 | 18 | 5/18 | 526 | 884 (+3%) | 163.5 (-2%) | 190 | 0.0 | 277 |
| 耐力关 · 血条关 | 18 | 3/18 | 493 | 769 (-11%) | 152.4 (-9%) | 494 | 0.0 | 466 |

读法（每组 18 局，胜率差 < 10 点不下结论）：
- **缺省（耐力 + 血条）与随行基本持平**：输出 +5%、存活 +43 秒，队长承伤 +20%，胜 5/18 对 6/18。耐力把突击压到每局约 200 秒，倒地平均 5 次。
- **只开血条、不限时最差**：一直突击，队友平均倒地 7 次，倒地期间不输出，输出 -41%、胜 1/18。机器人不会看血条主动归队；玩家会，这组是下限。
- **只开耐力**（相当于首版 + 仇恨）：输出 +3%、承伤 -2%——仇恨引走怪后，队长承伤从首版的 +22% 降到持平。
- **都关**：一直突击、无代价，输出反而 -11%：近战全离队，队长身边没人清怪，节奏被拖慢。
- 机器人是「能突击就突击」，不挑时机；玩家会在怪多时开、队友残血时归队，实际收益应好于这组数。要定数值请用同种子配对 + 更多 seed（云端例行任务）。

## 11. 10-23 用户实测修正（分支 `claude/command-fix`）

### 11.1 倒地留在原地

问题：倒地的队友以倒地姿势跟着队长漂移（随行 / 归队时仍按编队位跟随，归队闪回也把他们带走）。
改为：倒地期间 `character.follow()` 直接返回，不跟随、不瞬移归位；归队闪回跳过倒地的人；复活在倒地点（`squad._revive(o, o.pos)`）。复活计时照旧 25 秒；队长站到倒地者身边 `command/revive_near`（64）内时，计时按 `command/revive_near_k`（4 倍）走，也就是贴身约 6 秒。复活后离队长超过 700 的，按随行原规则直接归位。
核对（`--cmddown=66`、60 秒突击、75 秒归队）：66 秒推进之王倒在 (2125,−327)、维什戴尔倒在 (2207,−449)，75 秒归队没被带走，91 秒在同一坐标复活。只在用了指挥模式时同 seed 结果会变；不用指挥模式时不经过这些分支。

### 11.2 出击 / 归队语音听不到

原因：指挥回应走普通语音规则，会被三道限制吃掉：同一名干员 15 秒内说过话（队长常刚放过技能语音）、任何语音之后 3 秒的全队静默间隔、占线直接放弃。实战里技能语音很密，几乎每次都被挡掉。
改为：`Sfx.voice(..., urgent = true)`（只给指挥回应用）——
- 不受同人 15 秒间隔和全队静默间隔限制；
- 正在播战斗闲聊或部署语音时把它淡出，直接开播（同「技能语音可打断闲聊」口径）；
- 正在播技能语音或另一条指挥回应时，等它播完立即补播，1.5 秒内没轮到就放弃；
- `command/voice_gap` 6 秒节流保留（连按不刷屏）。
核对：实时窗口局（静音驱动，`--voicelog` 打印真正开播的语音）在 30 / 40 / 47 / 55 / 57 / 68.5 / 90 秒切换，除 57 秒（距上一次只隔 2 秒，被 6 秒节流挡掉）外每次都开播：30 水月 command、40 推进之王 entry、47 维什戴尔 command（等水月技能语音播完补播）、55 水月 entry、68.5 推进之王 entry、90 维什戴尔 command。改之前同样的切换大多被闲聊 / 间隔挡掉。（无头批跑会把游戏时间压缩，而语音占线按墙钟算，那里的日志不能用来判断。）声音实际听感没有人耳核对（测试一律静音）。

## 13. 指挥圆盘 + 索敌优先级（10-24，分支 `claude/command-wheel`）

用户 10-24 原话：「点击指挥模式出来一个类似于圆盘的指挥系统，玩家可以选择清杂优先或者 Boss 优先」。

### 13.1 圆盘

按指挥键（键盘 F / 手柄 LB（LT）/ 触屏「指挥」键）弹出圆盘，盖在 HUD 上，**局内放慢**（`command/wheel_slow` = 0.2，不全停；放慢只作用在对局步长，圆盘动画与输入用真实帧间隔）。五个扇区，上半圈是队形（三块各 60°），下半圈是索敌优先级（两块各 90°；10-24 用户定去掉「就近」，见 §13.2）：

| 扇区 | 选项 | 说明（圆盘里的文字） | 效果 |
|---|---|---|---|
| 左上 | 随行 | 跟在队长身边 | 直接回到随行（不闪回） |
| 上 | 突击 | 离队索敌，限时行动 | 同原突击（作战时限不够时飘「作战时限未恢复」） |
| 右上 | 归队 | 立即回到队长身边 | 归队闪回 + 集合（任何时候可选） |
| 右下 | 清杂优先 | 优先杂兵，向密集处开火 | 队友自动索敌、突击走位都偏向杂兵密集处 |
| 左下 | Boss 优先 | 优先 Boss；小怪贴近队长时先护主 | 缺省，与改动前的默认逻辑相同（只认 Boss，不含精英） |

当前生效的项带「当前」小标。中心圆显示悬停项的名字，圆盘下方一行说明 + 一行操作提示。画法（终末地风格、动效、减少动态效果）见 docs/144。

操作：
- **按住键**（> 0.25 秒）：往目标方向移鼠标（相对按下时的位置，> 30 像素算选中）/ 推摇杆（右摇杆，没推则看左摇杆），**松开确认**；没选中就松开 = 取消。
- **轻点**（< 0.25 秒）：圆盘留着，鼠标直接点扇区（悬停高亮），Enter / Ⓐ / E 确认悬停项；Esc / 再按一次指挥键 / 右键 / 点空白处取消。
- **触屏**：点「指挥」键弹出（轻点式），点扇区确认，点空白处取消。
- 圆盘打开时吞掉所有按键和点击（移动是轮询的，继续生效，只是被放慢）；离开对局状态（暂停、死亡）自动关闭。

### 13.2 索敌优先级

`squad.priority`：**0 Boss 优先（缺省）/ 1 清杂优先**，机器人从不改。只影响**队友**（`op_api.prio_mode()`：队长与没有编队时恒为 0），同 seed 下不开圆盘时一行不变。

10-24 统一（用户：「按你的建议统一：一个优先级函数两处共用、就近去掉 Boss 强制、Boss 优先加护主、能天使 / 德克萨斯也认优先级」；问到默认档时又定「就近要不然去掉呢」，并选「Boss 优先只认 Boss」，默认局一行不变）：

- **一个排序函数** `op_api.prio_order(cands, mode)`，攻击选敌（`nearest_enemies`）与突击走位选敌（`character.roam_target`）共用。`cands` = [[敌人, 得分], …] 按得分升序；攻击侧得分 = 离 origin 的距离，走位侧 = Codex 的原评分（离队尾距离，重装再加离队长距离）。档位判定 `prio_rank(e, mode)`，Boss 认定 `focusable_boss(e)`（活着、没假死、不无敌、没潜地 / 闸门无敌）。
- **Boss 优先（0）** = 改动前的默认逻辑 `ai/boss_focus`：第一个已是 Boss / 部件就不动；否则得分最小的可受击 Boss 提到最前（攻击侧：max_dist 内、不在最近 n 个里的 Boss 也进候选）；队长 `ai/boss_focus_guard`（60）内有非 Boss 贴脸时不提（**护主**）。精英不提前。突击走位现在也走这条（改动前走位不认 Boss）。
- **清杂优先（1）**：杂兵（非 Boss / 精英 / 部件）在前，按周围 90 像素内的杂兵数（含自己，封顶 6）由多到少、同数按得分；密集度只在得分最小的 24 只杂兵里算；没有杂兵保持原顺序。攻击侧候选池 = 最近的 max(6n, 14) 个（上限 24）。不抽随机数，稳定排序。
- 突击中换了优先级：当前目标不在偏好档位、而候选里的最优在，立刻换过去。Codex 的站位 / 绕行 / 卡住检测没动。
- **能天使**（`seg_exusiai._exu_targets`）：清杂优先下自动瞄准直接用优先级顺序，不再按精英加权重排、不把 Boss 提前；Boss 优先下照旧。
- **德克萨斯**（`seg_texas._tx_densest`，天赋 / 剑雨朝敌群冲）：清杂优先下只数杂兵找最密处，没有杂兵照旧数全部；其余选敌本来就经 `nearest_enemies`。
- 不影响：队长的所有目标选取；`target: random` 的随机目标（docs/108 F4）；召唤物 / 阵地类自带选取；以队长为中心的范围技能。

### 13.3 HUD 与反馈

## 14. 爆发窗口（10-24 用户定，分支 `claude/command-burst`）

用户原话：「突击改成爆发窗口：队友出击时攻速和技力回复明显加成、第一下冲锋带击退，加金色拖尾和喊话，耐力照旧限时。」

### 14.1 规则

- **加成**：突击中、肯出击（`command.roam` 非 false）、没倒地的队友，攻速 ×(1 + `rush_aspd`) = ×1.25、技力回复 ×`rush_sp` = ×1.5。走属性系统：`op_aspd` / `op_skill_sp` 各加一条 mult，来源 `command`，作用域 `op:<id>`（`squad._tick_rush_buff` 每帧对账，退出突击 / 倒地 / 换队长后立即撤）。医疗 / 辅助 `roam: false` 的不挂。属性面板（TAB）「攻击」栏多一行「突击加成（队友）：攻速 +25% · 技力回复 ×1.5」，左上状态栏多一枚金色标签（带耐力条）；不在突击时都不显示。
- **冲锋**：切到突击那一刻（`set_stance(ROAM)` → `Character.begin_rush`），每名出击队友朝自己的突击目标冲一段：速度 `rush_speed`（780 像素/秒）、最远 `rush_dist`（320），不出活动圈，被景物挡直线就不冲；离目标不到 `rush_min`（60）的原地顶一下。冲锋 ≤ `rush_max_t`（0.5）秒，撞上怪或冲到位就停，撞击点 `rush_hit_r`（56）内的怪被推开 `rush_kb`（340，经 `apply_kb`，同其它近战口径）：精英 ×`rush_kb_elite`（0.5），Boss / 部件 / 宝箱免疫；冲锋期间 `rush_inv`（0.6）秒无敌。之后进入正常突击。镜头不动（动的是队友）。
- **耐力**照旧：25 秒耗尽自动归队，`min_start` 0.3 冷却线不变。
- **表现**：身后金色轨迹（`rush_trail_life` 0.22 秒；每 0.03 秒一个点，每点 3 颗 2 / 4 像素方块，落在 2 px 网格，序号哈希摆位不用随机数；三阶透明度，新点带白芯；撞击点向外迸 8 颗；同时往光学发光层排发光点）；喊话 = 现有突击语音（`command/voice_gap` 6 秒节流）+ 说话人头顶金色「出击」；这名干员没有 `*_command` 语音素材时补一声通用音效（`Sfx.has_voice` 判断）。
- 选优先级（`set_priority`）复用语音但不喊「出击」、不冲锋。无头批跑不记轨迹（纯画面）。
- 开关：`command/rush`（缺省 1）；0 = 不挂加成、不冲锋（对照用 `--bal=command/rush=0`）。

| 旋钮 command/… | 缺省 | 含义 |
|---|---|---|
| rush | 1 | 爆发窗口总开关 |
| rush_aspd | 0.25 | 攻速加成 |
| rush_sp | 1.5 | 技力回复倍率 |
| rush_dist / rush_speed / rush_max_t / rush_min | 320 / 780 / 0.5 / 60 | 冲锋最远距离 / 速度 / 最长秒数 / 不足此距离就不冲 |
| rush_hit_r / rush_kb / rush_kb_elite / rush_inv | 56 / 340 / 0.5 / 0.6 | 撞击半径 / 击退冲量 / 精英系数 / 冲锋无敌秒 |
| rush_trail_life | 0.22 | 金色轨迹寿命 |

## 16. 卡帧修复 + 闪避 / 走位意识（10-27 用户：「发现队友的运动有点卡帧，这是为什么，修复一下，以及给队友的 ai 加上闪避意识和走位意识」）

### 16.1 卡帧原因与修复

60 帧无头逐帧采样（水月 + 推进之王 + 维什戴尔，seed 3，12 秒切突击）：随行段 864 帧匀速，没有折返；突击段每 9–12 帧有一帧被往回拽 1–3 像素。原因在局部绕行 `_cmd_walk`：队友的直线路径刚好擦着岩石底座边缘时，这一帧 `segment_blocked` 判「挡住」→ 换成侧向 60° 的绕行点 → 往旁边挪 1–2 像素后下一帧直线又不挡 → 立刻丢掉绕行点回到原方向 → 再慢慢贴回边缘，形成约 0.15 秒一次的振荡，画面上就是「一顿一顿」。
修复：绕行点选定后至少保持 `command/detour_hold`（0.3）秒或走到为止，期间不因直线暂时不挡就丢掉。复测 1500 帧突击段：单帧折返从每 100 帧 2.5 次降到 0。

### 16.2 闪避意识（`command/evade`，缺省开）

随行和突击中（归队、冲锋、连携位移不管），队友脚下是**未结算的敌方预警区**（圆 / 线 / 扇，判定同机器人 `bot._in_warn`，加宽 `evade_pad` 16），或 **`evade_t`（0.5）秒内会被敌弹擦到**（按子弹速度算最近接近点），就在身边 8 个方向 × `evade_step`（56）/ 112 两档里挑一个安全、没被景物挡、离原目标最近的点先躲过去，躲点保持 `evade_hold`（0.25）秒，之后回到原来的随行位 / 突击目标。不抽随机数。
注意：队友本身只在突击中被近战怪碰到掉血（§7），预警区和敌弹打不到队友，所以闪避目前是**观感层面**的「有意识」，不改队友承伤；它会让队友在预警期间离开编队位 / 目标几十像素，输出可能略降。

### 16.3 走位意识

- **近战挑边**（`command/side`，缺省开）：突击中近战队友围着目标的 8 个方位里，挑站位点 `side_r`（60）内近战怪最少的一侧（同数偏向队长一侧，所以没怪群时和旧规则一样站在目标朝队长的一侧）；现在这侧要多出 `side_hyst`（2）只才换边，不来回跳。已经在射程内、但站的这一侧被围（≥ `side_hyst` 只且别处更少）也会换边，不再站着挨打。

- **主因：随行（stance 0）的 lerp 不限速。** 近战队友的前压点（`melee_spot`，换目标 / 进出贴身距离时一帧跳几十到上百像素）和闪避点一变，`pos.lerp(target, 6·dt)` 就按距离比例一两帧冲过去，最快约 20 倍移速——画面上就是攻击时一下子闪到怪身边。修前 8 局随行类 5973 帧（其中 428 帧超过阈值 3 倍），占全部超阈值帧的七成；其次随行离编队位 700 以上直接瞬移归位（2 次）。
- 其余超阈值来源都是连续位移、不是闪现：突击冲锋（`rush`，780 像素 / 秒、带拖影，10-24 用户定）、推进之王跃空锤 / 德克萨斯冲刺（技能自带插值动画）、归队跑位（`recall_speed` 4 倍）、归队瞬回（玩家按归队，带特效）。

### 20.2 修复

- 随行移动限速：每帧最多 `队长移速 × command/follow_vmax`（2.8，阈值以内），近处照旧 lerp 减速；跟随冲刺（`dash_follow`）不变。
- 瞬移只剩两种：离队长超过 `command/leash × 1.6` 的掉队归位、玩家按下归队的瞬回；两者共用 `squad.blink_fx`（原地退场闪光 + 落点光圈）。原来「随行离编队位 700 以上直接归位」删掉，改为限速跑回。
- 结果（同 8 局）：随行 / 闪避 / 换边 / 截子代类超阈值帧 5976 → 41（剩下的最多 1.8 倍阈值，是贴柱子 `push_out` 的推出量），超阈值 3 倍的 0；snap 0。冲锋 / 技能位移不变（约 1400 / 650–820 帧，都是连续插值；德克萨斯冲刺是先快后慢的缓动，首帧最快）。
- 对照：`--bal=command/follow_vmax=999` = 原来不限速的随行。

### 20.3 指挥合唱

- `command/voice_mode`：0 = 旧口径（按编队轮换只一人开口）；**1 = 交替（缺省）**：所有出击队友都开口，轮换谁先，其余每人晚 `command/voice_stagger`（0.4）秒，允许尾部重叠；2 = 同时。
- `sfx.voice_chorus`：每名干员一个播放器（Voice 总线），同一名干员自己不重叠（他那条还在播就不再喊）；两条以上同时在播每条压 `command/voice_duck_db`（−3 dB，先开口的那条在第二条开口时压下，只压一次）。其余同原 urgent 指挥回应：正在说的战斗闲聊 / 部署语音淡出让路，技能语音正在播就等它播完补播（1.5 秒内）；播完照常记同人 / 全队间隔，`voice_gap` 节流不变。**10-29 用户「归队的时候不要语音了」：归队 / 随行不再开口**（`squad._stance_voice` 只在突击时请求，也不占 `voice_gap` 节流）；突击回应与其它语音改为每人多句轮换，见 docs/190。
- 验证：`voice_command` 新增合唱轮换 / 错开 / 旧口径 / 合唱通道间隔各项。
