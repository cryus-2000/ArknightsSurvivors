# 309 · 字体「fd is null」报错 + Toy 包余量（11-07，帧率会话，分支 claude/smallfix-1107）

> 协调人转用户 11-07「小毛病修复一下」：① 网页测量包日志里约 70 次 `Parameter "fd" is null` 查清来源并修；② Toy zip 49.21 MB（b430ddf42）离 50 MB 上限只剩约 0.8 MB，在无损或已批口径内压到 ≤ 47.5 MB。

## 0. 结论

1. **字体报错 156 → 0**（网页手机仿真同参数对照）。来源：`Cfg.slim_fonts`（进局清字形缓存 / 内存护栏清缓存）对 ui.ttf 调 `clear_cache()` 时，引擎先释放字形句柄再发 `changed`，**正挂着的 Label 在信号里同步重排、拿到刚释放的句柄**。全游戏只有性能自检浮层（core/perf_hud.gd，`?perf=1` 或性能报告页连点 5 次）是常驻 Label，所以只在浮层开着时出现——那一帧浮层字画不出，下一秒刷新后恢复。正式 Toy / itch 包浮层缺省关，不开浮层时为 0（桌面复现：不带 `--perfhud` 0 行）。
2. **Toy zip 49.21 → 45.92 MB**（目标 ≤ 47.5，留出约 4 MB）：网页包脚本改按源码导出并去掉整行注释，脚本那一块 4.87 → 约 2.2 MiB。无损：只改打包副本，画面 / 声音 / 玩法不变。

## 1. 字体报错

- 定位：桌面 `--perfhud --fontslim --touch` 复现 62 行，GDScript 回溯全部指向 `slim_fonts (settings.gd:174)` ← `game._ready`（进局清缓存）；网页那局的第二簇（约 86 行）是内存护栏第一步「清缓存」，同一个函数。
- 修（2c2002a18）：`clear_cache()` 期间 `set_block_signals(true)`，三份字体清完后重设 `fallbacks`（Font 先作废句柄缓存、再发 changed），回退链的上级 ui.ttf 一并重取。
- 验：桌面 62 → 0；网页测量包（手机 844×390 @3x，`--perfhud --memguard=200` 强制触发护栏清缓存）修前 `fd is null` 156 行 + `_get_font_data` 12 行 → 修后 0。退出时引擎的 RID 泄漏提示修前修后行数相同（引擎老提示，与本修无关）。

已批口径（语音 16k、音效 22 / 24k、插画 0.85、配乐 C / 最终 Boss D、旧粗体、WebP 无损最高档、字体子集 + WOFF2）**导出脚本里都已经用满**，没有余量。查过、不划算的：

- WebP 无损再提档：已是方法 6 / 系数 100。
- 整包 LZMA 代替 gzip：只省 0.69 MiB，手机上 JS 解 40 MiB 的 LZMA 慢且吃内存。
- 同内容重复条目 0.14 MiB、同名多份导入 0.48 MiB、pxp 不在帧条表也查不到名字的 52 张 0.04 MB——太小，且删错会静默缺特效。

采用：**网页包脚本按源码导出（script_export_mode 0）+ 去整行注释**（tools/export_web.py `script_text_export`，只改打包副本，仓库与桌面包不动）。压缩令牌是每个脚本各压一遍，整包 gzip 压不动；源码去整行注释后 9.13 → 7.40 MiB、整包 gzip 约 2.2 MiB。去注释只删「首个非空白字符是 #、且不在三引号字符串里」的行，换成空行（行号不变，报错行号对得上）；行尾注释和字符串一律不动（544 个脚本里三引号字符串内没有以 # 开头的行）。令牌模式加载时同样要解析 + 编译，只省分词，运行行为一样。
