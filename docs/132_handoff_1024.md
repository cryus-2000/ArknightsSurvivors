## 1. 工作方式（必须照做）

- **分工**：用户拍板产品决定。Claude 管游戏代码、接入、测试、出包和除角色 / 怪物外的美术；Codex（GPT）管角色与怪物美术，10-17 起也可在 `codex/<主题>` 分支改代码（`docs/106` §6），由协调人审后合入。
- **工作区**：主工作区 `E:\ArknightsSurvivors`（main）**只做合入和出包**；改代码一律在自己的 worktree 开分支：
  `git worktree add .claude/worktrees/<名> -b claude/<主题> origin/main`（Codex 用 `.worktrees/codex-<主题>`）。进 worktree 前守住 `cd X || exit 1`，免得 git 落回主工作区。
- **合入流程**（主工作区，只在 main 上；一次可合多条分支）：
  1. `git branch --show-current` 是 main、工作区干净；
  2. `git merge --no-edit <sha> && git merge-base --is-ancestor <sha> HEAD || exit 1`：**按提交号合，合完核实，失败立即停**（曾因提交号写错空合并后照样推送）；
  3. `python tools/check.py --rerecord-golden`：玩法 / 积木改动后「积木等价金样」必过期，**分支不提交金样，合入后在 main 统一重录**；
  4. `python tools/check.py --auto > 文件 2>&1; rc=$?`：**输出进文件看 rc，不要接管道**（管道会吞退出码）；
  5. 通过后：`git add game/tests/golden_current` 提交 → `git push origin main` → `python tools/release_all.py --ref <sha> --only internal` 出对内测试包（`build/release/final_<sha>/`）；
  6. **快检跑着时不要在主工作区 merge / checkout**，会让测试莫名失败。
- **合并冲突的老问题**：`docs/00_index.md` 常撞行（两边都加文档行，全保留即可）；`tools/check.py` 测试清单常撞（两边新增测试都保留）；未跟踪的 `*.gd.uid` 挡合并就删掉再合（uid 要随脚本一起提交，口径见 `docs/06`）。
- **对外发布**（用户 10-10 授权，合入过检后可直接发）：`python tools/release_all.py --ref <sha>`（三包 + 网页）→ `python tools/deploy_itch.py --ref <sha> --apply --confirm <sha>`；B站 Toy 走仓库内 `.claude/skills` 的 toy 技能，由用户触发。首次上架、改商店页、对外发链接仍先问用户。
- **测试与对照**：
  - 改局内代码但声称「只改画面」时，跑一局同 seed 对照（`python tools/trace_base.py 1 mizuki 240 --ref <基线> --here`），必须逐行相同；纯美术 / 文档 / 局外界面不跑。
  - 胜率对照（同 seed 配对）**一律上云**：建「一次性云端例行任务」（claude.ai 的 routines / RemoteTrigger），环境装法见 `docs/36` §7.5.1（`tools/cloud/setup_linux.sh`）。云端额度和本地额度分开算（用户 10-24）。
  - 云端任务提示词里要求**所有长任务前台直接跑**，不要后台 + 定时唤醒：10-24 的 tx-diag 两次后台挂起后不再继续、结果没推上来。
  - 云端偶尔被安全审查误判拦停（报 `[cyber]`），换个说法重建任务即可。
  - 胜率差 < 10 点不下结论（56 对噪声约 ±8–13 点）。
- **硬规矩**：
  - Godot 一律 `--headless`；必须开窗口时只走 `tools/godot_runner.py`（屏幕外、不抢焦点、`--audio-driver Dummy`）。**不许弹窗**，用户在同一台机器上干活。
  - 只按 PID 结束自己的 Godot，**不许按进程名杀**，会误杀别的会话的测试。
  - 同 seed 必须复现：玩法随机只用 `g.rng`，画面随机用 `g.vrng`；禁用 `Array.shuffle()` / `pick_random()` / 全局 `randf()` 写玩法。
  - `AGENTS.md` / `CLAUDE.md` 的改动要用户直接确认，不凭转达。
  - 玩家可见文案按 `docs/76`：明日方舟味；原作名字 / 设定只用可查证来源（PRTS 优先），不编。
  - 用户 10-15 亲口授权：可下载 PRTS 原作素材作内部参照，放 `build/`，不进 git、不进包。
