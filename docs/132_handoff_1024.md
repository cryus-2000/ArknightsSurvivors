## 1. 工作方式（必须照做）

- **角色**：一个「协调人」会话只做派活、合入、快检、出包、发布、回答用户；领域工作交角色会话（干员 / 怪物与 Boss / 数值 / 界面与美术 / 架构 / 测试 / 性能 / 局外），各在自己的 git worktree（`.claude/worktrees/<名>`）开 `claude/<主题>` 分支，做完报「分支 + 提交号」，**不自己合 main**。Codex 在 `.worktrees/codex-art` 的 `codex/art` 或 `codex/<主题>` 分支交付，协调人审后合。
- **模型**：用户 10-23 定**全部会话不用 Fable**：界面 / 架构类用 Opus，其余 Sonnet。新开会话显式指定 model。
- **不许弹窗**（AGENTS.md）：Godot 一律 `--headless`；必须带窗口只走 `tools/godot_runner.py`（副屏 / 屏幕外、不抢焦点、`--audio-driver Dummy`）。
- **合入流程**（主工作区 `E:\ArknightsSurvivors`，只在 main 上）：
  1. `git branch --show-current` 必须是 main，工作区干净；
  2. `git merge --no-edit <sha> && git merge-base --is-ancestor <sha> HEAD || exit 1`（**合并失败立即停**；10-23 曾因提交号写错空跑推送）；
  3. `python tools/check.py --rerecord-golden`（玩法 / 积木改动后金样必过期，分支不提交金样，协调人统一重录）；
  4. `python tools/check.py --auto > 文件; rc=$?`（输出进文件看 rc，别接管道）；
  5. 过了：提交 `game/tests/golden_current`、`git push origin main`、`python tools/release_all.py --ref <sha> --only internal` 出对内包；
  6. **快检跑着时不要在主工作区 merge / checkout**（会让测试莫名失败）。
- **对外发布**：`python tools/release_all.py --ref <sha>`（三包 + 网页）→ `python tools/deploy_itch.py --ref <sha> --apply --confirm <sha>`；B站 Toy 包见 docs/22「Toy 接入」，用户用 /toy 发。`build/release` 只留最新两份对内包 + `final_e97b4a2`（EA 冻结）+ 最新公开包。
- **汇报口径**：用户额度紧，只在完成或需要拍板时说话，三行以内；长内容进 docs。
