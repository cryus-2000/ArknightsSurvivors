# 133 补给箱回血（claude/supply-crates，10-24）

用户 10-24：参照《吸血鬼幸存者》靠打可破坏道具回血；「基础回血数值还是得稍微给一点」，生命感悟不删。

## 1. 改了什么

| 项 | 改前 | 改后 |
|---|---|---|
| 队长自带回复 `sustain/base_regen_mult` | 1 | 0.7（各队长 1.0–2.0 → 0.7–1.4） |
| 入队回复 `squad/regen_per_member` | 0.2 | 0.15（3 人满 0.45） |
| 补给箱刷出间隔（秒） | 35–50 | 5 分钟前 55–75、5–8 分钟 40–55、8 分钟后 28–40（前松后紧，场上同时最多 3 个不变） |
| 打碎掉落 | 源石锭 3–6、30% 灯油 | 另加：85% 应急补给（拾取回 25% 最大生命）、10% 磁铁、10% 临时护盾 +1 层（最多到护盾上限 +1） |

- 补给箱沿用现有的「补给箱」（`spawn_chest`，hp 22，15% 伪装成箱形恐鱼，伪装的现形后不掉）；机器人（bot.gd 高手 / autotest 普通）原来就会走到 450 / 400 像素内的箱子旁打碎，应急补给也加进了它们的拾取权重（同回复药剂）。
- **应急补给不吃 heal_mult**（`pickups.gd` 的 `pack` 分支单独算：最大生命 × 25% × 侵蚀创口折扣），有医疗和无医疗的编队拿到一样多；治疗来源记在 `heal_log["补给"]`。旧的回复药剂（精英 / Boss 必掉、小怪低概率，回 30%）不动，仍吃 heal_mult。
- 旋钮全在 `balance.json` 的 `crate` 段，`crate/pack_p` 0 = 整套关掉回到旧行为。
- 遥测：`data.crates`（打碎的箱子数）、`data.items.pack_drop / pack_pick / crate_shield`、`data.heal["补给"]`。

## 2. 本机冒烟（starts 7 编队 × 1 seed，标准 · 高手，无成长）

每局打碎 3–16 个箱子，掉应急补给 2–14 个、捡 2–11 个、临时护盾 0–2 次；补给的有效治疗每局 27–111（高手常在满血时捡，溢出的不算）；基础回复下调的那部分约 −100。总回复量大致持平，胜负由云端同 seed 对照定。

## 4. 云端同 seed 胜率对照（10-24，claude/regen-meta-eval，docs/36 §7.5.1 环境；只测，未改玩法代码）

分支 `claude/regen-meta-eval` = `origin/main`（20c5a22f）依次合入 `origin/claude/supply-crates`（63d54419）+ `origin/claude/meta-generous`（22ea05c529d）；两次 `git merge` 均**无冲突**（改动的文件互不重叠）。云端 4 核 / 15 GB，Godot 4.7.2 headless + Dummy 音频，starts 7 编队 × 8 seed（seed 1–8）× 高手机器人 = 56 局一组，两组同 seed 配对，`tools/balance_run.py` 跑，胜率 95% 区间按正态近似、配对显著性用 McNemar（docs/111 §8 同口径）。

**方法上的一个坑（已修正）**：`origin/claude/supply-crates` 分支是从 main 更早的提交（15becc9c）开出的，不含之后合进 main 的近战判定半径 ×0.85 收紧（docs/111 §8）、祭坛不当目标修复等 10 个提交；直接拿它当「只 supply-crates」一侧会把这些无关的 main 变化也算进差值。实际用的「只 supply-crates」一侧是 `claude/regen-meta-eval` 里 main 合 supply-crates、还没合 meta-generous 那一步的中间提交（`2850a4dc` = main 20c5a22f + supply-crates），与 main 20c5a22f 只差 supply-crates 这一个 diff。核对：`2850a4dc` 无成长·常规·同 56 seed 与下面 B 组的「无成长」逐局（胜负 + 存活秒数）**完全一致**（meta-generous 不带 `--meta` 时确实零影响，代码审查与实测一致）。

### 4.1 A 组：main vs 只 supply-crates（无局外成长）

| 档 | 一侧 | n | 胜率（95% 区间） | 均存活 | 承伤/回复（比值） | 补给箱破坏/拾取 |
|---|---|---|---|---|---|---|
| 常规 | main（20c5a22f） | 56 | 42.9%（±13.0） | 10:10 | 1225 / 1192（1.03） | 0 / 0 |
| 常规 | main + supply-crates | 56 | 28.6%（±11.8） | 9:55 | 1126 / 1057（1.07） | 8.8 / 4.8 |
| 高压 | main（20c5a22f） | 56 | 16.1%（±9.6） | 7:40 | 945 / 893（1.06） | 0 / 0 |
| 高压 | main + supply-crates | 56 | 10.7%（±8.1） | 7:46 | 935 / 871（1.07） | 6.7 / 3.9 |

配对（同 seed 都赢 / 都输 / 只一侧赢）：常规 8 / 24 / main 16·supply 8（McNemar p = 0.153）；高压 0 / 41 / main 9·supply 6（p = 0.606）。

- 两档都**没到统计显著**（56 对的噪声本来就有 ±8–13 点，docs/111 §8 同规模噪声 ±7.6–12.7），但方向一致地偏负：常规 −14.3 点、高压 −5.4 点，承伤/回复比值两侧都从 ~1.03–1.06 升到 ~1.07（回复没完全补上砍掉的基础值）。
- **main 本身（没有 supply-crates）常规档无成长已经是 42.9%，比 docs/109 §16 定的 45–60 目标低了一点**——大概率是近战判定半径 ×0.85（docs/111 §8，10-24 刚合）还没重新校准，不是这次改动的锅；supply-crates 在这个已经偏低的基线上再压 14 点，常规档会明显跌出目标区间，高压档本来就在区间外更低（16.1→10.7）。
- **结论：supply-crates 的回复砍量没被补给箱完全补回，净效应偏负，但本组数据不足以判定是否显著**；按 docs/133 §3 的后续手，想要扳平建议先调宽 `crate/pack_pct`（0.25→0.30 左右）或缩短 `early_lo/hi` 刷新间隔，而不是动基础回复倍率，再跑一轮同规模对照确认。

### 4.2 B 组：合并后，无成长 vs 满点成长（常规档）

无成长：合并分支不带 `--meta`；满点：`--meta=full`。`meta/stat_scale` 缺省 1，按 docs/109 §16 定的口径（无成长 45–60、满点 70–80）校准，用足了「最多两轮」的额度。

| 配置 | n | 胜率（95% 区间） | 均存活 | 承伤/回复（比值） | 补给箱破坏/拾取 | 是否达标 |
|---|---|---|---|---|---|---|
| 无成长 | 56 | 28.6%（±11.8） | 9:55 | 1126 / 1057（1.07） | 8.8 / 4.8 | **否**（目标 45–60，低了至少 16 点）|
| 满点，`stat_scale=1`（缺省） | 56 | 96.4%（±4.9） | 11:20 | 474 / 468（1.01） | 11.3 / 6.2 | 否（目标 70–80，高了 16+ 点）|
| 满点，`stat_scale=0.5`（第 1 轮重跑） | 56 | 92.9%（±6.7） | 11:17 | 874 / 867（1.01） | 10.9 / 6.3 | 否 |
| 满点，`stat_scale=0`（第 2 轮重跑，**采用**） | 56 | **75.0%（±11.3）** | 11:30 | 1016 / 998（1.02） | 11.1 / 6.2 | **是** |

无成长 vs 满点（`stat_scale=0`）配对：都赢 13 / 都输 11 / 只无成长赢 3 / 只满点赢 29；McNemar p < 0.001（显著）。

- **满点只有在把 `stat_scale` 压到 0（39 个数值节点的加成全部归零）时才落进 70–80**：`stat_scale` 从 1→0.5 胜率只降了 3.5 点（96.4→92.9），0.5→0 又降了 17.9 点（92.9→75.0），明显不是线性关系——说明满点大头的胜率来自**不受 `stat_scale` 缩放的「质变」规则效果**（危机感护盾反震、攻击性Ⅴ处决、生存本能Ⅴ免死、绝处逢生复活、领导欲Ⅳ升级再升；`meta.gd apply_run` 里只有 `effects` 里带 `stat` 键的加成乘了 `stat_scale`，带 `rule` 键的质变效果不乘）。`stat_scale=0` 时这些质变效果单独就能把胜率顶到 75%，39 个数值节点（伤害/生命/减伤/回复/经验/拾取范围等）名义上还在，但玩家点了完全没用——**这不是「校准成功」，是把唯一能调的旋钮调到失效边界才勉强达标，质变效果本身偏强**，真要留住数值节点的意义，得回到局外成长会话调质变效果自己的旋钮（`shatter_*` / `execute_*` / `last_stand_inv` / `revive_hp` / `double_level_chance`，均在 `balance.json` `meta` 段），这超出本次「只测不改玩法代码」的范围，记录在这里转交。
- **无成长胜率本身没达标**（28.6% vs 目标 45–60），和 §4.1 的结论一致：问题出在 main 基线偏低 + supply-crates 回复净砍量，不是局外成长树的锅，`stat_scale` 对无成长局完全不起作用（没有 `--meta` 时 `apply_run` 直接返回）。
- 补给箱拾取（破坏 8.8–11.3 个 / 拾取应急补给 4.8–6.3 个每局）在四组里相近，没有随成长程度明显变化；满点组存活更久（11:17–11:30 vs 9:55），承伤/回复比值反而更接近 1（回复跟得上伤害）。

### 4.3 结论与交接

1. **supply-crates 净效应偏负但未达显著**（常规 −14.3 点 / 高压 −5.4 点，p 均 > 0.1），建议下一轮用 `crate/pack_pct` 或刷新间隔微调后再跑一次同规模对照确认方向。
2. **无成长胜率不达标是 main 基线 + supply-crates 共同造成的**，与局外成长树无关；`stat_scale` 这一个旋钮管不到无成长局。
3. **满点达标（75.0%，`stat_scale=0`）是以数值节点全部失效为代价换来的**，质变类规则效果（护盾反震 / 处决 / 免死 / 绝处逢生 / 升级再升）本身已经偏强，需要局外成长会话单独校准这些效果自己的旋钮，而不是指望 `stat_scale` 一个数能两边兼顾。
