## 1. 入队回复台阶（替换时间成长）

### 1.1 规则

- 时间成长关掉：`sustain/regen_div` 300 → **0**（`combat.regen_time_mult()` 恒为 1）。旋钮和代码保留，`--bal=sustain/regen_div=300` 即回到 docs/82 定档。
- 入队加成（`squad.gd _apply_size_hp`，入队 / 离队时重算）：编队每多 1 名干员（开局干员不算，最多算 `squad/hp_member_cap` = 3 名）：
  - 队长最大生命 ×(1 + `squad/hp_per_member` × 人数)，每人 +15%。这一条原来就有（docs/46 §6，2026-09-27 用户定）。任务里写的 `enemy/hp_per_member` 实际在 `balance.json squad` 段，作为来源 `squad` 的 mult 加在 `max_hp` 上，叠在「坚韧」之上一起放大；入队时当前生命按比例放大，不显示掉血。
  - **新增**：队长生命回复 + `squad/regen_per_member` × 人数（生命 / 秒），作为来源 `squad` 的 flat 加在 `regen` 上。和干员 leader 段 regen、「自愈」同一个池，吃回复效果倍率（heal_mult，藏品 #69–71）。
- 数值：`regen_per_member` = **0.9**。编队 1 / 2 / 3 / 4 人时分别 +0 / +0.9 / +1.8 / +2.7 生命 / 秒（4 人需要编队上限 +1 的藏品）。

### 1.2 数值换算：满编 ≈ docs/82 定档 8:00 的水平

docs/82 定档（云端 sgv 验证过的续航）：回复 × (1 + min(t, 480) / 300)，4:00 ×1.8、6:00 ×2.2、8:00 起 ×2.6。乘的是整份回复（leader regen + 自愈 + regen_pct 藏品）。

| 队长（leader regen） | 昨天 4:00 / 6:00 / 8:00 起 | 现在 1 / 2 / 3 / 4 人 | 满编 3 人 / 昨天 8:00 |
|---|---|---|---|
| 维什戴尔、艾雅法拉、铃兰、逻各斯（1.1） | 1.98 / 2.42 / 2.86 | 1.1 / 2.0 / **2.9** / 3.8 | 101% |
| 凯尔希、流明、塞雷娅（1.0） | 1.80 / 2.20 / 2.60 | 1.0 / 1.9 / **2.8** / 3.7 | 108% |
| 斯卡蒂、德克萨斯（1.6） | 2.88 / 3.52 / 4.16 | 1.6 / 2.5 / **3.4** / 4.3 | 82% |
| 乌尔比安（2.0） | 3.60 / 4.40 / 5.20 | 2.0 / 2.9 / **3.8** / 4.7 | 73% |

- 换算：昨天 8:00 多出来的是 regen × 1.6；队长 regen 中位 1.1，×1.6 = 1.76 ≈ 2 名队友 × 0.9 = 1.8。所以 regen 1.0–1.1 的队长满编时和昨天 8:00 持平；regen 高的近卫队长（斯卡蒂、乌尔比安）少 18–27%（昨天的倍率按自身 regen 放大，现在是固定台阶）。
- 时间分布不一样：本机冒烟里第 2、3 名干员入队时刻中位 **1:17 / 1:42**（20 局全部在 2:00 前满编）。所以满编队从约 2:00 起就拿到「昨天 8:00」的回复，**2:00–8:00 比昨天多**（维什戴尔队长 4:00：2.9 对 1.98，6:00：2.9 对 2.42）；单人或没招满时比昨天少。
- 按最大生命比例：维什戴尔队长满编最大生命 110 × 1.3 = 143，回复 2.9 / 秒 ≈ 2.0% / 秒（不含自愈 / 坚韧）。
- 「自愈」卡、回复类藏品不再随时间放大：昨天 5 级自愈 8:00 起是 3.0 × 2.6 = 7.8 / 秒，现在就是 3.0 / 秒。拿回复卡的局后期回复比昨天少；如果云端看到这类局明显变难，可以调 `sustain/regen_card`（见 §2）。

### 1.3 文案（docs/76）

- 招募卡说明末行（`squad.join_bonus_text()`，数字读 balance.json，乘当前回复效果倍率；入队后台阶已封顶时不写）：「入队：队长最大生命 +15%，生命回复 +0.9 / 秒」。

- 属性面板「生命回复」：显示实际每秒回复，有入队加成时括号写出其中多少来自入队，例如「2.9 / 秒（入队 +1.8）」。

## 2. 回复卡与实际不符

### 2.1 原来差在哪里

实际每秒回复（`game._update`）= (regen + regen_pct × 最大生命) × heal_mult × 时间倍率。三处显示各算各的：

| 位置 | 原来的算法 | 漏掉的 |
|---|---|---|
| 「自愈」卡说明 | 固定文字「每秒回复生命 +0.6」 | heal_mult、时间倍率（8:00 起实际 +1.56） |
| 「自愈」卡预览 | g.regen → g.regen + 0.6 | regen_pct（藏品 #1 / #72 的 0.5% 最大生命）、heal_mult、时间倍率 |
| 属性面板 | (regen + regen_pct × 最大生命) × 时间倍率 | heal_mult |
| 「坚韧」卡预览 | 最大生命 → 最大生命 + 20 | 入队加成（×1.3）、Ⅷ 的 ×0.9：3 人编队实际 +26 |
| 「硬化」「水影」「轻盈」「感知」「护灯」预览 | 各自手算 | 与属性系统一致，但不走同一个式子 |

### 2.2 修法

- `combat.regen_per_sec(add_flat, add_pct)`：唯一的回复式子。回血逻辑、属性面板、「自愈」说明与预览、招募卡都调它。
- `StatBlock.value_with(stat, op, value)`：「再加一条修正后的最终值」，不改状态。生存 / 机动卡的预览都用它算选中后的数，和选中后属性面板显示的完全一致。
- 「自愈」说明改为按实际增量生成：「队长生命回复 +0.6 / 秒」（有 +20% 治疗量藏品时写 +0.72）。每级数值放进 `sustain/regen_card`（0.6），不改数值。
- 测试：`prot_test.gd test_squad_sustain_dash` 逐条核对：入队前后回复差 = 台阶 × heal_mult；招募卡写的数 = 实际；自愈 / 坚韧 / 硬化预览的后值 = 选中后的属性面板值。

### 3.2 冲刺

- 默认距离 **126 → 107**（−15%，`dash/dist`）。冲刺时间 0.18 秒不变（无敌时间不变），速度 = 距离 / 0.18。冷却 `dash/cd` 1.2 秒不变。
- 新卡（`doctor.gd PASSIVES`，cat mobility；三张在被动卡里的出现权重 `levelup/dash_weight` 0.7，其余被动 1，避免过多稀释原有卡）：

| 卡 | 每级 | 上限 | 满级 |
|---|---|---|---|
| 迅捷 | 冲刺冷却 −12%（×`dash/cd_card` 0.88） | 4 级 | 1.2 → 0.72 秒 |
| 远跃 | 冲刺距离 +12%（`dash/dist_card`） | 3 级 | 107 → 146（比旧默认 126 远 16%） |
| 连冲 | 冲刺可储存 2 次，冷却逐次恢复 | 1 级 | 连续冲 2 次，然后每 1.2 秒回 1 次 |

- 实现：`game.dash_cd` 改为「还欠的冷却秒数」：每冲一次 + 一次冷却，随时间减少；可储存 N 次时，欠的不超过冷却 × (N − 1) 就能冲。只有 1 次时与原来逐帧相同（测试里 `dash_cd = 0` 仍是「立刻可冲」）。`dash_ready()` / `dash_left()` / `dash_frac()` / `dash_dist()` 给界面和机器人读；`DASH_CD` / `DASH_SPEED` 常量删掉。
- 界面：队长脚下冷却环、触屏冲刺键、键鼠冲刺牌都改读 `dash_frac()`；有连冲时冷却环外侧一排小点 / 键上「×N」/ 牌上「冲刺×N」显示剩余次数。
- 依赖冲刺距离的地方：熟练机器人的冲刺落点检查原来写死 126（`bot.gd DASH_LEN`），改读 `g.dash_dist()`；指南、教程文案只写「冲刺中无敌」「冷却 1.2 秒」，不涉及距离，不用改；德克萨斯的冲刺是自己的 `dash_len`，与队长冲刺无关。
- 机器人：熟练（master）选卡分 迅捷 3.2 / 连冲 3.4 / 远跃 2.4（生存卡 2.5–4.0、协同 3.5–6.0）；高手（expert）不主动冲刺，三张各 −1.5。普通选卡权重 `bot/growth_weights` 0.4–0.6。
- 图标：`art/incoming/growth_dash_cd / dash_dist / dash_charge.png`（32×32，取 growth_speed 的配色）。

## 4. 物理减伤（硬化）对后期怪物攻击：检查（只报告，不改）

### 4.1 机制

- 硬化：每级物理减伤 +2，4 级上限 +8。队长自带 0–3（维什戴尔 1.5、斯卡蒂 2.0、塞雷娅 / 星熊 / 德克萨斯 3.0）。
- 结算（`combat.hurt`）：物理伤害 = max(1, 伤害 − 减伤)，**固定值**，每次受击减一次。只对「吃护甲」的物理伤害生效：小怪接触、近战预警招式（前刺 / 尾刃 / 扑咬）、物理子弹（enemies.json `atk` 为物理的，如凿石者）。法术（喷吐者 / 飘航者的弹、抛石、自爆、爬行者爆发）、真实伤害、冲击环（`ignore_armor`）、溟痕、侵蚀、神经损伤、黑潮都不吃。
- 敌人攻击时间曲线（`spawner.new_enemy`）：× (1 + min(t, 480) / 420) × 前期加成（0:00 ×1.3，4:00 回到 ×1）+ 后期 min((t − 420) / 900, 0.25)：0:00 ×1.30、4:00 ×1.57、8:00 ×2.21、10:00 ×2.34。难度：标准 ×1.0，Ⅷ ×1.25；精英再 ×1.3。

### 4.3 实战里占多少（本机遥测）

新增遥测 `armor_cf`（`combat._armor_cf`，只记账、不读随机数）：按 0–4 / 4–8 / 8 分钟以后三段，记受击总量（护甲 / 法抗之后、主控保护之前），其中吃护甲的物理受击在护甲前后的量，以及「再多 2 / 4 / 8 点减伤」时这些受击会是多少（逐发按 max(1, 伤害 − 减伤) 重算）。

- 物理单发随时间从 9–11 涨到 21–32（Ⅷ 后期奠基者 / 收割者 / 精英为主），固定减伤的比例跟着掉：1 级硬化在 Ⅷ 从开局的 −11% 掉到 8 分以后的 −3%。
- 吃护甲的物理只占后期受击的一半弱：法术弹、抛石、自爆、冲击环（不吃护甲）、溟痕、侵蚀、神经损伤占了另一半，而且这一半后期占比更高（受击次数里物理从 39–49% 降到 25–30%）。
- 对照同一时段的其他生存卡：
  - 自愈 1 级：+0.6 / 秒（× 回复效果倍率），是后期 1 级硬化（0.08–0.13 / 秒）的 **5–7 倍**；4 级硬化（0.32–0.50 / 秒）不到 1 级自愈。
  - 坚韧 1 级：基础 +20，满编时 +26 最大生命，按后期 2.6 / 秒的受击约等于多扛 10 秒；也让「入队 +15%」与百分比回复放大。
  - 硬化只在死前那一阵近身围攻（docs/82 §2.3：引痕者 / 收割者 / 滑动者接触为主，物理占比高）里比平均值更有用，但单发 28–50 时 +2 也只少 4–8%。
- 机器人选卡：Ⅷ 熟练 21 局合计 硬化 3 级、自愈 7 级、坚韧 11 级；标准高手 硬化 1 级。

### 4.4 结论与建议（交协调人定，本次不改）

**结论**：对不上。硬化是固定值，敌人攻击按 ×1.30 → ×2.34（Ⅷ 再 ×1.25）涨，物理单发后期是开局的 3 倍；同时吃护甲的物理只占后期受击的一半弱。1 级硬化后期只减总受击的 3–5%，4 级 12–19%，收益明显低于同类别的自愈 / 坚韧，也低于 4:00 前的自己。

可选方案（数值待定，交协调人；都可以先加旋钮在云端扫，不动其他卡）：

| 方案 | 做法 | 后期 1 级的效果（按 §4.3 估） | 代价 / 风险 |
|---|---|---|---|
| A 跟敌人攻击一起涨 | 硬化给的减伤 × 敌人攻击时间倍率 / 1.3（开局 +2，4:00 约 +2.4，8:00 约 +3.4，10:00 约 +3.6），卡面写「+2，随敌人攻击成长（8:00 约 +3.4）」 | 约 1.7 倍现值（Ⅷ 8 分后约 −0.14 / 秒） | 写法要按 docs/76 §6 给起点和增速；队长自带减伤不涨，只涨卡 |
| B 改成百分比 | 「受到的物理伤害 −8%」（乘算，4 级约 −28%） | Ⅷ、标准 8 分后都约 −0.10 / 秒，各时段一致 | 卡名「硬化」的直觉还在；和法抗（百分比）对称；对 Boss 物理招也生效，需看 Boss 战 |
| C 只提数值 | +2 → +3 或 +4 | 后期约 1.5–2 倍现值，前期小怪接触几乎全免 | 前期过强（开局物理单发 6–10，+8 就到保底 1 点），后期仍掉 |

不论哪种，硬化的上限受「吃护甲的物理只占一半」限制：即使后期物理全免，也只少约 1.2 / 秒（Ⅷ）≈ 2 级自愈。所以建议 A 或 B 把它定位成「扛近身围攻的一阵」的卡，而不是追平自愈；要追平只能连同法术一起减（例如改成「受到的伤害 −X%」），那就是另一张卡了。
