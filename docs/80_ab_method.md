# 80 平衡对照口径：置信区间 + 同种子配对（2026-10-12）

制作人 10-12 指出现行方法的三个问题：每组 56 局时胜率的 95% 区间约 ±13 个百分点，差距不到 10 点的结论不可靠；只看胜率太粗；机器人自然组队有混杂因素。本文是改进后的口径，工具是 `tools/cloud_compare.py`。docs/36 §8.2 的样本量说明仍有效，本文在其上补充。

## 1. 新口径（今后平衡结论必须遵守）

1. **结论必须带区间**。胜率写成「73%（41/56），Wilson 95% 区间 [60%, 83%]」；连续指标写中位数 + bootstrap 95% 区间。只有一个百分比的结论不收。
2. **优先配对对比**。两组用同一批 seed、同开局、同机器人、同档位（tier / 难度）跑，按局配对：报「两边都赢 / 都输 / 只 A 赢 / 只 B 赢」与 McNemar 精确检验 p 值，以及逐对差的区间。不配对的两组胜率相减只作参考。
3. **结论看三样：胜率 + 低血秒 + Boss 用时**。胜率是结果，低血秒（主控生命 <35% 的累计秒数）看「赢得险不险」，Boss 击杀用时看输出够不够；承伤、治疗量、每秒伤害作辅助。
4. **胜率差 <10 点不下结论**，除非配对检验显著（p < 0.05）。不显著时按脚本给的「要到 ±5 点约需多少对」决定加局还是放弃。
5. **10 项连续指标里只有 1 项区间不含 0，不作结论**（多重比较，偶然出 1 项是常事）；要复跑或加局确认。

## 2. 工具：tools/cloud_compare.py

```
python tools/cloud_compare.py <组A> <组B> [<组C> ...] [选项]
```

- 每个位置参数是一组；第一组是基准 A，其余每组各与 A 配对。来源可以是：cloud-results 的 tag（`ru-uncap-t0`，本地没有远程分支时自动 fetch）、`cloud:<tag>`、本地 balance_run 输出目录或单个 json。`名字=来源` 自定组名，`来源1+来源2` 合成一组。
- 配对键：开局编队 + seed + 机器人 + 难度 + tier（从 `--extra` 里的 `--tier=` 读）+ 流派。配不上的局单独报数量。
  - `--loose`：只按编队 + seed 配对（两组档位不同时）。
  - `--ignore squad`：编队不同、只按 seed 配对（每个编队单独一个 tag 时）。
  - `--split squad`：一组结果按编队拆成多组再配对（一个 tag 里跑了多个编队时）；`--base` 指定哪一组当 A。
  - `--bot expert`、`--squad wisadel,saria`：过滤。
- 每组输出：胜率 + Wilson 区间、单组胜率到 ±5 点约需多少局；用时、每秒伤害、Boss1 / Boss2 / 终局 Boss 击杀用时、低血秒、低血占比、承伤、承伤 / 分、治疗量的中位数 + bootstrap 区间 + 均值；输局死在第几分钟（超时单列）。
- 每对输出：四格表、McNemar p、胜率差的配对 bootstrap 区间、「胜负 / 用时 / 击杀 / 总伤害都相同」的对数、各连续指标逐对差的中位与均值（各带区间），最后一句结论。
- `--out x.md` 存报告，`--json x.json` 存数字。bootstrap 用固定种子，同样输入同样输出。只读结果，不跑游戏。

指标来源（都在 BALANCE 记录里，已有字段，不需要改游戏）：

| 指标 | 字段 | 说明 |
|---|---|---|
| 胜率 / 用时 | `data.win`、`data.t` | `--maxt` 截断的输局算「超时」，不进死亡时间分布 |
| 每秒伤害 | `sum(data.out) / data.t` | 全队按来源合计 |
| Boss 用时 | `data.bot.bosses[].t1 − t0` | 按出场时间分段（<5:00 Boss1、<9:00 Boss2、其后终局）；终局 Boss 胜利局按「出现 → 通关」计，同 balance_run；同段两个 Boss 只取第一个；配对时只用两边都击杀的对。终局 Boss 种类由结局决定，配对的两局可能不是同一种 |
| 低血秒 | `data.bot.low_hp_s` | 主控生命 <35% 的累计秒数（run/telemetry.gd），机器人和局终统计共用这个阈值，所以没有另加 30% 的字段 |
| 承伤 | `data.bot.taken`（缺时用 `sum(data.dmg)`） | 主控承伤总量 |
| 治疗量 | `sum(data.heal)` | 按来源合计 |

## 3. 固定编队对照的推荐写法

自然招募时队友由局内随机决定，比较「换一个干员」会混进队友差异。测单个干员或单项改动时：

```
# 固定两名队友，只换第三位；每个变体一个 tag，同一批 seed
python tools/balance_run.py --squad wisadel,skalter,lumen    --seeds 28 --bot expert --extra "--maxt=1000 --tier=0" --tag md-lumen
python tools/balance_run.py --squad wisadel,skalter,kaltsit  --seeds 28 --bot expert --extra "--maxt=1000 --tier=0" --tag md-kaltsit
python tools/cloud_compare.py 流明=md-lumen 凯尔希=md-kaltsit --ignore squad
# 若一个 tag 里跑了全部变体：
python tools/cloud_compare.py md-t0 --split squad --base wisadel,skalter,lumen
```

- 同一改动的前后对比：两边同开局、同 seed、同档位，最好同一台云端机器（docs/36 §7.5）。
- 改动只在少数局生效时（例如藏品上限 15），大部分对会完全相同，配对能直接看出「改动影响了几局、往哪边」；改动从开局就改变随机流时（例如开局给藏品），同 seed 两局很快分叉，配对的收益变小，仍要靠加局。

## 4. 示范（2026-10-12，现有云端结果，高手机器人，starts 7 开局 × 8 seed = 56 局）

| 对比 | 配对 | 都赢 / 都输 / 只 A / 只 B | 胜率 A → B（配对差区间） | McNemar p | 结论 |
|---|---|---|---|---|---|
| 藏品上限 15 → 不限，tier 0（ru-cap15-t0 → ru-uncap-t0） | 56，结果相同 35 对 | 39 / 14 / 2 / 1 | 73.2% → 71.4%，−1.8 [−8.9, +3.6] | 1.0 | 不显著；承伤均值差 −37 [−74, −7]，治疗量 −37，属小幅、单项不作结论 |
| 藏品上限 15 → 不限，tier 2（ru-cap15-t2 → ru-uncap-t2） | 56，结果相同 52 对 | 36 / 20 / 0 / 0 | 64.3% → 64.3%，0 | 1.0 | 胜负逐对一致，所有连续指标区间含 0：取消上限对胜负没有可测影响 |
| 流派基线 → 开局给 263（ls-base-t0 → ls-l1-t0） | 56，结果相同 0 对 | 33 / 8 / 8 / 7 | 73.2% → 71.4%，−1.8 [−16.1, +10.7] | 1.0 | 不显著；到 ±5 点约需 412 对；终局 Boss 用时均值差 −16 秒 [−31, −1] 是 10 项里唯一一项，不作结论 |

读法：

- 取消藏品上限：两档都是「绝大多数局完全相同，剩下的几局正负抵消」。这比「73% 对 71%」两个裸胜率有说服力得多。
- 开局给 263：同 seed 的两局从开局就分叉，不一致对 15 个（两组若完全独立，预期约 22 个），配对仍有些作用但不大，胜率差区间半宽 ±13 点，和不配对差不多。这类改动要么加到几百局，要么改看更灵敏的连续指标（Boss 用时、低血秒）。
- 高手机器人的低血秒中位数几乎都是 0（大多数局从没掉到 35% 以下），看低血秒时以均值和低血占比为准；改看熟练 / 普通机器人时这项更有区分度。
