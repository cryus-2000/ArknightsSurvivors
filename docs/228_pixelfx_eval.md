# 228 pixelfx 特效库评估（11-02）

用户 11-02 给了 [patch-gg/pixelfx](https://github.com/patch-gg/pixelfx)（MIT，244 个程序化像素特效）。本文回答两个问题：哪些特效值得用它替换或补充，以及两条接入路线各花多少。**只做了评估，没有改游戏代码。**

## 0 结论先看

**性价比前 3：**

1. **敌人眩晕星环**（status/stunned）。现在眩晕只是染色，没有专属特效。接入后约 8 KB，全体眩晕敌人共用一张表。
2. **稀有拾取闪光**（pickups/collect-burst）。现在拾取的那一刻没有任何特效。约 6 KB，只用在回复 / 磁铁 / 藏品上。
3. **技能 / 电系命中**（lightning/zap-hit）。现在用的是 16² × 4 帧的小帧条。约 8 KB，只用在技能和暴击命中上。

**路线：A（导出精灵表进 Godot）。** B（把 draw() 移植成 GDScript）只值得借鉴手法，不值得整体移植（理由见 §4）。

**不推荐：**
- 状态类里贴身的灼烧、冻结、中毒：标准小人的轮廓被烤进了表里，见 §3.2。
- 升级、转场、击杀 poof：太大、太长或太卡通。
- 终结技：主视觉不动。用户定的冲击帧（整屏白 + 黑剪影）是保留项。

前 3 名合计包体约 22 KB（64 色量化），无损约 160 KB。网页包现在 44.6 MiB，预算 44.5 MiB，几乎没余量，所以**要么先量化，要么在别处腾出同等体积再合入**。

安装前已审读 SKILL.md、README、package.json 和 tools/*.mjs，结论如下：
- 工具只用 Node 内置模块；不装任何依赖，没跑 npm install。
- 唯一的外部调用是 `spawnSync("ffmpeg")`，用来出 GIF / MP4 预览，可选。
- serve.mjs 只在本机 8080 端口起图库服务，本次没有运行。
- 没有网络请求，也没有删文件的操作。

技能在会话里叫 `pixelfx`，最常用的几条命令（在 build/pixelfx 下运行）：

```bash
node tools/list.mjs stun                      # 按关键词查特效
node tools/render.mjs status/stunned          # 接触表 records/<id>/contact.png
node tools/render.mjs status/stunned --sheet --fps 15 --opts '{"palette":["#04101f","#0a2540","#10446b","#1a6f9a","#2ea3c4","#6fd6e0","#c4f6f2","#ffffff"]}' --out ../pixelfx_out/sea
node tools/check.mjs status/stunned           # 越界、首尾接缝、随机数是否带种子、慢帧
```

--sheet 会输出透明 PNG 和 Aseprite 格式的 JSON，`meta.pixelfx` 里带 fps、pivot、帧尺寸和列数。导入 Godot 时要用最近邻过滤，并且关闭压缩。

**本作用法上的三条约定（本次实测得出）：**

- **密度按 @2x 算。** 干员和敌人都是 @2x，即 1 贴图像素 = 1 世界像素。pixelfx 的标准小人高 38 px，我们的敌人约 64 世界像素，所以 pixelfx 帧按 1:1 世界像素画，就和 @2x 精灵同密度、同尺度。如果按 `Game.PX` = 2 放大，会比怪物还大一圈（见 01 号对比图的初版）。
- **深海配色直接用 `palette` 重着色。** 上面那条 8 阶青色梯度就是本次用的。原色是暖色的命中特效（hit-spark、crit-hit）可以保留原色，因为暖色火花本来就是物理命中的口径。
- **帧率降到 15。** 它默认 30 fps；降到 15 后包体约减半，像素风的节奏感也没损失。命中类我们自己的帧条是 20–24 fps，所以命中类可以导 20 fps。

## 3 候选实测

导出参数：15 fps，深海重着色（hit-spark、crit-hit、burning、poof 保留原色）。各列说明：

- **裁边**：所有帧取并集包围盒后的尺寸。
- **无损 / 64 色**：裁边重排后、Pillow optimize 存出的 PNG 大小。
- **显存**：按 RGBA8 无 mipmap 计。
- **JS 每帧**：V8 下一个实例 update + draw 的耗时，60 步取平均。

### 3.1 观感

- **重着色有效。** 青色梯度下的电弧、星环和拾取环都融进了深海配色（见对比图 01–03）。
- **按 @2x 密度画时，像素密度和我们的怪一致。**
- **比我们的现有特效大、长。** 命中类 0.5–0.9 s，我们的帧条是 0.2 s；尺寸是 110–160 px，我们约 32 px。同屏实例数和过绘制都会是现在的 3–7 倍，所以只能给低频事件用。
- **拾取环是同心圈。** 力量感口径否掉的是「规整放射 / 同心圈」，但那是对冲击类特效说的，拾取闪光不在那条口径里。如果要更稳妥，可以只留中心闪光和散星，去掉内环。
- **眩晕星环带两只小鸟，偏卡通。** 鸟的颜色可以通过 `birds` 选项压暗；要彻底去掉得改一行代码，改在 build/ 里的副本上，不动它的源。
- **level-up 内置英文文字 "LEVEL UP!"。** 违反 docs/76，必须传 `text: ""` 才能用。即便去掉文字，它也比现有的光柱大一个量级，不换。

### 3.2 贴身状态特效不能直接用

burning、frozen、poisoned 这类特效会读 `o.actor`（它的 24×38 标准小人）的遮罩来染色、描霜和冒火。导出的「裸」表里留着这个小人的轮廓（白闪的剪影、褐色的身体，见 build/pixelfx_out/fps15/status/burning/burning.png）。我们有几十种怪，每种都要导一份表才对得上，不现实。

这类特效只能**借鉴手法**：现有的 `seg_*` 火舌和颗粒可以参考它的「四个热点轮流燃起、每 0.6 s 一次白闪」的节奏。stunned 的星环只挂在头顶、不碰身体，所以可以直接用。

## 4 两条路线

| | A：导出精灵表进 Godot | B：把 draw() 移植成 GDScript |
|---|---|---|
| 做法 | 用 render --sheet 导表，登记进 `art.gd` 的 V6_FRAMES，用现有的 `fx_sprite` / `spr_rot` 播放 | 把它的双缓冲（color + light）、4×4 Bayer 抖动和粒子模拟搬进 GDScript |
| 每实例 CPU | 每帧 1 次贴图绘制，和现在的帧条一样，会被合批 | V8 下已经要 48–3563 µs；GDScript 逐像素写缓冲还要慢 10–50 倍，**一个命中实例可能就要 0.5–2 ms**，后期几十个同屏实例会直接掉帧 |
| 包体 | 每个 2–10 KB（64 色）或 12–75 KB（无损） | 0 |
| 显存 | 每个 0.17–1.2 MB；推荐的 4 个合计约 2.6 MB | 每实例一张动态纹理，还要每帧上传 |
| 灵活性 | 颜色和朝向在导出时定死；朝向可以靠旋转绘制补 | 运行时可变色、可跟踪移动目标 |
| 工作量 | 每个特效半小时左右：导出、裁边、量化、登记、挂调用点 | 每个特效要整体重写，并且要改写成 draw_rect / 合批的形式 |

**取 A。**

B 只在两种情况下值得：
- 单实例的全屏转场。这时应该写成着色器，而不是 GDScript。
- 借它的手法改我们自己的程序特效。例如 hit-spark 那种偏心十字闪、长射线沿打击方向的做法，可以加进 `_tier_fx`。

另外，用 A 也必须做三件事：裁边（能省 20–50% 面积）、量化（我们的帧条本来就是少色的）、降到 15 / 20 fps。不做这三步，包体会是表中的 2–10 倍。

## 6 如果开工

1. 前 3 名用路线 A：15 / 20 fps、深海重着色、裁边、量化到 64 色以内，以 `@2x` 名登记进 `art/fx`，挂到对应调用点：
   - 眩晕：`world.gd:3070` 旁，挂在敌人头顶。
   - 拾取：`_pq_item` 被吸走时。
   - 技能命中：`hit_fx` 的技能分支。
2. 包体需要先腾出约 25 KB，交给负责网页包体的会话处理。（更正：`art/fx/_optical` 运行时在用，不能删，见 docs/229 §7。）
3. 本机只截图核对；同屏帧时走云端跑一局后期对照（docs/41 §云端）。

### 7.2 做法（以后铺开照这个走）

1. **写源码。** 放在 `tools/pixelfx_fx/<类>/<名>.js`，进 git，名字以 `ak-` 开头。按 pixelfx 的 AUTHORING 规范写（对象由 `create(o)` 返回、用带种子的随机数、结束时画面为空），在 build/pixelfx 下用 render.mjs / check.mjs 看效果，至少改三轮。
2. **导出。** 跑 `python tools/pixelfx_export.py [--only 名字]`。它会拷源码进库、导精灵表、以原点为中心对称裁边（枪口用 keep_canvas 保留原画布）、去掉末尾空帧、量化到 64 色、拼成单行帧条写进 game/art/fx，最后打印 art.gd 要登记的 `[帧数, fps]`。
3. **登记接入。**
   - 在 art.gd 的 V6_FRAMES 里登记，再跑 `python tools/asset_index.py`。
   - 跑 `godot --headless --import`，并把新 .import 里的 `fix_alpha_border` 改成 false，和兄弟文件一致。
   - 在干员 JSON 里换贴图名。
4. **尺度换算。**
   - 刀光（blade）：缩放 = r × k ÷ fit，单位是每个 1x 像素占几个世界像素。帧以斯卡蒂为中心（along 0），帧里刀弧半径 74 px，所以 fit = 74、k = 1，刀弧正好落在伤害半径上。另外 tint 要给白色，否则会被缺省色染蓝。
   - 直线斩：缩放 = 半长 ÷ fit。帧里斩线长 110 px，所以 fit = 55。
   - 贴图名**不要以 `fx_slash` / `fx_claw` 开头**，否则会被 blade_scale 再缩一遍。
5. **出对照。** 用 `tools/op_fx_audit_rec.py --tag px_before / px_after` 录同种子原速 30 帧，用 ffmpeg 把前后两段左右并排（hstack）。
