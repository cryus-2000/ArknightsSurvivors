用户 11-06：「普通难度略微调高」。基线 main 98a738904，分支 `claude/diff-normal-up`。口径：memory difficulty / balance-method —— 无认知（无局外成长，m0）目标 45–55%，18 细胞（m18）目标 65–75%；只动不给奖励的旋钮；≥ 3 份安慰剂实现取均值；单组差 < 10 点不下结论；数值自调授权（11-03 起：验证后再汇报）。

## 0. 结论

1. 现状（98a738904，普通难度 = `--tier=0 --tide=0`，即 `difficulty/standard`）：**m0 54–55%（窗口上沿），m18 74–77%（窗口上沿以外，偏简单）**，两档都在容易的一侧。
2. 旋钮：`difficulty/standard/enemy_hp`（海面档普通怪生命倍率，Boss 生命、伤害、经验 / 灯油 / 源石锭都不动）**1.08 → 1.14**。这是 11-03 难度回调（docs/216 §10）调过的同一个旋钮，不给奖励。
3. 预期效果：**m18 从约 76% 降到约 70%（窗口中段），m0 从约 54.5% 降到约 53%（仍在窗口，变化在噪声内）**。
4. 注意：这个旋钮对 m0 几乎不起作用（见 §3），要让 m0 也明显更难只能再动别的旋钮（伤害曲线之类），那会同时把 m18 推出窗口，所以本次不动。

## 1. 方法

- 机器人 expert，`--preset starts`（7 个开局编队 × 8 个种子 × 3 份安慰剂实现 = **每格 168 局**），GCP 批跑（`tools/gcp/batch.py`，`c2d-highcpu-16/32` 抢占式，结果分支 `cloud-results/diff-*`），不用缓存。
- m0 = `--tier=0 --tide=0`；m18 = `--tier=0 --tide=0 --meta=18`。
- 候选值通过 `--bal=difficulty/standard/enemy_hp=<值>` 在不改数据的提交上测，最终值与测试值相同。
- 胜率含超时（满血 Boss 未打完）按失败算。

## 3. 为什么选 1.14，不选更大的

| 候选 | m0 | m18 | 判断 |
|---|---:|---:|---|
| 1.12 | 57.7（噪声偏高） | 71.4 | 动得太少，m0 反而高出窗口 |
| **1.14** | **53.0** | **70.2** | m18 落在窗口中段，m0 仍在窗口，「略微」符合 |
| 1.16 | 52.4 | 67.9 | 可用，但 m18 离窗口下沿（65）只剩 3 点，低于单组噪声，有掉出窗口的风险 |
| 1.24 | 45.2 | 55.4 | m18 明显出窗口，过难 |

- 用户要的是「略微」：m18 −5 点左右，m0 保持窗口内；1.14 满足。
- 这个旋钮对 m0 作用小，原因（推断）：m0 的失败主要是 4–7 分钟被中期 Boss / 追踪者打死（基线失败构成里 `boss_carmen`、`contact_tracer`、`atk_tracer`、`corrode` 占大头），小怪生命 +6% 对这些死因几乎无影响；而 m18 队伍成型后输出过剩，敌人生命对冲正对口。
- 要让 m0 也再难 ~5 点：只能动伤害类旋钮（`dmg_curve/scale`、`enemy/dmg_x_*`），docs/201 已测过两档几乎同幅移动，m18 会掉出窗口（< 65），所以**本次不动**；如果用户更在意 m0（无局外成长的新玩家体感），请告诉我，我再做一轮「伤害 −2% + 生命 1.10」之类的组合测试。

## 4. 影响范围

- 只有 `balance.json` 的 `difficulty/standard/enemy_hp` 一个数。
- 修正表里海面档是潮位 0–3 的锚点（docs/216 §10 记过）：潮位 1–2 也跟着 ×1.14；潮位 3 起的 `TIDE_SET` 写绝对值，不变，所以**潮位 2 → 3 的小怪生命台阶从 +11% 缩到 +5%**（原 +20% → +11%）。高潮位没有重新校准，也不在本轮范围；高压 / 深潮不受影响。
- 不给奖励：经验、灯油、源石锭、藏品掉落都不变；Boss 生命、全部伤害值不变。
- 开关：`--bal=difficulty/standard/enemy_hp=1.08` 回到旧值。
