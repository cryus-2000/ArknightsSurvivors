「普通怪保持 1x」和实际不符。清点 `art/incoming` 发现：普通怪和精英的本体帧条**已经全部有 @2x**（97 条 `e_*@2x`），战斗里画的就是 @2x。只是这些 @2x 有 33–63% 的 2×2 块是纯色——相当于半放大、半细化，不是 docs/97 那种原生细节。所以真正要回答的不是「Boss 要不要追上小怪」，而是：**原生细节 @2x 的 Boss，和半放大 @2x 的小怪（还被 `enemy/scale=1.5` 整体放大）同屏，落差会不会比干员试验 2 里看到的更明显**（§5.4①）。

### 5.4 与现有 1x / @2x 怪物混放的风险点

① **同屏像素密度至少四档**：Boss / 干员是 1 美术像素=1 屏幕像素，普通怪 / 精英（半放大 @2x，又被 `enemy/scale=1.5` 整体放大）是 1.5（吐酸者 1.76），伊莎玛拉人形 / 骑士 Boss 是 0.68 / 0.70（画布本身被压缩，见②），剩下 1x 的 4 个 Boss 是 2.0。Boss 改原生细节后，旁边小怪会显得更粗糙，落差比干员试验 2 更明显。**这件事需要用户先定调**：按 docs/97 试验 2 的办法截一张 Boss + 小怪 + 干员的同屏真实倍率图给用户看，再决定要不要连小怪也排原生细节、还是把 Boss 做到小怪那种密度。

② **伊莎玛拉人形（0.68）、骑士（0.70）这两个 Boss 现在是被压缩着画的**：最近邻取样又没有多级纹理，约 30% 的行列会被丢掉，原生细节画了也看不见，移动时还会闪烁。**建议这两个暂不排原生细节**，除非先把画布按实际显示尺寸重做（×0.7 母稿）让 `draw_scale` 回到 1。

③ **同一 Boss 不同动作混密度会让战斗中切招时画面跳**：塑路者现在就是 `e_path`（1x）切到 `e_path_charge`（@2x）；接潮三体的本体 / `_move` / `_feign` 共 9 条要是分批交，也会出现同一只 Boss 一半原生细节一半不是。**交付必须整组**：本体、`_move`、`_attack`、`_feign`，以及按需加载的招式帧条（`spin` / `gaze` / `howl` / `sing` / `share` / `lob` / `slam`）一起交，不能拆单。

④ **轮廓光粗细会跟着密度变**：描边是运行时用白剪影往外扩 1 个贴图像素做的（`world.gd:3063-3086`），@2x 的 Boss 描边只有 1 屏幕像素宽，1x 的有 2 像素——塑路者从 `e_path` 切到 `e_path_charge` 时光圈会从 2px 变 1px。接入新 @2x 时这是个要改的代码点（`_outline_tex` 按 `A.hires_of` 折算外扩量），纯画面改动，和这次「只写预案」分开处理。

⑤ **`px_lint.py`（docs/97 配套的新验收工具）直接拿来查敌人会大面积误报**：它按单帧、带边距的干员画布设计——敌人的整条帧条会被当成一张图，帧数就是「连通体数」，直接判失败；脚底行、边距也是按单张图算的，普通怪本来就贴着画布最底行。要给敌人用，得先加「按帧切分」模式。现有 Boss @2x 的单点高光（新纪律要求 0）实测每条 40–278 个，远超干员标准，说明现版 Boss @2x 本来就不是按这套纪律画的——这也印证了 5.0 的结论：Boss 现在的 @2x 和新的「原生细节」不是一回事。

⑥ **文档口径目前互相冲突**：`docs/103` §5 第 3 款同一条里既写「@2x 只是 1x 的放大或同密度细化」，又写原生细节纪律；`docs/95` §13.1 写的是「重画细节、与 1x 逐帧剪影一致」；`docs/87` §1 的剪影差 ≤0.10 对敌人也适用；色数干员 ≤27、Boss ≤32 不统一。真要给 Codex 派单，先在 `docs/95` §13.1 或 `docs/87` §0 补一条敌人专用的原生细节条款，否则交付稿引用哪条都说得通，容易被退回。
