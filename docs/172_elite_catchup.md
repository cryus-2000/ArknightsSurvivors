# 172 精英化落后补偿（10-27）

> 用户 10-27 定：只做「落后补偿」（重新分配，不白送进度），不做「入队起点」。
> 代码：`game/scripts/run/progression.gd`（`catchup_on / catchup_weight / catchup_order / catchup_focus`）；旋钮 `balance.json` `levelup/catchup*`；回归 `build_progression_test.gd` `test_catchup`。

## 1. 规则

- **进度口径**：干员已应用的成长节点数 `prog`（0–6；全员成长线都是 节点 节点 精一 节点 节点 精二，所以每 3 个节点 = 1 个精英阶段）。
- **加权**：每次升级，把本次合法的干员深度卡按权重排序（取法同 `weighted_order`，用 `g.rng`）：权重 = `catchup_mult ^ (落后阶段)`，落后阶段 = （本次有卡的干员里最高 prog − 自己的 prog）÷ 3，封顶 `catchup_cap`。深度卡张数、第二张深度卡概率、招募 / 被动 / 填充都不变——只改「哪名干员排在前面」。
- **培养保底**（docs/119 §4.2）：最近培养对象比本次有卡的最落后队友领先 ≥ `catchup_focus_gap` 个节点时，保底位让给最落后的队友；否则照旧给最近培养对象。不多取随机数。
- **旋钮**（缺省值）：`catchup` 1（0 = 旧发牌：均匀洗牌 + 保底只看最近培养对象，随机数消耗同改前）、`catchup_mult` 1.8、`catchup_cap` 3.0、`catchup_focus_gap` 3。
- 新增遥测：记录里 `prog_log` = [秒, 干员, 推进后 prog]，可画全队累计培养曲线。

## 2. 基线与前后对比（本地 6 对同 seed，高手机器人 master、`--nodeath`，开局 维什戴尔 / 斯卡蒂 / 塞雷娅 × seed 1–2）

| 档 | 队长 精一 / 精二 | 队友 精一 / 精二 | 队友比队长晚（精一 / 精二） |
|---|---|---|---|
| 旧（catchup=0） | 0:52 / 2:08 | 4:24 / 6:11 | 3:31 / 4:04 |
| **新（缺省 1.8 / 封顶 3 / 保底差 3）** | 0:52 / **4:28** | 4:20 / 6:16 | 3:27 / **1:48** |
| 温和（1.5 / 封顶 2 / 保底差 6） | 0:52 / 2:12 | 4:22 / 6:22 | 3:29 / 4:10 |

全队累计培养张数（按分钟，旧 → 新）：1′ 2.8→2.8，2′ 5.2→4.5，3′ 7.5→7.3，4′ 10.3→10.0，5′ 13.0→12.8，6′ 15.2→15.0，7′ 17.0→17.2，8′ 起 18→18。整队成型节奏基本不变（2′ 处少 0.7 张，之后差 ≤ 0.3）。

招募时刻：两名队友约 1:10 / 1:50 入队。新档改变了随机数消耗，招到的队友与旧档不同（同 seed TRACE 变化属预期），单局对比只看整体。

## 3. 结论（要协调人 / 用户知道的）

1. **队友的绝对时刻几乎无法靠重新分配提前**：旧档里队长 2:08 就已精二，此后全部培养卡本来就只给队友；队友慢的根源是入队晚（1–2 分钟）+ 全队培养卡产出速率（约 2.5–3 张 / 分钟，两名队友分着用，每人 12 个节点要 4–5 分钟）。只重新分配、不加总量时，唯一能动的是**队友入队后的那段时间（约 1:10–2:10）队长少拿几张**。
2. 缺省档因此达到「队友精二比队长晚 1–2 分钟以内」（1:48），代价是**队长精二从 2:08 推迟到 4:28**；精一不变（队友入队前只有队长能拿卡，Lv.2–4 也只养开局干员）。队长仍然最快。队长精二在 4:28 时队友平均已在精一附近（4:20），画面上不再是「队长精二、队友精零」。
3. 温和档（只在差 2 阶段时才改保底）几乎等于旧行为——队友入队时队长领先不到 6 个节点。
4. 风险：队长中段战力推迟约 2 分钟，可能影响 2–5 分钟的难度；要云端胜率对照确认。如用户不接受推迟队长，就说明「重新分配」到不了目标，需要回到「入队起点」或提高队友入队后的培养卡产出（加总量），这两条都是用户 10-27 否掉的方向。
