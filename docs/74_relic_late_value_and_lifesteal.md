# 74 · 藏品后期价值审计 + 吸血藏品设计（2026-10-12）

起因（用户 10-12）：

1. 「像是罗德岛展示电台这种到了后期就没有用了，看看有哪些跟这个一样完全没用的」
2. 「是不是可以增加攻击敌人回血的藏品？你觉得可以吗」

本轮**只做审计和设计，不改玩法**。依据：main `c261669b` 的 `game/data/relic_effects.json` / `relics.json`、`relic_fx.gd`、`run/progression.gd`、`run/shop.gd`、`characters/squad.gd`、`data/balance.json`，以及云端结果分支 `origin/cloud-results/*` 里 10-11 / 10-12 两天的 53 个 BALANCE 结果文件，共 **2828 局**（标准·高手 1148、Ⅳ·熟练 336、Ⅷ·熟练 1344；中位存活 677 秒，胜率 59%）。本机没有跑新局。

> 用户说的「罗德岛展示电台」就是 **#189 罗德岛战术电台**（藏品里没有「展示电台」）。

**结论先说：**

1. **#189 罗德岛战术电台是真白板，而且不只是后期**：它只在「强制招募」那一屏生效，而编队中位约 2 分钟就满了。153 次拿取里 **151 次拿的时候编队已经满员（99%）**，拿了等于空占一个藏品位。它也没有像其他招募类藏品那样「满员就不出」，整局都会出现（806 次出现，其中 78 次是在 6 分钟后才拿的）。
2. **后期完全没用（A 类）还有两组**：
   - 只给源石锭的一次性藏品（14 件）和 #188 锈蚀的铁锤（商品半价）：最后一位商人 8:00 来，之后源石锭只剩 #207 / #208 投币玩具能用。8:00 后它们仍出现约 1000 次，被拿了约 220 次。而且源石锭本来就用不完，满 9 分钟的局结束时中位还剩 **163 枚**。
   - 一次性回血的 #191 阿卡胡拉饭碗：拿的时候主控几乎总是满血，记到的实际回复中位是 0。
3. **强衰减（B 类）**：升级触发的 #122 / #123（后期升级从每分钟约 3 次降到 0.7 次，加成覆盖时间从约 50% 降到约 12%）、Boss 奖励源石锭的 #14 / #251（10:00 那个 Boss 给的锭没处花）、#192、编队第 4 位的 #1（中位 9:33 才拿，新人从精零起步），以及 10-11 刚改过、需要继续观察的 #247 / #248。
4. **吸血我认为可以做，但必须有上限**。主控按「最大生命的百分比」设每秒上限，不按「伤害的百分比」设。全队伤害整局平均约 **1365 / 秒**，用户举例的「伤害的 0.5%」相当于每分钟回 410 点，是主控每分钟受到伤害（中位 105）的 4 倍，会把受伤这件事抹平。推荐的数值是**全队伤害的 0.05%，每秒最多回 0.5% 最大生命，生命低于 50% 时上限翻倍**：名义上每分钟约 52 点（低血时 105），实际有效量估计在凯尔希（65 / 分）的一半以下（§5）。

另外有一个放大问题严重性的系统事实：**藏品栏上限 15 件**（`relic/carry_cap`）。2828 局里有 926 局（33%）会拿满，拿满的中位时间是 10:08。所以白板藏品不只是「没用」，它会永久占掉一个位置。（10-12 起上限已取消，见 §10。）

## 1. 方法与口径

- **样本**：`cloud-results/*` 中提交日期为 10-11、10-12 的结果文件（`sk5-*`、`b3i-*`、`fsm*`、`sk4-*`、`rs-*`、`sks-*`、`rl-*` 等）。用到的字段有 `relic_offer`（[时刻, choice/shop, 候选]）、`relic_take`（[时刻, id, 当时编队职业列表]，列表长度就是当时编队人数）、`heal`（按来源记**实际回复量**，溢出不计）、`dmg`（按来源记主控受到的伤害）、`lv_times`、`ingots`、`kills`、`out_type`、`win`、`t`。脚本放在会话临时目录，没有入库。
- **选择偏差**：活得越久，拿的藏品越多，所以几乎每件藏品都是「拿了的局胜率 > 基线 59%」。同稀有度横向比更有意义：拿取 ≥ 30 次的藏品，「拿了的局」胜率中位是基础 67%、稀有 71%、核心 74%。取率是机器人按评分选卡的结果，只能当旁证。
- **漏记**：主控自带的每秒回复（`regen`，各主控 1.0–2.0 / 秒）、博士被动「自愈」和 `regen_pct` 类藏品（#1 / #72）**不进 `heal` 记录**（`game.gd` 第 1255 行直接加生命）。所以下文的「记录到的回复」偏低，§5 的校准需要先补这一项遥测。
- 10-11 的部分批次可能早于 docs/65 的改动，口径有轻微混杂，不影响本文的结论。

## 3. 逐件分类

先说 #189 罗德岛战术电台到底做了什么：

- 实装：`rule recruit_extra`，只在 `progression.open_levelup()` 的**强制招募**分支里用到（`recruit.slice(0, want + rule("recruit_extra"))`）。普通升级里的招募卡固定只有 1 张，不受它影响。
- 强制招募只在两个条件下出现：Lv.5 时编队只有主控一人，或 Lv.9 时编队不满 3 人。实测编队约 2 分钟就满，所以一局最多只有开头那一屏可能用上。
- 它的效果类型是 `rule`，不是 `trigger event: Recruited`，所以 `relic_fx.can_offer()` 里「编队满了就不出招募类藏品」那条判断管不到它，满员后照样出现。
- 数据：出现 806 次（三选一 670、商店 136），拿取 153 次，**其中 151 次拿的时候编队已经 3 人**，6 分钟后拿取 78 次。拿了的局胜率 61%，基础件的中位是 67%。
- 所以它不是「后期没用」，而是**整局几乎都没用**。

### 3.3 C 类：没问题的（抽查结论）

- **随时间成长的伤害**（#95 / #96 / #153 / #168 / #174 / #210 / #211 / #232 / #234）都乘了 `enemy_hp_time_mult()`，与敌人生命同步，不衰减。
- **封顶型**（#252 刻勋之手：约 300 次击杀就到 +30%，开局约 1 分钟；#172 / #180–#183 按编队人数，满员后封顶）：封顶后是常驻值，等于一件早到的属性件，不算衰减。
- **招募触发类**（#10 / #86 / #87 / #147 / #151 / #155 / #184–#187 / #244）：编队满员后 `can_offer` 已经不让它们出现（拿取记录里几乎都是 2 人时拿的），不会成为后期白板。价值窗口只有前 2–3 分钟，本来就很少被拿。
- **一次性灯火**（#30–#32 / #205）：反过来，前 6 分钟灯火是满的，会溢出；后期才有用。docs/65 已经去掉了后期降权，后期没问题。
- **典训**（#33–#40）：没有可推进的干员时不出现，或者改给一次成长三选一，不会成为白板。
- **#214 支援急救包**：只用藏品回复做近似，60% 的局一次都没用上（机器人很少残血）。它是保险，不是衰减，不改。
- **#207 / #208 投币玩具**：后期锭越攒越多，越来越强，正好是源石锭的出口。
- 其余属性型（伤害、攻速、减伤、生命、技力等）都是常驻值，没有衰减。

## 5. 吸血藏品设计

### 5.1 制作人判断：可以做，有界限

同意用户方向，并在协调人的「要有上限」基础上补三条：

1. **上限按最大生命的百分比计，比例（伤害的百分之几）只决定多快到上限**。全队伤害整局平均 1365 / 秒（p25 941、p75 1803），前期低、后期高，不同编队之间差好几倍。只按「伤害的 x%」算，要么前期没感觉，要么后期抹平受伤。对照：伤害的 0.5% 不设上限，每分钟回约 410 点，是受到伤害中位的 4 倍；就算设「每秒 1% 最大生命」，名义上每分钟也有 105 点，约等于受到的全部伤害，比凯尔希还强。所以上限必须更低。
2. **名义上限不超过一名奶位实际回复量（约 60 / 分）**，实际有效量要明显低于奶位。主控大部分时间是满血，持续回复会大量溢出，奶位干员靠「定时大口回复」在尖峰后补血，吸血不该抢这个位置。所以给吸血的特色是「**残血时上限翻倍**」：满血时几乎没用，被打残、还在输出时回得最快，正好落在尖峰之后的窗口里。
3. **后期价值天然上升**：比例吸血前期伤害低、回得少，后期伤害高、能顶到上限。这正好补上第 1 部分说的「后期没用」问题，适合作为守护·续航（H 流派）的后期件。

### 5.4 风险

- **与奶位重叠**：L1 的名义上限（52 / 分）低于凯尔希、塞雷娅、流明、水月的实际回复（56–65 / 分），有效量约一半。需要盯的是「没奶编队拿 L1 后的胜率」不要超过「有奶编队不拿」的胜率。
- **与 #72 演出用香水（稀有，每秒 0.5% 最大生命）**：L1 正常上限和它一样，但前期弱、后期强，残血时翻倍。二者叠加名义上限是每秒 1.0–1.5%，仍低于 #116 遥乡（区域内每秒 3%）。可以接受。
- **循环**：#102（溢出治疗转伤害）+ L1 会形成回路，必须排除 #102 的伤害（见 5.2）。藏品自身伤害本来就不进 `on_hit`。
- **实现缺口**：`rfx.on_hit(e, h)` 现在不带伤害数值，L1 需要从 `combat.damage` 把护盾之后的伤害传进去（一处调用）。L2 用已有的 `on_kill`。都只加数据驱动的 `do: lifesteal / killheal`，数值放在 `relic_effects.json` 的 args 里，代码里不写死。
- **机器人选卡**：`bot.gd` 的高手评分要给这三件加分（守护·续航，残血时更高），否则取率数据没有参考价值。

## §10 取消藏品上限（10-12）

用户 10-12：「藏品的上限删除掉，我们的爆率相当于设置了软上限。肉鸽游戏设置上限本来就不合理」。

- **规则**：`relic/carry_cap` 缺省改为 **-1 = 不限**（`progression.relic_cap()`）。不限时 `can_gain_relic` 只拒绝「已拥有且满级」，三选一、商人、补给箱、事件、祭坛、大教堂拼图等所有入口都不会因为件数被挡。结局信物预留槽（`endings.reserved_relic_slots`）只在旋钮 ≥ 0 时参与。设回 15 即恢复旧规则（含预留槽），只供对照测试（`--bal=relic/carry_cap=15`）。游戏里没有「满了替换 / 丢弃」的界面，原来满了只是不再出新藏品，这条路径随之失效。
- **候选池**：已实装可出现的藏品 200 多件，60 件时池里仍有 150 件以上，三选一不会退化（`economy_regression` 新增断言：40 件时仍有新藏品候选、商人能成交）。
- **按件数缩放的藏品**：只有 `per_relic` 规则会随件数增长。#253 / #254 按遭诅古物计、本来就有 4 件封顶；**#256 断杖-学识、#257 断杖-智慧之光**按全部藏品计、原来没有封顶（旧上限下最多 15 件 = 伤害 +30% / +45%）。现在加 `cap: 20`：最多伤害 +40%、+60% / 攻击速度 +40%，说明补「（最多 +40%）」「（最多计 20 件）」。其余随件数变化的只有流派加权（`lane_weight_cap 2.0` 已封顶）和投币玩具（按源石锭，已封顶）。
- **界面**：HUD 藏品栏写「藏品 N」，不再写「N / 15」。≤ 16 件 38 像素格；17 件起紧凑 22 像素格、一行 14 个、**最多 3 行**；超过 42 件只画最近获得的 41 件，第一格写「+N」，悬停提示「藏品栏只显示最近获得的 41 件。按 Tab 查看全部」。栏高封顶 126 像素，结局走向字跟着栏底走（原来按 8 个一行算，紧凑格时偏低）。Tab 面板（桌面 / 手机第五页）格子再加一档 22 / 30 像素，仍放不下时第一格写「+N」。作战记录中栏藏品格：原来压到 30 像素格；仍放不下时只画放得下的行，方向键选中项自动滚进视野、滚轮在藏品格上滚藏品，标题右侧写「第 a–b 行 / 共 c 行」。商人界面写「藏品 N · 商人还会停留 …」。
- **遥测**：BALANCE 的 `relics`（结束时件数）不变，可直接比较取消前后的件数分布。
