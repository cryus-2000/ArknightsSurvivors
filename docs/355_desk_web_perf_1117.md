## 1. 量法

- `tools/perf_web.py run --desk 1920x1080 --dpr <1|1.5>`（本次新加）：独立 Edge、屏幕外窗口，DevTools 设电脑视口和像素比（不触屏、不改 UA）；requestAnimationFrame 换 MessageChannel（量真实帧耗时，面板不可见也照跑）。
  场景 seed 13 浊心斯卡蒂 + 德克萨斯 + 能天使、高手机器人、中画质：
  - 帧时：`--balance --nodeath --bot=expert --realtime --perf --perfmin`，开局 0–70 秒、`--rtfrom=300` 5 分、`--rtfrom=540 --maxt=690` 后期 9–10 分 + 最终 Boss（10:00 起，`m10F` 段）。**不带 `--memlog / --ftrec`**：这两项每 30 秒扫一遍 WASM 堆、长帧逐帧打印，网页上会把整局拖到 6–15 帧（第一轮基线因此作废）。
  - 内存：`--rtfrom=9999 --maxt=640 --memlog --ftrec`（全程快进，约 3 倍速），读 `PF MEM / PF MEMJS / PF WASMTOUCH / PF MEMTEX / PF WEBMUSIC`。
  - 每 15 秒 `PF JSHEAP`（本次新加，不强制 GC）：JS 堆、WASM 容量、引擎网页样本、出包配乐解码缓冲、画布尺寸、显卡名；`PF MEM wall` 加 `rmax`（单个最大的渲染进程 = 游戏标签页）。
- `--cpuprof A:D`（本次新加）：快进结束 A 秒后 DevTools CPU 采样 D 秒，按函数合计自耗时。
- 网址 `glcount=1`（`PERFWEB_QS` 环境变量传）：每 5 秒打每帧 WebGL 调用数（建顶点数组、换着色器、绑贴图…）。
- 导出副本加了导入缓存（`build/_perfweb/_importcache`），第二次起导出从十几分钟降到几分钟。
- 显卡：本机 Edge 用的是 RTX 4060 Laptop（ANGLE）。本机负载波动大，帧时只比同时段、多轮取中位。

## 2. 大头在哪（对照手机网页与桌面原生）

### 2.1 帧时：电脑网页卡在 GDScript

- CPU 采样（后期 5:00，dpr 1）：**wasm 占 89%**，其中单个函数（GDScript 解释器主循环）独占 32%；WebGL 胶水（建 / 删顶点数组、上传顶点）合计约 5%；JS 桥、垃圾回收都在 1% 以下。
- 分辨率：dpr 1.5 下同局轮换「全分辨率 2880×1620 / 视口模式 1280×720」（`--stackab=30:0,128`）只差约 3 ms（46 对 43）；整套光学后期逐层轮换关掉也在噪声内。**电脑网页不是填充率瓶颈**，封画布像素比省内存不省帧。
- `--prof` 分块（放大约 2 倍，只看比例）：世界绘制占一半多，其中干员光环 / 地面层（`dw_shadows`，浊心斯卡蒂领域等）与排序实体（敌人本体）最大；HUD 约 3 ms。都是内容相关的 GDScript，前几轮（docs/50 §14、§37，docs/319 §22）已经抠过，本轮没找到能确定省下的通用项。
- 每帧 WebGL：约 210 次新建顶点数组（draw_circle / draw_polygon 每次都新建缓冲）、540 次换着色器、1200 次绑贴图。是引擎层的，脚本侧要逐处合批，收益分散。

### 2.2 内存：电脑网页比手机多出的三块

| 块 | 电脑网页（旧） | 手机网页 | 原因 |
|---|---|---|---|
| 字形缓存 | 进局预热约 150 个字号：显存约 130 MB + WASM 同量（堆 286→344→412→495） | 不预热（`mobile_font_slim`） | 大群横幅 10-22b 起固定 38 / 28 号，预热却还按旧写法画 38–68 共 31 档、每档约 25 个大号汉字 + 描边 |
| 配乐 | 48 kHz 双声道 float，一首 200 秒约 73 MB；战斗三层 + 商店同驻 150–220 MB，换曲旧曲还要挂 3 秒（峰值 323） | 24 kHz 单声道、只放底层 | 电脑网页没开「换曲即放」「静音层按需」 |
| dpr 1.5 的画布 | 渲染目标 ×2.25：显存 +100、WASM +70～+100 | 手机 Toy 已封 2 倍 | 系统缩放 150% 的笔记本很常见 |

## 3. 改了什么（每项有退回开关；只改不影响画面 / 声音的）

| 项 | 做法 | 净差（同条件） | 平台 | 退回 |
|---|---|---|---|---|
| 字形预热删过时字号 | `hud._warm_glyphs`：大群横幅只预热实际用的 38（描边 6）/ 28（描边 5）两档；升级字样按绘制处同一公式（× `float_text_k`）预热（原来大半预热的字号用不上、用的又没预热） | 1080p：显存 −80～−120、WASM 容量 495→344；dpr 1.5：WASM 594→412 | 全平台（桌面原生也省） | — |
| 配乐换曲即放 | `sfx._fast_swap_on` 改用 `Cfg.web_lean`：电脑网页也立刻放旧曲 | 配乐缓冲峰值 323→188 | 网页 | `--bal=web/desk_music_swap=0` |
| 静音层按需解码 | `sfx._wm_lazy_layer` 同上：战斗加层听得见才解码开播 | 开局 146→110 MB | 网页 | `--bal=web/desk_music_lazy_layer=0` |
| 光学压阶版原图不留 | `optical._fxq_drop` 同上 | 几 MB（只对 1 倍帧条生效） | 网页 | `--bal=web/desk_fxq_drop=0` |
| 压阶版尺寸不符时放掉 | `_fxq_step`：@2x 原图对 1 倍压阶版（浊心斯卡蒂 wave_big 等）不用，也不留在贴图缓存 | 约 −7 MB（浊心斯卡蒂） | 全平台 | — |
| 近战肉声文件存在性缓存 | `melee_impact._flesh`：每次命中都 `ResourceLoader.exists`（网页上是 JS 侧 MEMFS 路径查找，CPU 采样里能看到）→ 每名干员查一次 | 噪声内 | 全平台 | — |
| 字形瘦身拆四项 | `Cfg.font_slim_part(subpx / clear / nowarm / qs)`；手机四项照旧跟 `mobile_font_slim`，电脑网页按 `web/desk_font_<项>`，缺省全关 | 实测：subpx、clear 在电脑网页省不到；nowarm 再省约 50 MB 显存 / 58 MB WASM 但会带回开局字号首次出现的卡顿；qs 改弹出动画 | 网页 | 测试 `--fontpart=…` |
| 电脑网页画布像素比上限 | `web/desk_max_dpr`（缺省 0 = 不封），设了下次启动生效（同手机 `mobile_max_dpr` 路径） | dpr 1.5 封 1：显存约 −100、WASM 约 −70；帧时约 −3 ms | 电脑网页 | 缺省关 |

### 4.3 「旧版有负载时成倍变慢」没查实的部分

- 05:36–07:05 本机还有其他会话的 Godot 在跑，这段时间旧版后期 7 轮里 6 轮 P50 80–86 ms，同段新版 4 轮都是 38–40；07:15 之后机器安静，旧版 5 轮都是 36–39。
- 排除过：字形（旧版加 `--fontslim` 不预热，仍 80）；配乐 / 压阶版开关（新版逐个退回，4 轮都 38–39）；显存吃紧（另开页占到 7.0 / 8.2 GB 显存，旧 / 新 42 / 40 ms）。
- 所以不把它算作本轮的帧率收益，只说明新版在有负载的那段时间没出现这档变慢。

### 4.4 手机仿真（iPhone 844×390 @3，`--mobilecap`）

内存（快进到 10:30）：WASM 344 / 344、显存 178 / 185、音频 30 / 30 MB；后期帧时 P50 52.3 / 51.8、最终 Boss 42.9 / 45.1（各 2 轮，本身双峰 35 / 69）。不变。

## 5. 待定（要用户 / 协调人定）

1. **电脑网页封画布像素比**（`web/desk_max_dpr = 1`）：系统缩放 150% 的笔记本显存 −100、WASM −70，帧时几乎不变；浏览器把画布放大 1.5 倍，字和像素边略软。开关已做、缺省关。
2. **电脑网页配乐降规格**：现在一首战斗曲三层 48 kHz 双声道约 150–190 MB。改 32 kHz 解码约 −1/3，改单声道约 −1/2；会动音质，没做。
3. **电脑网页字形不预热 / 弹出字号按 4 号取整**（`web/desk_font_nowarm`、`desk_font_qs`）：再省约 50 MB 显存 + 58 MB WASM；代价是字号首次出现时可能卡一帧、弹出动画变成 4 号一档。开关已做、缺省关。
4. **帧率的大头是 GDScript 解释器**（wasm 89%）。Godot 官方网页模板用 `-Os` 编译；自编 `-O3` 模板通常能快一截，但要装 emsdk（10-15 用户定过「网页工具链先不装」）、wasm 约 +5 MB，而 Toy 包现在 49.74 / 50 MB，放不下。要做得先腾包体。
5. 标签页进程快进段一路涨、实时段平稳（§4.1）的来源没拆到，可能是浏览器分配器的高水位。
