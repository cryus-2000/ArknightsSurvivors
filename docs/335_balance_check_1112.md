### 1.4 叠层上限与软上限

- 藏品升级：纯属性藏品可拿到 3 级，二 / 三级按 LV_SCALE **1 / 0.7 / 0.5** 递减（合计 2.2 倍），卡面写「本级 70% / 50%」——这是 P3 的软上限思路；**但第 3 级之后不再出现，是一个按数量的硬上限**，和「不设数量硬上限、用爆率做软限制」的口径不一致（`relic_fx.max_lv` 固定 3；`relic/carry_cap -1`、`shop/relic_buy_limit -1` 这两项已按口径放开）。
- 效果本身的封顶（不是数量封顶）：#252 击杀永久增伤 +30%、#207 / #208 源石锭攻速 +20 / 30%、#253 遭诅古物减伤 −32%、#260 护盾减伤 −40%、#180 编队减伤 −12%、熔铸 +20%、#263 吸血每秒 0.5%、浊心斯卡蒂歌域 ×1.8；这些是「单件效果的上限」，跟数量无关，按 P3 属于防止乘区失控，保留。
- 升级卡：每张有 `max` 次数（1–5），每类最多 4 种（机动 3 种）。这是 Vampire Survivors 式的「槽位」设计，属于构筑约束，不算违反口径。
- 运行时乘区封顶：Boss 单次受伤 4%、主控单发 40% / 2 秒 68% / 全来源 2 秒 70%（超出 ×0.6）——都已在 calc_truth 里验证生效。

死亡分段（0–3:30 / 3:30–7 / 7–10 / 10:00 后）：常规无认知 3 / 22 / 16 / 11，高压无认知 11 / **83** / 17 / 9，深潮无认知 31 / **114** / 14 / 2。

读法（对照 P4）：
- **常规 → 高压一步掉 40 点（无认知 69 → 29）**，18 细胞也掉 35 点。Brotato 的危险等级是每级只加一条规则、逐级继承；本作界面上只有三档，相邻两档之间跨了潮位 1–5 共 5 级规则，单步落差太大。高压的死亡又集中回 3:30–7（69%），11-11 第一轮只在常规档压了这一段。
- **说明与实际不一致（相对常规）**：高压卡面写「敌人生命与伤害 +20%」，但常规档自己已经有 `difficulty/standard/enemy_hp` 1.14（11-03 / 11-06 两次上调），高压的 1.2 是绝对值、不叠在 1.14 上，所以**相对常规，高压的敌人生命只 +5%**、伤害 +20%；深潮「生命 +62%」相对常规是 +42%。卡面数字按「相对基础值」算没有算错，但玩家会按「相对常规」读。真正让高压难的是伤害 +20% × 队长生命 −10%（等效承伤 ×1.33）、大群 +20%、5:00 起小怪控制与寒霜 2 层冻结、灯油 −40%——这些卡面也写了。
- **认知的收益形状两头偏**：18 细胞只比无认知高 5 点（69 → 74），满点却把常规和高压都推到 ≈100%。目标是「满点常规 85–90、高压 70–80」，现在满点比目标高 10–30 点。推荐点法前 18 细胞是 护盾 +1 与 伤害 +8%，满点多了 生命 +30%、受伤 −13%、闪避 15%、每秒回复 +1.0、处决、锁血 1 次、复活 1 次（meta_tree.json）。对照 Hades：镜子点满后 0 热度确实会变简单，靠惩罚契约（热度）接住；本作的「热度」就是高压 / 深潮，所以满点后的目标应看深潮那一格——**而满点深潮也有 92.9%**（目标 55–65），三档在满点后都被碾平，没有留给老玩家的难度。
- **常规无认知 69% 比窗口上沿高 14 点**（11-11 第一轮之后 64–68%，这一轮 69%，方向稳定）。但 18 细胞已在窗口上沿（74.4%），用同一个旋钮整体收紧 14 点会把 18 细胞压到约 60%，跌出窗口——两档的差（目标约 20 点，实际 5 点）只能靠认知前段更值钱来拉开，这是设计取舍，不是单个数值。

## 2. 计算正确性

### 2.1 说明数字 ↔ 实际生效值（静态，逐条读代码）

## 3. 改动口径与本轮为什么不改数

- 用户授权数值自调（docs/80 同种子配对 + 多指标 + 云端）。本轮找到的偏离按性质分三类，**都不适合今晚直接改**：
  - **#1–#3 是同一个问题的三面**（认知树的收益形状 + 档位跨度）。只动一个难度旋钮会顾此失彼：整体收紧 14 点让无认知进窗口，18 细胞就跌到约 60%；只收紧高压 / 深潮，满点仍是 100%。要改的是认知树前后段的分配（meta v3 是用户 10-22 亲自确认的），属于设计取舍，先给方案。
  - **#5、#6 是机制**（换池渐入、去掉 3 级硬顶改爆率递减），按任务要求只出方案。
  - **#4、#7 是纯数值**，可以自调，但 #4 在 11-11 被用户叫停过一次（当时把「鸭爵」误解成中期 Boss），再动前应让用户明确一次；#7 只影响拿到那件的局，同种子配对要几百局才看得出，收益太小，排在后面。
- 所以本轮的改动只有「说明文字」和「测试」，数值文件（balance.json / enemies.json / waves.json / relic_effects.json / meta_tree.json）一个字没动。
