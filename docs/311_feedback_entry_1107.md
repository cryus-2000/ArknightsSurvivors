# 311 玩家反馈入口（11-07）

用户 11-07 批（协调人派）：结算页和标题页各一个「意见反馈」入口，itch / 桌面去问卷，B站 Toy 上请玩家在评论区留言，同时给一串可复制的反馈码。

## 1. 入口

名称统一叫「意见反馈」（11-07 用户：「反馈改成意见反馈」）。

| 位置 | 样子 | 反馈码内容 |
|---|---|---|
| 结算底栏（作战报告样式 `settle_base.footer`；旧样式在「分享」左边） | 按钮「意见反馈」，宽 120 | 版本 / 提交号 + 本局摘要 |
| 标题页底部一行（`title_jelly_menu` 菜单项 id 9，排成 设置 · 操作说明 · 意见反馈 · 退出） | 同底部其他项的文字入口 | 只有版本 / 提交号 |

起初在设置「操作」页最后一行，11-07 用户改到标题页底部，设置里不再列。点入口不走转场，直接打开浮层 `screens/feedback_view.gd`，同时把反馈码复制进剪贴板。浮层里有：

- 标题「意见反馈」和反馈码；
- 复制结果；
- 一句说明「只含版本号与本局的干员、难度、结果和用时，不含任何个人信息」；
- 三个按钮：主按钮「打开问卷」、「关闭」、「再复制一次」。
- **B站 Toy**（11-07 用户改）：不跳视频、不跳站外。浮层在反馈码下面写「请在评论区留言，并附上这串反馈码」，只有「再复制一次」和「关闭」两个键（「关闭」是主按钮，Enter / Esc 都是关闭）。

键位：Esc 关闭，Enter 前往，C 复制。触屏上不写键名。

## 2. 去向与配置

`balance.json` 的 `feedback` 段只有 `form_url` 一项，**缺省留空**，留空时 itch / 桌面不显示入口，不放坏链接。Toy 不用配置，总是显示入口。

| 平台 | 判断 | 目标 | 调用 |
|---|---|---|---|
| itch / 桌面 / itch 网页 | 页面里没有 `window.toy` | `feedback/form_url`（必须以 http(s):// 开头） | `OS.shell_open`（网页上就是 `window.open`） |
| B站 Toy | `window.toy.navigate` 存在（Toy 包一律加载 SDK） | 无（评论区留言） | 不跳转，只复制反馈码 |

- **Toy 不跳站外**（docs/99 外链条）。在 Toy 里即使配了 `form_url` 也不会用它。
- **问卷跳转只在玩家点按里发出**（浏览器弹窗要用户手势）。所以浮层先打开、复制好反馈码，玩家再点一次主按钮才离开游戏。
- 11-07 之前 Toy 走 `toy.navigate` 去作者视频评论区（配置 `toy_bv`），这一项已删。
- **网页剪贴板**：先用 `navigator.clipboard.writeText`。1 秒内没成功，就在 DOM 里盖一个只读输入框，让玩家长按或全选后复制。

用户给出问卷链接后，只改 `balance.json` 的 `form_url` 即可。

## 3. 反馈码

格式是 `AS-` 加 Crockford base32 字符，每 4 位一个横线，末位是校验字。标题页码大约 10 个字符，一局四人的码大约 25 个字符。

只包含下面这些字段，不含任何个人信息。反馈码由玩家主动复制，游戏不上传；对外包不写本地记录的规矩不变。

位表（v1，高位在前），与 `core/feedback.gd` 和 `tools/feedback_decode.py` 两处一致：

| 字段 | 位数 | 说明 |
|---|---|---|
| fmt | 3 | = 1 |
| kind | 1 | 0 = 只有版本，1 = 带本局 |
| 版本 主 / 次 / 修 | 4 / 7 / 6 | `build.json` version |
| 有提交号 + 提交号 | 1 + 28 | 前 7 位十六进制；源码运行为 dev（0） |
| 队长 | 6 | `OPS` 下标；0 = 无，63 = 表外干员 |
| 队友数 + 队友 | 3 + 6×n | 按入队顺序 |
| 难度（潮位） | 5 | |
| 结果 | 2 | 0 倒下 / 1 胜利 / 2 中途退出 / 3 其他 |
| Boss 演练 | 1 | |
| 倒下时刻 | 12 | 局内秒数，封顶 4095；没有倒下为 0 |
| 局时 | 13 | 真实秒数（开局到结算出现，含暂停与选卡），封顶 8191 |
| 倒下原因类型 | 4 | `CAUSES` 下标：普通 / 精英 / Boss / 稀有敌人、黑潮、溟痕、寂灭、藏品代价、敌方弹幕、侵蚀、侵蚀创口、神经损伤、其他。**只记类型，不记是哪个敌人** |

`OPS` 和 `CAUSES` 两张表**只许往后追加**。新干员不登记也不会出错，只是解码时显示「表外干员」。

解码：

```
python tools/feedback_decode.py AS-6800-1DKG-X4M1-EC72-9G5
```

- 大小写、横线、O/I/L 误写都能识别。
- 加 `--json` 输出 JSON。
- 校验字不对时返回 1。

## 4. 测试

- **回归**：`check.py --only feedback_code`，脚本 `tests/feedback_code_test`。检查的项：
  - 缺省时不显示入口；
  - 字符都在字母表里，带校验位；
  - 同一摘要得到同一个码，改一项就变；
  - 长度足够短；
  - 打印 `FBCODE` 行，供解码对照。
- **调试参数**（只在调试版读）：
  - `--fburl=<链接>`：覆盖配置；
  - `--fbtoy`：按 Toy 环境走；
  - `--fbopen`：结算入场演完、或标题页截图（`--titleshot`）时，直接盖上反馈浮层（截图用）。
- **截图**：`UIA_EXTRA='--fburl=… [--fbopen]' tools/probes/ui_audit_shots.py <目录> win,fail,title（结算截图加 `--resultwait=4`，等底栏升起）`。
