## 4. 待定（有损或要动代码 / 引第三方，需拍板）

| 项 | 能省 | 影响 / 风险 |
|---|---:|---|
| A. 分片改 Brotli（wasm 9.59 → 6.58，pck 31.66 → 30.95） | **约 3.7 MiB** | 完全无损。浏览器的 DecompressionStream 不普遍支持 brotli，要在加载器里内嵌纯 JS 解码器（google/brotli decode.js，MIT，约 20 KB gzip）；手机解压 wasm 估计多 1–3 秒，解码按分片做，峰值内存不变（输出缓冲本来就整块）。要改 loader.js + 回退路径 + 手机实测 |
| B. 贴图关掉 fix_alpha_border（只改全透明像素的 RGB） | **约 1.9 MiB** | 屏幕上不可见（全透明像素），但线性过滤 / 读透明像素颜色的地方会出黑边。贴图大多最近邻；需要同种子截图对照 + 查 art.gd 法线生成、fx_grains / optical_particles 取色是否只看 alpha |
| C. 配乐 / 语音 C 档（22.05 kHz / 质量 1.0；语音 22.05 kHz / 0.9） | 2.2 MiB | 有损：高频再少一点（截止约 15 kHz → 11 kHz 以内），叠层量化噪声增加；要出试听 mp4 |
| D. 音效降到 22.05 kHz（导入 max_rate） | 约 1.0 MiB（估） | 有损：打击 / 金属类音效高频发闷；内存同比减半（音效常驻） |
| E. 自编精简引擎模板（关 3D / 物理 / 导航等模块） | 约 3–4 MiB（估，wasm gzip 9.6 → 6 左右） | 要装 emscripten 编 Godot 4.7.2 Web 模板，之后每次升级都要重编；还会减 wasm 内存。工作量最大 |
| F. 脚本改未压缩令牌 + 外层压缩 | < 0.3 MiB（估） | 收益小，不建议 |

不建议：降贴图分辨率 / 有损 WebP（降画面）；语音按需下载（Toy 50 MB 按总量算，docs/121 §5）；敌人 @2x 存 1 倍图再放大（实测只省约 0.4 MiB，还要改 art.gd 读图路径）。

推荐顺序：A（无损、最大）→ B（做截图对照后）→ 需要时再 C / D。A + B 合计约 5.6 MiB，网页包可到约 35 MiB。
