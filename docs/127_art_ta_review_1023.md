## 2. 问题清单

严重度分三级：**A = 阻碍可读**；**B = 风格割裂**；**C = 整洁**。「谁做」中的「程序」指 Claude 程序侧调整，「Codex」指美术重画或补画。

### A · 阻碍可读（6）

**A1 普通怪整体太暗，剪影溶进深海地面。**
- 证据：E01、E02、E05。怪物明度中位 0.27，最低 0.13（骑士 0.16、伊比利亚等圣徒 0.13–0.20），深海地面约 0.07。外沿暗边率中位 0.74：描边本身是深色，压在深色地面上等于没有描边。E02 里卷须、刃脚这类细肢体，在游戏内只剩几个亮点。
- 改法：程序侧给普通怪和精英加一圈 1 像素冷色边光（现有 Look 边光是否覆盖怪物待程序侧核实），并把怪物受光封顶从 1.12 抬到约 1.25。不改帧条，约 0.5–1 天。如果还不够，再请 Codex 把骑士、圣徒这类深色怪的中间调整体提亮一档。
- 谁做：程序（先）+ Codex（视情况）。

**A2 战斗文字堆在队长身上（黑潮 / 回复 / 伤害数字 / 弱点 / 倒计时）。**
- 证据：E09。队长 ±120 px 内同时有：「身处黑潮！返回安全区」「+41 生命」「-5 溟痕」「0.4 秒后开始掉血」、4 个伤害数字、「架起·法术弱点」和一个大金色方向箭头，队长本体完全看不见。
- 改法（程序）：
  - 状态类提示（黑潮、掉血倒计时）挪到屏幕上方固定的提示行；
  - 回复与扣血数字往队长头顶外侧错开，同时最多 3 个；
  - 弱点文字只在命中的那只怪身上出现；
  - 方向箭头放在屏边，不放在角色旁边。
  约 1 天。
- 谁做：程序。

**A3 命中特效和伤害数字盖住 Boss 本体。**
- 证据：E07。Boss 圣徒卡门的脸被「243」和一团约 4–6 px 一格的白色碎块挡住，下半身又被青色大块盖住（见 A4）。
- 改法（程序）：对 Boss 的伤害数字统一放到头顶外圈；同一目标 0.2 秒内的数字合并；Boss 身上的命中特效透明度 ×0.6、像素格统一为 2 px。约 0.5 天。
- 谁做：程序。

**A4 青色大块（4–6 px 一格的地形 / 特效）压在角色和 Boss 上。**
- 证据：E07 中部、E08 左下。像素格是干员的 4–6 倍，比 Boss 还亮，读起来像一块「主体」。从截图判断不了是地形障碍还是技能残留（推进之王在 E07 的编队里），请地形会话与特效会话各自确认来源。
- 改法：如果是地形，按 2 px 格重画，明度降到地面以上一档即可，并且画在角色层下面；如果是特效，同 B6 的像素格规则。
- 谁做：先确认来源；之后 Codex 重画，或程序调层级。

**A5 Boss 预警线（白色粗描边）把队长盖住。**
- 证据：E07。白色双线斜穿队长，队长的剪影被切断。
- 改法（程序）：预警线经过队长半径 40 px 内时局部降透明度，或者把预警画到角色层下方（只留填充色，轮廓不压人）。约 0.5 天。
- 谁做：程序。

**A6 中期 Boss 体量偏小，压迫感不足。**
- 证据：E03 Boss 那张、E08。圣徒伊比利亚、卡门、接潮主教、蔑死体、斥亡体屏幕高 110 px，只有干员的 1.4 倍；E08 里卡门站在干员堆旁边，像一名精英。对比 E10 最终 Boss 伊莎玛拉（转化后）体量很足，读得很清楚。
- 改法：给 Boss 定一个体量下限，屏幕体高 ≥ 干员 1.8 倍（≈140 px）。中期 Boss 按 128 / 160 画布重出 @2x（Codex，每个 Boss 约 0.5 天）；在此之前程序侧可以先改 draw_scale ×1.25 试，代价是非整数缩放（B2）。
- 谁做：Codex 重画；程序临时调。

### B · 风格割裂（8）

**B1 两套像素密度并存。**
- 证据：E04、E05。干员由 Spine 渲染缩到 64 @2x，2×2 块同色率 0.02–0.17，单帧 79–163 色，本质上是高清缩略图。怪物是 1x 像素画放大 2 倍，同色率 1.00，单帧 4–23 色。同屏时干员像「高清小人」，怪物像「粗像素」，E07 放大后最明显。
- 改法：二选一，需要用户定。
  1. **统一到「1 美术像素 = 2 屏幕像素」**：在工具链里给干员 Spine 渲染加一步，先 2×2 降采样，再量化到 ≤ 32 色，然后重描 1 px `#080E18` 外描边，再放大回 @2x。程序工具约 2 天，加上 Codex 逐人验收（瞳色、标志色按 §4.3 保留）。
  2. **接受双密度**：把规格改成「干员高清、怪物像素」，同时让怪物的描边与明度向干员靠（A1）。
- 我的判断：选 1。docs/87 的像素风是本作定位，干员这种高清缩略图在 1280×720 下细节会糊成噪点（E04 能天使、星熊的盾面）。
- 谁做：程序（工具）+ Codex（验收）。

**B2 非整数缩放。**
- 证据：E03 黄字。喷吐者 1.17、塑路者 1.15、伊祖米克 1.12、偏执泡影 1.15、伊莎玛拉 0.68、骑士 0.70 / 0.98、水月 0.9。最近邻采样遇到非整数倍，像素宽度会不等，移动时出现像素抖动；伊莎玛拉缩到 0.68 后，细节像素直接被丢掉。
- 改法：draw_scale 全部回到 1。需要的体量交给 Codex 用对应画布重出：伊莎玛拉一阶段、骑士、水月回 64 主规格（docs/108 §5 已登记）。在此之前程序侧可以对这几只改用整数倍 + 画布裁切。Codex 共约 3–4 天。
- 谁做：Codex；程序配合改 json。

**B3 描边规格没有落地。**
- 证据：E05。规格要求外沿像素 100% 是 `#080E18`，实测干员只有 0.37–0.81，怪物 0.00–0.98。另外，伊祖米克子代 0.10、伊莎玛拉之泪 0.00 属于发光体，按设计可以豁免，但规格里没有写明。
- 改法：并进 B1 的工具链统一重描。规格补一条「发光体豁免名单」。
- 谁做：程序（工具）。

**B4 色数规格与现行流程脱节。**
- 证据：E05。干员单帧 79–163 色，而规格是 ≤ 24 / 28，art_lint 只报 WARN。
- 改法：随 B1 量化到 ≤ 32 色，并把 docs/87 §1 的色数条款改成「量化后 ≤ 32，设定色另列」；否则这条规格形同虚设。
- 谁做：程序 + 改文档。

**B5 没有统一的受光方向。**
- 证据：E05。干员左右差 −0.13~+0.14（来自各自原作立绘，方向随人）；怪物里一部分上亮下暗很明显（钵海收割者、囊海爬行者、狂奔者 +0.27~+0.38），另一部分没有方向。
- 改法：不重画。程序侧统一一个从左上来的环境光：Look 里所有角色叠一层很淡的从上到下的明度渐变，加上 A1 的边光，用来掩盖各自原画的差异。约 0.5 天。
- 谁做：程序。

**B6 特效语言不统一。**
- 证据：E11、§6。特效铺满全色相；像素格有 1 / 2 / 4 px 三种（§6.1 量化），看起来像柔光的那些（神圣光柱、日冕、铃兰九尾）其实是硬边 alpha 加色彩渐变，柔光感是运行时加法叠出来的。
  命中特效有十几种，大小、像素格各不相同（hit、hit_shell、hit_spirit、hit_flesh、exusiai_hit*、lumen_beam_hit、knight_impact、corrode_hit……）。
- 改法：定一套「命中三级模板」：普攻小（16 px）/ 技能中（32 px）/ 重击大（48 px），像素格统一 2 px，颜色按干员主色。Codex 先画 3 级 × 白模；程序侧把现有命中映射过去，干员个性只留在技能特效上。柔光类特效统一走加法层，并加上过曝上限（同屏加法叠加 ≤ 1.3）。
- 谁做：Codex（模板）+ 程序（映射与上限）。

**B7 动画帧数两套。**
- 证据：E06。干员待机 8 帧、攻击 8–12 帧、跑步 8 帧 13.3 fps；怪物待机 2 帧、移动 / 攻击各 4 帧。普通怪帧少可以接受（数量多），但 Boss 也只有 2 帧待机：伊比利亚、卡门两帧完全相同（接缝比 0.00，等于静止）；塑路者、偏执泡影没有攻击帧条，出手完全靠程序姿态。和 8 帧的干员同屏时，Boss 显得「僵」。
- 改法：Boss 补待机 4–6 帧、攻击 4–6 帧（含明确的前摇帧）。Codex 每个 Boss 约 0.5 天。
- 谁做：Codex。

**B8 Boss 与原作气质的对照还没做。**
- 证据：E03 Boss 那张。圣徒伊比利亚和卡门的剪影、配色几乎一样（同一套灰黑色加大礼帽），本次没有和 PRTS 立绘做 §4.3 要求的四列对照。
- 改法：按 docs/87 §4.3 给 10 个 Boss 补四列对照图（立绘 / 小人 / 现版 / 改后），先核两位圣徒的差异化（标志色、武器、帽饰）。
- 谁做：Codex（对照图）+ 协调人核。

### C · 整洁（3）

**C1 循环接缝与脚底跳动。**
- 证据：E06。
  - 待机接缝比偏高（>1.3 表示首尾跳帧）：水月 1.78、归溟幽灵鲨 1.51、星熊 1.34。
  - 攻击帧脚底跳动：水月 24 px、浊心斯卡蒂 23 px、拉普兰德 13 px、德克萨斯 12 px、斯卡蒂 10 px。其中一部分是设计好的跳斩，需要逐个确认是不是滑步。
  - 水月待机横向漂移 35 px，来自 36 帧 96 画布，是特例。
- 改法：Codex 逐条核；不是设计意图的，修首尾帧或在 json 的 `foot` 里补偿。
- 谁做：Codex。

**C2 HUD 左上的状态标签重复。**
- 证据：E07 的原图 `E10_boss_t225.png`。左侧「涌潮悲歌」显示了两行。
- 改法：程序去重。约 0.1 天。
- 谁做：程序。

**C3 白闪是纯白剪影，Boss 的白闪面积过大。**
- 证据：E01 第三行。全身白闪对普通怪清楚；但对 110–177 px 的 Boss，每次命中整块变白，和 A3 叠在一起刺眼。
- 改法：程序侧把 Boss 的白闪改成 50% 混合，或者只闪描边。约 0.3 天。
- 谁做：程序。

## 3. 分维度小结

| 维度 | 结论 |
|---|---|
| 像素密度与缩放 | 两套密度（B1），7 处非整数缩放（B2）；没有半透明 / 糊边（✔） |
| 剪影与可读性 | 怪物与背景：差（A1）；怪物之间：大小差异够，深色怪之间难分；干员与怪：干员更亮，能分清，但被文字和特效盖住（A2 / A3 / A5） |
| 调色板 | 干员色数远超规格（B4）；怪物色数合规，但明度分布整体偏暗（A1） |
| 受光与法线 | 没有统一光源（B5）；干员受光封顶 ×1.12 的观感预设合适 |
| 动画 | 干员 8 帧、节奏清楚；怪物 2 / 4 帧，Boss 偏僵（B7）；有少量接缝 / 跳动（C1） |
| 特效语言 | 三套画法 + 十几种命中（B6）；加法叠加没有上限（E09 黑潮里中心过曝） |
| HUD 与角色冲突 | 严重（A2），Boss 战次之（A3 / A5） |
| Boss 体量 | 中期 Boss 不足（A6）；最终 Boss 伊莎玛拉转化后合格 |
| 原作气质 | 干员来自 Spine 渲染，色调与立绘一致度高（优点）；Boss 待补四列对照（B8） |

## 4. 先做 5 项

1. **战斗文字与提示让出队长**（A2，程序约 1 天）：状态提示挪到顶部提示行、数字限量并外移、箭头放到屏边。收益最大，不动资源。
2. **怪物可读性**（A1 + B5，程序约 1 天）：普通怪 / 精英加 1 px 冷色边光，抬受光封顶，统一一个左上环境光渐变。
3. **Boss 战遮挡**（A3 + A5 + C3，程序约 1 天）：Boss 伤害数字放到头顶外圈并合并、命中特效降透明度、白闪改 50%、预警线不压队长。
4. **定像素密度方向**（B1 / B3 / B4）：请用户在「统一 2 px 格（我推荐）」和「接受双密度」之间选一个；选统一的话，先做工具链加 3 名干员试点（约 2 天），过了再铺开 20 人。
5. **Boss 体量与整数缩放**（A6 + B2 + B7）：定「Boss ≥ 干员 1.8 倍、只用整数倍」，Codex 先重出圣徒两位和伊莎玛拉一阶段（含 4–6 帧待机与带前摇的攻击帧），其余 Boss 排后。

## 5. 计数

### 6.4 问题（特效专项，编号接 §2 的三级）

**A 阻碍可读（3）**

**FX-A1 大面积技能与集体白闪盖住战场。**
- 证据：F1 中水月、维什戴尔、艾雅法拉；E09 中心。一次技能命中十几只怪时，每只都整只变白，叠上技能本体（白 / 红大面积），队长和怪都看不清。
- 改法（程序）：
  - 同一帧内被同一技能命中的怪，白闪改成「只闪描边」或 40% 混合，超过 6 只后其余不闪；
  - 技能本体在队长半径 60 px 内透明度 ×0.6；
  - 加法层整屏亮度封顶：同屏近白像素超过 15% 时按比例压。
  约 1 天。
- 谁做：程序。

**FX-A2 伤害数字成团重叠。**
- 证据：F1 中安洁莉娜、艾雅法拉、维什戴尔。相邻数字重叠成一串长数字（「74148」「47088」），既读不出数值，也挡住命中。
- 改法（程序）：同一目标 0.25 秒内的数字合并成一个；同屏同时最多 12 个；新数字避让已有的包围盒（上下错开）。和 §2 A2 / A3 一起做。约 0.5 天。
- 谁做：程序。

**FX-A3 我方技能用了敌方危险色。**
- 证据：F1 中凯尔希（Mon3tr 红）、维什戴尔（深红）、浊心斯卡蒂（红环）。敌方预警是洋红 / 红（world.gd `ENEMY_TELL`），我方大面积红色技能和它混在一起，玩家分不清哪一块是要躲的。
- 改法：定色彩规则——**红 / 洋红只给敌方**；我方技能主色按干员设定色，但红色系干员把饱和度降一档，并加白 / 金色描边以区分。程序侧可以先给这三人的技能特效整体乘一个偏橙或偏金的色（约 0.5 天）；正式版由 Codex 重着色。
- 谁做：程序（临时）+ Codex（正式）。

**B 风格割裂（3）**

**FX-B1 特效像素格三种（1 / 2 / 4 px）混用。**
- 证据：F2 中的 `fx_grid_alpha.png`。主体 162 张是 2 px 格，但新做的 @2x 特效有 52 张是 1 px 细格，另有 7 张 4 px 粗格。同一画面里，歌蕾蒂娅的细格龙卷、通用 hit 的 2 px 格和 Mon3tr 的 4 px 残影同时出现。
- 改法：跟 B1 的像素密度定案走。如果定 2 px：
  - 1 px 那 52 张在导入时按 2×2 降采样（程序工具，和干员同一条流水线）；
  - 4 px 那 7 张交 Codex 按 2 px 重画（每张约 1 小时）。
- 谁做：程序（工具）+ Codex（7 张）。

**FX-B2 命中特效十几种，大小和像素格不统一。**
- 证据：F2。命中类 37 张，宽度从 12 px（bullet_hit）到 128 px（eyja_ignite_hit）；同一名能天使就有 hit / hit_gold / hit_s1 / s2 / s3 五张，只换色。艾丽妮一次技能同时出现粉色闪粉和黄色爆炸两种画法。
- 改法：沿用 B6 的「命中三级模板」（16 / 32 / 48 px，2 px 格，白模 + 运行时着色）。能天使这种「同形换色」的，改成一张白模加运行时着色，既省包体又统一。
- 谁做：Codex（模板 3 张）+ 程序（着色与映射）。

**FX-B3 一部分干员的技能读感太弱。**
- 证据：F1。星熊、拉普兰德、推进之王、德克萨斯的技能在画面上只有零星小特效；归溟幽灵鲨的深蓝鲸影和地面同色。对比能天使、塞雷娅、逻各斯，技能「开了没有」一眼可辨。
- 改法：每名干员的三技能至少要有一个「招牌形」，在镜头 100% 下 ≥ 64 px，并且和深海地面的明度差 ≥ 0.25。归溟幽灵鲨加一圈亮边或提亮一档。Codex 按 F1 名单补，每人约 0.5 天；程序侧可以先给这几个技能的特效乘亮度。
- 谁做：Codex（补招牌形）+ 程序（临时提亮）。

**C 整洁（1）**

**FX-C1 未引用与只有 1x 的特效。**
- 证据：F2。`fx_hh_streak` 没有被引用；70 张只有 1x。
- 改法：删掉 `fx_hh_streak`；只有 1x 的那 70 张在 B1 定案后统一处理，不单独补 @2x。
- 谁做：程序（清理）。

### 6.5 特效先做 3 项

1. **白闪与加法过曝封顶 + 伤害数字合并**（FX-A1 / A2，程序约 1.5 天）：收益最大，不动资源。
2. **定「红只给敌方」的色彩规则**（FX-A3）：先由程序给维什戴尔、凯尔希、浊心斯卡蒂的技能特效临时偏色，正式重着色交 Codex。
3. **命中三级模板 + 弱技能补招牌形**（FX-B2 / B3，Codex）：先做模板 3 张，再补星熊、拉普兰德、推进之王、德克萨斯、归溟幽灵鲨。
