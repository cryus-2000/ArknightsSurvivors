# 129 · 乌尔比安 S3「必须开辟的通路」冲锋 + 歌蕾蒂娅钩索拉人修复（10-24）

> 状态：已实现（分支 `claude/ulp-glad`），数值待云端 56 局 × 3 份复核。依据：用户 10-24 实玩反馈；docs/61 §17.5（乌尔比安积木）、108（动画契约）、122 / 123 的设计稿写法。
> 前情：10-21 因「自己飞到 Boss 身边影响手感」删去了 S1 钩 Boss / S3 掷锚后的顺锁链弹射（`d80d8f2f`）；10-24 用户要的是 S3 的**主动跳跃改成冲锋**，S1 不恢复位移。

## 1. 乌尔比安 S3：冲锋

| 项 | 旧（10-21 起） | 新 |
|---|---|---|
| 位移 | 无，锚直接砸在落点 | 掷锚咬地后本体沿锁链冲向落点（`min(max(距离 / 1100, 0.14), 0.34)` 秒，先慢后快 k²） |
| 沿途 | 无 | 本体移动的每一帧对位移线段两侧 `s3_path_w` 50（全宽，+ 敌人半径）内的敌人结算 ×`s3_path_mult` **1.2**，每次冲锋每名敌人只吃一次（`an.hit[e.id]`）；Boss 也吃；不眩晕不击退 |
| 落地 | ×3.0 圆形 AOE（半径 140）+ 眩晕 3 秒 + 击退 | ×**2.0**（`s3_mult` 3.0 → 2.0，随技能强度）圆形 AOE（半径 140）+ 眩晕 3 秒（精英减半、Boss 0.8 秒）+ 击退 60 |
| 队长 / 队友 | 同 | 同：队长冲锋时 `squad.update` 把 `g.ppos` 带过去并给 0.12 秒无敌；队友自己位移 |

积木：只在现有 `verb.tether mode: zip` 上加两个可选参数 `path_w` / `path_mult`（`_num` 校验 1–300 / 0–20）；**写了 `path_w` 才冲锋**，S1（`mode: reel`，钩不到 / 钩到 Boss 落回原地砸）和别的 zip 用法不变。代码：`seg_ulpianus.gd` `_hw4_anchor` 的 `"zip"` 分支、`_hw_charge_sweep`、`_hw_anchor_bite`。native_motion 的 `zip.zip` 信号沿用（`zip_native` 帧条本来就是冲锋姿势）。

### 数值

沿途 120% 只给走在路上的敌人，落地 200% 给落点周围。旧版落地 300% 单次覆盖一个圆；新版总量：路径上的敌人 120%、落点半径内的敌人 200%（若路径末段也在落点半径内则两者都吃 = 320%）。**待复核**：云端 56 局 × 3 份，乌尔比安胜率不掉出 55–70；掉出就回调 `s3_mult`（落地倍率），不动沿途。

### 画面（走光学观感：粒子与特效照明，不用 Light2D）

> 10-24 起高 / 中画质改走像素颗粒版（docs/143）；下面这套是低画质 / 关光学观感的回退画法。

- 路径一道**锚链拖痕**：每帧在位移线段上留 0.35 秒 floor 线（钢蓝色）+ 本体残影与身后三道拖线（`hw_draw_tether` 冲锋段，沿用旧弹射画法）。
- 每走 36 像素扬起一团 `fx_ulpianus_drag_dust` 帧条（`spawn_fx_sprite`，贴地）；一次性帧条特效会被光学观感自动认出：`optical_particles.fx_burst` 按它的本色喷火星 / 碎片，`optical._dyn_lights` 把它登记成动态灯（强度随剩余寿命）——**不另挂 Light2D、不另写粒子**。
- 落地震地环沿用 `UlpImpact.spawn`（`ulp_wave` 水环 + `ulp_fracture` 地裂 + `fx_splash_blue` 帧条），同样自动得到粒子与灯。
- 命中沿途敌人：钢蓝火星（`g.vrng`），画面随机不碰玩法随机。

### 验证

- 回归 `tools/check.py --only ulpianus_charge`（`game/tests/ulpianus_charge_test.gd`，11 项）：冲锋期间本体位移、冲到落点、路径上两名敌人各一次且伤害一致、沿途 / 落地 = 1.2 / 2.0 = 0.6、走廊外且落点半径外的不受伤、S1 仍原地不位移。
- 同 seed：**玩法变化**（S3 位移 + 倍率），TRACE 会变；S1、普攻不变。

## 2. 歌蕾蒂娅「钩索拉不动人」

**复现**（`--balance --seed=2/3 --op=gladiia --sptest`，在拖拽起点打日志，三局共约 180 次钩）：

1. 机械上拖拽没坏：拖到位置的 `dist_to_spot = 0`，拖拽期间没有别的系统改写位置（`HOOKDRIFT` ≤ 5）。
2. **落点 230 ≈ 射程 240**：10-22 第 6 / 8 轮用户定「拖回落点离她 `hook_front` 230、不拉到面前」，而钩索射程只有 240，被钩的敌人本来就在 ~240 外，拖到 230 几乎不动；`push_out` 还会把线上更近的敌人**推出去**到 230。玩家看到的是「钩了，人没过来 / 反而被弹开」。
   回归 `gladiia_hook`（`tests/gladiia_hook_test.gd`）在旧版上的实测：射程边缘（236）的敌人被钩后 236 → 235（几乎不动）、钩索线上 60 处的敌人被推到 235；修复后普通怪 / 精英都拉到 hook_front 附近、线上更近的不被推出去。
3. 拖拽候选是**落地后 0.12–0.34 秒**才在「当前队长位置 → 落点」宽 40 的窄走廊里重新找：队长在动、敌人在动，被钩的那一名可能已掉出走廊（统计里钩中目标没死但不在走廊 / 被别的敌人挤出的占一小部分）。
4. 另有约七成的钩（102 次里 74 次），被钩目标在落地伤害里直接被打死（早期怪低血），没人可拖——这是设计结果，不是 bug。

**修复**（只动歌蕾蒂娅与钩索拖拽，不动乌尔比安数值）：

- `hook_front` 230 → **110**（身前），去掉四处 `push_out`（更近的敌人不再被推出去）；`hook_w` 40 → 52。
- `_hw5_hook_drag_start`：把钩索瞄准的那名敌人（`hk.tgt`）**无条件**加进拖拽名单（活着、非 Boss / 非固定物、在 `front` 之外），不再受走廊约束。
- Boss 照旧免疫（`_movable`）；精英与普通怪同样被拉。
- 文案：「拖到或推到身前」→「拖到身前」；`_leader` / `_range` 注释写明改动原因。

**待复核**：docs/123 §5 的云端单人胜率（op4 系列 22.9–56.2% 区间）会变，拉近后近战怪被扯进队长身边、队长承伤可能上升；`hook_front` 是单一旋钮，云端不理想就往 150–170 调。
