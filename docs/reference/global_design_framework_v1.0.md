# 水月·深海幸存者
## 全局游戏设计框架 v1.0

> 明日方舟同人 · 类幸存者肉鸽  
> 当前目标：先完成一套可稳定产出不同 Build、并能支持未来扩展干员而不大改底层的游戏框架。

---

# 1. 游戏定位

类型：

**类幸存者 + 集成战略 Roguelite**

当前阶段不优先扩大角色、Boss 和地图数量，而是先完成一套：

**可产生明显不同 Build、可重复游玩、未来容易扩展干员的底层框架。**

设计原则：

1. 保留《水月与深蓝之树》的名称、世界观和机制特色。
2. 战斗规则完全服务于类幸存者玩法。
3. 不照搬原作数值。
4. 一个角色必须可以形成多种 Build。
5. 新干员加入时不能要求重构商店、藏品、事件、成长等公共系统。
6. Build 通过机制联动形成，不依赖固定套装。

---

# 2. 核心游戏循环

单局暂时维持约 10 分钟。

核心循环：

**移动走位**
→ 自动攻击  
→ 击杀敌人获得经验  
→ 升级强化角色  
→ 精英 / 箱子获得藏品  
→ 获取源石锭  
→ 商店调整 Build  
→ Boss 提供核心成长  
→ 灯火持续制造压力  
→ Build 成型  
→ 最终 Boss  
→ 结算 / 解锁

当前阶段不优先增加节点地图。

先把：

**单地图 10 分钟 Vertical Slice**

打磨完整。

---

# 3. 单局阶段结构

## Phase 1：Discovery

约 0–3:30。

目的：

让玩家发现本局可能发展的 Build。

内容：

- 基础升级
- 第一批藏品
- 第一商店
- 普通怪逐渐增加
- 第一个 Boss

玩家问题：

**“这局我要怎么玩？”**

---

## Phase 2：Commitment

约 3:30–7:00。

目的：

让 Build 开始真正运转。

内容：

- Boss 核心奖励
- 第二商店
- 精英增加
- 大群压力提高
- 更多机制型藏品

玩家问题：

**“我要不要继续强化现在这条路线？”**

---

## Phase 3：Mastery

约 7:00–10:00。

目的：

让 Build 完成质变。

内容：

- 第二个 Boss
- 高阶藏品
- 第三商店
- 更高敌人密度
- 灯火压力
- 排异反应
- Final Build

玩家体验应该变成：

**“我的 Build 已经启动了。”**

---

## Phase 4：Exam

最终 Boss。

作用不是单纯增加生命值，而是检验：

- 单体输出
- 生存
- 控制
- Build 是否真正成型

---

# 4. 角色成长体系

整个角色成长分四层。

## Layer 1：基础成长

通过升级三选一获得。

包括：

- 伤害
- 范围
- 攻击频率
- 触手
- 技力
- 闪避
- 最大生命
- 移速
- 拾取范围
- 回复
- 减伤
- 灯火效率

作用：

**保证每局稳定成长。**

这些不是 Build 本身。

---

# 5. 技能成长

水月保持：

- 基础攻击
- 天赋
- S1
- S2
- S3
- 精一
- 精二
- 模组

S1 / S2 / S3 仍按照等级自动解锁。

但是技能进阶改成：

**互斥分支。**

例如：

```text
S1 唤醒
├─ 路线 A：强化伞击 / 范围爆发
└─ 路线 B：强化触手 / 追击
```

玩家选择其中一条以后：

后续强化继续加强这条路线。

目的：

让同一个水月最终形成不同技能形态。

---

# 6. Build 系统

Build 不采用：

**“某三件藏品集齐形成套装”。**

采用：

**Tag + Trigger + Synergy Engine**

---

# 7. 第一阶段核心 Build

初期先保证至少五条完整 Build。

## A. 伞击 / 创伤流

核心：

```text
攻击速度
→ 更多伞击
→ 更多命中
→ 创伤 / 范围效果
→ 连锁清怪
```

特点：

- 强清杂
- 近距离
- 高频攻击

---

## B. 触手 / 猎杀流

核心：

```text
伞击
→ 触发触手
→ 攻击低血敌人
→ 击杀
→ 再触发触手 / 技力 / 连锁效果
```

最终形态：

**伞击变成触手系统的启动器。**

---

## C. 控制 / 技能循环流

核心：

```text
束缚 / 晕眩 / 减速
→ 对受控目标产生额外效果
→ 击杀恢复技力
→ 更频繁使用 S2 / S3
→ 制造更多控制
```

---

## D. 反移情 / 收割流

核心：

```text
敌人进入低血状态
→ 反移情强化
→ 低血斩杀
→ 击杀回复
→ 击杀连锁
→ 更多敌人进入斩杀线
```

特点：

Build 存在明显“启动点”。

---

## E. 深蓝 / 低灯火流

普通玩家：

**灯火越低越危险。**

特殊 Build：

**灯火越低越强。**

可能关联：

- 攻击强化
- 技能强化
- 触手数量
- 排异反应
- 高风险奖励

最终实现：

**玩家主动选择是否维持低灯火。**

这是本作最有辨识度的 Build。

---

# 8. 援护系统

Lv.5 / 15 / 25 获得援护。

最多 3 名。

援护不是主 Build 系统，而是：

**辅助 Build 的副系统。**

例如：

- 狙击：单体
- 术师：AOE
- 医疗：回复
- 辅助：控制

以后可以加入：

- 援护攻速
- 援护击杀触发
- 援护与控制联动
- 援护与技力联动

形成可选的：

**指挥 / 援护 Build**

但暂时不作为第一阶段主要流派。

---

# 9. 藏品系统

藏品承担：

**改变规则与连接系统。**

而不是简单提供：

**攻击 +10%。**

一个好藏品应该：

- 增加一个 Trigger
- 改变一个技能行为
- 连接两个系统
- 改变资源用途
- 改变风险收益

---

---

# 11. 藏品等级

建议分：

## 基础
提供稳定增强。

## 稀有
强化 Build 联动。

## 核心
能够改变玩法。

## 升华
让已经形成的 Build 产生质变。

主要来自 Boss。

## 遭诅古物
强力效果 + 明显代价。

## 结局藏品
只负责剧情 / 最终 Boss / 路线变化。

不进入普通随机池。

---

# 12. 藏品设计原则

Build 必须满足：

- 1 件：能看出方向
- 2–3 件：Engine 开始工作
- 4–6 件：Build 明显形成
- 核心藏品：Build 发生质变

禁止：

**必须集齐三个指定藏品才能启动。**

---

# 13. 商店系统

商店定位：

**修正 RNG + 补 Build + 制造经济选择。**

不是主要强度来源。

## 第一商店

职责：

**Build Discovery**

主要提供：

- 基础藏品
- Starter
- 通用生存

## 第二商店

职责：

**Build Fixing**

商品结构：

- 当前 Build 相关
- 通用
- 完全随机

采用 Soft Steering。

只轻微提高相关 Tag 出现率。

## 第三商店

职责：

**Build Finalisation**

主要：

- 高阶联动
- 生存补强
- Boss 准备
- 风险交易

---

# 14. 商店商品结构

固定：

- 3 个藏品槽
- 急救
- 灯油
- 刷新
- 可能出现特殊交易

特殊交易可以包括：

### 灯火交易
降低灯火 → 获得强力藏品

### 生命交易
降低最大生命 → 获得强力效果

### 遭诅交易
获得高阶藏品 + 获得遭诅古物

### 赌博交易
支付源石锭 → 获得未知奖励

---

# 15. 刷新规则

刷新费用逐次提高。

下一次商店出现时重置。

目的：

允许玩家修正 RNG。

但不允许无限寻找毕业藏品。

---

# 16. Boss 系统

Boss 分为：

## 中期 Boss

职责：

**Build 推进。**

不是单纯障碍。

第一个 Boss：

提供核心 Build 选择。

第二个 Boss：

提供 Build 升华。

## 最终 Boss

职责：

**检验 Build。**

最终 Boss 不负责继续成长。

---

# 17. Boss 奖励设计

Boss 奖励优先采用：

**高质量三选一。**

第一个 Boss：

- 一个当前 Build 相关
- 一个其他 Build
- 一个通用

第二个 Boss：

出现真正的：

**Capstone / 升华藏品。**

---

# 18. 灯火系统

灯火继续作为全局压力系统。

正常状态：

灯火下降  
→ 世界越来越危险。

建议阶段：

### 高灯火
正常。

### 中灯火
环境开始异常。

### 低灯火
敌人强化 + 排异风险。

### 0 灯火
进入深海危险状态。

基础规则永远是：

**低灯火有风险。**

Build 可以改变：

**风险是否值得。**

所以低灯火 Build 不是取消惩罚。

而是：

获得更高风险收益。

---

# 19. 排异反应

排异反应不是简单：

**攻击 -10%。**

应该改变玩法。

例如：

- 移动能力变化
- 视野变化
- 攻击行为变化
- 防御变化
- 技能循环变化

部分 Build 可以：

利用排异反应获得额外收益。

---

# 20. 敌人系统

敌人按照职责分类：

### Swarm
制造数量压力。

### Bruiser
高血，阻挡路线。

### Ranged
迫使玩家移动。

### Area Denial
制造危险地面。

### Support
治疗 / 强化其他敌人。

### Summoner
产生新单位。

### Elite
改变玩家行动方式。

不要只设计：

**更高 HP 的普通怪。**

---

# 21. 敌人进化

保留普通海嗣长时间存活后进化。

目的：

防止玩家只绕圈不输出。

形成：

**软 DPS Check。**

---

# 22. 经济系统

源石锭主要来自：

- 箱子
- 精英
- Boss
- 特殊奖励

经济目标：

玩家每次商店都必须做选择。

不能：

**全部购买。**

也不能：

**什么都买不起。**

---

# 23. 获取来源职责

| 来源 | 职责 |
|---|---|
| 升级 | 稳定成长 |
| 精英 | 增加 Build |
| 宝箱 | 提供藏品机会 |
| Boss | 改变 Build |
| 商店 | 修正 Build |
| 事件 | 打破规则 |

这个职责划分以后尽量不要改变。

---

# 24. 难度系统

继续采用逐级解锁。

高难度原则：

优先改变：

- 敌人压力
- 资源压力
- 灯火压力
- 精英频率
- Boss 机制容错

少用纯：

**HP × 3。**

最终高难度应该改变玩家决策，而不只是增加战斗时长。

---

# 25. 结局系统

未来结局由关键藏品 / 事件决定。

最终 Boss 可以包括：

- 偏执泡影
- 伊莎玛拉
- 伊祖米克
- 其他原作结局

结局系统不应该影响基础 Build Framework。

它只决定：

**最终阶段内容。**

---

# 26. 局外成长

后续再做。

主要负责：

- 新干员
- 新藏品池
- 新结局
- 新难度
- 图鉴
- 美术解锁

避免：

**永久攻击 +100%**

这种直接破坏局内平衡的成长。

# 30. Stat System

统一计算顺序：

```text
Base
→ Flat
→ Additive %
→ Multiplicative
→ Override
```

任何藏品和技能都不能直接随意修改最终数值。

# 31. Build Profile

系统实时维护当前玩家 Build。

记录：

- 当前 Tag 权重
- 已拥有藏品
- 技能分支
- 灯火状态
- 援护
- 生存状态

用途：

- 商店 Soft Steering
- Boss 奖励
- 数据统计

不是：

强制给玩家指定 Build。

# 33. 未来增加干员

未来增加一个新干员应该只需要：

1. 新 OperatorData
2. 新基础攻击
3. 新技能
4. 新专属 Tag
5. 新动画 / 特效

不应该修改：

- 商店
- 藏品框架
- Boss 奖励
- 经济
- 灯火
- Modifier
- Event System

如果增加角色必须改这些系统：

**说明底层架构设计失败。**

---

# 34. Build 平衡原则

不同 Build 必须有：

- 优势
- 弱点
- 启动时间
- 适合的敌人类型

禁止出现：

一个 Build：

- 清杂最强
- Boss 最强
- 生存最强
- 还最快成型

---

# 35. Build 测试标准

不要只测试：

**能不能通关。**

必须统计：

- 最终 Tag
- 各伤害来源占比
- 藏品 Pick Rate
- 藏品 Win Rate
- Build 成型时间
- Boss 死亡率
- 灯火平均值
- 援护伤害占比
- 死亡原因

---

# 36. 判断 Build 是否成功

如果不同 Run 最终都是：

```text
伞击 55%
触手 25%
技能 20%
```

说明 Build 系统失败。

理想状态：

### Run A
伞击主导。

### Run B
触手主导。

### Run C
技能 / 控制主导。

### Run D
低血收割主导。

### Run E
低灯火高风险主导。

# 38. 暂时不做

当前阶段不要优先：

- 增加大量新干员
- 传统六武器系统
- 大量新 Boss
- 节点地图
- 大量剧情事件
- 大规模局外成长

原因：

这些都属于横向内容扩充。

当前项目最重要的是：

**先完成纵向系统深度。**

---

# 39. 最终核心设计哲学

本游戏不是：

**“水月 + 一堆属性加成”。**

也不是：

**“Vampire Survivors 换明日方舟皮肤”。**

最终应该形成：

**角色提供 Build 起点。**

**技能分支决定方向。**

**藏品连接机制。**

**商店修正随机。**

**Boss 完成质变。**

**灯火制造风险。**

**排异反应改变规则。**

**结局决定最终挑战。**

当这套框架成立以后：

未来增加任何新干员，都只是为成熟系统增加一种新的 Build 起点，而不是重新设计一款游戏。
