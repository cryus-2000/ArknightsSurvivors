## 2 为什么暂停

用户的判断是「不少比旧版差」。组长复盘有四条原因：

1. **新版普遍更细、更暗、更稀。**
   - 旧版 Codex 帧条是 2 倍粗块、实心、饱和；新版为了贴 pixelfx 原作，大量用半透明、颗粒、余韵。
   - 在游戏的缩放和深海暗底上，读出来的是「更淡、更碎」，不是「更有力」。
   - 光晕层是加色叠画，在暗底上补回一部分，但补不回实心体量。
2. **硬数字把冲击力压掉了。**
   - 近白 ≤ 12% 让各组把白热核心压暗。A 组首交时近白最高到 100%，被退回后为了达标把色阶封顶。
   - 32 色上限、单条 KB 上限，再加上变体要计入预算，各组只好收尺寸、减帧、降色。
   - 每条都「合规」，但首帧的爆亮感和体量都缩水了。
3. **验收只看数字，没有「不比旧版差」这一条。**
   - 验收项是覆盖率、体积、色数、近白、core，全是可量的项，没有一条要求新版观感不低于旧版。
   - 统一录像排在全部交付之后，第一次新旧同屏对照就已经是全量交付之后，返工成本最高。
4. **范围铺得太快。**
   - 只做了 3 名干员的试点、用户认可 1 条（斯卡蒂刀光 k 0.85）就铺到 20 人。中途口径又改了四次：光晕 + 余韵、变体 + 火星、近白口径、统一录制。
   - 各组反复重导，精力花在追规范上，而不是打磨观感。

## 3 以后若重启，先改这些

1. **先立「不比旧版差」这条硬卡，放在所有数字前面。**
   - 每人先出 1 条代表性技能，新旧同屏，过用户这一关再铺这个人的其余件。
   - 对照用静态关键帧对照图就够（本轮 `cmp_sheet.py` 的做法：只读 PNG，几分钟出 20 人），不必等录像。
2. **以旧版为基准做增量，不整套推倒。**
   - 保留旧版的实心体量和饱和色，只借 pixelfx 的手法：不规整外缘、首帧爆亮、余韵火星。
   - 「整套替换」改为「只换比旧版差的件」。
3. **硬数字改为上限提醒，不作为退回理由。**
   - 近白改为「核心可以白、白块不能盖住敌人轮廓」，由整屏 vreview 判；不再按帧条像素占比卡。
   - 色数、KB 只卡总预算（1.7 MB），不卡单条。
4. **密度回到旧版口径。** 旧 Codex 帧条在游戏里的尺寸和不透明度是用户校准过的，新件按旧件的屏幕占比来做，不按「伤害半径 × 0.85」重算。
5. **口径一次定好再开工。** 光晕、余韵、变体、火星都在试点阶段定下来，铺开后不再追加。
6. **公共机制可以留着用：** 分层光晕（`px_glow`）、变体与火星（`px_vary` / `px_spark`）、覆盖表、静态对照脚本。它们只对 `_px_` 帧条生效，不影响旧帧条，留在 fx-lead-prep 分支上，重启时直接合。
