# 318 Toy 加载页 iPhone 横屏适配（11-08）

用户 11-08 在 iPhone（B站 App，Toy 预览，横屏，截图 2868×1320 = 956×440 CSS px @3x）上看网页启动页（方向 4 PRTS 认证终端，`tools/web/loader.js` p4Init + `loader.css`），提了五处问题。都在加载外壳里，游戏内标题页不受影响。

## 原因与修法

| # | 现象 | 原因 | 修法 |
|---|---|---|---|
| 1 | 右上「ARKNIGHTS FAN GAME」被 B站 胶囊（分享 / 关闭）盖住 | SDK 容器状态没有胶囊矩形（FAQ 说「可获取」，但文档与回调里都没有这个字段），`__sySafe.capsule` 一直为空 | `container.js` 的 `guessCapsule`：沉浸模式、非桌面、状态里找不到胶囊字段时，按截图估计一个禁区（见下）；加载页标题行的右侧文字和分隔线停在胶囊左边 12 px，放不下就不写；胶囊伸到右侧面板时，面板往下移 |
| 2 | 左侧灵动岛挡住「完成 · 等待指令」 | `container.js` 收到容器状态后把 `innerWidth/innerHeight` 改成安全区尺寸（给 Godot 画布用）。加载页画布却还是铺满整屏，只是按安全区尺寸画，结果整张被拉伸；标志 / 动效层按安全区坐标摆，又没有加安全区偏移，所以和画布错位 | 加 `.p4box`，贴住安全区（`__sySafe` 的 left / top + 改写后的 innerWidth / innerHeight）；动效层、页脚、「开始游戏」都放在里面。画布 `.p4c` 铺满整屏，只画底色 / 点阵 / 扫描纹，其余内容 `setTransform` 平移到安全区里画。刘海和圆角下面跟背景同色，没有接缝 |
| 3 | 标志里「RHODES ISLAND」显示成「RI ODES」 | 240×240 原图先用最近邻降到 120×120 再做阈值，4 像素高的小字笔画被采丢（采样相位不同时也会丢成「RHODLS」） | 改用 240 原分辨率做阈值。显示尺寸够 240 物理像素时用 `pixelated` 放大，不够时用平滑缩小，缩小时不会丢笔画 |
| 4 | 「认证通过」被「开始游戏」按钮盖住一半 | 字在画布里按安全区高度定位，按钮在 DOM 里按另一套公式定位，两边的坐标系也不一样（见 #2） | 按钮由 p4Init 每帧定位：上沿在「认证通过」基线下方 14 px，底部至少给 RHODES ISLAND / 页脚留 24 px。往下放不下时按钮上移，字跟着上移 |
| 5 | 第二张图整屏暗粉 / 紫红，左边和上边各有一条亮粉细边（用户补充：这是 iPhone 上**游戏内存崩溃、页面自动刷新之后**出现的，不是正常加载流程） | 外壳里没有崩溃 / 重载分支，也没有任何粉色（加载页、container、预设 head_include、Godot 清屏色 / 启动底色都查过）。按截图像素反推：整页叠着一层**均匀的 (217,105,138) 粉色，不透明度约 19%**（底色、标志、青色三处算出的 α 一致），左 / 上边缘有约 2 CSS px **同色不透明**的细边。说明这是**页面文档之外**的粉色层（B站 App / WebView 的原生底，或崩溃恢复时的原生遮罩），透过来的原因是页面被挪开了约 2 px，或整个页面变成了半透明。iOS 刷新时会恢复上次的滚动 / 缩放偏移，这能解释细边；那层 19% 的罩色页面本身做不出来（加载页不透明），推断是 App 在崩溃恢复时盖的 | 页面侧防住能防的：`history.scrollRestoration = 'manual'`，滚动 / 尺寸变化 / pageshow 时贴回 0,0；`html` 不透明黑底，`html, body` 锁住滚动和回弹（`overflow:hidden; overscroll-behavior:none`）；顺带关掉 WebView 点按高亮（`-webkit-tap-highlight-color: transparent`）。那层罩色要是来自 App 原生，页面侧去不掉，**重传后请在真机上复现一次崩溃 → 刷新再看**。崩溃提示：游戏没有「崩溃后自动降载」，按协调人的口径（只有真降载了才写）不加提示；perf_hud 的 `sy_perf_alive` 标记只在性能浮层开着时才写，拿来判断上次是否崩溃也不可靠 |

## 胶囊估计值（Toy SDK 不给矩形时）

截图实测（iPhone 横屏，B站 App 沉浸模式）：胶囊约 82 × 31 CSS px，上沿离顶部约 11，右沿离安全区右沿约 12（按右侧安全边距 62 算）。
`guessCapsule` 在 viewport 坐标里外扩成 **安全区右上角 108 × 46** 的禁区：`{x: vw − safeRight − 108, y: 0, w: 108, h: 46}`。只在 `immersive` 为真且 `deviceType ≠ desktop` 时启用；SDK 以后给了 capsule / menuButton 之类的字段，就优先用 SDK 的（`findCapsule`）。

**游戏本体同样受益**：`Cfg.safe_insets()` 本来就会把 `__sySafe.capsule` 的下沿当作额外的顶部边距（docs/22「Toy 接入」）。以前真机上胶囊为空，局内右上的触屏按键可能被胶囊压住；现在触屏按键、选卡面板、设置面板顶部都会让开约 46 CSS px。docs/22 表里「容器状态里没有胶囊字段 → 顶部边距 0」这条已改。
