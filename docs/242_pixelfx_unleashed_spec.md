用户 11-03 看过斯卡蒂试验的新旧对照（docs/228 §9，`Claude outputs/pixelfx_unleashed_skadi/side_by_side.mp4`），结论是：新版更好，特效够亮眼，画面重心落到了主角身上。之后 20 人都按这份规范铺开，其中 10 人交给 Codex。

**11-03 定稿：§11（漏项定稿）优先于前文冲突处，预算、光晕、验收分工以 §11 为准。**

本规范**取代 docs/229 里与下文冲突的条款**。docs/229 中没有被改动的部分继续有效：密度 PX = 2、地面圈用透视椭圆、冲击帧只给终结技、敌方档。

样板是斯卡蒂，分支 `claude/pixelfx-unleashed-skadi`：
- 源码：`tools/pixelfx_fx/melee/ak-skadi-ul-slash.js`、`water/ak-skadi-ul-geyser.js`

## 1 相对 docs/229 放开了什么

| 项 | docs/229（旧，作废） | 放开版标准 |
|---|---|---|
| 近白 | 近白像素 ≤ 12% | **不设比例上限**，按时间管：白热只出现在第 1 帧（芯 + 外缘），第 2 帧余热降一档，第 3 帧起回到色阶中段。持续白（连续 3 帧以上大面积近白）算毛病 |
| 色数 | 32 色 | **256 色**（调色板 PNG）。实测斯卡蒂 13 张帧条：256 色 532 KB、128 色 531 KB、64 色 513 KB，降色数几乎不省体积，所以不限 |
| 体积 | 普攻 ≤ 3 KB / 技能 ≤ 20 KB | 按 §6 的每人预算管，单条不再设上限 |
| 尺寸 | 按旧帧条尺寸一对一重做；刀弧落在伤害半径 × 0.85 | **可以比旧版大**：刀弧落在判定半径 × 1.0，浪沫和火星可以甩出判定圈外 20–40%。帧画布按需放大（斯卡蒂是 260×260 1x） |
| 亮芯 | 爆亮 1 帧、最亮两阶占 ≥ 40% | 第 1 帧整条刀身 / 爆点白热，外加大光晕（pixelfx `glow` k 0.3–0.6）；第 2 帧余热；此后外缘白、内侧逐级变深 |
| 余韵 | 普攻 0.15 s、技能 +0.6 s | 队长：普攻 / 技能 **0.5–0.7 s**（浪沫、水雾、闪烁的光点慢慢散）；队友约一半（§3）。终结技 1–1.5 s |
| 火星 | 普攻颗粒数不加 | **帧条里烤**整条外缘的甩出物（水珠 / 火星 / 碎屑），**另加实时火星**：普攻 8 颗、技能 14 颗（`motes`，用 g.vrng），跟出手方向 |
| 随机变体 | 2–3 个种子 | 高频出手（普攻、连段、全方向斩）**至少 2 个种子变体**随机挑；全方向的整圈随机转角；帧条里撒甩出物的步长也要随机。都只用 g.vrng |

**仍然禁止**（用户 10-30 否过，docs/229 §2.6，memory「特效力量感做法」）：
- 规整的放射纹：等距火星、等距水刺、等距光线。
- 两道以上的同心圈。斯卡蒂的全方向斩因此去掉了内弧。
- 同一子图等距并排。
- 外缘用周期正弦。外缘起伏一律用 `noise()`。

## 2 判定与开关

- **全部放在开关 `fx/px_unleashed` 后面**（balance.json `fx` 段，缺省 0）。命令行 `--bal=fx/px_unleashed=1` 打开。关掉时画面和 main 完全一样。
- **只改画面。** 伤害、判定、命中状态、玩法随机数（g.rng）都不动；画面随机只用 g.vrng。
- **TRACE 验证（必做）：** 同种子无头批跑，开关 0 / 1 各一局，TRACE 必须逐行一致。至少两局：后期局（`--maxt=560`）和终结技局（`--maxprog --bal=ult/test_fill_at=…`）。脚本可参考斯卡蒂试验的 trace_ab（`--balance --seed=13 --op=<人> --bot=expert --nodeath --trace=1`）。
- **接入写法：**
  - 近战形状（cone）：在 `seg_<人>.gd` 写 `px_ul_shape(o, b, hits, ang, r) -> bool`，返回 true 表示已接管这一下的画面。ob_core 的接管点目前只认斯卡蒂（`_F().px_ul_shape`），新人物在这个函数里按 `o.id` 分发。**这一步只能组长改，或在合入时统一。**
  - 弹道类（能天使等）：在本人的 seg 里，按开关换 muzzle_fx / hit_fx / 弹体贴图。
  - 终结技：在各人的 ult_moves_* 里按开关换贴图调用（参照 `_sd_ul`）。
  - 通用近战刀光：`vfx.melee_arc` 按 `o.id` 跳过（参照斯卡蒂那一行）。

## 3 队长与队友（用户 11-03 定）

- **命中定格只给队长。** 普攻 0.05 s、技能 0.075 s，走 `o.impact_pause`（共享限频：模拟秒 0.28 s 一次、真实秒 1.5 s 一次）。队友命中不定格。受总闸限频，不是每下都定；不许改 fx/hitstop_gap（§11.1 第 9 条）。
- **队友版余韵短一些、透明度不降。** 队友用 `_tm` 后缀的帧条：余韵约减半，刀身和亮度与队长版一样。斯卡蒂的 _tm 版用 `quick: 1` 导出。没有 _tm 版时回退到队长版。
- 种子变体（`2` 后缀）只给队长版；队友版一张即可。

## 4 不换的部分（用户定）

- 逻各斯：普攻、设定字形、符文、咒文锁链。
- Lumen：发光单元。
- 铃兰：九尾虚影。

这些保持原样，开关打开也不动。同一人其余的技能 / 终结技可以换。

## 5 验收

1. **先用人眼。** 自己对比新旧，觉得「明显比旧版好」再交；只是数字达标不交。看的时候重点看三条：画面重心是否落在这名干员身上；出手那一下是否有力；连续出手时会不会叠成一团看不清。
2. **验收录像只给新版（用户 11-03 改）。** 不再录旧版，也不再录左右对照；自己和旧版比较时，用截帧或本地对比就行。录像要让用户看到这名干员的全部美术效果：普攻、S1、S2、S3、终结技，外加队友版（_tm）。分两段录：
   - **展示段**：每个招式按顺序各放 2–3 次。用演示 / 练习模式或强制施放都行，能看清就好；背景用正常地图加少量怪。
   - **实战段**：后期满编 30–60 秒，看特效混在战斗里的效果。
   - 两段都用 `--realtime` 原速 30 帧、原色，单段 ≤ 25 MiB。
   - 录制工具 `tools/px_unleashed_rec.py`：`--only new` 只录新版；`--extra="--squad=… --maxprog --sptest"` 让技能全解锁；终结技参数参照 `tools/ult_rec.py`。
   - 网页低档另补一段展示段，加 `--bal=fx/px_ul_lo=1`（§6）。
   - 命中定格会暂停模拟，所以两次录像不是同一局。
3. **vreview 只当预审。** ult_fx 检查单加 `--crop right`。
   - 「拼接感」和「连成一片」在全方向连续出手、终结技砸下这两个场景容易误报，先抽原尺寸帧自己核实。
   - 属实的改掉（斯卡蒂的等距放射纹就是这样抓出来的），误报写明理由。
4. **TRACE 开关前后一致**（§2）。

## 6 包体预算

**预算以 §11.1 第 3 条为准（11-03 定稿）：桌面全档每人 ≤ 900 KB；网页低档全队合计 ≤ 4 MiB、只出 E2、普攻不出 deco_lo；显存每人全档 ≤ 48 MB、低档 ≤ 12 MB。下文的 650 / 550 / 200 / 150 / 300 KB 都已作废。** 桌面包不紧，不用为凑数压画质。

斯卡蒂全档实测（普攻 / 技能 / 全方向 / 终结技水柱，含 2 个变体和 4 张 _tm，共 13 张）：拆层前 PNG 532 KB（导入后 .ctex 407 KB），拆层后 602 KB。

斯卡蒂低档实测：拆层前 5 张 167 KB，拆层后 186 KB。塞雷娅全档 34 KB、低档 28 KB；能天使全档 35 KB、低档 32 KB。

**网页版用低档帧条、桌面版用全档（用户 11-03 定）。** 以下照抄协调人规则 `Claude outputs/pixelfx_web_lo_rule_1103.md`，内容不改：

> 先以本文件为准。docs/242 §6 会照抄这份内容，由样板分支 claude/pixelfx-unleashed-skadi 补写。补写后的提交号会另行告知，内容不会改变。

### 1 两套帧条

| 档 | 用在哪 | 内容 |
|---|---|---|
| 全档 | 桌面版 | 按 docs/242 §1–§3 制作：原帧率，含种子变体 `2`，含队友版 `_tm` |
| 低档 `_lo` | 网页版 | 每个招式**只出一张**：15 fps、不要变体、不要 `_tm`，队长和队友共用 |

### 2 命名

- 全档：`fx_<人>_ul_<招式>[2][_tm].png`（不变）
- 低档：`fx_<人>_ul_<招式>_lo.png`
  - 从全档的「队长版、第一个种子」导出，按 15 fps 抽帧：原来 30 fps 的隔帧取，24 fps 的按时间最近取，余韵时长不变。
  - 画布、原点和尺寸都和全档一致，代码里不需要另给原点。
- `art.gd` 的 `V6_FRAMES` 里，低档同样每条一行：`"fx_<人>_ul_<招式>_lo": [帧数, 15]`。

### 3 导出

- 在 targets 条目里加 `"lo": true`，导出脚本出全档的同时，再按上面的规则抽帧出 `_lo`。
- 也可以单独写一个抽帧脚本，读全档 PNG 生成 `_lo`，结果一样即可。
- 256 色调色板照旧。

### 4 游戏里怎么选

- 统一走一个取名函数（样板分支会加进 `vfx.gd`，Codex 不要改 vfx.gd，直接调用就行）：
  - `vfx.px_ul_tex(base: String, variant: int, teammate: bool) -> String`
  - 网页版（`OS.has_feature("web")`），或桌面上把开关 `fx/px_ul_lo` 设成 1（用来在桌面预览低档）时：一律返回 `base + "_lo"`，忽略 variant 和 teammate。
  - 其他情况：按全档规则返回 `base` / `base2` / `base_tm`；缺的版本回退到 `base`。
- 在样板分支加上这个函数之前，Codex 可以在各人的 seg 里先写一个同签名的本地版本，合入时由协调人统一替换。

### 5 网页包只带低档

- 网页导出时排除全档帧条，由协调人在合入时统一改 `export_presets.cfg`，Codex 不碰。
- 交付时请分别报出全档和低档 PNG 的总体积。网页增量目标是每人低档 ≤ 150 KB。

### 6 验收录像

- 按全档录（docs/242 §5，只给新版：展示段 + 实战段）。
- 另外用 `--bal=fx/px_ul_lo=1` 补一段展示段，确认低档没坏，抽帧后不能看起来卡顿。

## 8 核心层 / 装饰层拆分（用户 11-03 批）

以下照抄协调人规则 `Claude outputs/pixelfx_layer_rule_1103.md`，内容不改：

> 用户 11-03 批：每个招式拆成「核心」和「装饰」两层，以后队友和拥挤时可以只削装饰，核心不动、透明度不降。本文件先生效，docs/242 会补一节照抄。**取代 docs/242 §7 的「_glow 烤进单张（做法 ①）」**：光晕不再烤进核心帧条。

### 1 两层分别放什么

| 层 | 内容 | 任何情况下 |
|---|---|---|
| 核心 `core` | 弹体、刀身 / 刀弧、命中的主要形状、第 1 帧白热芯、攻击范围的**边缘** | 必须完整保留 |
| 装饰 `deco` | 大光晕、烤进帧条的甩出物（水珠 / 火星 / 碎屑）、余韵（水雾、闪烁光点、残影）、范围的**内部填充** | 可以被削弱或关掉 |

判断标准：把装饰层整层关掉，玩家仍能看清**谁在打、打向哪、打到哪**，就算拆对了。实时火星（motes）和屏幕震动也归装饰。

### 2 命名

在 docs/242 原有命名之后、`_lo` 之前加 `_deco`：

- 核心：`fx_<人>_ul_<招式>[2][_tm][_lo].png`（与原来相同，内容改为只放核心）
- 装饰：`fx_<人>_ul_<招式>[2][_tm]_deco[_lo].png`

两层的画布、原点、帧数和 fps 必须完全一致，逐帧对齐。`V6_FRAMES` 两条各写一行。

### 3 导出

- 在 pixelfx 源码里按图层出：核心图元画在一层，装饰图元画在另一层。
- targets 条目加 `"layers": true`，导出脚本一次出 core 和 deco 两张。
- 256 色、`lo` 抽帧的规则照旧，deco 同样出 `_lo`。

### 4 游戏里怎么画

- 取名统一走 `vfx.px_ul_tex(base, variant, teammate, layer)`，`layer` 取 `"core"` 或 `"deco"`。样板分支会补这个参数；在它补上之前，可以先写成本地同签名函数。
- 先画装饰，再画核心，核心永远在装饰上面。
- 装饰层乘一个系数：开关 `fx/px_deco_k`（缺省 1.0）。现阶段只用这一个总开关，按拥挤程度动态削装饰的预算系统以后另做，接口先留好。
- 队友用 `_tm` 版：核心和队长版一样，装饰的余韵减半。透明度不降（用户定）。
- 网页低档：core_lo 和 deco_lo 都带上。网页包超预算时，先去掉普攻的 deco_lo。

### 5 验收补充

- 展示段里，每个招式另外用 `--bal=fx/px_deco_k=0` 放一次，确认关掉装饰后仍能看清攻击方向和命中位置。
- 包体按 core + deco 合计计算，每人全档 ≤ 550 KB 不变。

**样板实测（斯卡蒂，拆层前 → 拆层后）：**
- 全档：532 KB → 核心 150 + 装饰 452 = 602 KB，涨 13%，在 §6 调整后的 650 KB 以内。
- 低档：167 KB → 核心 45 + 装饰 141 = 186 KB，涨 11%，在 200 KB 以内。

两层分开量化、分开存，所以总体积略涨。

## 9 形状约束（用户 11-03 批）

以下照抄协调人规则 `Claude outputs/pixelfx_shape_rule_1103.md`，内容不改：

> 用户 11-03 批。本文件先生效，docs/242 会新开一节照抄。

### 1 判定形状：从游戏数据读，不手抄

- 和判定有关的形状必须用游戏里的判定参数来画：扇形角度和半径、冲击波半径、光束长度和宽度、落点范围等。画面和判定用同一组数字。
- 做法：
  - 导出脚本读取该干员的技能数据（`game/data/characters/<人>.json`，以及 seg / ult 里写死的常量），作为选项传给 JS 源码；
  - 源码里不能出现手写的判定尺寸数字；
  - 拿不到数据的（写死在 gd 里的常量），在 targets 条目里注明出处（文件和行号）。
- 核心层负责画这个形状的边缘：刀弧落在判定半径 × 1.0。装饰层可以甩出圈外 20–40%，但核心不能超出判定。

### 2 有原作形象的形状：先交参照轮廓

- 适用于原作里有明确外形的招式，例如：塞雷娅的晶簇、能天使的光环 / 弹体、水月、歌蕾蒂娅、凯尔希（Mon3tr）等的标志性招式，以及逻各斯除「不换」部分以外的招式。
- 流程：
  1. 参照轮廓的来源：优先用 `build/ark_ref/<人>/` 下从客户端解包出的原作特效贴图（不进 git、不进包），没有时再用 PRTS（立绘、技能演出、Spine 参照，见 docs/87 §4.3）。照原作画一张黑白参照轮廓 PNG：`tools/pixelfx_fx/ref/<人>_<招式>.png`。要求 1 位深（黑白）、原尺寸，并标出原点。
  2. 先发轮廓给协调人看，确认外形对了再做下一步。
  3. 源码用 `mask` 读取轮廓：**外形由轮廓定死**，代码只在轮廓内部做光的流动、碎裂、闪烁和生长动画。
- 有没有原作形象拿不准的，问协调人。纯自创的招式（本作新设计的终结技部分）不强制，但同样要先交草图。

### 3 否决过的图案：导出时自动检查

- 导出脚本加一步检查，任一项超标就报警、不产出：
  - **规整放射**：统计帧内甩出物和线条的方向角，如果分布在等距角度上过于集中（周期性明显），算放射纹；
  - **同心圈**：同一帧内同心环超过 1 道；
  - **等距并排**：同一子图按等距重复出现 3 次以上；
  - **持续白**：连续 3 帧以上大面积近白（docs/242 §1）。
- 公共模块（house.js / ak_layers.mjs）只提供不规则的工具：`noise()` 边缘、随机步长、随机转角、抖动间距。不提供等距阵列。
- 自动检查和 vreview 都只是过滤，最终仍由人眼判断。误报要写明理由后放行。

### 4 交付补充

每个招式交付时附三项：判定数据的出处、参照轮廓（若适用）、自动检查的结果。

**样板实现（claude/pixelfx-unleashed-skadi）：**
- **判定数据**：targets 条目写 `"judge": {"op": "<人>", "opts": {"span": "2*half"}, "src": "出处"}`，表达式里的名字从 `game/data/characters/<人>.json` 的 `base` 取值，代入后作为选项传给源码（`tools/pixelfx_export.py judge_opts`）。gd 里写死、读不到的常量直接写数字，并在 `src` 里注明文件和行号。
  - 斯卡蒂：普攻 `2*half`、S1 `2*s1_half`、S2 `2*s2_half`、全方向 `2*pi`。
  - 弧半径 = 运行时 fit 80，对应判定半径 × 1.0（`seg_skadi.px_ul_shape`）。
- **自动图案检查**：`tools/pixelfx_check.py`，导出时逐层检查，超标就不产出。地面透视的效果用 `"check_sy": 0.55`；放行用 `"check_skip": [...]` 加 `"check_note"` 写理由。`python tools/pixelfx_check.py --selftest` 用人工违规样例自检（等距放射线、三道同心圈、等距并排的同一子图、连续白帧），四项都要报出来。
  - **规整放射**：角度直方图 6–24 次谐波里有尖峰，尖峰 ÷ 左右邻居中位数 > 7，且尖峰 ≥ 总量 12%。
  - **同心圈**：一帧里有 2 道以上细线整环，即 360 格角度覆盖 ≥ 60%，并有 0.3 的突出度；实心光团不算。
  - **等距并排**：≥ 4 个逐像素相似的块（掩码 IoU ≥ 0.8）排成一线，间距相对差 < 6%；小颗粒和颗粒云不算。
  - **持续白**：连续 ≥ 3 帧，近白（RGB 最小通道 > 225）占可见像素 > 35%。
- **斯卡蒂校准结果**：校准后 36 张全部通过。中途查出两处真超标并改了源码，不是误报：全方向斩和终结技水柱连续白了 3 帧。现在爆亮只留首帧，第 2 帧余热降一档，所以白色比用户 12:22 看过的版本少一些。
- **参照轮廓**：`house.js refMask(o)`，配合导出条目里的 `"ref": "tools/pixelfx_fx/ref/<人>_<招式>.png"`。参照图是 1 位黑白（黑 = 内部），原点写在同名 `.json` 的 `{"origin": [x, y]}` 里。另有不规则工具 `jitterSteps` / `jitterAngles`。

## 11 漏项定稿（用户 + 协调人 11-03 定）

### 11.1 开工前必须照做

1. **导出要先反预乘（审查 #23）。** pixelfx 库往透明画布上贴帧时，rgb 会乘上 alpha，alpha 却原样保留；Godot 按直通 alpha 画，半透明处的亮度就成了 a²，光晕和水雾发暗、发灰。
   - `tools/pixelfx_export.py` 读精灵表后要先还原：a > 0 时 rgb = min(255, rgb × 255 ÷ a)，做法同组长分支 724b05688 的 `unpremultiply`。
   - 这一步由 pixelfx-eval 合进样板分支。合入后，斯卡蒂、塞雷娅、能天使重导一次。
   - **这一步合入之前，谁都不要开始导出。**
2. **光晕只进 `_deco`（审查 #26，选甲）。** 光晕用反预乘后的直通 alpha，画在装饰层帧条里，**不做 `_glow` 加色层**。§7 的做法 ② 作废，不依赖 claude/fx-lead-prep。

## 14 公共挂点补充（美术组长 11-04 批，样板分支维护）

### 14.1 连携接管（`vfx.px_ul_link`）
注册表加 `"link": {"dash": {…}, "hit": {…}}`，挂在**出手的搭档**（连携里位移、出手的那个人）名下；某条连携要单独换，写 `"link": {"<synergy.json 里的连携 id>": {"dash": …, "hit": …}}`。
- `dash`：冲出那一下，替换冲刺拖线和旧的 `strip`。`hit`：落点一击，替换刀光、落点环和火花。
- 条目 `{base, at, y, sc, fit, rot}`：`at` = `"to"`（缺省，画在落点 / 目标）/ `"from"`（起点 / 搭档站位）/ `"mid"`；缩放 = PX × sc，写了 `fit` 时再 × 距离（或判定半径）÷ fit；`rot` 缺省 true，随方向转。
- `hit` 也可以写 `{"shape": "<自己已登记的形状 src>"}`：落点一击复用自己的放开版刀光（px_ul_shape）；synergy.json 这一条 dir 上的 `px_src`（拉普兰德写法）等价。
- `cross` `{base, fit, …}`：`cross: true` 的连携里**施放者**那道交叉刀光，写在施放者的 `link` 里；施放者有注册表但没写 `cross` 时不画（旧暖金刀光和结晶撞色）。
- `col` `[r, g, b]`（或 synergy.json 的 `px_col`）：放开版下冲刺拖光 / 落点画面的颜色。
- 现在覆盖 `dash_strike` 和 `dash_cast`（集群狩猎、控场 → 收割同一套）；`volley` / `hook` 要用时再报。

### 14.2 fx 条目 `px`（`ob_fx.px_fx_spawn`）
干员 JSON 任何积木的 fx 列表里可以写 `{"px": "fx_<人>_ul_<名>", "at", "off", "fit" / "scale", "rot", "face_x", "skill", "variants", "cond", "every"}`：
- 帧条名走 `vfx.px_ul_tex`（种子变体只给队长、队友 `_tm`、精英档、缺图回退都同 §11.1 第 5 条），先画装饰层（× px_deco_k）再画核心层。
- `at` 只能是 center / self / leader / zone / hits；`skill` = 有命中时队长定格取注册表 `pause` 的技能档。
- `ground: true` = 贴地画面（optical 不自动补火星 / 颗粒，例：安洁莉娜失重井）。
- `rot`：`true` 或 `"vel"` = 随出手 / 飞行方向转（帧条正右对准方向）；`"face"` = 不转、朝左时水平翻（标记类）；缺省不转。
- 旧画面条目写 `"cond": "!px_ul"` 关掉。形状被注册表接管时，`px` 条目照常播（`ob_core.px_keep`）。

### 14.3 缺省地面环跟开关（`ob_core.ring_on`）
圆形 / 锥形判定的 `ring` 除了 true / false，还可以写条件串，例 `"ring": "!px_ul"`：开关关时照画（和 main 一致），放开版打开时不画。

### 14.4 形状换主形 `alt`
注册表 `shapes[src]` 加 `"alt": [{"cond": "<条件串>", "base": "…", "skill": bool, "draw": {…}}]`，按顺序取第一条成立的，换掉 `base`（和 `skill`），`draw` 逐字段覆盖画法（例 fit）。例：乌尔比安 S2 生效后锚击换形，`"cond": "skill_active:1"`。

### 14.5 接管后照常播的条目
形状被接管时，fx 列表里照常播：`cond` 为 `relic:` / `node:` 的附加条目、`px` 条目、只放声音的条目（只有 `sfx`，没有 strip / pfx / gfx / blade 等画面字段）。

### 14.6 图鉴演示录像 `tools/px_demo_rec.py`
`python tools/px_demo_rec.py <干员> [--segs basic:0,1,2/s1:0,1,2/s2:1,2/s3:2/ult:2]`：按图鉴干员详情页的技能演示，每招 E0 → E1 → E2 各录一段，左上角标招式和档位，带声，拼成一个 mp4（取景同图鉴：舞台框 × `--k`）。每段可写第三段秒数（`s1:0,1,2:8`），`--start` 改起录时刻。

### 14.7 发散光环取消（用户 11-04，通用规则）
用户：「一些发散性的光环特效是不是可以取消」「斯卡蒂洒水出去的特效是不是可以取消」。
- **公共代码：** balance `fx/px_halo`，缺省 0。放开版打开时，下面这些都不画：形状缺省地面环、技能开启脚下扩散环、升级光环、连携落点环、精英化段缺省环、注册表的起手 `cast` / 增益 `ally` / 治疗 `heal` 挂点。设成 1 恢复。放开版关掉时不受影响（同 main）。
- **各干员自己的帧条和 seg 代码：** 往外扩散的环、光圈、光晕圈（含脚下增益环、命中扩散圈）一律去掉，不靠开关；往外甩的水珠 / 火星 / 碎屑也去掉（斯卡蒂源码加了 `spray` 选项，缺省 0）。招式本体的主形（例：斯卡蒂 S3 浪墙）不算光环，保留。

### 14.8 刀波 `waves`（原型拉普兰德，11-04 收进样板）
注册表 `"waves": {"<src>": {…}}`，三种写法可以组合，三项都没有（或缺图）时不接管：
- `base` `{base, variants, y, dist}`：整段飞行烤进帧条，原点 = 出手点，开播时沿方向放一次画完全程；判定飞行距离被成长改长时按 `dist` 比例拉。
- `proj` `{base}`：弹体式（单体命中 / 追踪的远掷、双生刃）——弹体帧条换成放开版，keep 等宽 4 帧，飞行停第 1 帧、消散放 2–3 帧（同 `proj_hold`），先画装饰层。
- `hit` `{base, y, sc}`：刀波每命中一名敌人，在它身上放一张命中帧条（不另定格）。

### 14.9 技能期间身上常驻 `aura`
注册表 `"aura": {"<技能序号>": {base, y, sc, back}}`：技能开着时在本人身上循环播（先装饰后核心，队友取 `_tm`）；`back: true` 画在本体后面。注意 §14.7：不能是往外扩散的光环。

### 14.10 弹体命中跳过通用画面 `px_hit`
`weapons.bullet_hit`：弹体字典带 `"px_hit": true`、带 `"op": <干员 id>`，且这名干员在注册表里有条目（开关打开）时，跳过通用命中画面（法术团爆炸 / 爆炸贴图 / 火花、法术弹 `fx_arcane_hit` / 环 / 火花、普通弹 `fx_bullet_hit` / 火花），命中画面由本人的放开版帧条画。伤害、控制、音效照旧。铃兰先用。
命中帧条写注册表 `"bullet": {"hit": {base, y, sc, variants, flip}}`（命中处先装饰后核心；`variants` 队长随机取种子变体，`flip: true` 弹体朝左飞时左右翻）；弹体本身用 `remap` 换（例 `"proj_arcane": "fx_suzuran_ul_fox"`，§14.14）。

### 14.11 召唤物接管（格式照凯尔希 11-04 提案）

### 14.25 圆形判定的帧条朝向 `aim`（组长 11-04「去匀圆」）
