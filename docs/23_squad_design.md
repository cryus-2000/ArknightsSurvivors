## 1. 决策摘要

- 从"单干员幸存者"改为"博士指挥编队"。
- **博士**是场上唯一的受击体：有生命值，会移动，敌人只追博士。
- **干员**不掉血、不会死，跟随博士自动输出，本质是"会移动的武器"。
- 编队上限 **3+1**：常规 3 人（开局 1 人，局内招募补齐）；第 4 位只能通过事件、藏品或商店解锁，不在常规升级池出现。
- 干员成长：精零 → 精一 → 精二，精二需要满足条件（类似武器进化）。
- 一局目标 15 分钟；正常路线三名常规干员全部精二，取舍来自投资顺序与精二条件。
- 新增局外成长：博士基础属性、护盾、编队加成、开局与功能解锁。
- 首批干员池 **8 人，一职业一个**。
- 不推翻现有架构：伤害描述符、Character 基类 + JSON、allies 框架、敌人数据驱动全部沿用。

## 2. 业界参照

- 吸血鬼幸存者 / Brotato：武器栏 = 本作的编队位；主角是唯一受击体，武器不会死；武器进化 = 本作精二。
- 明日方舟集成战略：招募券、精英化、按职业加成的藏品——本作的成长与藏品逻辑直接对应。

## 3. 实体模型

| 实体 | 脚本（建议） | 职责 |
|---|---|---|
| Doctor | `characters/doctor.gd` + `data/doctor.json` | 移动、受击、生命、拾取、镜头跟随、排异反应、手动指挥技能 |
| Operator | `characters/character.gd`（基类沿用）+ `characters/<id>.gd` + `data/characters/<id>.json` | 跟随博士、自动普攻、自动技能；无生命值 |
| Squad | `characters/squad.gd` | 持有编队位列表、招募/替换、编队校验、跟随队形 |

- 敌人 AI：目标固定为 Doctor。`enemies/enemy_ai.gd` 只需把玩家引用换成博士引用。
- 猎潮的骑士（`scripts/allies/knight.gd`）保持为结局同伴，不占编队位。

## 4. 战斗契约 v2.0（相对 v1.8 的变化）

### 4.1 不变
- `g._hit(src, extra_tags)` → `{src, emitter, origin, range, kind, tags}`；`_damage` 与 `relic_fx` 只读描述符。
- 共享来源在 `game.gd HIT_BASE`，干员来源在 `data/characters/<id>.json` 的 `hit_sources`。
- 不写 `out_src`。

### 4.2 变化
- `emitter` = 干员实例（或博士）；`origin` = 该干员当前位置。藏品可按 `emitter` 的职业 / id 判定。
- 描述符新增只读字段 `class`（干员职业），供职业藏品使用。
- **技能结构（v2.1，2026-09-25 改）：每干员普攻 + 三个自动技能 + 天赋**（详见 docs/26）：
  - 每个干员 JSON 必须有 `attack`（普攻）和 `skills`（恰好 3 个自动技能，SP 充能；招募 S1 / 精一 S2 / 精二 S3）；可选 `talent`（被动，精一解锁）。
  - v0.6 的"每干员一个技能"已废弃：水月不再是主心骨而是 8 名可选开局干员之一，所有人同构。
  - 手动技能只有一个，属于博士（`doctor.json` 的 `command`）。唯一入口 Space / J → `doctor.try_manual_skill()`。
  - 校验：`Character.create()` 调 `validate_operator()`（attack + 3 个 skills 且都为 auto；`progression` 结构合法）；`Squad` 调 `validate_squad()`（全队 manual 恰好 1 个，来自博士；常规人数 ≤ 3，解锁后 ≤ 4）。
- `gallery.tags` 保留，仍然只用于展示；新增 `class` 字段（先锋/近卫/重装/狙击/术师/医疗/辅助/特种），职业会参与数值判定。

## 5. 数值分层（stat_block）

```
stats.add(key, value, scope = "squad")
scope ∈ "doctor" | "squad" | "class:<职业>" | "op:<id>"
```

- **博士层**（doctor）：hp、hp_regen、armor、move_speed、pickup_range。
- **干员层**：atk、aspd、range、crit、skill_sp、skill_power 等。
- 干员最终值 = 干员基础 + squad + class:<自身职业> + op:<自身 id>。
- 兼容：旧调用不带 scope 时，生存类 key 自动路由到 doctor，输出类 key 路由到 squad；保留一个版本后移除。
- 难度加成照旧挂在敌人侧，不受影响。

## 6. 升级选项池

经验共享：博士拾取经验，升级后三选一。不做每个干员单独记经验。

| 类别 | 内容 | 出现条件 |
|---|---|---|
| 招募 | 从干员池抽一名未拥有的干员加入编队 | 常规编队未满 3 人 |
| 干员深度 | 成长线上的下一个节点（见 §7） | 至少有一名可升级干员 |
| 博士被动 | 生命、移速、拾取、护甲等 | 种类上限 4，已满后只出现已有种类 |
| 全队被动 | 全队攻速、职业加成等 | 种类上限 4，同上 |
| 填充 | 回复博士生命、少量全队加成 | 其他类别全部满级时 |

出卡规则：
- 只要还有可升级的干员，三张卡里至少一张是干员深度卡。
- **开局养成期**：Lv.2–4 不出招募卡，只出第一个干员的深度卡与博士被动；目标是约 1:00 时第一个干员到精一。
- 招募卡从 Lv.5 起进入池子。
- **招募保底**（按等级，不按时间）：Lv.6 时仍只有 1 名干员 → 下一次必出招募卡；Lv.12 时仍不满 3 人 → 同上。
- 精二节点只有在条件满足后才进入池子。
- 其他招募来源：事件（waves.json events）、商店招募券（按职业）。
- 第 4 位编队位：由事件、藏品或商店解锁（候选：深蓝线"深海馈赠"栏、特定事件），获得时占用一次藏品或事件选择。第 4 位干员直接以精一加入。
- 编队满员后的替换只由事件提供，低频；被替换的干员成长清零。

## 7. 干员成长线

每个干员 6 个节点（含招募）：

| 节点 | 内容 | 性质 |
|---|---|---|
| 招募 | 精零，普攻和自动技能可用 | 入队 |
| 升级 ×2 | 数值强化（每个干员各不相同，由 JSON 定义） | 量变 |
| 精英化一 | 解锁天赋，技能强化 | 质变 |
| 升级 ×2 | 数值强化 | 量变 |
| 精英化二 | 技能形态改变 | 质变，**需要条件** |

- 精二条件：持有对应藏品 / 拥有某项博士被动 / 编队里有特定职业，每个干员自定义。条件在 Tab 面板和图鉴里提前显示。
- 条件难度目标：正常路线在 6:00–7:00 前后能满足。
- 重复招募（若开放问题 4 定为"可以"）：潜能 +1，少量数值，不占编队位。

### 7.1 数据格式（草案）

```json
"progression": [
  {"type": "stat",  "effects": [{"key": "atk", "value": 0.15}]},
  {"type": "stat",  "effects": [{"key": "range", "value": 0.10}]},
  {"type": "elite", "level": 1},
  {"type": "stat",  "effects": [{"key": "skill_sp", "value": -0.15}]},
  {"type": "stat",  "effects": [{"key": "atk", "value": 0.20}]},
  {"type": "elite", "level": 2, "requires": {"relic": [221]}}
]
```

- 数值节点通过 `stats.add(key, value, "op:<id>")` 写入。
- 精英化节点调用干员脚本的 `on_elite(n)` 钩子处理天赋解锁与形态变化。
- 新增干员只需 JSON + 脚本，不改 game.gd。

## 8. 局时长与升级预算

目标一局 **15 分钟**（当前实测为 10 分钟；拉长放到 P5，与编队制的重新平衡一起做）。

### 8.1 实测数据（10 分钟版，`--balance --nodeath`，多种子，两条进化路线）

| 时间 | 等级 | 该段升级次数 |
|---|---|---|
| 0:00 → 2:00 | Lv.1 → 7 | 6（约 20 s / 次） |
| 2:00 → 5:00 | Lv.7 → 17 | 10（约 18 s / 次） |
| 5:00 → 8:00 | Lv.17 → 26 | 9（约 20 s / 次） |
| 8:00 → 10:00 | Lv.26 → 32 | 6（约 20 s / 次） |

10:00 约 31–32 次升级，全程节奏基本均匀。

### 8.2 15 分钟目标

- 约 42–45 次升级；节奏保持现在的均匀（约 20 s / 次），后期至多略微放缓。
- **正常路线三名常规干员全部精二**，约在 12:00–13:00 完成；最后两三分钟以满配状态迎战最终 Boss，强度高潮与剧情高潮重合。

### 8.3 预算

| 用途 | 次数 |
|---|---|
| 招募第 2、3 名干员 | 2 |
| 三名干员：精零 → 精二（各 5） | 15 |
| 干员深度合计 | 17 |
| 博士被动与全队被动 | 约 25–28 |
| 第 4 位（若解锁，以精一加入）：精一 → 精二 | 3（占用被动预算） |

### 8.4 里程碑

| 时间 | 升级次数 | 目标 |
|---|---|---|
| 0:00–2:00 | 6 | 1:00 前后开局干员精一；1:40 前后招到第 2 人 |
| 2:00–5:00 | 10 | 3:20 前后凑齐 3 人；第 2 人精一 |
| 5:00–8:00 | 9 | 第 3 人精一；6:00–7:00 主力 A 精二 |
| 8:00–11:00 | 9 | 第 2 人精二 |
| 11:00–13:00 | 6 | 第 3 人精二（全精二） |
| 13:00–15:00 | 6 | 满配阶段，最终 Boss；剩余投入被动 / 第 4 位 |

### 8.5 取舍从哪里来

全精二是一局打得好的奖励，取舍不靠"练不满"，而靠：
- **顺序**：先精二的干员多发挥数分钟，先投资谁仍是核心决策。
- **精二条件**：每个精二占用一个藏品或博士被动的选择；三人条件对不上时需要取舍或绕路。
- **第 4 位**：是否解锁、是否也练到精二，留给高手。

### 8.6 偏差与底线

- 数据来自 `--nodeath` 机器人，真人拾取效率可能更低。底线：约 35 次升级时仍能达到"两个精二 + 一个精一"。
- 底线以**局外成长为 0** 为准（见 §9）。
- 编队制会改变击杀速度与经验获取；P2 完成后重跑 `--balance`，并让它输出升级次数与每次升级时间点。
- 复测明显偏少：每段数值节点从 2 压到 1（每干员 4 节点），或把招募移出升级池。明显偏多：放缓后期经验曲线。

## 9. 局外成长

### 9.1 目标与原则

- 让失败也有收获（缓解在第 13 分钟死亡的挫败感），降低新玩家门槛，给反复刷四个结局提供动力。
- 局外只加"底子"，不替代局内构筑。满级局外的总提升控制在有限范围（草案：有效强度约 +25%，待 `--balance` 校准）。
- **局外为 0 时游戏必须能通关**（至少结局一）。

### 9.2 货币

- 名称待定（优先用水月主题的名字）。
- 来源：存活时间、击杀精英 / Boss、事件奖励、结局达成（首次达成额外奖励）。
- 死亡同样按存活时间结算。

### 9.3 项目

| 类别 | 项目 | 作用层 |
|---|---|---|
| 博士基础 | 生命上限、护盾（§9.4）、护甲、移速、拾取范围、生命回复 | doctor |
| 编队 | 全队攻击、技能充能 | squad |
| 开局 | 开局可选干员解锁、开局重抽次数 | — |
| 功能 | 升级卡重抽 / 跳过 / 禁用次数 | — |

- 每项分若干级，费用递增。
- 具体数值与级数在 P6 用 `--balance` 校准。

### 9.4 护盾（新机制）

- 属于博士层：`shield_max`、`shield_regen_delay`、`shield_regen_rate`。
- 受击先扣护盾；一段时间未受击后开始回复。HUD 在生命条上方显示护盾条。
- 局外护盾初始为 0，点出第一级后才出现。
- 重装职业提供的护盾与之**共用同一个护盾池**（上限相加），不另设叠加规则。
- 局内的博士被动与藏品也可以提高护盾，走同一套 key。

### 9.5 实现

- 开局时把局外加成以 `stats.add(key, value, scope, source = "meta")` 写入；stat_block 需要支持 source 标签，Tab 面板可按来源分开显示。
- 存档复用现有保存 `Cfg.endings_cleared` 的存档文件；网页版的 `user://` 由浏览器本地存储保存，清除站点数据会丢档，需要在界面上提示（后续可考虑导出 / 导入存档）。
- 平衡测试：新增 `--meta=0` 与 `--meta=max` 两档，`--balance` 两档都跑；底线以 `--meta=0` 为准。

## 10. 职业定位（博士掉血、干员不掉血的前提下）

| 职业 | 定位 | 说明 |
|---|---|---|
| 先锋 | 节奏 | 加快全队技能充能 / 指挥技能冷却；近身低伤 |
| 近卫 | 近战输出 | 博士周围高频扫击 |
| 重装 | 护博士 | 阻挡圈（接触的敌人被推开或减速）或给博士护盾；带少量伤害 |
| 狙击 | 远程单体 | 优先精英 / Boss |
| 术师 | 范围法伤 | 无视护甲的群体伤害 |
| 医疗 | 护博士 | 治疗博士；技能附带少量伤害，避免纯空位 |
| 辅助 | 控制与增益 | 减速、易伤、给其他干员加成 |
| 特种 | 机制 | 位移、推拉、爆发 |

编队只有 3 个常规位，带重装或医疗意味着少一个输出位——这是有意保留的取舍。

开局约 1:40 内只有一名干员，因此：
- 每个职业的普攻都必须能独立清掉前两分钟的敌潮（医疗、重装也不例外），或由博士指挥技能补足前期伤害。
- 精一天赋不得依赖其他队友才生效，保证单人阶段拿到精一不是空卡。

选人原则：**人气优先，兼顾水月主题**；职业以官方资料为准，定稿前逐一核对。

### 11.2 解锁干员（战绩解锁）

| 干员 | 职业 | 解锁条件（草案） | 说明 |
|---|---|---|---|
| 浊心斯卡蒂 | 辅助 | 击败伊莎玛拉（结局三） | 歌声光环：提高其他干员攻击 |
| 待定 | — | 其余结局 / Boss | 候选：歌蕾蒂娅、乌尔比安、归溟幽灵鲨、能天使、银灰 |

- 解锁状态与 `Cfg.endings_cleared` 存在同一存档；选人界面显示锁定剪影与解锁提示，图鉴同步。

- 扩展节奏：系统验证完成后扩到 12–16 人，每个职业再加一种不同玩法的变体。

## 12. 水月、排异反应与结局迁移

- 水月从"主角"变为特种干员之一；原三技能压缩为 attack + skill，原手动技能的功能并入 skill 或 talent；原技能升级改写为她的 progression。
