# 128 干员 1 倍密度重画 + 移动攻击帧条（Codex 单，试点）

2026-10-23 用户定（光学观感预览后）：「可以交给 codex 重绘干员」；「是不是也得只做干员边跑步边攻击的效果，否则现在攻击动画还没播完就接上跑步动画显得很怪」。
口径仍以 docs/103（尺度、比例、七条约束）、docs/104（制作与验收流程）为准，本单只写范围和这两处改动。

## 1. 为什么改

- 光学观感（render/optical，docs/50 §25）把世界层画成「1 美术像素 = 2 世界像素」的统一像素格。干员是 @2x（半个美术像素的细节），放进这一层要么被硬缩（脸毁掉，见 `build/look_proto/ops2x/compare_face.png`、`downsample_test.png`：最近邻 / 平均 / 保线条三种自动缩法都不行），要么单独画在高清层：像素密度和世界不一致（用户：「果然还是怪」），也没法和怪物按站位前后遮挡。
- 结论：干员要按世界的像素密度**原生画 1 倍**，不能靠算法缩。

## 2. 1 倍重画口径（相对 docs/103 的改动）

- 交付 1x（不交 @2x）：画布、原点、脚底、帧数与现 @2x 帧条**逻辑尺寸相同**（@2x 数值 ÷ 2）；站立高约 32、头高 13–16（docs/103 @2x 卡值 ÷ 2，比例项不变）。
- **注意（需用户在试点时确认）**：10-15 I 批逻各斯首交 36 像素小人被判「脸被压扁」，之后才改成 @2x 原生画细节。1 倍下脸内只有约 14 像素，眼 1×1 或 1×2；docs/103 §5「Q 版大头、脸内比例取原作」照用。试点不过，退路是保留 @2x + 高清干员层（render/optical_ops_hi = 1，现状）。
- 按部件在 1x 网格上画（docs/104 §2 第 4 条），禁止由 @2x 整张缩图交付。

## 3. 移动攻击帧条（新槽 move_attack / 技能同理 move_skill_N）

- 现状：攻击出手帧之后只要在移动就切到跑步（character.gd `act_anim_yield`），收势帧被截掉；出手前移动则原地播攻击、脚不动地滑行。两种都怪。
- 新帧条：**下半身 = 本人跑步循环，上半身 = 本人攻击动作**，按 docs/104 §3 分层合成（同一套拆层，腿层取跑步、臂 / 武器 / 躯干层取攻击），不新造姿势（原作没有移动攻击，这里是原作两段动作的部件拼合，不算自创）。
- 帧数与时长 = 攻击帧条（含 fire 出手帧位置不变）；腿部按跑步相位循环，首帧腿姿 = 跑步第 0 帧，末帧能接回跑步任意帧不跳（腿层逐帧对齐跑步帧条）。
- 远程 / 施法同理；技能帧条中站定施放的（原作就是站桩的大招）不做移动版，由引擎决定是否锁移动表现。

## 4. 范围与节奏

1. **试点：水月**（流程同 docs/104 §5「流程验证一次」）：待机 f0（1x）→ 用户在局内（光学观感开）看过 → 跑步 → 攻击 → 移动攻击。
2. 试点过了再按簇包放开其余干员（docs/97 J 批名单顺序）。
3. 交付路径：`codex/art` 分支 `art/incoming/<op>_runtime_<kind>.png`（1x），handoff 写帧数 / fire / foot。

## 5. 引擎侧（Claude，交付后做）

- 加载：同名 1x 与 @2x 并存时按干员开关选 1x（试点期间可对照）。
- 动画：攻击 / 技能期间 `mv > RUN_ENTER` 且有 move_attack → 播移动攻击（攻击时间轴），结束接跑步，跑步相位取移动攻击末帧对应的腿相位；没有移动攻击帧条的干员维持现逻辑。
