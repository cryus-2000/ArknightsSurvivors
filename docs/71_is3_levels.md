## 0. 一页结论

- **16 级潮位 0–15，逐级叠加**：每升一级加一条新规则（或把前面某条「加重」），前面的规则全部保留；玩家可选任何已解锁的级；通关 N 解锁 N+1。
- **锚点不动**：潮位 0 = 今天的标准、潮位 4 = 今天的 Ⅳ（**逐键相等**）、潮位 8 = 今天的 Ⅷ + Ⅳ 的「寒流」两键。工具开头逐键核对（§2.3），现有校准继续有效；只有潮位 8 多了控制收紧，需要一轮 112 局确认（预计不动胜率）。
- **15 条规则里 14 条只用现有 dmod 键**，1 条要新键（领潮者 `elite_hp` / `elite_dmg`，约 1 小时；校准时用全局 `enemy/elite_*_mult` 代替，**不用等代码就能跑**）。
- **校准**：0 / 4 / 8 已有；新增检查点 12、15 各 224 局；中间各级只要求单调（同 seed 逐级扫描 + 每级「规则咬到了」的配对指标）。全套约 **2 300 局 ≈ 77 核时，4 个 16 核云端例行任务约 1.5–2 小时**，比 docs/68 的 6 050 局少六成。
- **荣誉**：每名主控「通关过的最高潮位」徽记（选人 + 图鉴 + 档案）、全干员最佳、结算写本局潮位与本级新规则；存档新段 `[tide]` + 迁移（§4）。
- **要用户定**（§8）：上限 15 还是像原作到 18；检查点 12 / 15 的目标；顶级用「潮不止息」（恢复最终 Boss 战刷怪）可不可以；对外包旧存档认不出「通关过 Ⅷ」怎么办。
- **工时**：P1 约 33 小时（数据 + 页面 + 结算 + 徽记 + 存档），P2 校准约 6 小时人工 + 云端；P0 一个 0.5 小时的小补丁建议**现在**先上（§4.4）。

## 1. 假设（制作人对「水月肉鸽风格」的解读，写明作为前提）

1. 原作水月「波涛迭起」是 **0–18 的编号难度**，每级在所有更低级之上**再加一条规则**（累加），玩家可选任何已解锁的级，通关第 N 级解锁第 N+1 级；难度列表把每级的规则全部列出、**新加的那条高亮**（docs/49a §3.8）。
2. 本作照此映射：「波涛迭起」是模式名，下面是**潮位 0–N**；沿用难度页现有的竖潮位尺（docs/67 §12），尺上的刻度从 3 档变成 N+1 级。
3. 有些规则是**加重**前面的规则（敌人生命 +20% → +70%），和原作「元素损伤 +15%」出现三次一样。
4. 只给荣誉：通关更高的级不解锁干员、藏品、结局或任何数值。
5. 本作 1.1 之前其实有过一版 11 级累计难度（`data.gd DIFFICULTY`，暗潮 / 浊流 / 昏灯……），1.1 用户定「界面只给 3 档，以后再推多难度」。这次是在 3 档校准过的内容上把它重新展开；旧的 11 级表只留给批跑 `--diff=`（旧数据对照），不再显示。

和 docs/68 比，**删掉**：自定义条目板、风险分、互斥、逻辑回归校准、帕累托前沿纪录。**沿用**：docs/68 的条目旋钮（作为 9–15 级的规则来源）、潮位徽记、结算版式、像素图标与配色。

## 2. 阶梯表

### 2.1 规则

- **每级一条规则**，一句话写完；必要时一条规则动 2–3 个同主题的键（「Boss 生命 +15%，预警缩短 15%」），和原作「精英和领袖攻防生命 +20%」同一种写法。
- **严格累加**：第 N 级的修正表 = 第 N−1 级的表再写入本级的键；同一键后写覆盖，**只能往更难的方向推**（工具 `严格累加检查` 断言）。
- **补偿跟着规则走，单列绿色**：今天 Ⅳ / Ⅷ 里的放宽项（围猎 `hunt_dur` / `hunt_ring_hp`、灯标 `beacon_every` < 1、终局杂兵 `boss_fight_enemy_hp`）挂在引起它的那一级上，规则行不写（读起来不像「难度规则里夹着放宽」），档案里在规则列表下用一行绿字「补偿：……」写明，不藏。
- **锚点块**：1–4 级的合计必须等于 Ⅳ，5–8 级的合计必须等于 Ⅷ（+ 寒流）。所以**块内的级可以随意换顺序或重新分组，锚点表不变**——这是单调性出问题时的第一手段（§2.5）。9–15 级没有锚点，可以自由调整。

### 2.5 为什么是这个顺序，单调性风险在哪

- 原则：每块里从「小、读得懂」到「大」；Boss 规则最先（只在 3:30 / 7:00 / 10:00 咬人，最温和），敌群整体加强放在块尾；补偿挂在最大那一级上（3 级的敌人 +20% / +20%、7 级的 +70%、8 级的溟痕常驻），不让「补偿」单独成为一级的净效果。
- **风险清单**（P2 扫描必须先看这几步）

| 一步 | 为什么可能不变难 | 依据 | 不单调时怎么办 |
|---|---|---|---|
| 2 → 3 | 灯标 ×0.8 与围猎放宽同时进来 | §8.12：灯标 +20 灯火、圈内安全 | 块内换序：把灯标补偿挪到 4 级（1–4 合计不变） |
| 3 → 4 | 控制旋钮对机器人零效果 | HM6 p 1.00 | 大群 +20% 那一半会咬（close7：Ⅳ 1.2 → 1.0 变易 71% → 82%）；仍不动就与 3 级对调 |
| 7 → 8 | 大群 1.6 是主要经验来源，加上它可能变易 | close7：Ⅷ 1.6 → 1.2 反而变难（39% → 21%） | 块内换序：大群 +60% 挪到 7 级与敌人生命同级、8 级只留溟痕；仍不行加 docs/68 的 `horde_xp`（大群经验不涨） |
| 8 → 9、11 → 12 | 后期伤害上限、词条提前的量级没测过 | — | 9–15 无锚点，直接换序或加量 |
| 3 → 4、5 → 6 中的「预警」部分 | 机器人测不出、人感觉得到 | HM4–HM6 | 不单独成级，已和生命 / 伤害捆在同一级 |

### 2.6 数据与调试参数（P1）

- `balance.json difficulty/ladder`：对象，键 `"1"`–`"15"`，每项是这一级写入的 dmod 键（含补偿键）；`difficulty/standard | hard | extreme` 删掉（或留作 `check.py` 的对照常量）。用对象而不是数组，是为了云端可以直接 `--bal=difficulty/ladder/7/enemy_hp=1.8` 改某一级（`Bal._load` 支持任意深度）。
- `data.gd`：`const LADDER`（名 / EN / 规则 / 短句 / 氛围 / 组色 / 加重关系，界面用）；`dmod_for_tide(n)` = DMOD_DEFAULT 逐级写入；`dmod_for_tier(t)` 改为 `dmod_for_tide([0, 4, 8][t])` 兼容旧调用；`DIFFICULTY_TIERS` 退役（HUD / 结算改读 LADDER）。
- 快检断言：`dmod_for_tide(0 / 4)` 与旧 standard / hard 表逐键相等；`dmod_for_tide(8)` = 旧 extreme + {ctrl_start 300, frost_max 2}；严格累加（同工具的检查）。
- 启动参数：新增 `--tide=N`；`--tier=0/1/2` 保留并映射到 0 / 4 / 8；`--diff=`（旧 11 级）不变。`g.diff` 改为潮位（今天就是 0 / 4 / 8，旧分析脚本照常读）；`runs.jsonl` meta 与 BALANCE 行加 `ladder_ver`（`"71-1"`），区分「旧 Ⅷ」和「潮位 8」。

## 3. 解锁

- **通关** = 打死最终 Boss 进入胜利结算（`victory_flow.record_win`），**四个结局都算**。不算：死亡、中途退出、Boss 演练（`g.trial.active`）、练习（`Cfg.practice_active`）、图鉴演示、BALANCE 模式与任何带 `--` 参数的测试局（同 `Cfg.save()` 的判定）。倍速照算。
- 通关潮位 N：`tide_unlocked = max(tide_unlocked, N + 1)`，上限 15。通关已经低于前沿的级不推进前沿（只可能刷新干员纪录）。
- 选择：任何 ≤ 已解锁的级都能出发；**未解锁的级也能翻过去看规则**（同现行），出发换成灰边「未解锁」，档案底部写「通关潮位 N−1 后解锁」，列表上紧挨前沿那一行写「通关上一级解锁」，更高的只画锁。
- 打开难度页默认选上次出发的级；**刚解锁的那一级第一次打开时默认选中**，行尾一个小「NEW」，之后恢复「上次出发」。
- 调试版 / 对内包「全部解锁」（`Cfg.unlock_all`）：只在内存放到 15，存档里的真实前沿由 `_real_progress` 写回（同现行）；纪录照常写（纪录是真打出来的）。
- 结算的「挑战潮位 N+1」只在这局刚解锁时出现。

## 4. 荣誉与存档

### 4.1 记什么

- **每名主控**（开局干员 `g.ch.id`）通关过的最高潮位 + 那一局的结局、用时、日期、版本、`ladder_ver`。
- 派生（不存）：全干员最佳（带干员名）、通关过任何潮位的干员数。
- 徽记分段**按级固定**（不像 docs/68 随校准移动）：未通关「-」暗灰空盾；0–3 钢蓝边；4–7（≥ 原 Ⅳ）潮水底；8–11（≥ 原 Ⅷ）S4 反白；12–14 反白 + 一道潮线；15 反白 + 潮线 + 泡沫光。
- 以后若改了某一级的内容（`ladder_ver` 变），纪录保留级数，档案里注「阶梯 v1」，不重算、不清空。

### 4.2 存档（`settings.cfg` 新段 `[tide]`）

| 键 | 类型 | 说明 |
|---|---|---|
| `tide_ver` | int | 1（迁移标记） |
| `level` | int | 上次选的潮位（取代 `progress/difficulty`） |
| `unlocked` | int | 已解锁的最高潮位（取代 `progress/diff_unlocked`） |
| `fresh` | int | 刚解锁、还没看过的那一级（−1 = 无；§3 的「NEW」） |
| `best` | Dictionary | `{op_id: 8, ...}` |
| `best_meta` | Dictionary | `{op_id: {"ending": "deep", "t": 702, "date": "2026-10-12", "ver": "2.0.x", "ladder": "71-1"}}` |
| `legacy_best` | int | 迁移来的「旧存档已通关的最高潮位（干员不明）」，−1 = 无 |

降级兼容：`progress/difficulty`、`progress/diff_unlocked` 继续按派生值写（`level` → 档 0 / 1 / 2 取不超过它的最高档；`unlocked` ≥ 5 → 2、≥ 1 → 1），旧版本读到的仍是合理的 3 档进度。

### 4.3 迁移（`tide_ver` 不存在时，一次性）

| 旧存档 | → `unlocked` | → `legacy_best` |
|---|---|---|
| `diff_unlocked` 0（没通关过） | 0 | −1 |
| `diff_unlocked` 1（通关过标准） | 1 | 0 |
| `diff_unlocked` 2（通关过 Ⅳ） | 5 | 4 |
| 通关过 Ⅷ | **9**（见下：对外包认不出） | 8 |

- `level` = 上次选的档 0 / 1 / 2 → 0 / 4 / 8，再夹到 ≤ `unlocked`。
- **对内包 / 调试版**：有 `user://runs/runs.jsonl` 时回填——`meta.result == "win"` 且 `meta.diff ∈ {0, 4, 8}` 且版本 ≥ 1.1（3 档时代）的行：`unlocked = max(unlocked, diff + 1)`、`best[meta.start_op] = max(…, diff)`。这样「通关过 Ⅷ ⇒ 解锁 9」在内部包里是准的，各干员徽记也能回填。
- **对外包认不出「通关过 Ⅷ」**：`diff_unlocked` 到 2 就封顶（`record_win` 只推到最高档下标），`endings_cleared` 不带难度，对外包也不记 `runs.jsonl`（docs/43）。见 §4.4。
- `legacy_best` 计入「全干员最佳」，图鉴档案页角落显示「旧存档：最高通关潮位 4（干员未记录）」；各干员徽记从下一局起记。

### 4.4 建议现在先上的小补丁（P0，约 0.5 小时，不改玩法）

`record_win` 里多写一个 `progress/diff_cleared = max(旧值, g.tier)`（只在非测试、非演练、非练习时），随下一次发版出去。之后迁移按它把「通关过 Ⅷ」映射成 `unlocked 9 / legacy_best 8`。补丁之前就通关过 Ⅷ、之后没再通关的对外玩家只能拿到 5（要再打一次潮位 8，内容 = 旧 Ⅷ + 寒流）。替代做法见 §8 问题 4。

### 5.4 单调判定

- 56 局的胜率差噪声约 ±9 点，单步（预估 2–6 点）测不出，所以**不用胜率逐步判**。三条一起看：
  1. **胜率不反向**：相邻两级同 seed 配对，负转胜 − 胜转负 ≥ 4（≈ 易了 7 点）记为可疑，进 S4 补到 112 对；112 对里符号检验 p < 0.1 偏易才算不单调。
  2. **规则咬到了**：每一级挑一个直接受这条规则影响的连续指标，同 seed 配对看方向（符号检验）：1 / 6 / 14 Boss 击杀用时与 Boss 伤害（`bosses`）、2 / 5 / 10 低灯秒数（`lamp`）、3 / 7 承伤与击杀用时（`dmg`）、4 被控次数（`ctrl`）与大群、8 溟痕伤害与灯火、9 7:00 后承伤、11 精英阶段用时（`elite` / `elite_stage`）、12 词条怪伤害、13 最低生命（`minhp`）、15 终局死亡数与终局击杀用时（`final_out`）。
  3. **整体趋势**：对 0–15 做带主控固定效应的逻辑回归（每级一个增量），报告每步增量与区间；作为报告，不作为单独的判定。
- 不单调时按 §2.5 在块内换序 / 重新分组（锚点不变），只重跑受影响的两三级。
- 检查点超出目标：只动 9–15 级（加量或换规则），0–8 不为检查点改。

## 8. 开放问题（给用户）

1. **上限**：15（本文）还是像原作做到 18？到 18 要再找 3 条规则，其中原作味最重的几条都要新键（§2.4），P3 再做比较稳。
2. **检查点目标**：潮位 12 熟练 35–50%、15 熟练 10–25%，可以吗？（0 / 4 / 8 仍按 50–70。）
3. **潮位 8 加上「寒流」**（控制 5:00、寒霜 2 层）让阶梯严格累加：同意的话跑 S0 确认（预计不改胜率）。
4. **对外包旧存档里「通关过 Ⅷ」认不出来**：推荐先上 P0 小补丁，补丁前的只给到 5（要再打一次 8）；或者干脆「通关过 Ⅳ 的旧存档直接解锁到 9」（只是开放挑战，不给奖励，最省事但不算「挣来的」）。
5. **顶级用「潮不止息」**（最终 Boss 战恢复刷怪）——它是用户 10-11 要求关掉的东西，放在 15 级当最终考验可以吗？不行的话换「限时击破最终 Boss」（新键 `final_limit`）。
6. **补偿写法**：规则行不写补偿、档案里绿字单列（本文），还是规则行直接写「（围猎与灯标随之放宽）」？
7. **名字**：模式名「波涛迭起」+「潮位 0–15」+ 各级名（海面 / 巨影 / 昏灯 / 暗涌 / 寒流 / 搁浅 / 渊影 / 甲潮 / 漫灌 / 夜潮 / 残烛 / 领潮者 / 异变 / 深压 / 渊主 / 潮不止息）是否满意？
