>
> **10-15 改版（用户定）**：卡值改按 §6 PRTS 实测；簇间靠肩宽、头身、服装区分，不再靠脸型；新增不驼背、细节对齐小人、像素尺寸对齐、优先级、朝向与持械、姿势取材、交付硬流程七条（§5）。改版前的卡（按现版脸下半分簇）作废。

## 1. 量法

- 工具：`python tools/body_metrics.py`，输出终端表与 `build/body_metrics/report.md`（`--json` 另存）。样本是 `sprites.idle` 的 f0，在 @2x 上量，**全部换算成 1x 像素报**。
- 自动量：站立高、头宽、肩宽、腿长、脚底 x。
- 人工标：眼和下巴在 1x 下只有 1–2 像素，自动识别不可靠（白发角色会把头发当成皮肤），所以在 @2x ×11 网格图上读数，写在脚本的 `ANNOT` 表里（`build/body_metrics/face2x_*.png`，±0.5 像素 1x）。
- 抽查：水月、逻各斯、凯尔希、塞雷娅四人和整身网格图（`build/body_metrics/grid_*.png`）对过。塞雷娅的下巴第一次读错（脸小，被盾的白色挡住），已改。
- 定义：
  - 站立高 = 脚底行 − 最高不透明行 + 1，帽 / 耳 / 角都算。
  - **头高 = 下巴 − 发顶 / 额头，不含帽 / 角 / 耳 / 光环**（10-15 协调人定口径）。发顶在整身网格上人工读（脚本 `HAIR_TOP`）。帽子盖住头顶的四人（斯卡蒂、浊心斯卡蒂、水月、乌尔比安）按「眼心 − 8.75」推算，8.75 是其余 13 人眼心到发顶的中位；乌尔比安面罩遮眼，按「下巴 − 12」推算。
  - 头饰高 = 发顶 − 最高不透明行，单列。
  - 头身比 = 头高 / 站立高。
  - 眼高 = 眼心在头高里的位置（0 = 发顶，1 = 下巴）。
  - 眼到下巴 = 下巴 − 眼心。这是脸下半的长度，不受帽子、角、耳影响，**比头身比更能区分脸型**。
  - 头宽 = 眼高那一行主体段的宽（含两侧头发）。
  - 下巴宽 = 下巴往上 1 像素处的脸宽。
  - 肩宽 = 下巴往下 1–4 像素的最大行宽。
  - 腿长占比 = 两腿分开的最高行到脚底 / 站立高。裙子和长外套会盖住腿，这一项只作参考。
  - **前倾** = 头部中心 x − 骨盆中心 x（1x，朝右为正）；**脖子** = 肩线 y − 下巴 y。三个点（头部中心、骨盆中心、肩线）人工标在脚本的 `POSTURE` 表：自动取中点会被长发、尾巴、武器、披风带偏（试过，偏到 ±8 像素）。头部中心 = 颅顶到下巴那块头的左右中点（不含马尾、耳、角、帽檐）；骨盆中心 = 胯部左右中点（裙 / 外套盖住时取两腿内侧中点）；肩线 = 肩膀最高点所在行。
  - 新卡的头身数、腰位、眼距 / 头高等比例项口径同 §6（头身数 =（脚底 − 发顶）/ 头高，不含头饰；腰位 =（腰 − 发顶）/（脚底 − 发顶））。

用户定「旧版画风为准」，美术现在整体暂停。现有 18 人按新卡逐个调比例，等于又一次整组重画，所以**不按卡返修**。§2 的表只记录现状；新卡只约束之后的新画和用户点名的返修。

## 4. 画法要点（来自 §6）

- **脸**：四簇共用一套比例——眼睛在头高 0.70–0.80 处，眼下到下巴 2.5–3.5 像素，瞳心距 4.5–5 像素。区分角色靠发型轮廓、瞳色、眼睛画法，照小人画。
- **身架**：成男肩最宽（外套 / 披风撑开），成女次之，少女再次，少年最窄；成人（成女、成男）头身比少 / 幼高一点，头显得小。
- **腰腿**：腰在身高约 0.6 处，腿至少占 0.25。跑动帧腿太短会糊成一团。
- **站姿**：头、脊线、骨盆在一条竖线上；脖子露出至少 2 像素，头不往前探。

## 5. 规则（Codex 新画 / 返修必须引用）

**优先级：PRTS 小人 > 立绘 > 模板卡。**三者冲突时按前者，交付说明里写明哪一项按什么取的。

1. **不驼背**（可量）：站立帧（待机全部帧）**|前倾| ≤ 1 像素**（头部中心与骨盆中心横向偏差，1x），脊线竖直，**脖子（下巴到肩线）≥ 2 像素**。交付时在 `tools/body_metrics.py` 的 `POSTURE` 表补这一行（头部中心 x、骨盆中心 x、肩线 y，1x），脚本给出前倾、脖子和 ✓ / ✗。
2. **细节对齐小人**：瞳色、发型轮廓、武器形制、衣服分色块、饰件位置**一律以 PRTS 小人为准**；立绘只在小人看不清的地方补充。**不许新增小人没有的饰件、武器、配色。**交付附「瞳 / 发 / 发饰 / 主服色 / 饰边与飘带 / 袜靴 / 武器」七项逐项对照。
3. **像素尺寸对齐**：画布 **64 × 64**（1x）/ **128 × 128**（@2x），脚底原点 = 旧 48 画布原点 **+ (8, 14)**（例：(24, 46) → (32, 60)，逻各斯 (25, 46) → (33, 60)），即水平居中、脚下留 3 行；角、帽、武器、披风画全，不许被画布裁到（离画布边至少 1 像素）。同簇发顶到脚底 ±1（§3）；同一干员各动作帧的画布网格、脚底线、原点一致；不混 1x 与 2x 的细节密度（@2x 只是 1x 的放大或同密度细化，不在 1x 帧上画半像素细节）。
   - 接入（10-15 代码已适配，48 与 64 画布可混用、同一干员不同动作也可不同）：帧尺寸按贴图读，json 里改该动作的 `foot` 即可；帧条里标了逐帧定位点的（星熊 `shield`），换画布时点不用重标，在该动作加 `pt_foot` = 旧 foot。界面判倍率按身体高（脚底往上 37 美术像素封顶，`UI.fit_h`），角 / 武器超出不降倍、超出部分可能被卡片 / 舞台边裁掉。
   - **@2x 原生细节纪律（10-15 用户定，docs/97 I 批试验 3）**：① @2x 层也按像素画：禁止抗锯齿式的单点高光，高光、亮边至少 2 像素成组；② 1x 由 @2x **自动缩图**生成（面积平均 + 吸附色板），再用 `tools/px_lint.py` 把孤点 / 单点高光清到 0，只人工修工具圈出的点；不要求逐像素人工重排（10-15 用户定：战斗里用 @2x 层，PX = 2 下 1:1 显示，验收以 @2x 为主，1x 只过 px_lint）。@2x 和 1x 的比例、设定色、姿势一致。
4. **朝向**：一律朝右。
5. **持械**：武器拿在小人的同一只手、同一侧，各动作不镜像、不换手。
6. **姿势取材**：待机、攻击、技能三组动作按 PRTS 小人对应动画的帧取姿势（`build/prts_ref/<id>/idle_* / attack_* / skill_*`），不自创动作。
7. **交付硬流程**：
   - 先只交**待机 f0 单张**（1x + @2x）。
   - 验收看**四列对照**（立绘 / PRTS 小人 / 上一版 / 本版）加**量表**：站立高、头身数、眼高、眼到下巴、眼距、肩宽 / 头宽、腰位、腿长占比、前倾、脖子，以及第 2 条的七项对照。
   - **任一项超出 §3 区间或第 1–6 条，整张退回**；用户看过说「没问题」才画其余动作。
   - 其余动作交付时同样附量表（每帧前倾、脚底线、原点）。
8. **返修**：在 main 现版帧上改（docs/87 §4.3），交付附改前 / 改后逐像素 diff；按用户点名的项改，其余不动。
9. **整组重画**：只有协调人单子写明「重画造型」才允许，同样走第 7 条的硬流程。

## 7. 脸部符号化与认人三要素（草案，**待用户认可**；10-15 界面与美术）

> 来源：用户问「除了压缩像素还有没有别的办法」，选了架构列的第 1、2 条先试（10-15）。逻各斯试验图：`.claude/worktrees/manual/build/sym_compare_1015/`（界面与美术工作树的 build/，不入库）。**本节不改 §3 卡值**，用户认可后再并入 §4 / §5。

### 7.1 分工：认人和像原作分开

- **战斗小人**只负责「一眼认出是谁」，靠下面三要素（§7.3），不追求五官像原作。
- **像原作**交给已有的大图：队伍栏头像、招募卡、图鉴立绘。
- 可选（新机制，未做）：技能释放时的大头像特写（cut-in），要先出静态示意图给用户审。

### 7.2 脸部符号化口径（1x；@2x 对应翻倍、可在同一位置加细节）

| 项 | 口径 |
|---|---|
| 眼睛 | **2 × 2 的瞳色点**（头高 13 以下可用 1 × 2）；不画眼白、眼线、睫毛。瞳色仍按 PRTS 立绘设定色（docs/87 §4.3），不能因为符号化丢设定色 |
| 鼻 | 不画 |
| 嘴 | 待机 / 跑步不画；只在表情帧（受击、放技能）画，1–2 像素 |
| 眉 | 不单画，靠刘海下沿 |
| 省下的像素 | 给发型轮廓和头饰（角、耳、光环、帽檐）——剪影最高点要清楚 |
| 比例 | 眼高、眼到下巴、眼距仍按 §3（符号化只改画法，不改位置） |

逻各斯试验结果：在返修 1 的 B / C 稿上只改眼睛和眼线 / 鼻 / 嘴（B 18 像素、C 15 像素），B 稿在实际尺寸下眼睛一眼可读、「脸被压扁」的观感明显减轻；C 稿本来就是 2 × 2 瞳，变化小。
