# 118 干员响应动作（设计稿）

状态：设计稿（10-21），只出方案、未改代码。分支 `claude/op-verbs-design`。
依据：用户与协调人 10-21 讨论——干员之间现在基本只差数值，玩家作为指挥者没有可做的决定。方向已定：在自动技能之外，给每名干员加一层**响应动作**，由队长的动作触发。

## 1. 原则（已定）

1. **轻**：响应是附加收益。不触发不吃亏——不触发时干员和现在完全一样，没有「必须做 X 才能打出伤害」。
2. **不动现有规则**：自动技能、普攻、成长线不变；「手动技能只对队长」不变（docs/114 之外不新增手动键）。
3. **四类触发源**，都是玩家本来就在做、不新增按键的动作：
   - **冲刺**：队长按下冲刺（现有冲刺键，冷却 1.2 秒，机动卡最低约 0.72 秒）。
   - **站定**：队长连续 0.6 秒没有移动（摇杆 / 方向键松开；被定身不算）。
   - **开技能**：队长自己的技能释放（自动或手动都算，看出手那一刻）。
   - **指挥**：指挥模式切换（docs/114：随行 → 突击 → 归队），各条写明认哪一种切换。
4. **机动性约束**（用户原话：「队友的冲刺和队长的冲刺间隔一致比较合理，否则队友机动性太强」）：凡是让**队友自己位移**的响应（冲刺、跃起落到别处、顺锁链弹射、扑击换位），要么由队长冲刺触发，要么冷却不短于队长冲刺的当前冷却（读 `dash.cd` × 机动卡倍率，不写死 1.2）。原地动作、拉怪、推怪不受此限。
5. **每人一条**，一名干员只响应一类触发源，便于玩家记。
6. 响应效果尽量复用现有积木（shape / verb），新增的只是四个触发器（§3），干员接入仍然只填 json（docs/108 §10）。

## 2. 四类触发源的分配

| 触发源 | 人数 | 干员 |
|---|---|---|
| 冲刺 | 4 | 德克萨斯、能天使、斯卡蒂、乌尔比安（推进之王已删，用户 10-29） |
| 站定 | 5 | 星熊、塞雷娅、艾雅法拉、维什戴尔、流明 |
| 开技能 | 4 | 铃兰、凯尔希、逻各斯、浊心斯卡蒂 |
| 指挥 | 4 | 水月、归溟幽灵鲨、艾丽妮、安洁莉娜 |

分配思路：冲刺给本来就以突进 / 近身为主的人；站定给重装、阵地型和炮手（站定 = 「把阵地守住」）；开技能给辅助和医疗（跟着队长的节奏加持）；指挥给突击时最受影响的近战特种与控场。

## 3. 实现框架（共用）

### 3.1 四个触发器（积木 tag）

| tag | 触发时机 | 参数 | 现状 |
|---|---|---|---|
| `trig.on_leader_dash` | 队长冲刺起步（`g.dash_t` 上升沿） | `cd`、`cond` | **已有**，但只在德克萨斯段（seg_texas）里处理；要挪到共用段，所有数据干员可用 |
| `trig.on_leader_still` | 队长连续 `secs`（缺省 0.6）秒没移动后触发一次；之后每站满 `every` 秒再触发（不写 = 只触发一次，移动后重置） | `secs`、`every`、`cd`、`cond` | 新增；「没移动」读队长本帧位移 < 1 像素，被定身 / 冲刺中不计 |
| `trig.on_leader_skill` | 队长的技能出手那一刻（`_release_skill`） | `skill`（只认某个技能，缺省全部）、`cd`、`cond` | 新增；队长是本人时也触发（自己给自己响应，见 §5.3） |
| `trig.on_stance` | 指挥模式切换（`squad.set_stance`） | `to`（`roam` / `recall` / `guard` / `gathered`＝归队集合完毕）、`cd`、`cond` | 新增；依赖 docs/114 指挥模式已合入 |

- 所有响应都写在干员 json 的 `blocks.response`（一条），结构同现有 `trait` / `talent`：`{"trig": …, "do": [...], "cd": …, "_doc": "…"}`。
- `do` 里只用现有积木（`shape.dash_line`、`shape.circle`、`verb.sp_secs`、`verb.buff_*`、`st.*` 等）；§4 每条注明用哪些，缺的标「新积木」。
- 冷却：`cd` 缺省 0；含位移积木（`shape.dash_line`、`verb.leap_slam`、`verb.tether` 弹射、召唤物扑击）时，校验要求 `trig = on_leader_dash`，或 `cd` 写成 `"$dash_cd"`（运行时取队长当前冲刺冷却）。写进 `operator_contract.gd` 作 V10。
- 画面：每次响应触发时干员头顶闪一个小标（职业色箭头 / 盾 / 音符…，按触发源区分），让玩家知道「这下是我按出来的」。图鉴干员页加一行「响应：……」（文案按 docs/76）。

### 3.2 同 seed 影响

- 四个触发器都只在队长做动作时求值，**只读**队长状态，不抽随机数（需要随机的效果一律走 `g.rng_op`，同现有积木）。
- 响应本身会改战斗（这是目的），所以**开了响应的干员同 seed 结果会变**。第一批上线前加总开关 `balance.json response.on`（缺省先 0），关时所有 `blocks.response` 不求值，TRACE 与现在逐行相同；切片验收时 `--bal=response/on=1` 对照，确认后再改缺省。
- 机器人：expert 会冲刺、会停下读条，响应会自然触发；指挥类只有 `command/bot_roam=1` 时触发。数值判断按 docs/27 机器人矩阵 + 同 seed 配对，胜率差 < 10 点不下结论（balance_method）。

## 4. 18 人逐条

表头：**效果**（起始值，后续按测试调） / **原作身份**（只写 docs/76 附录 A 已核实的事实；标「待核」的，写成文案前按 docs/76 §4 查证） / **与现有技能**的关系 / **难度**（小：只填 json；中：要一个小积木或改一处手写段；大：新机制）。
**同 seed**：18 条一样——`response.on = 0` 时逐行不变；打开后，触发过的局结果会变（有意的），不抽 `g.rng` 之外的随机数，同参复跑仍逐行相同（§3.2）。

## 5. 交互与边界

1. **队长本人**：队长就是这条响应的主人时，冲刺 / 站定 / 开技能 / 指挥照样触发自己的响应（例如德克萨斯当队长：她冲刺时自己就是冲刺，不再额外冲一次——德克萨斯这条在队长是她本人时**不生效**，其余 17 人生效）。
2. **多条同时触发**：同一下冲刺可能同时触发 5 人，按编队顺序结算，互不影响。
3. **开技能**：队长的技能来源只有自动技能 + 手动技能；队友自己的技能不算触发源（否则变成自激）。
4. **指挥**：只认玩家切换和耐力耗尽自动归队；切换被拒（耐力不足）不触发。
5. **网页 / 触屏**：四类触发源都是现有输入，不新增按键。

### 6.1 第一批实现记录（10-21，分支 `claude/op-verbs-p1`）

- 共用：`game/scripts/characters/blocks/responses.gd`（`blocks.response` 段：`trig.on_leader_dash` / `on_leader_skill` / `on_stance` 三类事件 + 站定类 `trig.passive` 带条件 `still >= 秒`）；条件新增 `still`（`g.leader_still_t`，队长连续站定秒数，移动 / 冲刺 / 被定身清零）与 `response_on`；总开关 `balance.json response.on`（缺省 1）。`hint` = 触发 / 生效那一刻头顶飘一次职业色短名。
