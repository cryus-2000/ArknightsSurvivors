## 3. 实现

- `game/scripts/render/fx_pxplane_sz.gd`：铃兰一节（单独文件，少撞 `fx_pxplane.gd`）。事件 → 件表；运行时逐格画狐火弹 / 光域边 / 传火线 / 连携追迹（与 `tools/pxplane_suzuran_art.py` 的 `fox_bolt()` / `aura_ring()` / `pass_line()` 同算法）。光域边按（半径, 拍, 状态）缓存，一拍只算一次。
- `fx_pxplane.gd`：`IDS` / `METAS` 加铃兰（键前缀 `sz_`），`owns_id` 只在 `fx/px_plane = 1` 时为真，`ev / draw_floor / sort_items / draw_sorted` 各一处转到 `_szx()`。
- `fx_recipe.gd`：颗粒材质加 `flame`（同 ember 画法，4 px 大颗，满足 docs/270「边长 ≥ 3」）。
- 只画钩子（`_FXR.ev`，没接管时第一行返回）：`seg_suzuran` 出手 `sz_fire`（给弹体写画面专用键 `_pxv` = 是不是全力以赴那一发）/ 大狐火离手 `sz_big` / 贯穿 `sz_bhit` / 狐火点点每跳 `sz_att` / 传火 `sz_pass` / 落点 `sz_drop`（原圣光柱位置）/ 队长回复 `sz_heal`；`fox_cast` 接管时不放全局放射光（`g.fx rays`）。`weapons.gd` 狐火（arcane，op = suzuran）命中接管时不画通用环 + 火星，改发 `sz_hit`；`late_shape` 扩散发 `sz_splash`；`skill_link` l_suzuran 接管时发 `sz_link` / `sz_link_hit`、不画旧岩块形状与颗粒。技能起手（符阵 / 火环 / 尾焰）用 `data_operator` 已有的 `skill` 事件；响应「祈愿」与围炉·添薪用 `ob_core.exec_shape` 已有的 `shape` 事件。
- 原画法（光域椭圆、九尾程序尾巴、Codex 狐火帧条、封印 / 灼印程序环、pfx）接管时由 `data_operator` / `character.draw_pfx` / `op_api.spawn_fx_sprite` 统一跳过。
- 帧条：`game/art/fx/pxp/pxp_sz_*.png`（70 张，约 196 KB）+ `game/data/pxp_suzuran.json`；重新生成 `python tools/pxplane_bake_suzuran.py`。`.import` 不由脚本写（e70548cbf：脚本写的 uid 不合规），GCP / 本机 Godot `--import` 时生成后随提交。
- 颜色组 `game/data/fx_pxplane/suzuran.json`（颗粒 / 照地光 / 受击反应闪暖金）。
- 送审 GIF：`python tools/pxplane_gif_suzuran.py [--only atk,s1,…]`。

## 5. 自查（docs/246 口径 + docs/270 §3 设计值）

| 项 | 结果 |
|---|---|
| 视角 | 贴地层压扁 0.72（光域边、火环、符阵、金印、封印、薄雾）；立起层竖直（火苗、狐火、九尾、尾焰），按脚底 y 排序；火环 / 尾焰前后半圈分开排序 |
