# 56 · 引航灯标「去不去」机制级方案（玩法系统，2026-10-11，方案稿；§5 原型已实装，缺省关）

> 背景：圈内安全（docs/49g 候选 e）已三档全开（7dd0af7），把「进了圈被杂兵远程逼出来」修掉了，但整体点燃率只到 22–28%。
> 刷新距离 A/B（docs/38 §8.12 灯标段）112 局不显著，距离这条已到头。瓶颈记为「灯标附近、走过去这段路上的危险」，本稿给机制级候选。
> 机制与旋钮见 `run/beacon.gd`，机器人寻灯见 `core/bot.gd`（`beacon_hold` / `bot/beacon_seek_r` 300 / `beacon_walk_r` 120、血量 > 25% 才去、700 内才看）。

## 1. 现状与数据

现行规则：自然溟痕出现后每 60–75 秒在主控 250–400 外、溟痕最密处立一座；光圈 r 70、读条 2.5 秒（低灯 ×1.5、流明区 ×2）、离圈每秒退 20%、45 秒没点就熄灭；点燃清 clear_r 340 内溟痕、30 秒禁刷、+20 灯火、清神经损伤；读条期间非 Boss 子弹进圈消散、远程杂兵不起手（`safe_bullet` / `safe_ranged` = 1，`safe_slow` 0）。

圈内安全修好的是「站进圈以后」：进圈后点燃率抬 14–20 点、承伤 −11%。没修好的是「去」：六成多灯标从没人进圈，每座只进 0.6 次，而且距离近一点也不改这个数。机器人在 300 内就会把灯标当目标（`beacon_hold`），说明不是看不见，而是走到一半（或到了圈边）被杂兵的预警 / 子弹打分挡住，掉头去躲——和圈内 danger 同一群怪、同一种出招，只是发生在圈外。标准档溟痕少，灯标作用小、点燃率本来 36–45%，问题集中在 Ⅳ / Ⅷ。

**约束**：标准高手 70.5%、Ⅷ 熟练 50.9%（67a3e87）都贴着 50–70 框边。候选只能改「去不去」，不能变成常驻安全区；超框只用不给奖励的旋钮（unlit_life、半径）收。

## 2. 候选机制

口径：机器人只看距离 / 血量 / 危险打分，不看伤害与回报；凡「真人能看到、机器人看不到」的候选，只能靠问卷（docs/52）判断。所有候选加旋钮、缺省 = 现行为，先 --bal 对照再定正式值。测试统一：Ⅷ 熟练 7 干员 × 4 seed = 28 局 / 组初筛（`--keep=BEACON,BDBG,BDBGC --bdbg`），有效再 112 局（bd8 式 2 × 56）确认，附标准高手 28 局白给检查。成功指标：点燃率（两比例 z，p < 0.1）、每座进圈次数、未进圈熄灭占比；胜率在框内且同 seed 翻转对称（符号检验 p > 0.2）。

### a 「引路」——未点燃灯标附近即驱散（圈内安全外扩到路上）
- 规则：灯标未点燃期间（最长 45 秒），以它为心 `guide_r`（建议 160，约 2.3 倍光圈）内：① 非 Boss 子弹进入即消散；② 远程杂兵不对 `guide_r` 内的主控起新远程招（冷却照走）；③ 杂兵每秒被向外推 `guide_push`（建议 40 px/s，只推不伤）；Boss 一概不受影响；点燃后三条立刻结束，换成现有的点亮效果。
- 机器人：直接削减打分里的预警 / 子弹两项（danger 主因的 92%），而且作用在走近的最后 90 px 上——正是现在掉头的地方。预计每座进圈 0.65 → 0.9 以上，点燃率应比圈内安全多抬一截。真人：看到子弹在灯边碎掉、怪被光推开，「走向灯」有可读的正反馈。
- 难度风险：中。它等于把每座灯标前 45 秒变成 r 160 的半安全区，Ⅷ 低血时可能借它喘气，胜率可能上浮；靠「只在未点燃期间」「点燃即收」「45 秒寿命」限住。超框先降 guide_r 160 → 120，再降 unlit_life 45 → 35。
- 溟痕 / 灯火：点燃多 → 溟痕存量降、低灯秒数降（+20 灯火），这是想要的；没有新的灯火来源。
- 实装：`beacon.gd` 的 `charging` 判定旁加 `near_unlit`（主控在某座未点燃灯标 guide_r 内），`bullet_eaten` / `ranged_held` 的半径与条件改读它；推开在 `enemies.gd` 移动处加一个力。约 2 小时，prot_test 3 条。
- 旋钮：`beacon/guide_r`（0 = 关）、`guide_push`、`guide_ranged`（0/1）；对照 A 现行 / B guide_r 160 只开 ①② / C B + push 40。

### b 「灯标灯笼」——未点燃也有一圈弱光
- 规则：未点燃灯标自带 `dim_r` 110 的弱光（无伤害、无清痕）：弱光内溟痕不生效、神经损伤不涨、灯火不扣；随读条进度弱光变亮、半径长到 clear_r；点燃后进入现有亮灯效果。
- 机器人：打分里溟痕项本来就是 0%（49g §0），弱光不改任何项 → **点燃率不动**，A/B 测不出。真人：走到灯边就有收益（溟痕里不掉血、灯火不漏），对普通玩家「溟痕 11% 死因」有帮助；是「到了就有奖」的手感。
- 难度风险：低。溟痕免疫只在 r 110、45 秒内；灯火不扣对高手几乎没差（高手很少低灯）。
- 溟痕 / 灯火：不清痕只免疫，溟痕存量不变；灯火省一点，Ⅷ 低灯秒数可能略降。
- 实装：溟痕伤害 / 灯火扣减处各一个距离判定，画面加弱光环（world 读 b.prog 已有）。约 1 小时 + 美术出弱光样式。
- 旋钮：`beacon/dim_r`（0 = 关）。只做真人问卷项，不进机器人对照。

### c 「接力点亮」——进度带走，打了就跑也能点
- 规则：离圈后进度先保持 `decay_delay` 秒不退，之后每秒退 `decay_pct`（旋钮已在 main：5eda688，缺省 0 / 0.2）；在此之上加 `relay_r`（建议 140）：主控在 r 70–140 环内时进度不退（不涨）；未点燃寿命按累计进度延长（`life_per_prog` 10 秒 / 每 25% 进度）。
- 机器人：49f §4 已证 decay_delay 对机器人无效（离圈后不回头）；环内不退只在它贴着圈边躲时有用，预计 +2–4 点，28 局内不显著。真人：「蹭一下走开再回来」成立，配合 a 效果最好。
- 难度风险：低。只改点燃节奏，不改安全区。
- 溟痕 / 灯火：同 a 的方向，幅度小。
- 实装：`beacon.gd` 退进度分支加环判定与寿命延长，约 0.5 小时。
- 旋钮：`beacon/relay_r`、`life_per_prog`；可零代码先试 `decay_delay 5 / decay_pct 0.1` 叠在 a 上。

### d 刷新选址——刷在主控去向、或下一波威胁之间
- 规则：候选点仍取 16 方向 × 3 半径，但加权：与主控当前移动方向（`g.pvel`，近 3 秒平均）夹角 ≤ 60° 的候选加 `head_bias`（溟痕数 ×1.5）；距离改 220–340；Boss 在场时刷在主控与 Boss 的连线中点侧，不刷在 Boss 背后。
- 机器人：机器人风筝方向随怪群变，「去向」不稳定；距离 200–320 只换来 +2.8 点，选址单独用预计 +3–5 点。真人：顺路的灯更容易被捡起来，但灯标同时是「溟痕在哪」的指路标，偏向去向会削弱这一层。
- 难度风险：低；Boss 在场不刷 Boss 背后会让 Boss 战里的灯标更可用，Ⅷ 泡影段略宽松。
- 溟痕 / 灯火：选址偏离溟痕最密点 → 单座清痕量下降，存量可能略升。
- 实装：`_spawn()` 加权一处 + 记录近 3 秒速度，约 0.5 小时。
- 旋钮：`beacon/head_bias`（0 = 关）、`dist_min` / `dist_max`（已有）、`boss_side`（0/1）。

### e 「背光刷怪」——未点燃灯标在场时，不从灯标方向刷杂兵
- 规则：有未点燃灯标且它在主控 600 内时，`spawner.edge_pos()` 排除朝向灯标 ±`shade_deg`（建议 50°）的扇区（Boss / 事件刷新不管）；点燃或熄灭即恢复。
- 机器人：新怪从别处来，主控与灯标之间的路上少怪、少预警，机器人追灯时前方打分变好；怪群从身后追来反而把它往灯推。预计每座进圈 +0.1–0.2 次。真人：灯那边「看起来清净」，自然会走。
- 难度风险：低到中。总刷怪量不变，只改方向；但单侧刷怪会让怪群更集中，Ⅷ 可能更好风筝。超框把 shade_deg 50 → 30。
- 溟痕 / 灯火：同 a 方向。
- 实装：`edge_pos()` 一处角度重采样（最多重试 4 次），约 0.5 小时。
- 旋钮：`beacon/shade_deg`（0 = 关）。

## 3. 推荐

**主推 a（引路，只开 ①② 子弹消散 + 远程不起手外扩到 guide_r 160）叠 e（背光刷怪），c 的 relay_r 作可选第三层；b 与 d 不进机器人对照。**
- 理由：诊断链很直——圈内 danger 的 92% 是杂兵远程预警 / 子弹（49g §0），圈内安全把这两项在 r 70 内压掉后进圈后点燃率抬 14–20 点；没人进圈是同一群怪在圈外 90–160 px 处做同一件事。a 就是把已验证有效的机制外扩到走近的最后一段，改动小（复用 `bullet_eaten` / `ranged_held`）、真人可读、Boss 不受影响。e 从源头减少路上的怪，便宜且和 a 互补（a 管已经在的，e 管新刷的）。
- 推开（a ③）和减速一样（49g §5 D 组）预计是边际收益，先不开，只在 ①② 不够时作 C 组。
- b 不进对照的原因是机器人测不出，但它对普通玩家是最直观的「到了就有奖」，建议和 a 一起进 EA 后真人问卷，不占云端槽位。
- d 已被距离 A/B 判了一半（距离不是瓶颈）；选址偏向去向会削弱「指路标」定位，放最后。
- **回退**：a 若把 Ⅷ 熟练推出 70，先 guide_r 160 → 120、再 unlit_life 45 → 35（都不给奖励）；a 在 112 局仍不显著（点燃率 < +5 点），则改走 c + 「机器人追灯时容忍更高危险分」校准口径——但那会动 Ⅳ / Ⅷ 熟练基线（§8.12 直走的教训），要和数值一起重跑基线。

对照组（Ⅷ 熟练 28 局 / 组，同 seed）：A 现行；B `guide_r 160, guide_ranged 1`；C B + `shade_deg 50`；D C + `guide_push 40`。过线（点燃率 ≥ +8 点 或 每座进圈 ≥ 0.85，胜率翻转对称）的组进 112 局 + 标准高手 28 局白给检查；112 局判定：两比例 p < 0.1、Ⅷ 胜率 50–70、标准 ≤ 70。

## 4. 度量

现有遥测够用来回答「去不去」的大半：
- `BEACON spawn / expire / lit cleared=N / mires`（`beacon.gd _log`，非 PLAY 模式）：出现数、熄灭数、点燃数、溟痕存量 → 点燃率、未点燃熄灭占比。
- `BDBG leave why= in_s= prog=`（`--bdbg`）：离圈次数与原因、圈内秒数、最高进度 → 每座进圈次数 =（离圈 + 点燃）/ 出现；进圈后点燃率。
- `BDBGC why= {...}`：离圈前一帧打分拆解（敌人贴近 / 预警 / 溟痕 / 子弹，出手者 B / m）→ 看 a 之后 danger 剩下谁。
- `BDBG t= hold= in55= stand= danger=`（每 60 秒）：追灯帧占比 vs 到圈帧占比。

**要加的一个字段**：现在没有任何一行说「这座灯标没人进圈时主控离它最近多远、追了多久、为什么放弃」。建议在 `BEACON expire` 行加 `min_d=`（寿命内主控最近距离）、`hold_s=`（机器人 `beacon_hold` 指向它的累计秒数）、`quit=`（最后一次放弃 hold 的原因：danger / boss / hp / none），由 `beacon.gd` 记 min_d、`bot.gd` 在 hold 切走时回写。有了它才能把 63% 的未进圈灯标分成「没追」「追了半路放弃」「到了圈边没进」三类，分别对应 d、e、a 三个候选的作用区；`balance_run.py --keep=BEACON,BDBG,BDBGC` 原样接收。真人侧 `_log` 不在 PLAY 模式打，EA 问卷（docs/52）补「灯标常常来不及点 / 走过去太危险」两问。

## 5. 原型实装（2026-10-11，制作人定 a + e + 遥测缺口；缺省全关 = 现行为）

| 旋钮（balance.json beacon 段） | 含义 | 缺省 | 对照用 |
|---|---|---|---|
| `beacon/guide_r` | 引路半径：未点燃且寿命 ≤ `guide_life` 的灯标，以它为心 guide_r 内 ① 非 Boss 子弹 / 抛石进入即消散（走现有 `bullet_eaten` / `eat_fx`，不要求主控在读条）② 主控在 guide_r 内时远程杂兵不起新远程招（`ranged_held`，冷却照走）。光圈 r 70 的圈内安全只是它的内圈；不依赖 `safe_*`。0 = 关 | **0** | 160 |
| `beacon/guide_life` | 引路只在灯标出现后这么多秒内生效（与 unlit_life 45 同长 = 整个未点燃期） | 45 | — |
| `beacon/shade_deg` | 背光刷怪半张角：有未点燃灯标且在主控 `shade_dist` 内时，`spawner.edge_pos()` 不朝灯标 ±shade_deg 刷杂兵；点燃 / 熄灭即恢复。Boss / 事件刷新不经 edge_pos。0 = 关 | **0** | 50 |
| `beacon/shade_dist` | 背光生效的灯标—主控距离 | 600 | — |

- 难度表可按档覆盖：`difficulty/<档>/beacon_guide_r`、`beacon_shade_deg`（≥ 0 时优先，同 `beacon_safe_*`）。
- 推开（a ③ `guide_push`）这次没做，等 B / C 组结果。
- **随机数**：背光不重掷。`edge_pos()` 仍只取 1 个角 + 1 个距离，把 [0, TAU) 的随机角均匀映射到扇区以外的弧上（`u = fposmod(ang − (θ + half), TAU)`，`ang' = θ + half + u·(TAU − 2·half)/TAU`）。所以随机数调用次数与旋钮无关：旋钮缺省时同 seed 与 main 逐帧一致；旋钮开着时同 seed 同旋钮也可复现，但与关着的局从第一次刷怪起分叉（角度不同），属预期。
- **画面**：引路生效期间 guide_r 处多一圈很淡的同款虚线（world.draw_beacons，alpha 0.16–0.20），子弹被吞用现有的暖色光屑（`eat_fx`）。
- **遥测**（§4 的缺口，`beacon.gd` 记，不改机器人）：`BEACON expire min_d=<寿命内主控最近距离> hold_s=<主控在 2×r 内的累计秒> quit=<none|approach|edge> t= mires=`。`quit`：none = 从没进过寻灯半径（读 `bot/beacon_seek_r` 300）；approach = 进过寻灯半径但没到 2×r（半路放弃）；edge = 到过 2×r（圈边或进过圈）没点。BDBG / BDBGC 格式不变。
- 机器人不改（`bot/beacon_seek_r` 300 照旧）：机制对机器人和真人一样生效。
- 验证：旋钮缺省时同 seed TRACE / BALANCE 与 main 一致（3 干员）；prot_test 加 9 条（引路开 / 关、Boss 不受影响、背光扇区与随机数调用次数）。
