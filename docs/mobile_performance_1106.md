# 手机性能与生命周期修复（2026-11-06）

状态：`codex/mobile-performance-1106` 分支实施与回归完成，整场帧时和手机验收待测；未合入、未发布。基线为 main `a6b030e8a`。用户授权 Codex 改代码，并要求尽可能优化性能；目标是手机中画质 30 FPS、控制内存增长。用户确认最低验收设备为 iPhone 15 Pro，运行于浏览器 / 哔哩哔哩 Toy。

验证期间主线已推进到 `985466dac`（新特效等集成后的金样更新）。本文结果只属于 `a6b030e8a` 上的本分支；协调人合并时须保留后续特效改动，并对集成后的代码重新快检，不能把本轮分支验证视为新主线全量验收。

## 本轮改动

1. **释放上一局的对象与资源。** 修复 world/bullet_fx、world/地裂 sink、character/地裂 sink、转平面 renderer/七个子模块、HUD/子组件、终结技 HUD/视图、结算页/样式之间的 `RefCounted` 强引用环。子对象以 `WeakRef` 回指拥有者，拥有者销毁时释放其缓存；不依赖对象必须先进入场景树。HUD 缓存绘制回调改由随场景释放的 Control 持有，消除 HUD 自持有 Callable。未引入全局常驻缓存。
2. **抑制内存护栏反复清理。** 持续超预算只执行一次字体清理；低于预算至少 32 MB 才重新允许清理，两次字体清理至少相隔 60 秒。闲置贴图仍在每次超预算采样时立即回收，避免延迟释放新闲置的敌人帧条和白剪影。原有第二次超线降画质、严重超线降分辨率的机制保留。护栏不是 30 FPS 验收手段；本轮没有降低默认中档画质。
3. **减少同色网格工作量。** 浊心斯卡蒂歌域条带使用单个颜色值，146 顶点条带不再分配 146 个重复颜色或逐个调色。BatchCanvas 同时支持小型网格的索引展开；铃兰光域矩形的连续同色顶点复用调色结果，仍支持非均匀颜色。
4. **减少回指读取。** 安洁莉娜、能天使、维什戴尔和敌弹上层的五个绘制入口将父对象暂存为局部变量，避免循环中重复读取 WeakRef。函数返回即释放该引用，不恢复跨帧持有环。

未改变战斗随机流、伤害/敌人数、模拟步长、绘制几何、层序或技能节拍。未改音乐层数、贴图分辨率、原始美术文件或 `art.gd` 静态缓存策略。

## 仍需实机验收

- 当前证据证明释放路径和局部渲染优化有效，**尚未证明手机中画质稳定 30 FPS**。30 FPS 每帧预算为 33.3 ms，需看重压战斗帧时分布、长尾卡顿和持续发热后的结果。
- 应在 iPhone 15 Pro 的浏览器和哔哩哔哩 Toy 中分别覆盖满编队、后期密集特效、Boss/终结技、招募/换曲，以及连续多次结算后重新开局。记录浏览器/进程总内存和 GPU/音频分项；现有显存加音频护栏不是整个进程内存。
- 实机每次测试后可从「设置 → 画面 → 性能报告 → 复制报告」留存本局记录（`core/perf_report.gd`）。浏览器和 Toy 分别记录；必须确认一直使用中档、没有触发内存护栏降档，不能把降档后的 30 FPS 算成中档达标。
- 本轮没有可靠的“节省多少 MB”整局测量。资源哨兵和 WeakRef 断言证明对象可以释放，不等同于驱动/浏览器立即归还物理内存。
- `docs/287` 的手机音频分层音乐、同步图集读取和其他帧时热点仍需按最新代码测量。削减音乐层数会改变体验，本轮保留；不能把历史优化的收益重复算成本分支收益。
