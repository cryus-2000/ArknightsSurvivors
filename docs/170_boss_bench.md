# 170 Boss 单场测试台（2026-10-27）

> 用户 10-27：「改好的可以上云端去测一下，看看能不能直接测而不是跑满全局，按照正常三组干员打到最后 boss 的属性」。
> 分支 `claude/boss-bench`（基于 `codex/boss-fx-rework` 72f41c3c7，六条 Boss 改版分支的共同起点）。不合 main 也能用：云端对照脚本会把测试台钩子 cherry-pick 到被测分支上。

## 1. 做法

**快照 = 成长事件日志**，不是整个对象的内存转储。录制局（`--benchsnap=<前缀>`）在开局设置完成后，把每次「顶层」改动按时间记下来，连同当时的 `g.rng` 状态与 `g.t`：

| 事件 | 钩子位置 |
|---|---|
| 藏品（宝箱 / 商店 / 事件 / 认知「物由心生」） | `progression.gain_relic` |
| 入队 / 换人 | `squad.add` / `squad.replace` |
| 推进成长节点 / 精英化（含分支路线） | `character.advance` |
| 成长卡 / 补充卡 / 支援 | `progression.pick` 的 growth / filler / weapon 分支 |
| 事件给的最大生命 / 直接效果 | `endings._max_hp` / `relic_fx._on_gain` |

只记最外层（depth 0）：藏品里再招一个随机干员这类嵌套效果不单独记，重放时先把 `g.rng` 恢复到当时的状态，嵌套的随机结果逐个复现。录制只读不抽随机数，同 seed 结果不变（§5 核对）。

每只 Boss 登场那一刻（刷怪器选好这一批、刷出之前）写一份 `<开局>_m<认知>_s<seed>_slot<k>.json`：事件日志 + 登场时的 `g.rng` / `g.rng_spawn` 状态 + 等级 / 经验 / 灯火 / 源石锭 / 场地圈 / 主控位置 / 威胁等级 / 刷怪与灯标计时 / 藏品运行期变量（刻勋之手、急救包、熔铸池…）+ 场上存活杂兵（种类、位置、血量比例）+ 溟痕 + 当时的队长 + **核对指纹**（编队 id / 精英化 / 节点数 / 路线、藏品与层数、支援、等级、全部属性修正逐条）。

**开打**（`--bossbench=<快照>`）：照快照里的开局参数正常开局（同 `--seed / --op / --meta / --tide`，开局编队与认知塑造由开局自己重做），第 2 帧按顺序重放事件日志，写回登场时状态，换回当时的队长，刷回杂兵和溟痕，再把时间拨到该登场位的时刻（3:30 / 7:00 / 10:00）前 0.02 秒、恢复随机数状态，**由刷怪器照常刷出 Boss**（`--benchboss` 换成要测的那一组）：最终 Boss 的场地冻结、中期 Boss 撤离、骑士入潮重生、Boss 在场停刷、伴随机制全走正式代码，时间照常走（不是 `--bosstest` 的冻结时钟）。机器人照常打，Boss 战中照常升级选卡。

结束条件：中期 Boss 全部倒下 / 最终 Boss 进入胜利 = 胜；队长倒下 = 阵亡；登场后 `--benchmaxt`（缺省 180 秒，同正式局 10:00 后 3 分钟）没打完 = 超时。打印一行 `BENCH {...}` 退出：

- `result`（win / dead / timeout）、`fight_t`、`taken` / `taken_pct`（队长实际掉血 / 最大生命，可 > 100%，含回复抵掉的）、`hp_end_frac`、`boss_hp_left`
- `dmg`（打在这批 Boss 上的实际伤害）、`brk_dmg_share`（其中打在破绽上的比例）、`brk_time_share`（有破绽的时间比例）。**破绽 = `e.break_t > 0`（公共破绽 / 韧性）或 Boss 脚本 `taken_mult(e) > 1`**（骑士撞柱 / 喘气、偏执泡影坠地等自带受伤倍率的窗口）
- `phases`：每只 Boss 进各阶段的时刻；`fp_diff`：还原后指纹与快照不一致的项

开打时队长**满血**（`--benchhp=snap` 改用登场时的血量）：去掉登场前那段的噪声，只看 Boss 本身。

## 2. 口径

- **3 组编队**：`balance_run --preset starts`（现行难度校准就是 starts 7 开局，docs/158 §4）里取远程 / 近战 / 医疗各一：**维什戴尔、斯卡蒂、凯尔希开局**，自然招募（快照里的编队就是机器人在那一局真实招到的）。
- **两档成长**：`--meta=0`（无认知）与 `--meta=18`（18 细胞推荐点法），`--tide=0` 常规档，`--bot=expert` 高手。
- **录制加 `--nodeath`**：保证每个 seed 都能走到 10:00、三只 Boss 都有快照（不加的话最终 Boss 的快照只剩活下来的强队，偏易）。`--nodeath` 只把生命托底在 50%，不改经验与选卡；开打不带它。
- **登场位**：塑路者 / 圣徒卡门 = 3:30（第一只中期 Boss 只从这两只里抽）；圣徒伊比利亚 / 接潮组两种 = 7:00；最终 Boss 四只 = 10:00。各 Boss 用对应登场位的全部快照（`--slot` 可改）。
- **对照**：测试台分支本身（= 72f41c3c7 codex 基线 + 钩子）；**改版** = 各 Boss 分支 + cherry-pick 测试台代码提交 4121e81ee。快照在对照代码上录一次，两边用同一批，结果按快照配对。

## 3. 用法

```
python tools/boss_bench.py record --ops wisadel,skadi,kaltsit --metas 0,18 --seeds 1-16 --out build/boss_bench/snaps
python tools/boss_bench.py run --snaps build/boss_bench/snaps --bosses all --tag base
python tools/boss_bench.py run --snaps build/boss_bench/snaps --bosses paranoia --tag new --game <改版工作树>/game
python tools/boss_bench.py table build/boss_bench/res/base.json build/boss_bench/res/new.json
```

`--bosses` 键：`path, carmen, iberia, bishop+archon, bishop+immortal, paranoia, knight_boss, ishar, izumik`。录一局约 50 秒（本机），开打一局 15–70 秒（Boss 战本身 20–180 秒模拟时间）。

云端（docs/36 §7.5.1）：`NAME=… NEW=origin/<分支> BOSSES=… BENCH=4121e81ee bash tools/cloud/boss_bench_ab.sh`，同机顺序跑 录快照 → 对照 → 改版 → 对照表，推 `cloud-results/boss-bench-<NAME>`（`compare.md` 是表，`base.json` / `new.json` 是逐局记录，快照打包在 `snaps.tar.gz`）。

| Boss | 胜率 | 胜局用时（中位） | 承伤 | 破绽输出 | 破绽时间 |
|---|---|---|---|---|---|
| 塑路者 | 6/6 | 31 秒 | 5% | 0% | 0% |
| 圣徒卡门 | 6/6 | 37 | 20% | 16% | 9% |
| 圣徒伊比利亚 | 6/6 | 20 | 19% | 0% | 0% |
| 接潮组（主教+执政官） | 6/6 | 20 | 12% | 0% | 0% |
| 接潮组（主教+斥亡者） | 6/6 | 19 | 9% | 0% | 0% |
| 偏执泡影 | 4/6（2 超时） | 122 | 87% | 18% | 7% |
| 最后的骑士 | 6/6 | 109 | 135% | 62% | 26% |
| 伊莎玛拉 | 6/6 | 56 | 98% | 6% | 3% |
| 伊祖米克 | 6/6 | 51 | 36% | 0% | 0% |

只是能跑通的小样，不下结论；但方向已经看得出：基线上中期 Boss 对 7:00 前成型的编队几乎没有威胁（20–40 秒打完、承伤 ≤20%），除骑士外破绽输出远低于 35–40% 的目标。

**保真度**：同一份快照在真实录制局里的那场 Boss（`BENCHREAL`）和测试台结果对得上量级（例：维什戴尔 s1 塑路者 真实 32 秒 / 测试台 32 秒；偏执泡影 真实两局拖到局终 / 测试台同两份快照超时）。还原核对：54 局里编队 / 精英化 / 路线 / 藏品层数 / 属性修正全部一致；剩下的只有凯尔希编队一项移速 186 → 150（登场时正好在一个限时移速加成里，开战后按局内规则重新触发）。**不比**的临时修正：灯标庇护（按站位）、`relic_haste`（每帧重算）、干员积木的叠层 / 光环（`blk:*`，如乌尔比安击杀叠攻、铃兰领域，开战后重新叠）——这是测试台和真实局唯一系统性的差别，略偏难。

同 seed 可复现：同一份快照开打两次结果相同（偏执泡影 维什戴尔 m0 s2 两次都是 110 秒胜）。

## 5. 同 seed 核对

钩子不抽随机数、只在 `--benchsnap` / `--bossbench` 下记账：`python tools/trace_base.py 1 wisadel 650 --ref 72f41c3c7 --here` **TRACE 513 行逐行相同**（10-27，seed 1 维什戴尔 650 秒，对 72f41c3c7）。

## 6. 目标区间（建议，待协调人 / 用户定）

整局胜率 ≈ 活到 10:00 的比例 × 最终 Boss 单场胜率。常规档高手无认知整局 30–40%、18 细胞 50–60%（用户 10-25）。高手在 10:00 前的死亡占了大头，所以 Boss 单场应明显高于整局：

| | 无认知 | 18 细胞 |
|---|---|---|
| 中期 Boss（单场，满血开打） | 80–90% | 90–95% |
| 最终 Boss（单场，满血开打） | 55–70% | 70–85% |
| 破绽期输出占比（各 Boss） | ≥ 35–40% | 同 |

中期 Boss 不该是整局的主要死因（它们的作用是逼走位、给破绽输出），所以单场胜率高；最终 Boss 承担终局门槛。中期 Boss 单场 100%、承伤 < 20% 说明太软。
