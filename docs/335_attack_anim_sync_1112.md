# 335 · 动作与攻速对齐检查（11-12）

> 协调人转用户 11-12：「攻速快的时候动作也是攻速快的，不会出现为了播完整个动作而卡住」。全员实测 + 修复。分支 `claude/determined-bardeen-4a122e`。工具：`game/tests/atk_rate_test.gd`、`tools/atk_rate_table.py`（批跑放 GCP）。

## 1. 结论（三行）

1. 20 名干员的普攻动作条（25 条带 attack_timing 的帧条）全部随攻速等比缩短（docs/153），出伤帧都落在对应动作帧的时间区间内（机检 25/25）；没有「等动作播完才出下一击」，也没有动作被截断后从第 0 帧反复重开（最大出手间隔 = 面板间隔）。
2. 唯一真问题：**歌蕾蒂娅**（普攻是 `lock` 的钩索，钩子飞出 / 绷紧 / 拖回约 0.45 秒不随攻速变，钩不回来就不普攻）——2× 攻速只有 1.65×、4× 只有 1.9×（偏差 −20% / −52%）。乌尔比安同一套钩索代码（精二掷锚），一并改。已修：钩索三段按 max(1, op_aspd) 等比缩短，修后 240 帧下偏差 0.0% / +0.9%。
3. 其余偏差全是 **帧取整**：出手间隔不满 1/60 秒的整数倍时，下一击顺延到下一帧（冷却重置不带余量），60 fps 下 4× 攻速最多 −9%（能天使 0.0875 → 0.1 秒），240 fps 下全部 ≤ 4%。这是计时口径不是动作卡住，**没改**（带余量会让所有干员 1× 频率抬约 2–3%，所有数值基线跟着动，要数值会话定，见 §5）。

## 2. 方法

- 场景：单名干员当主控，右侧 50 像素一只不动的木桩（同木桩表 docs/79），技能关（sp 压 0），攻速用 `op_aspd` 乘数 1 / 2 / 4，各统计 30 秒（热身 2 秒）；`--realtime` + `--fixed-fps 60 / 240`。（批跑模式默认 `bal_dt` = 0.066 秒步长太粗：第一次跑所有间隔都被量化到 0.0526 秒的倍数，不能用来查攻速，已弃。）
- 理论值 = 同一干员 1× 的实测出手数 × 倍率（面板间隔也列出：`attack.every ÷ op_aspd`）。偏差 > 5% 标 ⚠。
- 凯尔希的普攻是 Mon3tr 的治疗（support 形状，不计 atk_n）：表里出手列为 0，起手列 8 / 17 / 34 ≈ ×1 / ×2 / ×4，没问题。
- 技能开的一轮（by_anim：每次动作起手的窗口 vs 出手间隔）：窗口 > 间隔的次数为 0（水月 skill_s1_attack 也是 0.72 → 0.36 → 0.18 随攻速缩）；技能开时的偏差来自技能动作占用普攻（正常），不算。

### 3.4 动作帧率与出手间隔

窗口 = min(标称时长, 间隔 × active_ratio 0.9)；`窗口 ÷ 间隔` 在上表末列（> 1 的格子是读数时机造成的伪值，窗口恒 ≤ 0.9 × 间隔）。动画倍率 k = 标称时长 ÷ 窗口 > 3 后画面隔帧抽取（docs/153）。典型：能天使 4×：标称 0.25 → 窗口 0.079，k = 3.2，刚过隔帧线；水月 4×：0.72 → 0.18，k = 4，隔帧步长 1.33。

## 4. 统一规则（写进代码）

1. **出手窗口跟间隔走**：动作条整条（前摇 / 出手帧 / 收势）按间隔等比缩短，不设下限（docs/153，`character._start_action`）。
2. **会 `lock` 普攻的外挂时间轴（钩索、往返弹体）也按攻速缩**：钩索 `seg_ulpianus.hook_speedup` = max(1, op_aspd)，开关 `balance.json atkspeed/hook_follow`（0 = 旧行为，对照用）。新写的会占住普攻的机制必须自带这个缩放。
3. 动画倍率过 3 隔帧抽取，出手帧一定显示（不卡逻辑）。
4. 怪物 / Boss：动画从逻辑计时器取帧（蓄力 `wind` / `blast_w` / `dash_w` 前两帧，出手后 `atk_until` 0.2 秒后两帧），不反向卡逻辑；不吃玩家攻速；倍速（1.5×）按游戏时间 g.t 走，整体等比，代码里没有挂在真实时钟上的动画（`get_ticks_msec` 只用于加载 / 性能）。冰冻 / 减速的敌人按 `vt` 画面时钟，不在本次修复范围。
