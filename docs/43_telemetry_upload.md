## 1. 原则

- **只收匿名对局数据**：本局怎么玩、怎么结束。不收账号、昵称、设备型号、设备序列号、硬件信息、位置、通讯录之类的任何个人信息。
- **默认不上传**：首次启动先征得同意；玩家可在设置里随时关掉（§5）。
- **不影响游戏**：上传在后台进行，失败不弹窗、不卡结算；断网照常玩，攒着下次再传。
- **本地记录是唯一来源**：上传的就是 docs/40 写在 `user://runs/runs.jsonl` 里的那一行（外加匿名安装编号），服务器和本地分析用同一种格式（`tools/runs_report.py` 可直接汇总）。
- **测试运行不上传**：带任何 `--xxx` 参数启动都不上传（与「测试不写玩家存档」同一判定）；上传自测用专门的参数指向本地模拟服务器（§8）。

## 2. 上报哪些字段

每局一条，结构与本地记录相同：

```json
{
  "schema": 1,
  "run_id": "b1f0…（本局随机 UUID，服务器按它去重）",
  "install_id": "7c2e…（首次同意时随机生成的 UUID，只存在本机；不是设备号）",
  "meta": {
    "version": "2.0", "commit": "abc1234", "platform": "Windows | Web",
    "time": "2026-09-26T07:51:48（UTC）", "seed": 123456, "diff": 0, "map": "deep_sea",
    "start_op": "mizuki", "result": "win | dead | quit", "lang": "zh"
  },
  "run": { … docs/40 的整局记录 … }
}
```

| 类别 | 字段（`run` 里） | 用途 |
| --- | --- | --- |
| 结果 | `win` `t` `lv` `ending` `kills` `elites` `bosses` `boss_hp` | 胜率、存活时间、卡在哪个 Boss |
| 成长 | `lv_times` `marks` `ops` `elite_stage` `prog_offer` `prog_pick` | 升级节奏、选卡偏好、精英化时机 |
| 藏品 | `relic_offer` `relic_take` `relics` `relic_out` | 藏品出现率 / 拿取率、流派 |
| 伤害 | `out` `out_type` `out_tag` `final_out` | 输出构成、谁在出伤害 |
| 生存 | `dmg`（承伤来源） `heal` `maxhp` `lamp` `drone` | 死因、治疗是否够 |
| 行为 | `bot`（受击、低血时长、熄灯、移动 / 站桩比例、Boss 用时、每 30 秒曲线） | 难度曲线、玩家压力 |
| 大群 | `hordes` | 大群清怪速度 |

- **不上传** `prof`（性能计时，只对开发有用、体积大）；`floor_hits / floor_times` 只在测试模式有值，玩家局为空。
- 体积：一局约 10–30 KB JSON；上传时 gzip 压缩后约 3–8 KB。
- 新增字段不用改 `schema`；**改名 / 删除 / 改含义**时 `schema` +1，服务器按 `schema` 分别解析。

## 3. 何时上报

1. **结算时一次**：进入胜 / 负结算（`telemetry.on_state`）写本地记录后，立即在后台尝试上传这一条。
2. **中途退出**：写本地记录（`on_exit`）时不上传（退出过程中网络请求常被打断），留到下次启动。
3. **启动时补传**：进入标题页后，把队列里还没传成功的记录分批补传。
4. 局内不足 20 秒的对局本地就不记（docs/40），自然也不上传。

## 4. 离线缓存与重试

- **队列就是本地记录**：`runs.jsonl` 每行加一个本地状态文件 `user://runs/upload_state.json` 记录已上传的 `run_id`（或已上传到的行号），不另存一份数据。
- **批量**：每次最多 20 条、单次请求 ≤ 256 KB（压缩后），超出分批。
- **重试节奏**：网络错误 / 服务器 5xx → 1 分钟、5 分钟、30 分钟后重试，再失败留到下次启动；4xx（格式不对、被拒）→ 该条标记放弃，不再重试，记本地日志。
- **上限**：未上传的记录最多保留 200 条或 5 MB，超出丢最旧的（本地 `runs.jsonl` 本身另有 8 MB 上限，docs/40）。
- **幂等**：服务器按 `run_id` 去重，重复上传同一条无害（「上传成功但响应丢了」的情况会发生）。

## 5. 开关与同意

- **首次同意**：第一次进入标题页（或第一次结算前）弹一次说明：「分享匿名对局数据，帮助我们调整难度与平衡。不包含任何个人信息，可随时在设置中关闭。」按钮「同意」/「不同意」，**没有预先勾选**。未选择前视为不同意。
- **设置开关**：设置 → 数据 → 「分享匿名对局数据」。
  - 关掉后立即停止上传，并提供「清除本地未上传记录」。
  - 设置页显示本机的匿名编号（`install_id`），玩家若要求删除已上传的数据，凭它申请。
- **存储**：`Cfg`（`user://settings.cfg`）新增 `telemetry_consent`（未问 / 同意 / 不同意）、`telemetry_consent_ver`（说明文本版本）、`install_id`。
- **重新征求**：上报范围扩大（新增一类数据）时把说明版本 +1，已同意的玩家下次启动重新确认一次。
- **隐私说明**：一页短文（游戏内「关于」或发布页），写清收集什么、用来做什么、保存多久（建议 1 年）、如何关闭与申请删除、联系方式。大陆发布受《个人信息保护法》约束——匿名安装编号仍算标识符，所以按「最小必要 + 明示同意 + 可撤回 + 可删除」来做；上架平台（如 Steam、TapTap）另有各自要求，发布前由「部署」核对。

## 6. 接口（后端选定后细化）

```
POST https://<域名>/v1/runs
Content-Type: application/json
Content-Encoding: gzip            （可选）
X-Client: ShuiyueSurvivors/2.0 (Windows)

{"schema": 1, "install_id": "…", "runs": [ {run_id, meta, run}, … ]}

200 {"accepted": ["run_id", …], "rejected": [{"run_id": "…", "reason": "…"}]}
413 / 400  → 放弃这批里被拒的
429 / 5xx  → 按 §4 重试
```

- 只走 HTTPS；不做账号鉴权，用一个写死在客户端的「公开写入密钥」区分正式包与测试请求（防误写，不当作安全措施）。
- 服务器侧：按 `install_id` 限流（例如每小时 60 条）、单条大小上限、**不长期保存 IP**（接入层日志按平台最短期限滚动）。
- 存储：原始 JSON 原样落库（按 `schema` 分区），分析时导出成 `runs.jsonl` 直接喂给 `tools/runs_report.py`；需要的聚合表另建。

## 7. Windows 版与网页版的差异

| 项 | Windows 版 | 网页版 |
| --- | --- | --- |
| 网络请求 | Godot `HTTPRequest`（自带证书链） | 同一 API，底层走浏览器请求；**服务器必须配置 CORS**，允许发布站点的域名 |
| 本地记录 / 队列 | `%APPDATA%\Godot\app_userdata\<项目名>\runs\`（项目名改了目录就变） | 浏览器 IndexedDB；**清除站点数据即丢失**队列与 `install_id`（会被当成新安装） |
| 中途退出 | 下次启动补传 | 关闭页面时可用 `navigator.sendBeacon`（经 JavaScriptBridge）尽力发一次，发不出去就算了 |
| 混合内容 | 无 | 页面是 HTTPS，接口也必须 HTTPS |
| 同意弹窗 | 游戏内 | 游戏内（不依赖浏览器的 Cookie 横幅） |
| 大陆访问 | 服务器与域名需在大陆可访问 | 同左；若游戏页与接口不同域，两个域名都要可访问 |

- **域名备案**：服务器放在大陆需要 ICP 备案；放在境外则要注意数据出境与访问稳定性。这由「部署」的后端调研一并给出结论。
