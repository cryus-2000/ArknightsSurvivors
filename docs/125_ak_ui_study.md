## 2. 可执行规则（本作版）

1. **骨架照锚点**：背景用选人 B+ 的深海青 → 深紫斜向渐变；舞台用职业色斜带 `UI.class_band` + 巨型描边英文 `UI.ghost_name`；面板 `UI.bpanel`（藏青半透明 + 紫细边 + 青饰角菱形）、页签 `UI.btabs`、标签片 `UI.pill` / `UI.btab`、主按钮 `UI.deploy_button`、名册卡 `UI.roster_card`。不另起面板样式。（规则 1、2，锚点）
2. **一屏一个强调色**：主操作青 `B_ACC` / `CYAN`；「当前」紫 `VIOLET`；局外资源有自己的识别色（生机细胞 = 源石锭绿 `GREEN`，三种券 = 青 / 紫 / 近白）。黄只留给图鉴；金 `#FFC450` 只用在寻访的金档。（结论 1、10）
3. **几何**：矩形 + 小圆角（B 语言），斜线只用在舞台斜带和卡内斜带缩影；不加平行四边形、警示条（那是图鉴 C 的专属）。（结论 2，docs/37 §1）
4. **质感**：大面积底加 6 px 网点（1 px、2.5% 白），不用模糊；要突出的区域靠压暗周围（`B_FILL` 半透明面板 + 舞台留暗）。（结论 3）
5. **标题层级**：中文大字（粗）+ 一行彩色斜体英文 + 一行微型代码 `No.xx // 分类 // 英文`；段落头统一「ENGLISH // 中文」小号灰字。英文只装饰，不承载必需信息。（结论 4、13）
6. **数据**：关键数字「大号数字 + 小号中文标签 + 更小英文」横排；明细是表格行（项目 / 次数 / 分值，右对齐，行间 5% 白细线）；比例用读数条（细轨 + 实段 + 白色端点刻度）。（结论 8、13）
7. **结算照集成战略**：逐项计分 → 总计 × 潮位系数 → 换算生机细胞，算式写出来；局标识（种子）放右上角。（结论 8、9）
8. **奖励有光圈**：生机细胞、券图标背后三圈台阶式光圈（像素版，不做柔光）。（结论 3）
9. **立绘大而居中、站在斜带上**：整数倍（桌面 5–6 倍、手机 3–4 倍），可以压过斜带和描边英文；人物色调与原作一致（docs/87 §4.3）。（结论 11、12）
10. **寻访视差**：入口页意向干员大剪影居前，另两名小剪影在后、无投影环。（结论 6）
11. **揭示分三拍**：拉包 / 漏光（蓄势）→ 光炸 + 碎三角（爆发，金档）→ 名字块定格；名字块就是选人 B+ 的名字块。（结论 7、12，docs/124）
12. **转场**：同一主题内横向滑入 / 展开；进出系统深色淡出；次级内容（意向选择、券说明）用浮窗。（结论 5）

| 项 | 图鉴 C4′ / 选人 B+ 现状 | 结算现状 | 寻访现状（headhunt-ui） |

| 逐项计分 → 系数 → 换算 | — | **没有**（只有一行生机细胞） | — |
| 奖励光圈 | — | 没有 | 没有 |
| 局标识（种子） | — | 没有 | — |
| 网点底纹 | T5s 有抖动 | 没有 | 揭示屏有扫描线 |

## 4. 两屏设计

### 4.1 结算（`result_desktop.png` / `result_phone.png`）

- **舞台**：队长站在职业色斜带上（5 倍），背后是结局英文名描边大字（PRECIOUS DAYS）；失败时斜带换洋红、描边字换击倒者英文名。
- **左上名字块**：`No.01 // ENDING // 结局一` → 大字「探索完成」/「探索中止」→ 斜体 `OPERATION COMPLETE` → 标签片「平凡即是喜乐」「首次达成」→ 一句结局文案。
- **关键数字**：探索时间 / 击杀 / Boss 击破 / 造成伤害，大号数字 + 小号标签横排。
- **左下编队**：名册卡 + 伤害占比读数条 + 招募时间。
- **右侧面板**（页签 结算 / 数据 / 藏品；「数据」「藏品」即现在的作战记录页，docs/77，收进同一屏的页签里，不再另开页）：
  - 结算页签：逐项计分（存活 / 中期 Boss / 通关 / 结局首达，项目 · 次数 · 分值）→ 一行算式「评分 × 潮位系数 ÷ 8」→「局外收获」：生机细胞大卡（+N，评分与首通赏金两行，认知塑造进度读数条）→ 三种券各一张小卡（来源一行：每次结算 / 通关 / 首通潮位 N）。
- **右上**：种子编号片 + 潮位片；**右下**：出击式主按钮「前往寻访 ›」（有券时；没有券时主按钮是「再次探索」），次按钮 再次探索 / 回到标题。
- **手机**：舞台居中偏左（3 倍），左列名字块 + 三个大号数字 + 计分表，右侧局外收获面板，底部主按钮 + 三个次按钮（≥ 29 设计像素高，按 `ui_k` 放大后 ≥ 44 屏幕像素）。
- 数值口径：docs/109 §3.1（结局首达不乘系数，算式按实际公式写）。

### 8.3 招牌动效：解锁时枝条长亮（`meta_tree_unlock.gif` / `meta_tree_unlock.png`，A 版演示）

1. 按下「确认塑造」：父节点到新节点之间的暗虚线上，白色光头沿枝条推进，身后留下 4 px 青白实线（0–0.55 秒）。

3. 收尾（实现时再加）：整条链从根部向上扫一道亮光（0.3 秒）；这条链上下一个节点变成「可解锁」并开始呼吸；如果解锁的是末节，链顶的质变短句标签闪一下并转为暖白。
4. 背景：解锁瞬间，节点周围 150 px 内的几何线提亮一次，再在 0.6 秒内回落。

### 8.7 第二轮 B2 / D2：不规则碎片（10-22，用户看了四版后的要求）

用户要求：几何图案要「不规则」，不要网格、等高线、整齐三角阵；流动也要「无规则」，不是整层平移，每块碎片的方向、速度、自旋都不同，偶尔停顿、偶尔加速。气质参照明日方舟莱茵生命。PRTS 上查了 SideStory「孤星」的预告横幅（特里蒙 / 莱茵生命篇），只学气质，不用素材：浅灰实验舱板块，细线勾边，零散的小号等宽标注和刻度，整体是精密实验室的图纸感。

样图：`python -X utf8 tools/probes/meta_tree_mock2.py`，输出在 `build/ak_mock/` 下，包括 `meta_tree_{B2,D2}.png`、`meta_tree_{B2,D2}_flow.gif`（流速 ×6，每帧 1.5 秒真实时间，共 72 秒）、`meta_tree_{B2,D2}_flow.png`（0 / 24 / 48 秒三帧）和总览 `meta_tree_sheet2.jpg`。图谱与左栏沿用 B / D，没有改动。

**碎片系统**（34 片，固定种子）
- 形状：30% 是切角板块（矩形随机切 1–2 个角，莱茵实验舱板的感觉），70% 是 3–8 边的不规则多边形（顶点角度和半径都随机抖动）。尺寸 40–300 px，对数均匀分布，所以小片多、大片少。
- 画法：1 px 青白描边，不透明度 22–42%；填充 5–10%。约 35% 的碎片带内部细线（一条对角线加两道平行短线），25% 沿一条边有刻度（每 8 px 一道，每 5 道一长），30% 带引线小标注（如「R-72 / 0.37」）。
- 运动：每片有自己的方向和基础速度（0.5–3 px/s），自旋 ±2°/s。速度倍率 = 两组慢正弦相乘再加一项小扰动，低于 0 时截为 0，所以会自然出现停顿（倍率 0）和加速（约 1.8 倍）；方向每秒偏转 ±0.03 rad，轨迹是弧线，不是直线。
- 零散小标注：16 个十字准星 / 比例尺 / 角括号，各自以 ≤0.6 px/s 漂移，不跟随碎片。
- 选中提亮：碎片中心距选中节点 260 px 以内时，描边和填充按距离线性提亮，最多约 1.9 倍。

**两版差异**：B2 是暗场 #13171E 配青白线，左侧浅色斜切，和寻访是同一套；D2 是石板蓝 #22344A，碎片描边更亮，整体明度更高。我的判断仍然是 **B2 首选**：暗场让碎片的细线最清楚，左白右黑的系统与寻访 / 结算一致。如果用户觉得 B2 仍偏暗，就选 D2。

**实现要点**（定版后）：碎片数量不多（30–40 片），每帧直接用 draw_polyline / draw_colored_polygon 画即可，不必烘贴图；运动参数开局随机生成一次，每帧按 delta 积分；标注文字用 10 px 等宽字。网页低画质档把碎片数减半。

## 9. 地图美术方向：溟痕「被抹平」（10-24，协调人单 / 用户定）

用户定：地图美术**围绕已有的溟痕与黑潮缩圈**，不做「走到远处换区域」。海嗣把一切归于同一，所以溟痕侵蚀表现成「被抹平」，不是血肉腐烂。

### 9.1 原作查证（PRTS）

| 出处 | 原文要点 | 对方向的意义 |
|---|---|---|
| PRTS「溟痕」装置页（英文名 Sealed Floor） | 溟痕是特殊地面，每 12 秒向相邻可通行地面扩散一次；我方站在上面持续受法术伤害与神经损伤；有单位站着的格子不扩散 | 机制：地面被逐格「铺满」，本作的周期扩散与灯标清除与此一致 |
| 「水月与深蓝之树 / 事件一览」·悬高之葬 | 溟痕覆盖着海面，且正在向着山崖蔓延 | 「覆盖」：成片铺开的一层，而不是零散的血肉块 |
| 同上 · 灯塔看守人 | 溟痕吞噬了这个国家引以为傲的光亮，最后一座灯塔也已腐蚀倒塌 | 溟痕「吃光」：被侵蚀处暗、吸光；灯塔 / 灯标作为对抗它的光源成立 |
| 同上 · 点滴星火 | 噬尘已经覆盖了整座城市，文明产物都将被**有序消解**，化作海嗣生育后代与进化的养料 | 「有序消解」：直接支持「被抹平、规整」而非杂乱腐烂 |
| 同上 · 引火之木 | 片叶不生的树，树皮薄而通透，**光滑得像是皮肤** | 被海嗣同化的东西表面光滑、均匀 |
| 同上 · 设身处地 | 选项「喂食水池边的溟痕」 | 溟痕是活的物质，可以有缓慢的「呼吸」起伏 |

- **结论**：原作支持「覆盖、吸光、有序消解、表面光滑」。原作文字里也用「腐蚀」「吞噬」（灯塔腐蚀倒塌），所以前沿可以有侵蚀感，但被覆盖之后的区域是平整、规整的。
- **没找到的**：「清洁工」这个词本身，在已查的 PRTS 页面（溟痕、斯卡蒂的海嗣、事件一览、浊心斯卡蒂 / 归溟幽灵鲨 / 乌尔比安 / 斯卡蒂 / 水月干员页）里没有出现。最接近的原文是「有序消解」。
- **原作外观**：没有找到对溟痕地块外观的文字描写（BWiki 溟痕页「描述」一栏为「无描述」）。按本作已统计的原作海嗣发光色（青蓝为主，见光学观感颜色语言），荧光取青蓝。
- **现状差异**：本作现在的溟痕贴图（`terrain_mire`）是紫黑底 + 不规则青色网状脉络，读起来是「血管 / 腐烂」，和新方向相反，需要重画。
