# 141 · 打击感偏弱的原因调研（10-24，测试与验收）

用户：「研究一下现在为什么我玩起来打击感弱」。只读调研，没改任何游戏代码 / 数据。行号按 main ca543373 读；A / B 的行号单独标。
界面会话在 `claude/hit-tiers` 做「三级命中模板 + 近战刀光」（本文写成时是 `interesting-kilby-98da4d` 工作树里的**未提交改动**：7 个文件 +194 / −4，分支头仍是 8b158b5a），§4 按它现在的 diff 判断覆盖面。

## 0. 结论（三条）

1. **「同屏被打的东西少了一半以上」是最大的单项。** 怪物密度 0.4（10-14，acdb9c6a6）之后，同一 seed、同一机器人、水月单人：1 分钟击杀 144 → 57，7 分钟累计 2733 → 1231，7 分钟同屏敌人 147 → 101。队长自己的命中频率变化不大（3 分钟内命中音请求 334 → 227，水月命中 177 → 185），但击杀（爆点 / 击杀音 / 顿帧触发）少了 2.2–2.5 倍（队伍因机器人招人而分叉，只作量级参考）。
2. **每项手感旋钮单看都不大，叠起来是「全往下压」**：顿帧只有 1–3 帧且被 0.5 秒真实时间间隔卡成每秒 ≤2 次（10-11，20d50389b）；普通命中火花清零（10-14，bd5ebf6c6）；命中环 / 辐条不画（10-13）；后期降噪 3 档在拥挤时把白闪压到 0.45、群闪再 ×0.35（≈0.16）、普通白字伤害数字上限降到 0（10-12 / 10-23）；Boss 白闪减半。基础近战击退折成位移只有 1–3 世界单位，和没有一样。
3. **hit-tiers 现稿补的是「画面分档 + 刀光」，没动顿帧间隔、击退、拥挤降噪、伤害数字、受击姿态时长、命中音优先级**；这几项仍要新增，其中收益最大的是放宽顿帧间隔并抬时长（零性能代价）。

## 1. 方法

- 代码走读 + `git log e97b4a2..HEAD -S<常量>` 找每项数值被改的提交。A = `e97b4a2`（EA 冻结，9/30），B = `c72aa86a`（光学合入前，10-23），C = HEAD `ca543373`（光学开）。
- 同 seed 数据：`--headless --balance --seed=1 --bot=expert --op=mizuki`（水月单人，机器人自己招人）A / B / C 各跑 420 秒，`--trace=10` 取击杀与敌人数（B 与 C 的模拟逐行相同，光学只改画面）；C 另跑 `--perf --sfxstat`（无头 + `--realtime --rtfrom=330` 的 90 秒真实步长窗口）取顿帧 / 音效请求数。**无头跑里顿帧的「实给」次数不可信**（`UM.now()` 界面时钟在无头下几乎不走，0.5 秒间隔把几乎所有请求挡掉），所以顿帧只用「请求数」与代码上限推算，不报实给次数。
- 画面：`tools/godot_runner.run_godot` 开窗口（副屏、静音）、`--fixed-fps 60`、`--balance --drawtest --realtime --shots=帧,…`，三个版本各开 `git worktree`（用完已删）。**光学观感开着时，视口截图里世界层是空的（只有 HUD 和一片浅蓝底），原因没查**（`--bal=render/optical=0` 世界正常画出）；所以 C 的截图是光学关的样子，**光学开时的实际画面本调研没看到**，也不对光学下的白闪 / 辉光叠加下结论（docs/130 B1 的推断未验证）。
- 截图只有静帧：顿帧、闪白几帧内的变化、刀光出现的那一两帧都不能靠它判断；画面对照图主要看「敌人密度 / 描边 / 火花」这类静态差别。

只引用 docs/110「动作节奏人眼验收」（10-22）：18 人普攻起收比例逐个核对，**未发现仓促 / 卡住**；水月 / 塞雷娅 / 铃兰 / 维什戴尔收势占 63–78%（重武器后摇，待用户定）；对照图在 1920×1080 下干员只占几十像素，**蓄力细节人眼看不清，只确认帧间连续**。docs/128：1 倍帧条下身体 / 衣服 / 武器读得清，脸糊（已转 Codex）。本次不重做；补一条本调研的量化：普攻出手帧武器只伸出身体 24–76 世界单位（§2.9），远小于判定。

## 4. 与 hit-tiers 现稿的覆盖对照
