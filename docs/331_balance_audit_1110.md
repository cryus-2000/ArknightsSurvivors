# 331 全局数值体检（11-10，只诊断不改数）

> 协调人派：当前 main 的敌人血量、干员 / 队友伤害、我方血量、Boss 伤害是否在合理范围、是否沿合理成长曲线走。本文**没改任何数值**，下面的「建议改法」都要用户 / 协调人定了再做，做的时候按 docs/80 同种子配对 + ≥3 份实现验证。

## 0. 方法与口径

- **代码**：main **175e43971**（未改动）。
- **数据**（全部 GCP，结果分支 `cloud-results/audit-1110-*`）：
  - 正常局：`--preset starts`（7 名开局干员 × 种子 1–8）、expert 机器人、常规档，无认知（m0）56 局、18 细胞（m18，`--meta=18`）56 局。
  - 不死模式（`--nodeath`，曲线跑满全程）：同样两档各 56 局，用来看 7 分钟后的曲线（正常局后段只剩活下来的局，有幸存者偏差）。
  - 木桩表（docs/79，`tools/op_dummy_table.py`）：20 人 × 精零 / 精一 / 精二 × 木桩 / 怪群 × 队长 / 队友，240 局。
- **静态复算**：`tools/balance_audit_1110.py` 按 balance.json / enemies.json / waves.json 照抄 spawner.gd、combat.gd、dmg_curve.gd 的公式，算单只生命、池平均一下伤害、每秒涌入血量。同一个脚本读遥测出图和 `Claude outputs/balance_audit_1110/audit.json`（本文所有数字的出处）。
  - 复跑：`python tools/balance_audit_1110.py --m0 <dir> --m0nd <dir> --m18 <dir> --m18nd <dir> --dummy <table.json>`
- **口径**：
  - 全队秒伤 = 遥测 `outc`（累计全队造成伤害）相邻两格之差 ÷ 30 秒，中位数。**注意：这是「实际打出的」，受怪物供给限制**——怪都死了就没得打，所以它在后期近似等于涌入血量，不代表上限。上限看木桩表。
  - 压力 = 每分钟承伤 ÷ 最大生命 %（docs/146 同口径，100 = 一分钟挨掉一整条血）。
  - 普通怪「一下」= 打在队长身上的单次伤害，扣受伤 0.9 与平均护甲 1.9（dmg_curve 口径），含密度换算与后期补偿。
  - 单份 56 局胜率组间 sd 约 6–8 点，**本文只有 1 份实现，胜率差 < 10 点不下结论**（docs/80）；胜率只作方向参考。
- 时间点：1 / 3 / 5 / 7 / 9 / 10 分钟。

**总体胜率（参考）**：m0 **64%**（目标 45–55），m18 **86%**（目标 65–75）。两档都比窗口上沿高约 10 点，方向一致但只有 1 份，需要再跑 2 份确认才能定「整体偏松」。不死模式下 m0 98%、m18 100% 通关，`--nodeath` 托底次数几乎为 0（机器人没真正掉到 0 血）。

结论：
- **太松的一段：7–10 分钟**。秒伤 ×1.6（2447 → 3852），敌人生命池 ×1.4，高阶怪单只还在变薄、一下伤害在 8:40 回落；精英 1 秒、引痕者 0.25 秒就死，压力降到全程第二低（只高于第 1 分钟），m0 / m18 都几乎没人死在这段。这是「割草过头」的地方。
- **断崖的一段：4:00–7:00**。伤害补偿拉满、换池、卡门同时落在这 3 分钟，秒伤还没到精二 + 满级的量级，在场敌人堆到 73；m0 死亡 90% 在这里。
- 前 3 分钟、最终 Boss 段的形状合理。
