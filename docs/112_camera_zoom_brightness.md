## 1. 镜头候选

### 1.1 各档视野与像素

`@2x` 帧条 1 个贴图像素 = 1 个世界像素（`PX` 2 ÷ 密度 2）。屏幕上每个贴图像素占的屏幕像素数 = 窗口倍率 × 镜头倍率。窗口倍率：720p 是 1，1080p 是 1.5，1440p 是 2，4K 是 3。

| 档 | 视野（世界像素） | 面积 | 半宽 / 半对角 | 720p | 1080p | 1440p | 4K |
|---|---|---|---|---|---|---|---|
| 现状 ×1.0 | 1280×720 | 1.00 | 640 / 734 | 1.00 | 1.50 | 2.00 | 3.00 |
| ×0.85 | 1506×847 | 1.38 | 753 / 864 | 0.85 | 1.275 | 1.70 | 2.55 |
| ×0.75 | 1707×960 | 1.78 | 853 / 979 | 0.75 | 1.125 | 1.50 | 2.25 |
| **×2/3** | 1920×1080 | 2.25 | 960 / 1101 | 0.667 | **1.00** | 1.333 | **2.00** |
| 手机现状 ×1.2（2340×1080） | 1300×600 | — | 650 / 716 | | 1.80 | | |
| 手机 ×1.0 | 1560×720 | — | 780 / 859 | | 1.50 | | |
| 手机 ×0.9 | 1733×800 | — | 867 / 955 | | 1.35 | | |

**像素结论**：

- **不会发糊**。世界层贴图一律最近邻采样（`default_texture_filter=0`），还开了变换和顶点的像素对齐，所以任何倍率都不会模糊。非整数倍率的毛病是像素宽度不均匀：一部分贴图像素占 1 个屏幕像素，一部分占 2 个，移动时这种分布跟着变，就会看到细线和描边轻微爬动。
- **1080p 的现状 ×1.0 本来就是非整数（1.5）**，这种爬动现在就有。×0.85 是 1.275，×0.75 是 1.125，越接近 1 越不显眼。
- **×2/3 在 1080p 和 4K 上正好是整数（1.00 / 2.00）**，是最干净的一档，比现状更干净。它在 1440p 上是 1.333，和现状 1080p 的 1.5 差不多。
- 720p 窗口下，拉远到 1 以下就会漏掉贴图像素，细描边可能时有时无。720p 是最小的窗口档，玩家很少用。

### 1.2 拉远后会露出来的东西（逐项查过代码）

玩法不读视口，这一点仍然成立：各档同 seed 模拟一致，机器人和难度不受镜头影响。但下面这些写死的距离是按 1280×720 视野定的，拉远后会**在画面里**露馅：

| 项 | 位置 | 现值 | ×0.85 | ×0.75 | ×2/3 |
|---|---|---|---|---|---|
| 普通刷怪环 | `spawner.gd edge_pos` | 离队长 720–820 | 左右两侧在屏内（半宽 753） | 左右整段在屏内（853） | 大半圈在屏内（960） |
| 大群刷怪环 | `spawner.gd` 大群 | 560–640（再加 −70 到 +90） | 屏内 | 屏内 | 屏内 |
| 掉队拉回 | `enemies.gd` | 超过 1300 就挪回刷怪环 | 不可见 | 不可见 | 屏角 1101，接近 |
| 经验回收视野 | `pickups.gd` | 固定 1280×720 + 96 | 屏幕边缘的结晶 6 秒后**在画面里**消失 | 更明显 | 屏幕外圈约 1/3 的结晶都会消失 |
| 钵海收割者伏兵 | `spawner.gd spawn_enemy` | 超过 700 才挪近 | 刷在屏内时不挪 | 同 | 同 |
| 灯火光圈（画面） | `world.gd` | 半径 150–520 | 屏幕四周暗区变大 | 更明显 | 满灯时屏幕约一半在暗区 |
| 屏外红边提示 | `hud_banners.gd` | 只在 zoom > 1 时画 | 不受影响 | 同 | 同 |
| 地面、前景、雪、光柱、黑潮暗区、溟痕带、大景物 | 按 `view_size()` 铺 | — | 自动铺满（已有，10-13 起支持到 80%） | 截图里没漏底 | 截图里没漏底 |
| 敌人 / 溟痕 / 掉落剔除 | `view_rect` 按画布变换 | — | 自动 | 自动 | 自动 |
| 命中火花、跳字的距离门槛 | `vfx.gd` | 650 / 700 | 屏幕边缘被打的怪没火花 | 同 | 同 |

结论：**任何一档拉远都要同时改刷怪环和回收视野**，否则怪会在屏幕里凭空冒出来，结晶会在屏幕里凭空消失。现在设置里调到 80% 的玩家已经会碰到这个问题（半宽 800，刷怪环 720–820）。

### 1.3 刷怪 / 地图要不要跟着改，对难度的影响

- **地图**：地图是无限的程序生成，按 560 一格放大景物，按 512 一块铺地面。拉远只是一屏里看到的景物、地形块更多，世界密度不变，**不用改地图尺寸**。黑潮圈半径（1300 → 480）和地形阻挡也不读视口。拉远以后，黑潮缩圈在屏幕里更早看得到，算加分。障碍密度要不要加，属于观感问题：×2/3 时一屏的大景物数是现状的约 2.25 倍，截图里不显空也不显挤，**建议不动**。
- **刷怪环**：建议改成一个跟设备和设置都无关的「逻辑视野」常量（比如 `view/logic_w × logic_h`），刷怪环、回收视野和伏兵门槛都按它算；玩家自己设的缩放只改画面。这样同 seed 在任何机器上结果仍一致，桌面和手机难度也一样。刷怪环半径 ≈ 逻辑视野半对角 + 60。
- **难度影响（估算，没跑小样）**：普通怪移速中位数约 55 / 秒。刷怪环外移后，接敌时间：×0.85（环约 920–1020）多约 3.6 秒；×0.75（环约 1040–1140）多约 5.8 秒；×2/3（环约 1160–1260）多约 8 秒。前期压迫会下降，后期敌人数上限不变。补偿办法有两种：（a）刷怪环不画成圆，改成「视野矩形外 60」，上下方向反而比现在近，平均只多约 2–3 秒；（b）按接敌时间等比提高 `spawn_base`。选定档位后，要跑难度小样（docs/80，≥3 份独立实现取均值）再定。

### 1.4 帧率（同局轮换实测）

见 §3 的表。量法：同一局里每 60 帧轮换一次镜头档，按「这一帧画的是哪档」分桶，换档后头 5 帧不计。镜头只改画面，模拟逐帧相同，所以机器负载起伏对各档影响一样。数字已同步给性能会话。

### 1.5 触屏布局和 HUD

HUD 在界面层，按 `Cfg.ui_k` 缩放，不读镜头。手机三档截图里摇杆、冲刺键、编队栏、声呐位置一样（`sheet_p_full_t0240.png`）。`touch_layout_test` 里的「手机缺省 1.2」那条断言要等缺省改了以后同步。

## 4. 推荐

- **镜头：桌面缺省 ×2/3（设置里显示 67%，内部存精确 2/3）**。1080p 和 4K 下 @2x 正好 1:1 / 2:1，是唯一比现状更干净的一档；人物在 1080p 上约 90–100 屏幕像素高。如果用户觉得太小，退一档用 ×0.75（1080p 下 1.125，爬动很轻）。×0.85 变化不大，又照样要改刷怪，性价比最低。
- **手机：×1.0**（现 1.2）。手机像素密度高，1.5 倍的不均匀几乎看不出来；×0.9 的人物在 6 寸屏上偏小。
- **配套必做**：刷怪环、经验回收、伏兵门槛改成按「逻辑视野常量」算（§1.3）；设置下限从 80% 放到 60%，并且做吸附（1080p 下靠近 2/3 时取精确值）；灯火光圈的**画面**半径按 1/zoom 放大，判定 `lamp_r` 不动，不然满灯时屏幕一半是暗的。改完跑难度小样（各档熟练机器人 50–70%）。
- **亮度：亮 B**（暗部回提 + 环境光 ×1.3）。暗灯场面提亮最明显，高光和截白不变。想再亮一点就选 C。改法是 balance.json 两行（`render/look_toe` 1.0、`render/ambient_mult` 1.3），可以整条回退。
