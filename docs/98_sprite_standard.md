# 98 · 角色与怪物立绘统一标准（v2，2026-10-14）

> 用户 10-14：「写完之后再出一版最新的人物和怪物的立绘标准」。本文把干员（docs/87）、普通 / 精英怪（docs/94 §0）、Boss（docs/38 §6.2 + docs/95 §13.1）、召唤物（docs/92、93）的条款合成一份，**跨类别条款（像素密度、同屏比例、敌我配色、特效归属）以本文为准**；各类别的细则（动作质量指标、机检阈值）仍在原文，冲突时以本文为准。
> 适用对象：Codex 交付的所有人物类帧条。特效 / 弹体 / 地面件走 docs/93 §0。

## 1. 像素密度：全游戏一致

| 项 | 规定 |
|---|---|
| 世界比例 | 1 美术像素（1x）= 2 屏幕像素（`Game.PX = 2`）；画布尺寸、脚底锚点、判定半径都按 1x 定 |
| **@2x 为主** | 所有人物类帧条一律交 1x + `@2x`（每帧 2 倍），**以 @2x 为主绘制**，1x 由 @2x 对应导出并修像素；游戏优先加载 @2x、绘制倍率减半，画面上 1 个 @2x 像素 = 1 屏幕像素 |
| 覆盖范围 | 干员、博士、水月、普通怪、精英怪、**Boss**、召唤物 / 人偶 / 海嗣、同伴（骑士）。**Boss 不再允许只有 1x**（docs/95 §13.1 补齐 8 个 Boss） |
| 一致性 | 1x 与 @2x 逐帧对应：帧序、起伏量、腿的前后关系一致；@2x 缩到 1x 剪影差 ≤ 0.10（机检 `pair`） |
| 不允许 | 非整数倍缩放的像素（程序 `enemy/scale` 旋钮只用 1.5 / 2.0 这类让 @2x 像素仍为整数屏幕像素的档位） |

## 2. 通用硬规格（所有人物类帧条）

| 项 | 规定 |
|---|---|
| 排列 | 横向一行等宽帧，RGBA PNG，宽 = 帧数 × 单帧宽；1x 与 @2x 同名加 `@2x` |
| 透明 | alpha 只有 0 / 255；不画阴影、半透明、辉光（影子、受光、白闪、描边光由程序画） |
| 外描边 | 1px `#080E18`（@2x 2px）：与透明区四邻接的像素 100% 为 `#080E18`，@2x 往里第二圈也是；描边必须闭合 |
| 朝向 | **只画朝右**，朝左由程序镜像；同一角色所有动作同向、切换不跳 |
| 脚底锚点 | 干员 / 博士 / 水月：(24, 46)；普通怪 / 精英 / Boss：**脚底贴画布底边、水平居中**（docs/94 规格；enemies.json `anchor: "foot"`）；漂浮类（浊心斯卡蒂、安洁莉娜浮空、浮海飘航者）按各自工单的离地行，并在 art_lint WAIVERS 登记。安洁莉娜浮空（`op_angelina_float` / `_float_move` / `_float_attack` 全部帧、`_float_in` f3）：最低不透明行 **38 ± 1**（@2x 76 ± 2），脚底中心 x 仍 24 ± 2；`_float_in` f0–f3 最低行 46 / 46 / ≈ 42 / 38（docs/archive/92 §2；2026-10-14 制作人定写入本文，原为只指回工单） |
| 色数 | 每个角色全部动作合计 ≤ 24 色是目标，**让位于设定色**：保不住瞳色 / 标志色时允许到 28，handoff 写明多出的是哪几色；色数只 WARN（docs/87 §4.3）。普通怪 ≤ 16，Boss ≤ 32；1x、@2x 各算（2026-10-14 制作人定，原为「≤ 24 色」硬上限） |
| 洋红残留 | 0 |
| 命名 | 干员 `op_<id>_<idle\|run\|attack\|skill>`；水月 `player_*`；博士 `doctor_*`；敌人 `e_<id>[_move\|_attack\|…]`；召唤物 `op_<owner>_<name>_<act>` |
| 出手帧 | attack / skill 写进 manifest；末帧回到该角色 idle f0（干员逐像素相同；敌人 attack f3 与基础 f0 重合） |

## 4. 同屏比例（1x 站立高，按脚底对齐并排时的观感）

```
小怪 12–30  <  精英 24–30  <  干员 32–36（召唤物 ≤ 干员）  <  中期 Boss 40–56  <  最终 Boss 72–96
```

- 干员之间差 ≤ 4px（逻各斯 / 流明已安排放大）。
- 程序放大（`enemy/scale`，缺省 1.5，用户 10-14 定；2026-10-14 制作人定，原为「试验中」）只对普通怪 / 精英整体生效，不改帧条；Boss 不放大。
- 新角色交付前必须出一张与三名参照干员（斯卡蒂、浊心斯卡蒂、流明）并排的 lineup，脚底线对齐，亮 / 暗（整体乘 0.55）两行。

## 6. 什么归 Codex、什么归程序

| 归 Codex（帧条） | 归 Claude（程序 / 或 docs/93 规格的 fx 单） |
|---|---|
| 人物本体全部动作、召唤物本体、Boss 本体与专属招式动作 | 影子、受击白闪、受光 / 暗淡、描边光（Boss）、死亡溶解、头顶标记 / 血条 |
| 本体上的武器、标志物、发光器官（画在帧里） | 刀光、弹体、预警图案、命中 / 残留特效、地面件、歌域 / 光环（走 fx_* / proj_*，docs/93 §0；重点特效可另下单给 Codex） |
| 鼓胀 / 变身 / 入潮等「本体形变」动作（如 `e_pocket_swell`） | 缩放、着色、淡入淡出、镜头 |

## 7. 交付与机检

- 每次交付：PNG（1x + @2x）、manifest（帧数 / fps / 单帧尺寸 / 原点 或脚底行 / 出手帧 / 色数）、handoff（造型依据 + 量得的站立高、脚底 x）、预览 GIF（深色地面 `#0e1428` 底，按游戏比例）、lineup（§4）。
- 干员：`python tools/art_lint.py --ops <id>` 未豁免 FAIL = 0，WARN 逐条说明；敌人：按 docs/94 §2 自检表；Boss / 召唤物：Claude 接入时同帧截图核对 1x / @2x 切换与锚点。
- 原作依据必须可查证（PRTS 等），本作原创要在 handoff 标明；不使用官方图、不描摹。

- `preserve_palette` 保留已整理的原生统一调色板，不再次执行全局 pop；受击白闪和眩晕仍走现有渲染。普通怪额外 scale 与现有密度放大共同生效，不修改碰撞半径、伤害范围或 AI。
