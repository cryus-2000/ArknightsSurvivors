# 骑士攻击连段

状态：已实现，已录制实机预览，完整回归通过。分支 `codex/boss-fx-rework`，继承 168 的冰晶弧斩；未合入 main。用户要求把独立招式衔接，例如斩击后接冲锋。本作改编，保留原有寒冷、冰柱和重生冲锋主轴，不宣称这些连段来自原作。

## 连段表

| 起手 | 后续 |
|---|---|
| 断潮劈击 | 一阶段：冲锋 → 近身连刺；二阶段：冲锋 → 重新瞄准的再冲锋 → 近身回旋；玩家已拉开则收招 |
| 踏冰裂阵 | 一阶段二幕起接掷枪，否则接断潮劈击 → 冲锋 |
| 侧踏挑枪 | 近身接连刺／回旋；远处接冲锋 |
| 掷枪 | 冲锋 |
| 长枪回旋 | 长枪连刺 |
| 长枪连刺 | 断潮劈击 |
| 冲锋 | 一阶段近身收招；三幕追加一次再冲锋后近身收招；二阶段保持三连冲后收招 |
| 冰线 | 沿锁定冰线寒冷追击；一阶段近身收招，二阶段再接一次转向冲锋 |

每组最多 4 个命名攻击阶段（连刺自身的三刺、侧踏自身的位移与挑枪仍完整保留）。每段仍使用已有动作与正式预警管线，下一段按当时主控位置重新瞄准；冰线后的寒冷追击沿已锁定线行进。一阶段段间至少留 0.22 秒收势，二阶段 0.10 秒；二阶段冲锋预警从 0.8 秒缩至 0.6 秒，仍保留 0.4 秒固定锁向，冲锋后等待实际自冲位移结束再接招。普通冲锋沿用配置倍率；连段中的寒冷追击与再冲锋使用基础伤害 ×1.35，避免长连段每一冲都叠加最高伤害。

## 生命周期

- 正式 AI 在可选招式轮换前处理连段，防止新的独立招式插队。
- 不将每个子招再展开成新连段；二阶段旧连冲计数与冰线旧计时由当前队列接管，避免重复冲锋。
- 最后一招若为飞行弧斩，等待其自然结束再喘息，避免破绽状态提前取消弧斩。
- 每组结束进入一阶段 1.6 秒、二阶段 2.5 秒破绽。保留既有破绽受伤倍率，让玩家完成闪避后有反击机会。
- 一阶段撞柱、外部眩晕、破绽、无敌阶段、死亡、转幕／重生会清除尚未释放的预警、后续招式及新增攻击实体；已发出的普通投射物和当前冲刺惯性保留，撞柱／重生仍按原逻辑停止冲刺。冰柱批次不因此重置；二阶段仍可撞碎冰柱继续冲锋。
- 每组有 18 秒保护性上限；状态保存在敌人字典，模拟不使用额外随机数。

## 10-27 第二轮：速度、有效射程与交替冰阵

- 断潮劈击保留身前 75–160px 成形的凸弧和冰晶切面，初速 65→220，加速度 700→2400，最高速 740→1000；约 0.325 秒达到最高速，飞行寿命 1.05 秒。1.7 秒成形预警保留。

- 踏冰裂阵替换三条窄冰线：两波交错宽带、固定同一初始坐标系，第二波覆盖第一波空挡；第一波释放后才显示第二波预警，避免重叠预警抹掉安全路线。每波三条 150px 宽、1000px 长的条带，总覆盖 900×1000；第一波 1.3 秒、第二波 2.7 秒。

本轮完整检查 `build/check/quick_1027_144902`：133 项、失败 0、520 秒，同 seed 4 分钟逐字段复现通过，原生核心对照因本机未编译而跳过。实际录像 `knight_combo_v4` 高低档各 54 秒；单招 `knight_ice_v1` 各 36 秒。两档事件、朝向、本体位置与移动记录完全一致，源码 SHA256 与提交内容相符，无 SCRIPT ERROR / Parse Error。预览页首卡 0/18/36 秒分别为一阶段弧斩、双冰阵、二阶段弧斩变招；旧骑士单招卡同步更新。只读复核发现的椭圆距离问题已修正并加入回归。录像为无敌玩家移动探针，未作为整局难度或手机性能验收。


## 10-27 第三轮：冰面传播与放射双阵（实机复核中）

用户否定第二轮的回旋白盘与平行冰带；第二轮为历史候选，不作为视觉验收通过。本轮以用户截图反馈为准：

- 回旋改为冰面向外扩张的寒冰冲击波，判定随冰锋前沿传播，不再使用白盘和一圈圆珠表现。
- 长枪三刺逐次放出前进冰锋，各自有警示、释放与传播过程；不以整片扇形闪一下代表刺击。
- 踏冰裂阵以骑士起手位置为中心，360°八组放射冰柱与扇形间隔；第二波偏转半格，在第一波间隔升柱。两波固定共同坐标，不追着玩家重排空挡。
- 弧斩初速、加速度、最高速进一步提高，增加短促分层残影；实体刀锋与残影明确区分，残影不增加伤害。
- 二阶段增加独立轮换招式「冰枪封径」「冻潮夹击」：前者三次落枪爆裂后短暂封路，后者双侧冰锋相向推进、保留中间出口。均为本作改编，并非原作已有技能的引用。
- 素材审计：骑士 spin/plant/thrust/charge 动作与 emit 层齐备，晶柱有 64×96 的 idle 4 帧、rise 3 帧、break 6 帧。`fx_knight_frost_burst`、`fx_knight_frost_floor`、`fx_knight_thrust` 只有登记、缺少实际 PNG；现有 48px impact 只够局部碎冰，不能承担整片冰面。白盘／珠串来自旧 spin_ring 的白钢刀光、大 ring 及通用粒子链，本轮整体替换，复用晶柱资源并补充程序冰面与传播前沿，无须新造 Spine 动作。验证和实机录制记录完成后补充。


本轮定值：冰波最大地面半径 560、前沿宽 46、扩张速度 400，中心 70 与背后 ±0.7 弧度缺口安全；三刺冰锋实体长 90，预警总射程前两次 400、第三次 520，按总射程计算速度。放射柱阵两波各 8 扇区，半角 π/16，第二波偏转 π/8，半径 560、中心 60 安全，两波在 1.3/2.7 秒释放。晶柱有升起与破碎动画，地面材质显示命中扇区。弧斩速度 450→1450、加速度 5000，0.2 秒加满、寿命 0.8 秒，三层短残影不参与命中。

二阶段独立轮换优先出冰枪封径／冻潮夹击。落枪在 1.2/1.65/2.1 秒释放，半径 105 的冰区持续 2 秒，每区对玩家最多一次命中；夹击两条冰锋长 700、半宽 28、速度 210、寿命 1.05 秒，最终保留约 119px 扣除玩家碰撞后的净通道，预警显示移动方向与停止线。二阶段不再绘制已经失效的寒气圈，一阶段改为地面裂纹与淡边。

独立复核发现并修正：骑士移动实体寿命到点前完成最后时间片的扫掠，再移除，避免射程不足；冲击波缺口将世界角转换到椭圆参数，预警与实体共用精确边界分段，避免画面安全而判定有伤。加入大步长终点命中／到期移除及斜向缺口精确边界回归。

## 贴身绕圈与脱身跳（10-28 用户实玩）

用户：「骑士如果一直在他旁边转圈的话，他会放不出攻击并且一直挨打 … 可以给骑士加一个挨打超过一段时间一下子跳走的机制」。

**根因**：用测试机器人复现，`--bot=circle` 不躲，贴着 Boss 按 `bot/circle_gap` 绕圈，每 0.5 秒打一行 `CIRCLE`。骑士贴身时并没有停招，长枪连刺、断潮劈击、侧踏挑枪、踏冰裂阵照常循环。问题出在命中：这些近身招全是从身体中心瞄队长的窄线（宽 24–34），追踪到锁定再到结算之间，贴身绕圈的角速度约 1.5–2 弧度/秒，锁定那一刻的方向早就被甩开，所以「放了也像没放」。一阶段又没有不靠瞄准的近身招，长枪回旋只在二阶段有。

**改动**（`knight_boss.gd`，旋钮都是 `Bal.v` 缺省值）：
- **贴身挨打计时** `kn_hug`：贴身（地面距离扣半径 < `boss/knight_hug_r` 130）且 0.5 秒内骑士掉过血时累加。离开或没挨打时按 0.5 倍回落。破绽、眩晕、重生读条期间不计，那些是给的输出窗口。
- **一阶段贴身回旋**：`kn_hug` ≥ `boss/knight_hug_spin`（1.5 秒）时，一阶段也放长枪回旋。这是一道由内向外扩的冰面冲击环，身后有缺口，和二阶段共用 7 秒冷却。
- **脱身跳**：触发条件同时满足以下几条：
  - `kn_hug` ≥ `boss/knight_hug_t`（3.5 秒）；
  - 冷却 `boss/knight_leap_cd`（12 秒）已过；
  - 手上没有正在结算的有伤招或冰锋。

  触发后：
  - 取消连段，下蹲 0.3 秒；
  - 向远离队长的方向跃出 `boss/knight_leap_len`（280）。贴墙时在 ±70° 范围里挑离队长最远的落点。落点画无伤低亮圈预告；
  - 空中 0.5 秒，弧高 56，空中无接触伤害；
  - 落地：缩小的撞柱冰爆 + 朝队长 5 片冰屑，随后马上接冲锋，一阶段二幕起改为掷枪。

  脱身跳不算破绽，照常受伤。总开关 `boss/knight_leap`（0 = 关）。

**验证**：
- 绕圈机器人（斯卡蒂 s1）贴身 20 时，开战约 5 秒和 19 秒各跳一次，落地接冲锋 / 掷枪。
- 录像 `build/knight_circle/knight_circle_leap.mp4`（26 秒原速）。
- 单项回归 knight_combo、final_attack_grains、boss_fx_geometry、route_knight 均 0 失败。
- 测试台复测交给 boss-bench：专家机器人平时不贴身，预计影响很小。

### 出招霸体（10-28 用户「骑士的攻击会被打断」）

**根因**：干员的眩晕 / 浮空走 `enemies.add_cc` 直接写进 `e.stun`。骑士只要被晕一下就会被打断：
- `knight_boss.combo_step` 见 `stun > 0` 取消整套连段；
- `final_attacks.cancelled` 让已经起手的最终 Boss 招（踏冰裂阵 / 断潮劈击 / 侧踏挑枪及二阶段冰枪）作废；
- 击退（`apply_kb`，重型只削到 0.3）和拖拽（`hold_at`）会在蓄力时挪动它。

**改动**：新增 `boss_ai.super_armor(e)`，由 Boss 脚本选择实现，没实现的 Boss 不受影响。`enemies.add_cc` / `apply_kb` / `hold_at` 遇到霸体中的 Boss 时：
- 不写眩晕；
- 不吃击退；
- 不被拖走；
- 减速照常生效。

骑士的霸体条件（任一满足即霸体）：
- 自己的预警在走；
- 冰锋在结算；
- 连段进行中；
- 自冲中；
- 再冲锋未完；
- 正在脱身跳。

破绽期（撞柱眩晕、收招破绽、喘气）没有霸体，照常吃控制。开关 `boss/knight_armor_cast`（0 = 关）。`knight_combo_test` 加了 `check_super_armor`：出招中眩晕、击退、拖拽无效，连段不断，减速照常；破绽期眩晕生效。

**其他最终 Boss 也有同样问题**（未改，转对应会话）：
- `final_attacks.cancelled()` 对偏执泡影、伊莎玛拉、伊祖米克同样见 `e.stun > 0` 就作废已起手的最终 Boss 招；
- `boss_patterns.resolve()` 见 `e.stun > 0` 直接不结算，放空的是弹幕模板招，也覆盖这三只。

这些 Boss 实现 `super_armor(e)`（可参照骑士）就能接上同一套霸体。

## 分阶段风格（10-28 用户「每个 boss 不同阶段是不是得做出点不同的风格来？」）

数值之外，每一阶段的配色、冰系特效形态、招式节奏、场地都要一眼可分。阶段 = 一阶段的三幕（`gates_passed` 0 / 1 / 2，66% / 33% 卡点）+ 10:00 后重生（phase 2）。

| 阶段 | 配色（本体乘色 / 冰颗粒 / 冰面） | 冰系特效形态 | 招式节奏 | 场地 |
|---|---|---|---|---|
| 一幕 霜甲（100–66%） | 霜白 + 浅青（原样） | 冰晶碎片、细霜纹 | 稳：连段间隔 0.22 秒；冲锋、连刺、冰线 | 原地面 + 五根冰柱 |
| 二幕 冰棱带（66–33%） | 青绿偏冷 | 冲锋留冰面 3 秒；冰颗粒偏青 | 加掷枪；连段间隔 0.18 | 场地边缘结霜带，随幕内时间往里爬（24 → 60 像素） |
| 三幕 寒潮（33%–重生） | 深蓝 + 雪白 | 斜落飘雪（只画视野内、按时间定位、不抽随机）；寒气圈 180 | 掷枪两连、冲锋折返；连段间隔 0.15 | 霜带加宽到 100、偏深蓝 |
| 重生 冲锋形态 | 黑冰：钢蓝暗色 + 白裂纹 | 冰颗粒、冰面、碎冰都压暗成黑冰，只有裂纹和高光是白的 | 冲锋三连 + 喘气（原样），慢走快冲 | 重生点一片放射状裂冰（半径 220），残柱碎尽；霜带转暗 |

过幕时打一行横幅（二幕 / 三幕；重生已有「冲锋形态」），同时换本体乘色。只有连段间隔这一项改节奏，其余都是表现。
