# 133 件实装藏品：效果二次分类与强度复核（2026-09-28）

以 `relic_effects.json` 和 `relic_fx.gd` 当前实现为准；旧 `relics.json` 改编文字只作为无覆盖描述的后备。每一件都显式给出最终稀有度及主效果分类。此表是设计复核，未声称通过实战胜率实验确定最优平衡。

## 规则与架构

- 基础：较小的常驻单项增益、有限职业收益、一次资源或需发动机的基础配件。稀有：实用中幅强化、单次成长、中等条件收益。核心：高幅持续收益、明显双属性组合、构筑发动机或高收益风险条件。升华：改变编队/失败规则、强终端协同或既有控制系Boss终端奖励。
- 综合有效覆盖、触发占空比、前置、数值上限、风险与获取时点，不按数值大小一刀切；相似系列仍保留上下位梯度。
- 例如79全队伤害20%为稀有，89全队技力30%为核心；111仅1秒翻倍窗口、169排除Boss的职业斩杀、252需击杀累积且封顶30%，从升华降到核心。
- 118开启护盾循环，199/200需要118且只增加容量，不增加生成速率，因此分别为稀有/基础/稀有。
- 原ID、效果对象和数值、来源、商店许可、前置/冲突、职业限制、lanes/tags全部保留。遭诅古物/结局不折算到普通四档；其效果分类仍按实际作用。
- 新增 `effect_category` 稳定英文键与顶层 `effect_categories` 中文名表；`RelicDB.effect_category_names` 暴露名称。原 `cat`、`lanes`、`tags` 不改变，分类只用于检索展示，不叠加抽取权重。
- `RelicDB` 先解析最终 `rarity`，`price_class` 未显式指定时跟随该结果，消除旧表等级导致的错价。显式价格覆盖能力保留。
- 保留原Boss来源，即使某件降档也不会自动进入商店/普通宝箱；第二Boss池按现有升华条件工作，仍有足够候选。
