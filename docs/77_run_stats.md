# 77 · 作战记录（局终统计界面）

> 2026-10-12 用户：「最后可以加一个统一界面，各个干员伤害统计之类的，你看着进行指标设计和UI设计」。
> 本页是指标与界面的设计和实现说明。概念图：`python tools/concept_run_stats.py` → 主仓库 `build/run_stats/concept_*.png`（不入库）。
> 实现：数据 `scripts/run/run_stats.gd`，界面 `scripts/screens/run_stats_screen.gd`，计数 `scripts/run/telemetry.gd`。
> 文字按 docs/76（语言风格）和 docs/37 §6（术语）写。

## 1. 入口与流程

- 胜利 / 结局结算和失败结算的按钮从两个变成三个：「再次探索 R」「作战记录 Tab」「回到标题 T」。结局演出和结算面板不变。
- 结算上按 Tab / C、点「作战记录」，或手柄选中后按 Ⓐ，进入作战记录总览。
- 总览：← → 选干员，Enter / Ⓐ / 点卡进入详情，Esc / Ⓑ / Tab / 「返回结算」回到结算。
- 详情：← → / LB RB / 右上「‹ ›」换干员，↑ ↓ / 滚轮滚动伤害来源，Esc / Ⓑ / 「返回总览」回总览。手机上主控详情分两页「伤害来源 / 生存」，点页签或按 Tab 切换。
- Boss 演练结算没有这个按钮（演练只看一个 Boss，不需要编队统计）。

## 2. 指标（按优先级）

所有数字都来自局内计数，只累加，不读 `g.rng`，不改对局状态，同 seed 复现不受影响（§4）。

### 2.1 P0 · 总览必看

| 指标 | 显示 | 口径 | 来源 |
| --- | --- | --- | --- |
| 结果 | 标题旁的标签 | 胜利写结局名 +「探索完成」（青）；失败写「探索终止」（洋红） | `g.state` / `g.ending` |
| 探索时间 | 像素字 `08:00` | 局内时间 | `g.t` |
| 难度 | 罗马数字（Ⅳ / Ⅷ 档）或档名（标准档） | `DIFFICULTY_TIERS` 名称 | `g.tier` |
| 击杀 | 千分位 | 全部击杀 | `g.kills` |
| 等级 | `LV 22` + 主控精英阶段 | | `g.level` / `g.ch.elite` |
| 藏品 | 件数 | | `g.relics.size()` |
| 最高单次 | 数值 + 来源名 | 一次命中算出的伤害（不按敌人剩余生命封顶） | `telemetry.best_hit` |
| 全队伤害 | 总量 + 平均每秒 | 有效伤害（按敌人剩余生命封顶，同 `dmg_out`） | `telemetry.op_out` |
| 干员 · 全队占比 | 分段条 + 卡片大字 | 该行伤害 ÷ 全队伤害。整数百分比用最大余数法取整，合计恰好 100 | 同上 |
| 干员 · 造成伤害 | 卡片 | 归到该干员的所有伤害来源之和（`hit_sources` 的 `op` 字段） | `telemetry.op_out` |
| 干员 · 每秒 | 卡片 | 造成伤害 ÷ 在队时长（入队到局终或离队）。后加入的干员不会被开局前的空档拉低 | 同上 + `joins` |
| 干员 · 入队 | 卡片副标题 | 「主控 · 开局」「01:17 加入」；被祭坛事件替换的干员另写「· 06:10 离队」 | `telemetry.joins` |
| 干员 · 击杀 | 卡片 | 最后一击记给当时的伤害描述符所属干员。各行合计可能少于总击杀（极少数击杀不经过伤害结算） | `telemetry.op_kills` |
| 干员 · 技能 | 卡片 | 技能发动次数（`spend_sp`，含自动与手动） | `telemetry.op_casts` |
| 干员 · 治疗 | 卡片（有才显示） | 回复给主控的有效量，按治疗记录里与干员同名的来源 | `g.heal_log` |
| 干员 · 主要来源 | 卡片底行 | 该干员伤害最高的来源和它在该干员伤害里的占比 | `op_out` |
| 藏品与支援 | 最后一张卡 | 没有干员归属的伤害：援护（无人机）、藏品、地雷、骑士等 | `op_out["_other"]` |

### 2.2 P1 · 详情

| 指标 | 显示 | 口径 |
| --- | --- | --- |
| 伤害来源 | 每条：类别标签 + 名称 + 数值 + 占比 + 条 | 类别按 `hit_sources.origin`：core = 普攻、skill = 技能、talent = 天赋、route = 分支、support = 支援、relic = 藏品。占比在该干员内取整，合计 100 |
| 在队时长 / 离队 | 身份卡 | |
| 每秒伤害（单人时间线） | 来源少、面板有空位时画在来源下面（桌面） | 同总览时间线的分箱，只取这一行 |
| 主控 · 受到伤害 | 总量 / 受击次数 + 前 4 个来源 | `dmg_log` 按敌人类型合并（同一敌人的接触、招式、冲击环算一个）；侵蚀、黑潮、溟痕、神经损伤单列；灯火熄灭的持续掉血写「寂灭（灯火熄灭）」 |
| 主控 · 生命回复 | 总量 + 各来源 | `heal_log` 原样：干员名、吸血、击杀回复、自身回复、藏品、拾取、商店、事件……（吸血 / 击杀回复 / 自身回复在 `wip/relic-late-impl` 合入后出现，界面不用改） |
| 主控 · 灯火 | 四档分段条 + 各档时长 | 通明（≥ 70）/ 摇曳（30–69）/ 暗淡（< 30）/ 寂灭（0），每帧按当时灯火累计 |
| 主控 · 闪避 / 冲刺 / 护盾抵挡 | 次数 | 闪避判定成功、冲刺、护盾挡下一次伤害 |
| 主控 · 生命低于 35% | 时长 | 原有遥测 `low_hp_s` |

### 2.3 P2 · 总览下半

| 指标 | 显示 | 口径 |
| --- | --- | --- |
| 全队每秒伤害时间线 | 10 秒一格的像素柱，按干员堆叠（同卡片颜色） | 每格有效伤害 ÷ 10。Boss 登场画暗洋红虚线，击破画洋红虚线 + 菱形 + 名字 |
| Boss 记录 | 名字 + 击破时刻 + 用时（`+00:52`） | 用时从登场算。没打完写「未击破」，撤场写「撤离」 |
| 引航灯标 | 点燃 / 出现 | `beacon_sys.lit_n` / `g.beacons` |
| 源石锭熔铸 | 全队伤害加成 | 读 `rfx.fuse_pct()`；`wip/relic-late-impl` 合入前没有这个字段，这一行不画 |

### 2.4 没有放进来的

- 经验来源、同屏峰值、伤害按 tag：给数值调平用，玩家看不出意义，留在 runs.jsonl。
- 控制时长（眩晕、减速）：现有 `ctrl_report` 按来源记的是施加次数，不是干员维度；要做得先补计数，以后再说。
- 跨局记录（历史最高、平均）：需要存档字段，用户 10-12 已去掉标题页的灯火日志，这里不做。

## 3. 界面

### 3.1 风格

局外 T5s（docs/37 §8、docs/67 §12）：全屏压暗 + 一块大藏青抖动面板；格子、要点格、卡片、按钮都是像素阶梯切角；数字、英文用 5×7 像素字（这次加了千分位逗号），中文用 ui.ttf；只用冷色（青、藏青）和干员职业色，危险（Boss、受到伤害、探索终止）用洋红 `UI.RED`，回复用绿 `UI.GREEN`。选中卡 = S4 近白反白 + 细青边 + 台阶式外光，和标题磁贴一致。

### 3.2 版式（桌面 1280×720，UI 逻辑坐标）

- 标题行：`RUN RECORD` 像素小字 +「作战记录」28 号 + 结果标签。
- 要点六格：探索时间、难度、击杀、等级、藏品、最高单次。
- 全队伤害：总量与平均每秒，下方 20 高的分段条（每名干员一段，段上写占比）。
- 干员卡（260 高）：职业色竖条、名字、入队；占比大字（像素字 4 倍）、伤害、单人条；待机帧（每格美术像素 = 2 逻辑像素，高清帧条自动减半）；每秒 / 击杀 / 技能 / 治疗；底行主要来源。「藏品与支援」卡窄一点（0.82）。
- 下半：左 64% 全队时间线，右边探索记录。底部操作提示 +「返回结算」。
- 详情：左 300 宽身份卡（近白，待机帧 3 倍），中间伤害来源，主控右侧多一栏「生存」。
- 1920×1080：窗口按 canvas_items 拉伸，UI 逻辑仍是 1280×720，像素字和切角按屏幕像素取整，不糊。

### 3.3 手机（UI 逻辑约 1044×481）

- 一格 = 1.4 逻辑像素；要点去掉「藏品」剩五格；卡片占满中间，待机帧 1.4 倍。
- 不画时间线和探索记录面板，底部一行写 Boss 击破时刻和灯标。
- 「返回结算」按钮 44 高（触点再外扩 6），右上「‹ ›」触点外扩 8。
- 主控详情：来源 / 生存两页签（120×34，触点上下外扩 6）。
- 触屏不画按键提示。

### 3.4 动效（docs/62 §3.24）

主动作「分段拼合」：全队伤害条的每一段按干员顺序从条的右端滑入、落到自己的位置（每段 T2，`out_cubic`，错开 90 ms，最多 5 段参与错开），落定时一格近白亮边闪一下（T1）。每段落定后，对应卡片的单人条注满（T2）、占比和伤害数字计数到终值（T3，线性）。约 0.45 秒起时间线从左往右扫出（T3）。要点六格按 `steps(3)` 硬步进出现（错开 60 ms）。详情：来源条依次伸长（错开 60 ms，T2），单人时间线扫出。

- 和其他界面的区别：难度页是水位升降，属性面板是亮线开机，胜利结算是盖章；这里是「各段拼成一整条」。数字计数（docs/58 已占用为选人页主动作）在这里只是次要动作。
- 招牌动效期间确认键 / 点击先跳到终态（docs/62 §2.5）；Esc 照常返回。命中区一直按终态位置算。
- 减少动态效果：全部直接终态，只留面板 T1 淡入；待机帧停在第一帧。无头批跑直接终态。

## 4. 计数与复现

`telemetry.gd` 新增（都只累加）：

| 字段 | 写入处 |
| --- | --- |
| `op_out {干员: {来源: 伤害}}`、`out_bins`（10 秒一格）、`best_hit` | `combat.damage` 记 `dmg_out` 的同一行之后（`on_dmg`） |
| `op_kills` | `combat.damage` 里 `kill(e)` 之前（`on_kill_credit`） |
| `op_casts` | `character.spend_sp`（`on_cast`） |
| `joins` | `squad.add` / `squad.remove`（`on_join` / `on_leave`） |
| `dodges` / `blocks` / `dashes` | `combat.on_dodge` / `combat.shield_block` / `game._try_dash` |
| `lamp_s` | `telemetry.tick` |

- 这些字段没有写进 `record()`，BALANCE 行和 runs.jsonl 的格式不变（SCHEMA 不升）。
- 不读写 `g.rng`；同 seed 复现由快检原有的 repro 项覆盖。
- 守恒：每次有效伤害同时进 `dmg_out` 和 `op_out`，所以 `op_out` 合计 = `dmg_out` 合计 = 时间线合计（快检断言）。

## 5. 验收

- 快检 `run_stats`（`tests/run_stats_test`，`--balance --op=mizuki --squad=skadi`）：
  - 假记录（`RunStats.fake_raw()`，四名干员，其中一人中途离队）：各行之和 = 全队伤害；整数占比合计 100；每行来源之和 = 该行伤害，来源占比合计 100；离队干员的在队时长；承伤按敌人合并；最大余数法边界；千分位。
  - 真实短局（机器人打到 45 秒）：`op_out` 合计 = `dmg_out` 合计 = 时间线合计；入队记录；最后一击合计 ≤ 击杀；灯火四档时长合计 = 局内时间；模型守恒。
  - 界面：失败结算有「作战记录」按钮 → 打开；卡片数 = 行数；← → 不循环；Enter / Esc / 点卡 / 点返回；关掉后结算三个按钮；假记录在 1280×720 与 1044×481 下命中区不出屏、卡片不重叠，手机主控详情有页签。
- 实机截图：`--statsshot=<秒>[,dead]`（autotest 钩子，机器人打到该秒后进结算，依次截 结算 → 总览动效中 → 总览 → 主控详情 → 第二名干员详情，存 `--shotdir`）。本次截图在主仓库 `build/run_stats/impl_1280/`、`impl_1920/`、`impl_phone/`（`--touch` 1560×720）、`impl_1280_dead/`。
