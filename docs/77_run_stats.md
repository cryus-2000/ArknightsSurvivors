## 1. 入口与流程

- 胜利 / 结局结算和失败结算的按钮从两个变成三个：「再次探索 R」「作战记录 Tab」「回到标题 T」。结局演出和结算面板不变。不自动弹出（用户 10-12 定）。
- 总览：← → 选干员，Enter / Ⓐ / 点卡进入详情，Esc / Ⓑ / Tab / 「返回结算」回到结算。
- 详情：← → / LB RB / 右上「‹ ›」换干员，Esc / Ⓑ / Enter / 「返回总览」回总览。
- Boss 演练结算没有这个按钮。

## 2. 显示什么

### 2.1 总览

| 项 | 口径 |
| --- | --- |
| 结果 | 标题旁：胜利写结局名 +「探索完成」（青），失败写「探索终止」（洋红） |
| 一行要点 | 探索时间 · 难度 · 击杀 · 等级（含主控精英阶段） |
| 全队伤害 | 总量 + 每秒；下面一条分段条，每名干员一段（干员颜色） |
| 干员卡 | 待机帧、名字、入队（「主控 · 开局」「01:17 加入」，被替换的写离队时间）、全队占比大字、伤害 · 每秒 |
| 藏品与支援 | 最后一张卡：没有干员归属的伤害（援护、藏品、地雷、骑士等） |
| Boss 击破 | 一行：每个击破的 Boss 名字和时刻 |

- 全队占比 = 该行伤害 ÷ 全队伤害，整数百分比用最大余数法取整，合计正好 100。
- 每秒 = 该行伤害 ÷ 在队时长（入队到局终或离队），后加入的干员不会被开局前的空档拉低。
- 伤害都是有效伤害（按敌人剩余生命封顶，和 `dmg_out` 同一口径）。

### 2.2 详情

| 项 | 口径 |
| --- | --- |
| 身份卡 | 造成伤害、全队占比、每秒、击杀、技能（发动次数）、治疗主控（有才显示）、最高单次（只在打出全局最高一击的干员上显示） |
| 伤害来源 | 前 5 条（名字、数值、该干员内的占比、条），其余并成「其他」 |
| 生存（只有主控） | 受到伤害；生命回复总量与前 3 个来源（干员名、吸血、击杀回复、自身回复、藏品、拾取……）；灯火通明的时间占比；源石锭熔铸（触发了才显示：全队伤害 +x%） |

- 击杀 = 参与击杀：敌人死前 3 秒内命中过它的干员各记一次（用户 10-12 定）。一个敌人可以记给几名干员，所以各行相加可以大于总击杀。
- 治疗主控按治疗记录里和干员同名的来源算。

### 2.3 去掉的（v1 有，v2 不显示）

六格要点里的藏品数和最高单次、卡片上的技能 / 治疗 / 主要来源行、全队每秒伤害时间线、探索记录面板、来源类别标签、单人时间线、承伤来源明细、灯火四档时长、闪避 / 冲刺 / 护盾抵挡 / 低血时长。计数仍在 telemetry 里，以后要用可以直接拿。

## 3. 界面

- 风格：局外 T5s（docs/37 §8）。全屏压暗 + 一块藏青抖动底；只有卡片、身份卡、生存块和按钮有阶梯切角，其余直接排在底上，少框、多留白。数字用 5×7 像素字（加了逗号和撇号），中文用 ui.ttf。选中卡是 S4 近白反白 + 细青边。只用冷色和干员颜色，失败与危险用洋红，回复用绿。
- 桌面 1280×720：卡片 250 宽、280 高、居中排；待机帧每格美术像素 = 2 逻辑像素（高清帧条自动减半）。详情左边身份卡 280 宽，中间来源，主控右边生存块 300 宽。1920×1080 按 canvas_items 拉伸，UI 逻辑仍是 1280×720，像素按屏幕取整。
- 手机（UI 逻辑约 1044×481）：一格 = 1.4 逻辑像素；卡片 ≤ 220 宽；详情三栏照排（身份卡 210、生存块 250）；「返回」按钮 44 高，触点再外扩 6；不画按键提示。
- 动效（docs/62 §3.24）：主动作「分段拼合」——全队伤害条按干员一段段从右端滑入落位（每段 T2 `out_cubic`，错开 70 ms），落定时一格近白亮边闪一下（T1）；落定后对应卡片的占比数字计数到终值（T3，次要）。详情的来源条依次伸长（错开 60 ms）。确认键 / 点击先跳到终态；减少动态效果直接终态，只留 T1 淡入。

## 4. 计数与记录

`telemetry.gd` 新增（只累加，不读写 `g.rng`，同 seed 复现不受影响）：

| 字段 | 写入处 |
| --- | --- |
| `op_out {干员: {来源: 伤害}}`、`out_bins`（10 秒一格）、`best_hit` | `combat.damage` 记 `dmg_out` 的同一处（`on_dmg`） |
| `op_kills`（参与击杀） | `on_dmg` 在敌人身上记 `_hb {干员: 最近命中时刻}`（纯记账字段）；`kill(e)` 之前 `on_kill_credit` 按 3 秒窗口记给各干员 |
| `op_casts` | `character.spend_sp` |
| `joins`（入队 / 离队） | `squad.add` / `squad.remove` |
| `dodges` / `blocks` / `dashes` / `lamp_s` | 闪避、护盾抵挡、冲刺、灯火四档秒数（界面不显示） |

**runs.jsonl**（用户 10-12「可以记录一下」）：本地记录每局多一段 `run.op_stats`，每名干员一项：`id`、`join` / `left`（秒，-1 = 没离队）、`dmg`、`share`、`dps`、`kills`（参与击杀）、`casts`、`heal`（治疗主控）、`top`（主要来源）。只在 `save_local` 里加，所以沿用原来的规则：调试版与对内包写，对外包不写，测试运行不写。BALANCE 行（`record()`）不变，SCHEMA 不升。

## 5. 验收

- 快检 `run_stats`（`tests/run_stats_test`，`--balance --op=mizuki --squad=skadi`）：
  - 假记录（`RunStats.fake_raw()`）：各行之和 = 全队伤害；整数占比合计 100；每行来源之和 = 该行伤害；「前 5 + 其他」守恒；离队干员的在队时长；承伤合并；最大余数法边界；千分位。
  - 真实短局（45 秒）：按干员拆的输出 = `dmg_out` 合计 = 时间线合计；参与击杀每名干员 ≤ 总击杀、主控有记录；`op_summary()`（runs.jsonl 那段）占比合计 1；灯火四档时长合计 = 局内时间。
  - 界面：结算上有「作战记录」→ 打开；卡片数 = 行数；← → 不循环；Enter / Esc / 点卡 / 点返回；关掉后结算三个按钮；1280×720 与 1044×481 下命中区不出屏、卡片不重叠。
- 实机截图：`--statsshot=<秒>[,dead]`（autotest 钩子，机器人打到该秒后进结算，依次截 结算 → 总览动效中 → 总览 → 主控详情 → 第二名干员详情，存 `--shotdir`）。
