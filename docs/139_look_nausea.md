# 139 画面「恶心 / 粘腻」排查（10-24）

> 用户原话：「为什么我会对现在的画面感到有点恶心，并且有点粘腻感」；追加：「画面的色调什么的也看看，是不是也跟紫色有关系」。
> 本页只做调查、量化和方案，**缺省值一律没改**（例外：10-24 用户直接要求的溟痕改色、不用蓝色环境光、环境去色 + 暖色、敌弹改蓝，§6.4 A / §6.6 / §6.7 已成缺省）。分支上加了几个试验旋钮（缺省 = 现状）和一个「推荐组合」开关 `render/nausea_safe`，等用户看对照后拍板。

## 0. 结论（原因按贡献排序）

| # | 原因 | 证据（§2） | 建议 |
|---|---|---|---|
| 1 | **镜头逐帧步长不匀 + 队长在屏幕中心来回抖**：镜头取整到 1 世界像素，低分辨率层再按 2 世界像素一格吸附，两套取整节拍不同。队长恒速走时，地面每帧位移是 4 / 2 / 3 / 2 像素循环（真值 2.875），速度忽快忽慢 ±40%；队长在屏幕上 +1 / 0 / −1 / 0 像素抖，一半的帧都在动 | 早段 240 帧：地面步长直方 {2:119, 3:60, 4:60}，相邻帧步长差均值 1.5 px；队长抖动 120 / 239 帧 | `render/cam_round=0`（镜头不取整，靠低分辨率层已有的亚像素补偿）→ 步长差 1.5 → 0.5 px；队长抖动要彻底消掉需把队长画到高清层（§3.1） |
| 2 | **非整数放大的像素蠕动**：电脑缺省镜头 ×1.15 让 1 美术像素占 2.3（720p / 1080p）、3.45（1440p）、4.6（2560×1600）个物理像素，最近邻放大后像素列宽 2 / 3 交替，镜头一动，宽窄列的位置跟着内容滑，全屏地面「蠕动」 | 地面带对齐后的非刚性残差：×1.15 = 0.96，×1.0 = 0.24（降 75%）；残差 >24 的像素 0.45% → 0.08% | `render/optical_int_zoom=1`：把「战斗画面缩放」并进整数倍率（1440p 由 3.45 → 4，可见 417 行 → 360 行；1080p 由 2.3 → 3） |
| 3 | **显示器 165 Hz / 144 Hz，游戏锁 60 帧**：本机笔记本屏 2560×1600 @165 Hz，外接 2560×1440 @144 Hz；`Engine.max_fps = 60` + 垂直同步时每帧在屏上停 3 / 3 / 3 / 2（165 Hz）或 2 / 3 / 2 / 3 / 2（144 Hz）个刷新，帧在屏时长 12.1 / 18.2 ms 交替，再叠上 #1 的步长不匀 | 刷新率实测（Win32_VideoController：165 / 143）；帧间隔实测见 §2.4（后台窗口偏慢，只作相对参考） | 设置「最高帧率」加「跟随显示器」并在高刷屏缺省；或锁到整除档（165 → 55 / 82.5 不现实，所以首选不锁） |
| 4 | **命中顿帧太密（粘滞感）**：顿帧总闸最小间隔 0.5 秒，命中中 / 重档、击杀、破绽都走它；后期 5 秒内全屏冻结 6 次、每次约 45 ms（2.7 帧），5.3% 的帧是冻住的，约 1.2 Hz 的「一顿一顿」 | 后期段 camlog：hitstop 6 次 / 300 帧 | `fx/hitstop_gap` 0.5 → 1.5，`fx/hit_pause_m` 0.014 → 0（中档不顿），重档 / 击杀 / Boss 保留 |
| 5 | **色调：暗而浓的单色青蓝 + 溟痕靛紫网纹**：后期画面 92% 有色像素在青蓝（170–230°），平均饱和度 0.73、平均明度只有 0.16——暗部是高饱和蓝，不是近中性灰，读起来「浓稠」；溟痕是近黑靛紫（色相 226–240°、饱和 0.8、明度 0.1），占屏 15%，上面是亮青脉络，边缘密度是其余画面的 2.6 倍，像有机网 / 细胞纹 | §2.5 | 环境光去饱和 `render/ambient_desat` 0.4 + 深海滤镜 `render/optical_sea` 0.55 → 0.3（饱和 0.735 → 约 0.64）；溟痕脉络减量 / 降对比交 Codex（与 docs/132 §4 第 5 条合并） |
| 6 | 次要：开火微震、受击后坐、受击形变（非整数缩放的「果冻」） | 后期段：微震 1 次 / 5 秒、正在后坐 0.6 只、正在形变 0.8 只；关掉后与原图同帧差 <0.3%，量级远小于 1–5 | 推荐组合里减小（§4），单独不足以解释 |
| — | 不是主因：辉光、分阶硬边、发光预算、特效照明、LUT、溟痕发光 0.35、敌人增强 | 逐项关掉，与原图同帧差 0.1–1.1% 像素（§2.3） | 不动 |

一句话：**「恶心」主要是运动问题（1–4），不是颜色问题**；颜色（5）让画面显得「浓、闷」，加重粘腻感，但单独改颜色不会解决晕。

配色对照（§6，10-24 追加）：与水月肉鸽原作 66 张关卡比，本作暗部饱和是原作 3 倍、蓝占 95% 无暖色兜底、溟痕景紫占 24%；溟痕可以只改色保留蓝调（紫 24% → 2%），见 §6.4 方案 A。

## 1. 方法

- 工具：`tools/probes/look_nausea.py`（录帧 / 指标 / gif / 色调 / 帧间隔），测试探针 `--camlog=<秒>`（每帧打印镜头、画布原点、低分辨率层偏移、顿帧、后坐 / 形变敌人数）、`--nohitstop`、`--maxfps=N`（`run/autotest.gd`、`run/run_setup.gd`，只在测试参数下生效）。
- 同一局：seed 3，队长水月 + 推进之王 / 维什戴尔 / 凯尔希，熟练机器人，`--playclock`（玩家局的切步与顿帧），`--fixed-fps 60` 每帧存图（录像不受机器负载影响，逐帧可比；除顿帧变体外各变体同帧画面相同，已核对）。
- 两段：早段 6.0 秒起 240 帧（地面多、怪少，量镜头与蠕动）；后期段 300 秒起 300 帧（约 60 只同屏 + 溟痕 + 特效，量光学、顿帧、色调）。窗口 1280×720（k = 2）。
- 图像指标（窗口像素）：上 / 下两条地面带在相邻帧间的整数平移 = 世界层每帧位移；中心 80×100（队长）的平移 = 队长在屏上的抖动；地面带对齐后的平均残差 = 非刚性变化（像素蠕动、漂移）。
- 产物在主仓库 `build/look_nausea/`：`early/`、`late/` 下每个变体一个目录（`rec_*.png`、`camlog.txt`、`metrics.json`），`gif/`（原速 30 fps + 1/3 速，并排对照），`hue_hist.png`、`color.json`、`color_cmp.png`，`pace/`。

## 2. 证据

### 2.1 镜头（早段，队长恒速约 150 世界像素 / 秒）

`camlog` 原始数据（节选）：镜头 x 每帧 +3 / +2 / +3 / +2 世界像素，画布原点每帧 −3.45 / −2.30 窗口像素；低分辨率贴图补偿位置 −2 / −1 / −1 / −2 循环。图像实测：

| 变体 | 缩放 | 地面步长直方（px:帧数） | 步长差均值 | 队长抖动帧 / 239 | 非刚性残差 |
|---|---|---|---|---|---|
| base（现状） | 1.15 | 2:119 3:60 4:60 | 1.50 | 120 | 0.96 |
| cam_round=0（不取整） | 1.15 | 2:60 3:179 | **0.50** | 161 | 0.96 |
| cam_round=2（取整到美术像素） | 1.15 | 2:179 5:60 | 1.51 | 101 | 0.96 |
| ×1.0（--camzoom=100） | 1.0 | 2:119 3:120 | 1.00 | 120 | **0.24** |
| optical_int_zoom=1 | 1.0* | 同上 | 1.00 | 120 | 0.24 |
| 不取整 + 整数缩放 + 高清干员层 | 1.0* | 2:119 3:120 | 1.00 | **35** | 0.24 |
| 关低分辨率层 | 1.15 | 2:119 3:90 4:30 | 1.25 | 122 | 1.23 |
| 关光学 | 1.15 | 2:59 3:150 4:30 | 0.74 | 160 | 0.37 |
| 关开火微震 | 1.15 | 同 base | 1.50 | 119 | 0.96 |

\* 720p 窗口下整数化后 k = 2，所以和 ×1.0 一样；1080p / 1440p 会变成 3 / 4（见 §3.2 表）。720p 时每帧 2.5 窗口像素本身就只能 2 / 3 交替，所以 ×1.0 那行的 1.00 是下限；高分辨率下不取整的收益更大（每帧 3–6 像素，±0.5 像素的取整误差占比更小）。

- 原理：镜头取整到 1 世界像素（= 0.5 美术像素），每帧 2.5 世界像素的移动被取成 3 / 2；低分辨率层只能按整格平移、剩下的在放大贴图上补到物理像素，两次取整叠出 4 / 2 / 3 / 2。队长本身画在低分辨率层，位置按美术像素格落（每帧 1.25 格 → 1 / 1 / 1 / 2），与镜头的节拍不同，所以在屏幕中心来回抖。
- 视野里最大面积的地面在抖（周边视觉 → 晕动），注视点（队长）也在抖（中央视觉 → 看着累）。
- 开火微震：后期段 5 秒内 1 次（队长普攻中 / 重档才震），不是主因。

### 2.2 非整数放大

每美术像素占的物理像素（现行算法，`optical._lo_step`）：

| 窗口 | k | ×1.0 | ×1.15（缺省） | 整数化后 | 可见行（×1.15 → 整数化） |
|---|---|---|---|---|---|
| 1280×720 | 2 | 2 | 2.30 | 2 | 313 → 360 |
| 1920×1080 | 2 | 2 | 2.30 | 3 | 470 → 360 |
| 2560×1440 | 3 | 3 | 3.45 | 4 | 417 → 360 |
| 2560×1600 | 4 | 4 | 4.60 | 4 | 348 → 400 |

非整数时最近邻放大的列宽不等（2.3 = 2,2,3 循环；3.45 ≈ 3,4,3,4,3…），内容一平移，宽列的位置就相对内容移动，是典型的 pixel crawl。残差 0.96 → 0.24 就是这一项。关键帧放大图 `build/look_nausea/early/crawl_keyframes.png`：上排现状连续 4 帧（同一块地面，4 倍放大），美术像素宽窄不一、逐帧换位；下排推荐组合，每格等宽。

### 2.3 光学观感层逐项

后期段同帧对比（与 base 的差，均值 / 差 >12 的像素比例）：辉光 0.23 / 0.2%，分阶硬边 0.38 / 0.3%，发光预算 0.27 / 0.1%，特效照明 0.74 / 1.1%，深海滤镜 2.70 / 1.9%，LUT 2.75 / 1.7%，溟痕发光 0.71 / 1.2%，敌人增强 0.29 / 0.1%，整个光学 8.90 / 12.5%。
- 辉光 / 发光点在发光层（主视口，跟镜头），和世界层同一次取整，没有和地面不同步的漂移；荧光孢子是世界坐标、每秒 3–9 像素慢漂，量级可忽略。
- 地面荧光斑按 64 世界像素格哈希、固定在地上，只明灭不移动。
- 结论：光学层本身不是晕的来源；它带来的问题只有「低分辨率层 + 非整数放大」（§2.2）。

### 2.4 帧间隔

- 本机显示器：笔记本屏 2560×1600 @ **165 Hz**，外接 2560×1440 @ **143.9 Hz**（`Win32_VideoController`）；测试窗口所在屏 Godot 报 165 Hz。
- 设置缺省「最高帧率 60」（`Cfg.max_fps`，`Engine.max_fps = 60`）+ 垂直同步：165 / 60 = 2.75、144 / 60 = 2.4，不是整数，每个游戏帧在屏上停留 2 或 3 个刷新（12.1 / 18.2 ms 或 13.9 / 20.8 ms）交替。即使帧时间完美稳定在 16.7 ms，画面运动也带 15–20 Hz 的抖动。
- 实测（后期 30 秒、约 60 只同屏，`look_nausea.py pace`）：

| 档 | 帧上限 | 帧间隔中位 | 标准差 | P95 | 相邻帧差 >4 ms 的比例 |
|---|---|---|---|---|---|
| 中 | 60 | 31.5 ms | 6.5 | 44.0 | 40% |
| 中 | 不限 | 30.4 | 7.4 | 44.0 | 43% |
| 高 | 60 | 27.0 | 5.2 | 35.6 | 25% |
| 高 | 不限 | 31.2 | 6.1 | 41.7 | 37% |

  渲染 CPU 中位 1.2–1.4 ms、GPU 0.9–1.0 ms，帧时间主要耗在逻辑（含机器人）上，而且测试窗口在副屏后台、当时本机还有 3 个别的 Godot，绝对值比用户实玩慢很多（docs/132：中画质 100 只稳 60），**只说明帧间隔本身就不匀**（相邻帧差 >4 ms 占 25–43%），不作性能结论。用户实机的帧间隔分布要在前台量一次（§5 待办）。

### 2.5 色调（用户追问「是不是跟紫色有关」）

后期段每 10 帧一张、HSV 统计（有色 = 饱和 >0.2 且明度 >0.1）：

| 变体 | 青蓝占有色 | 紫 / 洋红（250–330°） | 平均饱和 | 平均明度 | B−G 均值 |
|---|---|---|---|---|---|
| base | 91.9% | 1.3% | **0.735** | 0.156 | +13.0 |
| 关光学 | 91.3% | 1.6% | 0.692 | 0.148 | +11.0 |
| 关深海滤镜 | 91.6% | 1.5% | 0.696 | 0.148 | +10.6 |
| 环境光去饱和 0.5 | 91.1% | 1.7% | 0.681 | 0.142 | +9.1 |
| 去饱和 0.5 + 关深海滤镜 | 89.4% | 1.9% | 0.636 | 0.135 | +6.9 |

- 「紫」主要不是洋红，而是**溟痕的近黑靛紫**：取样色 (4,6,24)、(2,5,15)、(25,25,59)，色相 226–240°、饱和 0.8、明度 0.06–0.25；按色相 222–300° 且饱和 >0.45 统计**占屏 15.4%**，平均明度 0.097。光学层 / LUT / 溟痕发光开关对它几乎没影响（15.2–16.0%），是贴图本身的颜色。
- 溟痕上的亮青脉络：溟痕区域（膨胀 9 像素）边缘密度 26.9，其余画面 10.5（2.6 倍）。暗紫底 + 亮青细网 + 不规则团块，是「有机网 / 细胞」读法——这一项最可能是「恶心」里「看着不舒服」的那部分，和运动无关。
- 整体：环境光 CanvasModulate = 主题 (0.16, 0.22, 0.32) × 1.3，B 是 R 的 2 倍；深海滤镜再往青蓝推。结果是暗部全是高饱和蓝（饱和 0.73 / 明度 0.16），没有中性的暗灰——「深而稠」，正好对上「粘腻」。
- 洋红只在危险预警（激光预警框等）出现，占比 1–2%，不是问题。
- 图：`build/look_nausea/late/hue_hist.png`（色相直方）、`color_cmp.png`（base / 去饱和 / 去饱和 + 关滤镜 同帧）。

## 3. 建议的修改

### 3.1 镜头（原因 1）

- `render/cam_round`（新旋钮，缺省 1 = 现状）：**改 0**。低分辨率层已有亚像素补偿（`lo_rect.position` 取到物理像素），镜头不必再取整；地面步长差 1.5 → 0.5 px。
- 队长抖动（cam_round=0 时 120 → 161 帧）：根因是队长和地面同在低分辨率格上、相对位移只能按整格走。彻底消掉要把**队长**（只队长，队友仍在低分辨率层）画到高清层、按物理像素定位：试验里「不取整 + 整数缩放 + 高清干员层」把抖动降到 35 帧。现有 `render/optical_ops_hi=1` 是整队上高清层，10-23 因与怪物的前后遮挡（脚底 y 排序）被关掉；要做就是「只队长上高清层 + 与怪物按 y 分两段画」，属于新机制，**先给方案、等用户点头**。
- 镜头跟随平滑（lerp 拖尾）：现状没有平滑（每帧直接对准队长 + 切队长 0.25 秒缓动），不是「拖着走」，不用改。

### 3.2 缩放（原因 2）

- `render/optical_int_zoom`（新旋钮，缺省 0）：**改 1**。缩放取 round(窗口高 × 设置缩放 ÷ 450)，至少 2。1440p 屏由 3.45 → 4（看得更近：417 → 360 行），1080p 由 2.3 → 3。用户若嫌 1440p 太近，可把设置里的缩放改到 ×1.0（→ 3，480 行）；设置界面的缩放档位改成「整数倍档」是界面会话的活。

### 3.3 帧率（原因 3）

- 设置「最高帧率」加一档「跟随显示器」（`Engine.max_fps = 0`，垂直同步开），**高刷屏缺省用它**；60 帧上限只在 60 Hz 屏或用户自选时用。逻辑本来就按真实步长（PlayClock），帧率高不改玩法。
- 前提：桌面中画质 100 只同屏在 144 / 165 Hz 下的帧时间要先在前台实测（§5）；达不到时与其锁 60，不如锁到刷新率的整除档（144 → 72、165 → 82.5 做不到整除，只能 55）。

### 3.4 顿帧（原因 4）

- `fx/hitstop_gap` 0.5 → **1.5** 秒；`fx/hit_pause_m` 0.014 → **0**（中档不顿）；重档 `hit_pause_h` 0.03、击杀 `kill_pause` 0.033、Boss / 精英击杀（must）不动。顿帧手感是用户 10-11 定的「保留」，这里只减频率。

### 3.5 色调（原因 5）

- `render/ambient_desat`（新旋钮，缺省 0）：试 **0.4**，环境光往同亮度的灰拉，暗部不再一片饱和蓝；
- `render/optical_sea` 0.55 → **0.3**（深海滤镜减半，保留「深海」方向）；
- 溟痕贴图：减少青色脉络数量、降低脉络与底色的明度差、底色靛紫往暗青灰靠（颜色语言「环境暗青灰」）；交 Codex，与 docs/132 §4 第 5 条（溟痕偏花）一起定。`render/optical_mire_emit` 只管发光层，改它影响很小（同帧差 1.2% 像素）。

### 3.6 次要项

- 开火微震 `fx/leader_kick` → 0；受击后坐三档 2 / 3 / 5 → 0 / 1 / 2 美术像素；受击形变 `fx/squash_basic` 0.14 → 0、技能 0.18 → 0.06（非整数缩放在低分辨率层上像素撕裂，读作「果冻」）。量级小，随推荐组合一起看。

| render/cam_round | 1 | 0 |
| render/optical_int_zoom | 0 | 1 |
| fx/hitstop_gap | 0.5 | 1.5 |
| fx/hit_pause_m | 0.014 | 0 |
| render/ambient_desat | 0 | 0.4 |
| render/optical_sea | 0.55 | 0.3 |
| fx/leader_kick | 1 | 0 |
| fx/recoil_px1 / 2 / 3（/ recoil_px） | 2 / 3 / 5（3） | 0 / 1 / 2（1） |
| fx/squash_basic / dot / skill | 0.14 / 0.08 / 0.18 | 0 / 0 / 0.06 |

帧率（§3.3）在设置里，不在这个开关里：对照时手动把设置「最高帧率」切到不限。

### 7.4 怪物冲刺预警：线以外的表现手法（试验，10-24）

用户：「冲刺看看有没有办法优化一下，除了线以外别的游戏还有什么表现手法」。动作 / 幸存者类常见做法：

| 手法 | 做法 | 优点 | 代价 |
|---|---|---|---|
| 蓄力姿势（anticipation） | 冲之前身体往反方向缩、压低、停顿 | 看怪本身就知道要冲，不加任何覆盖物 | 方向要靠朝向读，小怪 1 倍像素时不够明显 |
| 本体变色 / 发光 | 蓄力期间本体渐变到危险色（不闪） | 一眼知道「这只要动手」 | 和受击白闪、精英发光要分开 |
| 脚下箭头 / 「›」 | 怪物前方 2–3 个短箭头依次点亮 | 方向 + 倒计时都在，面积很小 | 没有完整落点，长冲刺低估距离 |
| 只给威胁者画 | 只有会打到自己的才画指示，其余只有身体表现 | 满屏时只剩跟自己有关的 | 侧面掠过的冲刺不提示 |
| 短箭（技能指示器式） | 冲刺距离前一段 + 箭头，不画全长 | 有方向有尺度，面积小一半 | 仍是线 |
| 残影 / 拖尾 | 冲刺途中身后 2–3 个半透明残影 | 「正在冲」读得清，事后知道冲过哪 | 是事中提示，不是事前预警 |
| 起冲扬尘 | 起冲瞬间脚下一小团尘 | 强调起步，打击感 | 同上 |
| 声音 | 蓄力音 / 起冲音（本作已有冰面急冲音） | 不占画面 | 满屏时声音会糊 |
| 屏幕边缘指示 | 屏外冲过来的在边缘给小箭头 | 防屏外偷袭 | 本作冲刺距离短，意义不大 |

本作试验开关 `render/dash_tell_style`（缺省 0 = 收敛后的预警线）：

- **1 = 身体蓄力 + 脚下箭头（不画线）**：蓄力期间本体往冲刺反方向缩 `render/dash_pull` 3 美术像素、颜色随进度渐变到危险色 `render/dash_flash` 0.6（不闪）；会打到队长的怪脚前 3 个「›」按蓄力 ⅓ / ⅔ / 1 依次点亮，打不到的只亮最近一个、半透明。
- **2 = 只给威胁者画短箭**：会打到队长的画冲刺距离前 `render/dash_short` 45% 的短箭 + 箭头；其余只有身体蓄力（同 1）。

对照见 §7.5。
