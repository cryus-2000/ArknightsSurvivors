# 40 · 局内数据记录

> 2026-09-26：为以后分析玩家数据打底。本次只做本地部分（统一格式 + 正常游玩也记 + 版本号 + 分析脚本）；
> 上报通道、服务器与玩家同意流程等上线、定下发布平台后再做（§4）。代码结构见 docs/39，测试规范见 docs/36。

## 1. 做了什么

- **`scripts/run/telemetry.gd`（game.gd 字段 `telemetry`）**：一局一条「整局记录」，平衡机器人与真实玩家同一格式。
  - 整局指标（受击次数与每分钟承伤、低血 < 35% 时长、熄灯时长、死因、Boss 出现 / 击杀时间、精英化与入队时间、移动与站桩比例、每 30 秒曲线）原在 `core/bot.gd`，只有机器人局才采；现在所有对局都采。
  - `record()` 拼整局记录：胜负、时长、等级与升级时间、编队与精英化、深度卡被提供 / 选中、藏品候选与获得、伤害按来源 / 类型 / tag、承伤、治疗来源、大群记录、Boss 剩余、结局、灯火、无人机等级……
  - 平衡测试照旧打印 `BALANCE {...}`，**字段与之前完全相同**（批跑、A/B 工具不用改）；机器人局仍由 `run/autotest.gd` 按原节奏驱动采样（`tick(0.066)`），`core/bot.gd` 选卡时读 `g.telemetry.low_hp_s`。
  - 藏品获得记录原来只在平衡局记，现在所有对局都记。
- **本地保存**：真实玩家局结束（胜 / 负 / 中途退出）时追加一行到 `user://runs/runs.jsonl`：
  ```json
  {"schema": 1,
   "meta": {"version": "2.0", "commit": "abc1234", "platform": "Windows", "time": "2026-09-26T07:51:48",
            "seed": 123456, "diff": 0, "map": "deep_sea", "start_op": "mizuki", "result": "dead"},
   "run": { …整局记录，与 BALANCE 同格式… }}
  ```
  - 局内不足 20 秒就退出的不记；文件超过约 8 MB 丢掉较早的一半。
  - **测试运行不写**（带任何 `--xxx` 参数，docs/36「测试不写玩家存档」）；图鉴演示不写。自测写记录用 `--runslog=<路径>`，写到指定文件、不碰玩家目录。
  - `seed` 是本局对局随机数的种子：同 seed 可复现（docs/36 §3），配合以后的操作录制就能在本地原样重放玩家那一局。
- **版本号**：`game/data/build.json`（`version`、`commit`）。开发时 `commit` 为 `dev`；`tools/export_build.py` 打包时把真实提交号写进包里的这个文件，玩家记录因此能按版本区分（改平衡前后的数据不会混在一起）。
- **分析脚本 `tools/runs_report.py`**：读本地记录，转成 `balance_run.py` 的记录形状，复用它的汇总表（总览、按开局干员的胜率 / 存活 / 伤害构成 / 治疗 / 死因、行为指标、藏品流派拿取）。
  ```
  python tools/runs_report.py                      # 本机全部记录（%APPDATA%\Godot\app_userdata\水月 · 深海幸存者\runs\runs.jsonl）
  python tools/runs_report.py --since 2026-09-26 --commit abc1234 --out build/runs_report.md
  ```

## 2. 记录格式的约定

- `schema` 是格式版本：字段有**不兼容**改动（改名、删除、改含义）时 +1，分析脚本按它区分；只加字段不用改。
- 整局记录里的 `bot` 字段是「整局行为指标」（名字沿用平衡工具的历史叫法）：机器人局 `profile` 为机器人档位，玩家局为 `player`。
- 记录只观察、不改状态、不用对局随机数，所以不影响同 seed 复现；A/B 验证见 §5。
- 不记任何个人信息：没有账号、设备号、IP；`time` 是 UTC。

## 3. 以后加埋点

- 整局级的数字：加在 `telemetry.gd record()` 里（加字段不用改 `schema`）。
- 过程中的事件（例如「每次选卡提供了什么、选了什么」已有 `prog_offer / relic_offer`）：在对应的 `run/` 模块里往 `g` 的记录数组 append，再在 `record()` 输出。
- 不要在每帧都记事件（文件会很大）；逐帧的东西做成累计量或每 30 秒采样（`curve`）。

## 4. 上线前还要做的（本次不做）

1. **上报通道**：有网时用 HTTPRequest 批量上传本地记录，失败留待下次；网页版走浏览器请求，注意清站点数据会丢本地队列。
2. **服务器**：一个收数据的接口 + 存储（如云函数 + 数据库），需要决定服务商与托管方。
3. **玩家同意**：首次启动询问是否分享匿名游戏数据、设置里可关；默认不开，勾选才上传；随机生成的匿名安装编号；简短隐私说明（国内受《个人信息保护法》约束，上架平台另有要求）。
4. （可选）**操作录制**：记录每帧输入，配合 seed 在本地原样重放玩家的一局，用来查 bug 与复盘平衡。
