# 162 · 后期换人频率（10-26）

> 用户：「现在后期换干员的频率高吗？检查一下，如果过高我觉得需要降低点。」协调人派活：先量，再决定改不改；只调权重，不加新机制、不设硬上限。
> 基线 origin/main 8531fd672；分支 `claude/recruit-freq`。统计脚本 `tools/probes/recruit_freq.py`（读 balance_run 原始 JSON，遥测新增 `recruit_offers` / `levelup_t`）。

## 1. 量法

常规档，`--preset starts`（7 名开局干员）× 机器人 normal / expert × seed 1–2，共 28 局，`--nodeath`（都跑满 10 分钟，后期样本完整）。
统计每段：升级面板次数、面板里出现的招募卡 / 换人卡（编队满员后的招募卡）/ 强制招募保底，以及实际换人次数。

出现招募 / 换人的来源只有升级面板：强制招募保底只在编队 < 3 人时触发；节点卡「重整编制」、深蓝之心「办公室」、引火之木是直接入队（满员时改为一次成长三选一），不弹换人选择；商店不卖干员。

## 2. 改前（基线）

| 时段 | 升级面板 / 局 | 招募卡 | 换人卡 | 保底招募 | 换人卡间隔 | 带招募 / 换人的面板占比 |
|---|---|---|---|---|---|---|
| 0–3:30 | 10.9 | 1.4 | 2.7 | 1.1 | 约 77 秒 | 47% |
| 3:30–7:00 | 8.0 | 0 | 4.6 | 0 | **约 46 秒** | **57%** |
| 7:00–10:00 | 5.5 | 0 | 3.0 | 0 | **约 59 秒** | **56%** |

判断：编队通常 2 分钟前就满 3 人，之后每次升级都按 55%（与招募同一概率）出一张换人卡，过半的升级面板有一格被换人卡占掉（占的是成长 / 被动卡的位置），中段每 46 秒就弹一次换人选择。**偏高。**
（机器人缺省不换人 `bot/swap = 0`，所以「实际换人」为 0；真人玩家的换人次数取决于本人选择，这里只量出现频率。）

## 3. 改动（只调权重）

`balance.json levelup` 段：
- `swap_chance` 0.25：编队满员后换人卡出现率（原来跟招募一样 0.55）；
- `swap_chance_late` 0.12、`swap_late_t` 420：7:00 后再降一档；
- `swap_keep_growth` 1：本次升级已有两张干员深度卡时不出换人卡（换人卡不挤掉成长卡）。
- 强制招募保底本来就只在编队 < 3 人时触发，满员后不触发，不用改。
- 编队未满时的招募卡概率（0.55）不变；没有硬上限。

## 4. 改后（同 28 局）

| 时段 | 升级面板 / 局 | 招募卡 | 换人卡 | 保底招募 | 换人卡间隔 | 带招募 / 换人的面板占比 |
|---|---|---|---|---|---|---|
| 0–3:30 | 10.8 | 1.4 | 0.6 | 1.1 | 约 368 秒 | 28% |
| 3:30–7:00 | 7.8 | 0 | 1.1 | 0 | **约 184 秒** | **15%** |
| 7:00–10:00 | 5.6 | 0 | 0.7 | 0 | **约 265 秒** | **12%** |

后期从「约每分钟一次、过半面板」降到「中段约 3 分钟一次、7:00 后约 4–5 分钟一次」，换人仍可遇到。前期组队（招募卡 + 保底）不变。
平衡影响：机器人本来不换人，换人卡空出的位置给了成长 / 被动卡，后期构筑略强；按 docs/132 胜率差 < 10 点不下结论，未另跑胜率配对。
