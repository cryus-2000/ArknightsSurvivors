## 1. 规则与数据结构

- 开关（`balance.json levelup` 段，缺省都开）：`branch`（分支培养）、`focus_guard`（培养保底）。关着时节点按 JSON 顶层字段 = 旧成长线，同 seed TRACE 逐行不变（§5）。
- JSON：节点 4 顶层字段仍是旧节点（德克萨斯 `back` 等），另带 `branch {路线 id: {id, name, desc, icon}}`、`branch_desc`（培养卡文案）、`bot`（机器人 / 赠送推进的固定路线）；节点 5 顶层仍是旧节点，另带 `routes {路线 id: {id, name, desc, icon}}`。路线节点的积木写在 `blocks.progression.<id>`，`node:<id>` 条件照常可用。`ob_check` 要求 routes 的键与 branch 一致、每个路线节点都有积木。
- `character.gd`：`route`（每人自己的路线 id）、`node_view()`（按路线解析节点）、`prog_view()`、`needs_route()`、`route_choices()`、`bot_route()`；`advance()` 遇到分支节点：给了路线就用，没给且已选用已选，都没有 → 玩家局交 `progression.branch_defer` 排队（本次不推进），机器人 / 测试 / 演示按 `bot_route` 固定选（`--route=<op>:<id>` 可覆盖）。节点解析后再 `prog += 1` 与 `NODE_ATK`，同一节点不会重复加成。
- `progression.gd`：外层只出一张带 `branch` 的培养卡；选中进 `open_branch`（kind `branch`：两条路线 + 返回）；「返回」`cancel_branch` 恢复原卡组（同一个数组、不重抽、不扣）；确认把原卡换成带路线的卡走原结算（只扣一次升级）。换入会继承到节点 4 及以上的试点干员：`swap_out` 先进路线屏，确认后 `squad.replace(old, new, route)` 按新路线一次性重建。赠送推进（典训 / 博士银印 / 人事部铜印）：`branch_queue` 排队，`game.check_pending` 在演出之后、宝箱 / 升级之前弹出，只能确认、不扣升级、不重发奖励。机器人在路线屏 `auto_branch_pick` 选固定路线、不取随机数（`autotest.bot_pick`）。
- 培养保底（§4.2 简化版）：`focus_op` = 最近一次选中培养卡的干员；它还有合法成长卡时在 `open_levelup` 里挪到 `deep[0]`（只重排，不加选项、不多取随机数）；离队 / 养满自然失效，选了别人就切换。
- 界面：`choice_panel` 标题标签 `GROWTH PATH`，路线卡标签「路线 · 干员」，返回卡「返回  BACK」+ 出口图标；属性面板成长点用 `prog_view()`。截图 `build/shots/branch_panel.png`（`build_progression_test.tscn -- --branch_shot`）。
