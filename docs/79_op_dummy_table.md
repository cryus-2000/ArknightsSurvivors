# 79 · 干员木桩表（理论预算）

> 2026-10-12 制作人定：调干员数值前先看一张自动生成的对照表，补上「理论预算」这一层。之前只有云端机器人批跑的胜率（docs/27、docs/29），
> 胜率混了生存、走位、选卡和机器人时机，看不出「这名干员本身的输出 / 治疗预算是高是低」。木桩表只回答后一个问题。

## 1. 口径

每名干员（`game/data/characters/*.json` 全部，现为 18 人）× 精英阶段 E0 / E1 / E2 × 场景（单体木桩 / 怪群）× 身份（主控 / 队友），各跑一局：

| 项 | 口径 |
| --- | --- |
| 场地 | `g.sandbox = true`（game.gd，只由测试场景置位）：不刷怪（含 Boss、溟痕、威胁上升）、不走事件 / 围猎 / 灯标 / 商人 / 拾取。主控站桩（`--bot=afk`），无藏品、不升级、不开箱 |
| 时间 | 热身 20 秒（技力从 0 开始充）+ 统计 60 秒；`--balance` 步长每帧 0.066 秒；种子 1，同参数可复现 |
| 精英阶段 | 成长线统一为「节点 节点 精一 节点 节点 精二」：E0 = 0 个节点，E1 = 推进到精一（3 个节点），E2 = 整条线（6 个节点）。精英化节点有选项时取第一个（同图鉴演出）。全队同阶段，推进后所有技力清零 |
| 单体木桩 | 主控右侧 50 像素一只骨海漂流体外形的木桩：不动、不攻击、生命恒满（10⁹，低血量加成 / 斩杀不会触发），每帧钉回原位（击退无效） |
| 怪群 | 主控周围 180–240 像素持续补满 round(30 × k) 只普通近战怪（骨海漂流体 / 底海滑动者 / 壳海狂奔者 / 伊祖米克的子代轮换，每只固定 400 / k 生命，照常移动与攻击，不掉经验；k = 怪物密度 `enemy/density`，docs/50 §16，缺省 0.4 → 12 只 × 1000 血，总血量池不变；`enemy/scale` 时判定半径同乘）；刷怪位置用测试自己的随机数（种子固定） |
| 主控状态 | 每帧把主控生命压在 60%（所有治疗都是有效治疗）、灯火 100；`--nodeath` 兜底 |
| 手动技能 | **就绪即放**。机器人缺省是保命型时机（主控生命 < 30% 才放，乌尔比安 S3 例外），这里取上限；表头注明 |
| 队友身份 | 主控固定为星熊（测星熊自己时换塞雷娅），主控每帧技力压 0、不放技能（普攻与天赋照常）；只统计被测干员名下的伤害 / 治疗 / 击杀。选星熊是因为它不加伤、不治疗、不给技力（流明的「照亮」+25% 易伤、塞雷娅的治疗、推进之王 / 德克萨斯的回技力都会污染队友数据） |

记的东西（全部从运行时读，不从 JSON 抄）：

| 字段 | 来源 |
| --- | --- |
| 秒伤 `dps` | 统计期内被测干员名下的有效伤害（`telemetry.op_out[干员]`，与作战记录同一份账）÷ 秒数 |
| 拆分 普攻 / 技能 / 召唤 / 其他 | 按伤害来源表 `g.hit_src`：`emitter = summon` 记召唤；否则 `origin = core` 记普攻、`skill` 记技能、其余（天赋 / 分支）记其他 |
| 治疗 / 秒 `hps` | `g.heal_log` 的增量，去掉「自身回复」（主控回复属性）和基准主控名下的来源 |
| 护盾 / 秒 `shield_ps` | 被测干员积木护盾 `sm.shield` 每帧的正增量之和 ÷ 秒数（按生命点算）；博士护盾层数另记 `shield_layers` |
| 击杀 `op_kills` | 参与击杀（死前 3 秒内命中过的干员各记一次，docs/77）；`kills` 是全场击杀 |
| 技能次数 `casts` | `telemetry.op_casts`（spend_sp 次数），手动技能另记 `manual_casts` |
| 普攻命中间隔 | 统计期 ÷ 普攻在木桩上造成伤害的帧数。持续型 / 多段普攻会贴近一帧（0.066 秒），只作横向参考 |
| 主控层属性 | `g.max_hp / armor / arts_res / regen(+regen_pct) / speed / dodge`：主控身份、单人编队时就是该干员 leader 段 + 博士基础值 |
| 干员系数 | `op.stat(op_atk / op_aspd / op_range)`、`skill_power()`、`sp_need(0..2)` |
| 怪群在场均值 `horde_alive` | 每帧补怪前的在场数平均。接近 round(30 × k) = 没打空；明显偏低 = 补怪速度成了上限、怪群秒伤被低估 |

## 2. 怎么跑

```
python tools/op_dummy_table.py                       # 全部：18 人 × 3 阶段 × 2 场景 × 2 身份 = 216 局，本机约 6–8 分钟
python tools/op_dummy_table.py --ops wisadel,saria --stages 2
python tools/op_dummy_table.py --secs 60 --warm 20 --jobs 4
python tools/op_dummy_table.py --report-only         # 不跑，用上次的 table.json 重出 table.md
```

- 并行最多 4，经 `tools/godot_runner.py` 启动（受全机上限 `GODOT_MAX_PROCS` 约束），全部 `--headless`、静音、临时用户目录，不写存档。
- 输出：`build/op_dummy/table.md`（表）、`build/op_dummy/table.json`（每局原始记录 + 参数 + 提交号）、`build/op_dummy/logs/<干员>_e<阶段>_<场景>_<身份>.log`。
- 单局手动跑：

```
godot --headless --path game res://tests/op_dummy_test.tscn -- --balance --bot=afk --nodeath --seed=1 --op=hoshiguma --squad=wisadel \
      --dummy_op=wisadel --dummy_role=mate --dummy_scene=horde --dummy_stage=2 --dummy_secs=60 --dummy_warm=20
```

  结束时打印一行 `DUMMY {json}`。
- 快检（`tools/check.py`）里有一项 5 秒的自检 `op_dummy`（星熊主控 + 维什戴尔队友、怪群、E2，`--dummy_check`）：只看场景能跑、有伤害、怪群有击杀或有承伤（k < 1 时每只 1000 血，5 秒未必打死）、没有报错。

## 3. 怎么读

- `table.md` 开头是**摘要**（E2、主控身份）：每职业木桩 / 怪群秒伤最高与最低、治疗最高。
- 每个精英阶段一张**主表**，按职业分组；每格是「数值（相对该列 18 人中位数的百分比）」，偏离超过 ±30% 的格子**加粗并标 ▲ / ▼**。
  治疗 / 护盾列只在有这项能力的干员之间取中位数，没有的记「—」。
- 主表下面是**木桩秒伤拆分**（普攻 / 技能（括号内为技能次数）/ 召唤 / 天赋与分支），用来判断偏高偏低出在哪一块。
- **基础属性**表：主控层属性（E0）、普攻命中间隔（E0 / E2）、E2 的攻击 / 攻速 / 范围系数、三个技能的技力需求。
- 最后是**偏离清单**：所有被标出的格子按阶段、列排序。
- 职业之间本来就不该拉平（狙击 / 术师的秒伤高于重装、医疗是正常的），**主要看同职业内的差距**和「某人在所有列都偏」这种模式；
  跨职业只作量级参考。
- 「木桩 vs 怪群」的比值大致反映单体 / 群体取向；「主控 vs 队友」的差异来自主控层加成、站位（队友跟随位离木桩更远）和手动技能（只有主控有）。

## 4. 局限

- **不反映生存**：主控生命被压在 60%、不会倒下；重装 / 护盾 / 减伤类干员的价值大半不在表里（护盾只记了生成量）。
- **不反映走位**：主控站桩不动，冲刺 / 位移型干员（德克萨斯天赋会带着主控冲）的落点与真实对局不同；近战队友要自己走到目标身边。
- **不反映机器人的技能时机与选卡**：手动技能就绪即放是上限；没有藏品、博士被动、援护，也没有成长线以外的技能强化卡。
- **怪群是低压力的近战怪**：没有远程怪、精英、Boss，也没有溟痕与缩圈；怪群生命固定，不随时间成长。
- **单一种子、单一站位**：数字可复现，但不是多种子的均值；小于 ±10% 的差异不要当真。
- 结论：木桩表用来**找出理论预算明显偏离的干员和出问题的那一块**，调数值前先看它；定数值仍以机器人批跑胜率为准（docs/27 §6.4、docs/29）。
