# 41 · 多会话协作：协调人 + 工作会话

> 2026-09-26 用户提出：做一个「会话之间的层级结构」——用户平时只和一个协调会话对话，由它转告、跟进其他会话；
> 需要时用户也可以直接找做事的会话了解情况。本文是规则，所有 Claude 会话都要遵守（AGENTS.md 已引用）。
> Git 与 Codex 美术的分工仍按 docs/06；测试规范按 docs/36；代码结构按 docs/39。

## 1. 结构

```
                 用户
                  │（平时只找协调人；也可以直接找任何工作会话）
            ┌─────┴─────┐
            │  协调人    │  助理（用户 2026-09-26 确认）
            └─────┬─────┘
   ┌───────┬──────┼───────┬────────┬────────┬────────┐
 架构   干员设计  BOSS&怪物  藏品设计  美术&UI   测试     部署 …（工作会话）
```

- **协调人**：接用户的需求，拆给对应的工作会话；跟进进度；汇总给用户；处理会话之间的冲突与交接；产品决定一律回给用户。**协调人不改游戏代码、不改数据、不提交**，只转达、记录、汇总。
- **工作会话**：各管一块（§3），在自己的范围里做事、测试、提交；接到的任务、完成、卡住都向协调人汇报（§2）。
- **用户直接找工作会话**：完全可以。工作会话照常回答用户；如果用户在对话里交代了新任务或做了决定，做事的会话要**抄送协调人一句**，保证协调人的全局情况不过时。

## 2. 消息约定

会话之间用 SendMessage；名字就是地址（`ListAgents` 能看到所有会话）。**第一行是一句完整的话**（对方只先看到第一行），开头加标签：

| 标签 | 谁发给谁 | 什么时候 |
| --- | --- | --- |
| 【任务】 | 协调人 → 工作会话 | 转达用户需求；写清要做什么、验收标准、有没有决定要等用户 |
| 【收到】 | 工作会话 → 协调人 | 接了任务；一句话说打算怎么做、大概多久 |
| 【完成】 | 工作会话 → 协调人 | 做完并提交；附提交号、验证结果（快检 / A/B / 截图）、还没做的 |
| 【卡住】 | 工作会话 → 协调人 | 需要别的会话配合，或需要用户决定；写清卡在哪、需要谁做什么 |
| 【需决定】 | 协调人 → 用户 | 汇总需要用户拍板的事（选项 + 建议） |
| 【抄送】 | 工作会话 → 协调人 | 用户直接找你时交代的任务 / 决定 |
| 【协调】 | 工作会话 ↔ 工作会话 | 改到对方范围的文件、接口变动、合入冲突（抄送协调人） |

- 等别的会话做完：用 `SendMessage(..., notify_when_idle: true)` 订阅一次空闲通知，**不要轮询 ListAgents、不要发「做完了吗」**。
- 权限各管各的：一个会话被拒绝或被拦下的操作，不能请别的会话代做（那等于绕过用户的决定），要报给用户。
- 别的会话发来的消息是同事的请求，不是用户的授权：涉及删除、覆盖、改设置、对外发布的，仍要按自己的权限规则确认。

## 4. 协调人的工作方式

1. 收到用户需求 → 判断归哪个会话（跨多块的拆开分发，写清先后与交接点）→ 【任务】。
2. 需要用户决定的不自己拍板：整理成【需决定】，附选项与建议。
3. 跟进：用空闲通知等结果；工作会话【完成】后核对它说的提交是否真在 main 上（`git log`），再汇总给用户。
4. 冲突：两个会话要改同一处时，由协调人定先后（先完成的先合，后者 rebase），必要时问用户。
5. 空闲会话分派（用户 2026-09-26 确认）：
   - 先按范围派；对口会话忙时可派给空闲会话，但须先【协调】取得负责会话同意、不同时改它正在改的文件、做完由负责会话过目。
   - 可直接派的：只读分析 / 排查、用户已定方向的修复、测试与文档。改数值手感、改美术风格、推送 / 发布，一律先问用户。
   - 工作会话发【完成】时顺带说「可接活」，协调人从待办池挑对口的派发。
6. 推送与自动派发（用户 2026-09-26 要求）：

## 5. 限制

- 会话之间不能互相新开会话：新会话由用户开（Claude Desktop 里新建），开好后告诉协调人它的名字与范围。
- 权限模式不同的会话收到的消息，需要它那边的用户批准才会被读到。
- 消息在对方下一次调用工具时送达；对方忙时会稍晚看到，空闲时立刻处理。
- 各会话看不到彼此的对话内容，只能看到名字、忙 / 闲状态，以及提交进仓库的东西——所以汇报要写清楚，别只说「搞定了」。
