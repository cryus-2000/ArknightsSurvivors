### 1.1 涨在哪（按贡献）

1. **pxp 转平面帧条 +8.54**：2790 张无损 WebP，平均 3 KB。其中：
   - `*_raw*`「旧做法对照」帧条 **115 张 / 1.28 MiB**（§2.1）；
   - 斯卡蒂终结技大图集 `art/fx/pxp/ult_sd/` **10 张 / 1.92 MiB**，单张约 4000×1700 像素（§3.2）；
   - 各方向变体：`_d<角度>` 897 张、`_dm<角度>`（反方向）598 张，共约 2.6 MiB（磁盘大小）；镜像并不严格相等（598 对里仅 9 对完全水平翻转相等、59 对上下翻转相等），**不能直接用翻转代替**；
   - 按干员排（磁盘 MiB）：艾雅法拉 1.63、推进之王 0.59、星熊 0.58、浊心斯卡蒂 0.55、乌尔比安 0.48、维什戴尔 0.47、凯尔希 0.46、水月 0.44。
2. **字体 +0.87**：11-05 新增 `fonts/ui_phone.ttf`（手机字体，`settings.gd` 在触屏上替换 ui.ttf 的数据）。它**没有被子集化**——`release_slim.SUBSET_FONTS` 只列了 `ui.ttf`、`serif.ttf`——整份 840 KB 进了包。
3. **脚本 +1.01**：代码本身增长（world / fx_pxplane / ult_moves / ob_summon 等）；已是压缩令牌，无损招数已用尽。
4. **数据 / 导入记录 +1.07**：每张新帧条一个导入记录条目，加上 19 份 `pxp_*.json`（每份 200–500 KB 原始、压后 30–60 KB）。
5. 配乐 −4.02 是 11-02 起音频瘦身的结果（docs/187 §9–10），现在已在 C 档最低质量 + 部分降到 16 kHz。

## 2. 无损 / 不影响画面与听感的项（推荐全部做）

### 2.1 「旧做法对照」帧条不进包：**−1.28 MiB**

- `fx_pxplane.gd` 的 `mode() == 2` 是「旧做法对照」，只由 `--bal=fx/px_plane=2`（开发参数）触发；正式包缺省 `fx/px_plane` = 1，开发参数被 `Cfg.dev_args()` 守卫挡掉。`raw` 标志为真时才用 `pxp_*_raw*` 帧条（`_add(..., raw, "raw_xxx_e%d", ...)`）。
- 115 张 `pxp_<干员>_raw_*.png`（含 `pxp_sk_raw_s3_e2` 194 KB、`pxp_ey_raw_ignite` 85 KB 等）。
- 做法：`release_slim.REVIEW_ART_GLOBS` 或网页 / 公开包的导出 exclude 加 `*_raw_*`（限 `art/fx/pxp/`）。桌面对内包可保留，便于对照。
- 影响：画质 / 听感 0；内存只减不增。
- 风险（低）：实施前要确认没有非 mode 2 路径引用 raw 帧条。德克萨斯 `_tx_draw_raw_lines`、水月 `_h3mz_draw_jellies` 等我只看到在 mode 2 分支里；实施时先跑 `tools/asset_unref_scan.py` + 全员冒烟确认无缺图。

### 2.2 手机字体子集化：**−0.53 MiB**

- `ui_phone.ttf` 1137 KB → 子集 577 KB → WOFF2 容器 **300 KB**（实测，同 `release_slim.font_chars` 字表；现在 pck 里 840 KB）。
- 做法：`SUBSET_FONTS` 加 `ui_phone.ttf`（字表和 ui.ttf 相同，设计就是同字表）。导出脚本已有 WOFF2 容器步骤。
- 影响：字形 / 度量不变（同 10-28 字体子集的验证口径）；运行时内存略降。
- 需验证：`touch_layout` 冒烟（手机字体排版不跑位）。

### 2.3 开发用脚本不进包：约 **−0.2 MiB**（等代码整理合入）

- 现在 562 个 .gdc 里有 `autotest`（80 KB）、`boss_bench`、`ult_bench`、`enemy_demo`、`outwin_probe`、`ak_mock`（界面示意，76 KB）等开发 / 测试脚本，合计约 0.2–0.3 MiB。图鉴（gallery）是正式功能，不能排。
- 做法要改引用（`game.gd` 等可能 `preload` 了它们），属于代码改动，**交给代码整理会话**一并处理；本稿只记账。

## 3. 有损项（要用户点头）

### 3.1 选项一览

| 项 | 预计省 | 画质 / 听感代价 | 内存 | 建议 |
|---|---:|---|---|---|
| 斯卡蒂终结技大图集：方向由 9 个减到 5 个 | −0.9 | 瞄准角度精度 22.5° → 45°（最大偏差约 22°） | 减 | 可做，需用户看一眼 |
| 同图集改有损 WebP（质量 ≥ 0.9） | −1.2（估，未实测） | 光晕渐变处可能有轻微块；像素硬边处可能有杂边 | 同 | 先出 PSNR 对照图（同 10-31 事件插画做法，PSNR 40 dB 以上才行） |
| 最终 Boss 8 首配乐降到 D 档 | −2.4（估：8 首共约 7.2 MiB，按 D 档整体 −33%） | 22 kHz、再低一档质量，高频发闷；只在最终战听到 | 减 | **需用户重新试听**（10-28 否过全局 D 档，本项只针对最终战） |
| 全局配乐 D / E 档 | −5.6 / −7.7 | 全程可闻 | 减 | 10-28 用户没选，不推荐 |

### 3.2 pxp 大图集与方向变体

- `ult_sd`（斯卡蒂终结技）每张约 4000×1700 像素，压缩后 170–260 KB，**一次起手只加载一张**（`ult_px_sd.gd` 注释：约 20 MB 显存，招式结束 2 秒后释放）。体积合计 1.92 MiB。
- 其它 pxp 方向变体（`_d*` / `_dm*`）是按干员、招式烤的瞄准方向，各自方向数不同；本稿没有逐套核对哪些能减方向，**不做统一缩减**，实施前由各干员的 pxp json 决定。
- 不推荐：对像素硬边帧条用有损（`1 特效像素 = 1 美术像素` 要求逐像素准确）。

### 3.3 近似镜像去重（待研究，不进首轮）

598 张 `_dm*` 与对应 `_d*` 不完全镜像。若逐张做「近似镜像（平均误差 < 1/255）」判定，可能有一部分能在运行时翻转代替，最多省约 1.0 MiB。要先在 GCP 上跑像素差统计和同 seed 画面对照，**收益不确定，首轮不做**。

### 3.4 配乐

- 现状：23 首 Suno + 标题 / 部署 / 开场等，C 档（libsndfile 压缩级 1.0）；8 个能量很低的曲目已降到 16 kHz（docs/187 §10）。
- 体积分布：最终 Boss 8 首（knight / izumik / ishar / final 的 p1 + p2）合计约 7.2 MiB，占配乐 43%；其余曲目已无无损余量。
- 「按需加载」（把最终战配乐拆成单独 pck，9:00 前再下载）：**不推荐**。Toy 的 50 MB 按总量算，不省；要自写分片下载器和 `load_resource_pack` 流程，工程量大、网页失败风险高，违反「不崩溃优先」。

## 4. 不做 / 已否

| 项 | 为什么 |
|---|---|
| 自编精简引擎模板（估 −3 MiB） | 用户 10-26 定不做网页自编模板 |
| 帧条降分辨率 / 全面有损 WebP | 降画面（干员保持高清，用户定）；pxp 像素硬边 |
| 脚本换未压缩令牌 + 外层压缩 | 收益 < 0.3 MiB |
| `@2x` 换 1 倍图再放大 | docs/187 §8 实测只省 0.27 MiB |
| 把 pxp 帧条按干员拆成「进局才下」的分包 | Toy 按总量算；工程量大；失败时画面缺图 |
| 去掉 E0–E2 档帧条 | 改玩法画面，每档要肉眼可分（docs/245 / 249） |
