# Shared agent collaboration rules

Read docs/06_git_collaboration.md before making changes.

Docs index: docs/00_index.md lists every document by topic with its status (current spec / implemented record / in progress), a one-line summary and who references it; archived documents live in docs/archive/ with a one-line pointer left at the old path. Read first, all sessions: docs/00_index.md, 06, 41 §1–§3, 36 §1–§3 (including §1.1) and §7.5.1, 39, 76. The index's 「新会话先读」 table adds the per-role list (operators, Boss & enemies, balance / relics, UI & art, audio, deploy, copy).

Multi-session coordination (Claude sessions): docs/41_agent_team.md. The user normally talks to one coordinator session, which relays tasks; worker sessions report 【收到】/【完成】/【卡住】 to the coordinator and CC it (【抄送】) when the user gives them tasks directly.

Original-game reference (Arknights 集成战略 / battle mechanics / boss originals, sourced from PRTS and unpacked game data): docs/49_原作参考.md (sub-files 49a / 49b / 49c). Check it before designing mechanics, numbers or names that borrow from the original.

Language style (binding, user 2026-10-12): all player-facing text (UI, guide, banners, skill / relic / talent effects, gallery, lore, endings, events) must follow docs/76_language_style.md: Arknights / Rhodes Island register, terse and exact, no slogans or moralising tail sentences, the canonical terminology table, and canon character quotes / facts only from verifiable sources, PRTS first (never invented; docs/76 §4). Run its self-check list before committing text.

- User owns product decisions. Codex owns character and monster art (player, allies, NPCs, enemies, bosses: idle / move / attack / feign strips and their portraits). Claude owns gameplay code, integration, builds, and all other art: attack and hit effects (fx_*), projectiles (proj_*), warnings, drone / weapon / evo / skill / relic / growth icons, terrain, props, pickups and UI.
- Claude sessions change code and docs in their own worktrees (.claude/worktrees/<name>, own branch); the main checkout E:\ArknightsSurvivors on main is only for the coordinator's merges and releases (docs/41 §3). Codex uses E:\ArknightsSurvivors\.worktrees\codex-art on codex/art.
- Worktree convention: .worktrees/ (ignored by Git). Do not change branches in the other agent's directory.
- Codex art scope: character and monster files in art/incoming/ (player_*, ally_*, e_*, boss*, bosses/, doctor, merchant, mizuki_*) and their handoff documentation. Claude scope: game/, implementation documentation, and every other file in art/incoming/ (fx_*, proj_*, evo_*, weapon_*, skill_*, relic_*, growth_*, terrain_*, prop_*, tiles, gem_*, chest, oil, jelly, slash, tentacle, drone_*, light). Coordinate before modifying the other's files. Update 2026-10-11 (user): selected high-visibility skill effects may be commissioned from Codex via a Claude-written FX brief (file names, frames/fps, frame size, origin, back/front layers, when it plays); Codex delivers assets + @2x + manifest + handoff only (no game/ edits), body-wrapping effects come as `_back` / `_front` layers sharing origin and frame index plus an unlayered `_orbit` fallback; Claude reviews and integrates. All other fx_* / proj_* / icons stay with Claude.
- Codex code scope (user 2026-10-17): Codex may also change game code, data and docs, on branches `codex/<topic>` cut from main (never on codex/art), following docs/106 §6: run `python tools/check.py --auto`, keep same-seed runs identical (docs/36 §3.2), deliver branch + commit hash; the coordinator merges. Codex does not merge main, ship, or edit AGENTS.md / CLAUDE.md / tools/ship.py.
- Commit only explicitly selected files belonging to your work; never sweep another agent's changes into a commit.
- Do not discard changes, force-push, reset --hard, or clean the other agent's work.
- Deliver art with a commit hash and affected paths. The coordinator reviews, then merges codex/art into main from a clean main checkout (docs/06). If conflicts occur, resolve deliberately; do not overwrite either side wholesale.
- Art under incoming is authoritative delivery. Refer to docs/05_art_handoff.md for file locations, naming and import rules; sprite dimensions and specs: docs/98_sprite_standard.md (all characters and monsters) and docs/87_art_spec.md (operator strips).
- Do not commit .godot/, build outputs, node_modules, credentials or local art backups.
- Automated runs must be silent: any launch with a `--xxx` user argument (autotest, balance, screenshots, gallery shots) mutes the Master bus in sfx.gd. Never remove that mute, and never add a test mode that bypasses it — the user works while tests run. Prefer `--headless` for anything that does not need a screenshot.
- Testing standard: docs/36_testing.md. Before committing game code or data, run `python tools/check.py --auto --jobs 3` (tiered by what changed: core contracts, smoke runs for the affected operators, same-seed reproducibility) plus your own regression items, and do not commit if anything fails; the full quick check runs once in the coordinator's `tools/ship.py` (docs/36 §1.1). Any SCRIPT ERROR or Parse Error counts as a failure.
- Launch test Godot processes only through tools/godot_runner.py (used by check.py and balance_run.py). It enforces a machine-wide cap (GODOT_MAX_PROCS) shared by all sessions; do not start extra batches outside it.
- Same seed must reproduce the same run. Gameplay randomness uses the seeded `g.rng` (shuffle with `g._shuffle`); visual-only randomness uses `g.vrng` or the global RNG. Never use `Array.shuffle()`, `pick_random()` or global `randf()` in gameplay code.
- Compare before/after only on the same code base. Balance A/B runs in the cloud (docs/36 §7.5.1: role sessions report the commit, the coordinator pushes and creates the run); same-seed TRACE comparisons use the cached baseline (`tools/trace_base.py`, docs/36 §3.2). Do not run A/B batches locally. Other sessions change operators on main all the time.
- Git is version control, not an agent messaging service. origin (GitHub) exists; pushing and releases follow docs/41 §3 and docs/33 (`tools/ship.py`).
