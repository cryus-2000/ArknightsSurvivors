cloud telemetry-p0 — 同 seed 对照验证结果
===========================================

结论（先说重点）：新提交 129254bf2 无法运行。telemetry.gd 在 _snap(t: float) 函数体内
使用了未声明的标识符 dt（第 322 行 `boss_win_acc += dt`、第 346 行 `boss_acc += dt`；
该函数只有参数 t，没有 dt），属于 GDScript 解析期错误（Parse Error），导致 game.gd /
title.gd 等依赖脚本全部编译失败，headless 进程不会退出，只会每帧刷
"Invalid call. Nonexistent function 'update' in base 'Nil'" 直到被外部杀死。
该提交自己的提交信息也写明「P0 遥测代码...已写未验证」。
因为这是解析期错误、与 seed/op/是否带 --telemetry=full 无关，必然在任何参数组合下
100% 复现，所以第 2 步只对 129254bf2 跑了 1/4 局（skadi）确认复现，未重复跑其余 3 局；
第 4、5 步（遥测体积/帧时开销，均要求在 129254bf2 上测）、第 3 步的逐行 diff 全部
因此无法进行。详见下方逐项记录。

5. 根因与建议
--------------
game/scripts/run/telemetry.gd 第 322、346 行在 `func _snap(t: float) -> void:`
内使用了 `dt`，但该函数签名只有 `t`，没有 `dt` 参数，也没有局部变量 dt。
需要改成函数内部自行从 t 推导时间增量（例如用上一次 _snap 的 t 做差），或者
给 _snap 加上 dt 参数并在调用处传入。修好编译错误之后，才能重新跑本轮全部
步骤（同 seed TRACE 对照、体积、帧时开销、--auto）。
