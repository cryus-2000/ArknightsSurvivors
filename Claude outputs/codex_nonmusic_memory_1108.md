# 手机网页非音乐内存路径复核 · 2026-11-08

审查代码为 `main 2d5838c3f9`。目标为 iPhone 15 Pro、中画质、同一页面连续打局。核对了运行时代码、素材文件头、已归档 Toy 包 `ed28cd083` 的实际 `index.js`，并复用了 11 月 8 日的 Edge 玩家流程对照。本轮没有新增 Safari 或 B 站 Toy 真机采样。下文 MiB 均按 1,048,576 字节计。

## 音效与语音

`Sfx` 是跨场景 Autoload。首次出发会预热当时 `streams` 中的全部音效。初始名单里的 172 个 WAV 合计 131.88 秒，按 24 kHz、双声道 Float32 解码约 **24.15 MiB**。其中 `OP_SFX` 的 85 个干员音合计 62.18 秒，约 **11.39 MiB**。按队伍预热时仍需保留通用音和实际用到的借音依赖。局中 `ensure()` 加入的音效也会留在表里。见 `game/scripts/sfx.gd:194,277,1333`。

语音首次请求会将 `AudioStream` 放进 `voice_streams`；真正注册成 WebAudio 样本则取决于播放路径。`voice_reset()` 停播、清队列，仍保留流。现有显式退样本逻辑按曲目查流，未覆盖历史语音。逐文件读到 237 段 OGG，源文件全是单声道，总时长 540.31 秒。直接检查归档 Toy `index.js`，`_godot_audio_sample_register_stream` 固定 `numberOfChannels=2` 并拷贝左右通道。**若全集都曾注册并同时保留**，24 kHz 下对应 **98.93 MiB**。这纠正了按源文件单声道估算的 49.5 MiB；实际一局只涉及其中一部分。分组日志 `sample_report()` 未遍历历史 `voice_streams`，有 JS 补丁时 `__syAudioMB` 的总量则按实际 AudioBuffer 去重。见 `game/scripts/sfx.gd:313,333,691,937,1151`、`tools/web/engine_patch.py:14`。

## 哪些数字能用于验收

旧 Toy 真机报告的首次峰值 600 MiB 中贴图为 442 MiB；另两局贴图为 343–344 MiB。三份报告的音频都在 135–137 MiB。已有 Edge 仿真在同一包、同一进入路径切换多项修复，走过图鉴时，开局贴图 **360 → 128 MiB**；直接出发时 **304 → 128 MiB**。包含显存及音频的开局读数分别是 **579 → 269**、**511 → 259 MiB**。这些是组合效果，无法从表中拆出某一个改动的净收益。依据为 `Claude outputs/codex_brief_mobile_1108.md` 和性能工作树的 `docs/319_ios_mem_1108.md` §1–2。

游戏内正式报告约每五秒采样引擎显存与 WebAudio 缓冲，无法覆盖 JS、虚拟文件、WASM 堆和宿主，也可能错过帧内的解码峰值。调试浮层可另外观察 WASM 容量。容量高水位、各子系统的峰值和进程总驻留不可直接相加。此前桌面 Edge 后期三人局已出现过同一测试中游戏报告约 438 MiB、WASM 容量最高约 418 MiB 的情况，两者分别记录即可。见 `game/scripts/core/perf_report.gd:94,180`、`game/scripts/core/perf_hud.gd:177`、`docs/305_perf_night_1107.md` §7。

## 修复顺序与复测

1. 优先集成已有的载入名单过滤，验证一次正常出发和一次中途招人。修复 `op_node` 的所有权：对局退出时由创建它的光学组件显式释放外置节点。回标题两帧后验证上一局 `WeakRef(op_node)` 失效且根窗口直接子节点数恢复；这个对象仍挂在树上，只看孤儿节点数会漏掉它。接着清图鉴条目、白图和仅上一局使用的干员光学贴图，保留共享与在用资源，按唯一纹理 RID 和尺寸核账。
2. 将敌人减半判定前移到 Web 构建，保留 6 张有差异的资源及原有祛雾、倍率逻辑。先比导入后的可见像素，再测同一敌人首次出现及淘汰后再出现的帧时和峰值。语音按实际已注册字节设置上限，淘汰时保护播放、淡出与合唱中的样本。
3. iPhone 15 Pro 的 Safari、B 站 Toy 分别测试。各自冷启，在同一页面跑固定编队、种子与操作的三局，再换队重跑。每轮记关闭图鉴、载入峰值、开局、后期同一战段、结算、回标题十秒、下一局开局，另测结算直接重开。对齐时点记录唯一贴图字节、注册音效与语音字节、对象计数、可取得的进程占用及页面是否重载。比较连续同队时的基线与换队后的台阶；同时保留后期三人局 P95 帧时和超过 33.3 ms 的帧数，核对节省内存有没有换来新的长帧。
